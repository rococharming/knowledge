# BlueOS开发 领域规则

## 领域概述

BlueOS（蓝河操作系统）应用层开发：UI 框架、前端框架、快应用（RPK）、开发工具链与工程实践

## 分类体系

wiki 页面按以下子目录组织：

- `summaries/` — 官方文档、技术文章、视频教程的摘要与核心要点
- `architecture/` — 框架架构、模块设计、系统架构图、数据流与分层设计
- `concepts/` — UI 框架概念：组件生命周期、响应式原理、布局系统、事件机制
- `implementations/` — 代码实现方案、核心代码、踩坑记录、Bug 修复、Workaround
- `research/` — 技术调研、方案预研、竞品分析、技术选型
- `comparisons/` — 技术方案对比：快应用 vs 小程序、前端框架选型、跨平台方案
- `guides/` — 开发流程、调试指南、构建配置、发布流程、最佳实践、CI 集成

## 标签体系

领域初始标签（统一使用英文，便于检索和 Dataview 查询）。标签是动态扩展的——以下只是种子标签，LLM 在 ingest 时会根据素材内容自动补充：

- `#blueos` — BlueOS 平台特性、版本变更、生态与发布动态
- `#ui-framework` — UI 框架：组件系统、布局、样式、动画、自定义组件
- `#frontend` — 前端框架：JS/TS 运行时、API 能力、模块化、状态管理
- `#quick-app` — 快应用（RPK）：规范、打包、签名、发布、运行环境
- `#devtools` — 开发工具链：IDE、CLI、模拟器、调试器、构建工具
- `#rpk` — RPK 包格式、构建配置、资源管理、性能优化
- `#components` — 内置组件库、第三方组件、组件封装与复用
- `#performance` — 性能优化：渲染性能、包体积、启动速度、内存管理

**标签添加原则**：
- 初始标签作为 ingest 时的参考基准
- 当素材涉及新的子主题时，自动创建新标签
- 定期 review 标签使用情况，合并过于细分的标签

## 特殊约定

- **RPK 规范跟踪**：涉及 RPK 规范的素材需标注版本号（如 RPK v1.2），并在页面中说明该版本的生效时间范围
- **IDE 版本对齐**：工具链相关内容需注明适用的 IDE 版本号，避免因版本差异导致操作失效
- **平台能力标注**：涉及 BlueOS 平台特有 API 或组件时，标注最低支持系统版本
