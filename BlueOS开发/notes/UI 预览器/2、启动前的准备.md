
## 目标

macOS 不能直接把 Rust 源码当成应用窗口运行。 为了看到 hello UI，我们最终需要得到两个可以被操作系统使用的产物：

![[assets/Pasted image 20260728153823.png]]

本项目需要做一些启动前准备，依赖分为两类：

- 开发环境依赖：把源码变成可执行产物，如`jax`、BlueOS NDK/SDK、`cmake`、`ninja`、`cargo` 和 `rustc`
- 应用运行产物：构建完成后真正参与运行，例如 `uipreviewer`、 `system_framework` 和 hello 的 `libapp.dylib`。

快速开始：

```bash
# 1. 安装依赖（自动下载 NDK + jax 构建工具）
pnpm install

# 2. 构建并运行 hello 示例
cargo run --bin run -- examples/hello
```

- `pnpm`：读取`package.json`和锁文件，下载项目声明的 Node 工具包，放进`node_modules`，并执行安装后的初始化脚本
- `blueos-pack`：它是 pnpm 下载的包，它向项目提供`jax`命令
- `jax`：理解 BlueOS 应用的目录和构建配置。`jax buildndk` 时，它组织 Cargo、CMake/Ninja 等工具，把 hello 构建成预览器可加载的动态库。
- `NDK / BlueOS SDK`：NDK（Native Development Kit），原生开发工具包。它提供构建本地二进制所需的 工具和平台资料。当前 runner 明确要求 `~/blueos_sdk/cmake/bin/cmake` 和 `ninja` 存在。
- `CMake + Ninja`：CMake 理解为“生成施工计划”，把 Ninja 理解为“按计划执行构建”。`jax`会调用它们。
- `Cargo + rustc`：Cargo 管理 Rust 工程并安排构建，rustc 真正编译 Rust 代码。 它们既用于构建桌面预览器，也参与构建 hello Rust 动态库。

pnpm 把 jax 送到项目中，jax 调度 NDK/SDK 和 Rust 工具链，这些工具共同产出 previewer 与 app。


## pnpm install

1. pnpm 读取项目清单

`package.json` 声明需要 `blueos-pack: "ndk"`； `pnpm-lock.yaml` 锁定实际版本，保证不同开发者尽量拿到同一套工具。

2. 下载并安装 blueos-pack

工具包进入 `node_modules`，同时在 `node_modules/.bin` 暴露 `jax` 命令 （Windows 对应 `jax.cmd`）。

3. 自动执行 jax init-ndk

这是 `package.json` 的 `postinstall` 脚本。 它负责下载或准备 BlueOS NDK/SDK，让后续 `jax buildndk` 有可调用的原生构建环境。

4. 形成执行 cargo run --bin run -- examples/hello 的环境

这条命令通常是**首次拉取仓库**、删除了 `node_modules`、或 `package.json`/`pnpm-lock.yaml` 发生变化时执行。它成功不等于 hello 已经构建，只表示工作台基本就绪。


## cargo run --bin run -- examples/hello

所以这条命令不是直接调用 hello 的入口。它先启动仓库自己的crates/ui_previewer/src/bin/run.rs)， 由这个 runner 代替你连续执行下面的工作。

1. 确认工作台可用：查找 `jax`，检查 `blueos_sdk` 中的 CMake/Ninja， 再检查 `cargo` 和 `rustc`。
2. 构建“容器”：uipreviewer：runner 执行 `cargo build --bin uipreviewer`， 在 macOS 生成 `target/debug/uipreviewer`。 它负责创建窗口和承载应用。
3. 构建“内容”：hello app：runner 在 hello 目录执行 `JAX_ABI=local jax buildndk`。 jax 读取示例的构建配置并产出 `dist/libs/local/libapp.dylib`。
4. 让容器和内容使用同一套 UI 运行时：runner 把刚构建的 `system_framework` 动态库同步到 hello 的 `src/libs/local`。先把它理解成 previewer 和 app 共用的“UI 发动机”。
5. 告诉操作系统去哪里找动态库：macOS 设置 `DYLD_LIBRARY_PATH`。这不是业务配置， 而是帮助进程找到 `system_framework`、Rust 动态库和 app 的地址清单。
6. 进入 native Rust UI 启动主线：runner 用 `UIPREVIEWER_DYLIB_APP_PATH` 指向 hello 动态库， 然后启动 `uipreviewer --native`。 previewer 最终加载 `app_start_main` 并把 hello UI 挂到窗口。
