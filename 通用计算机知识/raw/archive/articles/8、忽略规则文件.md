# 一、概述

前面已经学过，Git 会通过`git status`告诉我们工作区里发生了什么变化。

例如：

- 新增文件会显示为未跟踪
- 删除文件会显示为 deleted
- 重命名文件可能会先显示为删除旧文件、新增新文件

但是在真实项目里，并不是所有出现在工作区里的文件都应该交给 Git 管理。

比如这些文件：

```text
app.log
dist/
node_modules/
.DS_Store
.env
```

它们通常有几个特点：

| 特点 | 例子 |
| --- | --- |
| 可以重新生成 | `dist/`、`build/` |
| 每个人电脑上可能不一样 | IDE 配置、系统文件 |
| 文件数量多或体积大 | `node_modules/` |
| 可能包含敏感信息 | `.env` |

如果这些文件一直出现在`git status`里，就很容易干扰判断。

更麻烦的是，如果执行：

```shell
git add .
```

它们会被一起加入暂存区。

所以这一篇要解决的问题是：

> 哪些文件不应该让 Git 管，怎么让 Git 默认忽略它们。

# 二、从未跟踪文件开始

假设工作区里新增了一个日志文件：

```shell
touch app.log
```

执行：

```shell
git status -s
```

可以看到：

```text
?? app.log
```

这里的`??`表示`app.log`是未跟踪文件。

如果这个日志文件只是程序运行时临时生成的，就不应该提交到仓库。

当然，可以手动删除它：

```shell
rm app.log
```

但问题是，日志文件以后还可能继续生成。

这时更合适的做法不是反复删除，而是写一条忽略规则。

# 三、.gitignore

`.gitignore`是最常见的 Git 忽略规则文件。

它通常放在项目根目录，用来告诉 Git：

> 哪些未跟踪文件不需要纳入版本控制。

例如，在`.gitignore`中写入：

```gitignore
*.log
```

表示忽略所有以`.log`结尾的文件。

这时再执行：

```shell
git status -s
```

通常就不会再看到：

```text
?? app.log
```

因为`app.log`已经被`.gitignore`中的`*.log`规则忽略了。

需要注意：

> `.gitignore`本身需要提交到仓库。

因为它属于项目规则。团队其他人拉到这个项目后，也应该使用同一套忽略规则。

# 四、常见忽略规则

## 1、忽略某类文件

```gitignore
*.log
```

表示忽略所有`.log`结尾的文件。

例如：

```text
app.log
error.log
debug.log
```

这些文件都会被忽略。

## 2、忽略某个目录

```gitignore
dist/
```

表示忽略`dist`目录。

类似的目录还有：

```gitignore
build/
node_modules/
```

这类目录通常是编译产物或依赖安装目录，可以通过命令重新生成，不适合提交到仓库。

## 3、忽略某个具体文件

```gitignore
.env
```

表示忽略`.env`文件。

`.env`通常保存数据库密码、API key 等本地敏感配置，一般不应该提交。

如果项目需要说明有哪些环境变量，可以提交一个示例文件：

```text
.env.example
```

真正保存本地密钥的`.env`则写入`.gitignore`。

## 4、取消忽略

如果前面忽略了一类文件，但其中某个文件想保留，可以使用`!`取反。

例如：

```gitignore
*.log
!important.log
```

含义是：忽略所有`.log`文件，但不要忽略`important.log`文件。

也就是说，`app.log`会被忽略，但`important.log`仍然可以被 Git 看到。

# 五、查看忽略是否生效

默认情况下，`git status`不会显示被忽略的文件。

如果想确认哪些文件被忽略了，可以执行：

```shell
git status --ignored
```

例如，`.gitignore`里有：

```gitignore
*.log
```

工作区里有：

```text
app.log
```

执行：

```shell
git status --ignored
```

可以看到：

```text
Ignored files:
        app.log
```

如果想知道某个文件为什么被忽略，可以执行：

```shell
git check-ignore -v app.log
```

输出可能类似：

```text
.gitignore:1:*.log    app.log
```

这表示：忽略规则来自`.gitignore`文件的第1行的`*.log`规则，忽略的文件为`app.log`。

# 六、已经被跟踪的文件不会被忽略

这是`.gitignore`里最容易误解的地方：

> `.gitignore`只影响未跟踪文件。

假设`config.json`已经被 Git 跟踪了。

后来在`.gitignore`里加入：

```gitignore
config.json
```

这并不会让 Git 停止跟踪`config.json`。

因为 Git 已经知道这个文件了。后续它发生修改，`git status`仍然会显示它。

如果想让 Git 不再跟踪它，但保留本地文件，可以执行：

```shell
git rm --cached config.json
```

这个命令前一篇已经见过，它的作用是：

| 区域 | 结果 |
| --- | --- |
| 暂存区 / 索引 | 移除`config.json` |
| 工作区 | 继续保留`config.json`文件 |

需要注意：

> `git rm --cached`不是删除电脑上的文件，只是让 Git 以后不再跟踪它。

所以完整流程通常是：

```shell
echo "config.json" >> .gitignore
git rm --cached config.json
git add .gitignore
git commit -m "stop tracking config.json"
```

# 七、.git/info/exclude

除了`.gitignore`，Git 还有一个本地忽略文件：

```text
.git/info/exclude
```

它的写法和`.gitignore`类似，也可以写忽略规则。

区别是：

| 文件 | 适合放什么规则 | 是否提交到仓库 |
| --- | --- | --- |
| `.gitignore` | 项目通用忽略规则 | 通常会提交 |
| `.git/info/exclude` | 只和自己电脑有关的本地规则 | 不会提交 |

例如，你自己临时生成的本地测试文件：

```text
local-test.txt
```

如果只想在当前仓库忽略它，不想影响团队其他人，可以把规则写到：

```text
.git/info/exclude
```

# 八、小结

这一篇可以和前面的操作连起来理解：

| 场景 | 处理方式 |
| --- | --- |
| 文件只是临时生成，不想让它出现在`git status`里 | 写入`.gitignore` |
| 文件已经被 Git 跟踪，但以后不想再跟踪 | `git rm --cached <file>` |
| 规则是团队共享的 | 写入`.gitignore` |
| 规则只对自己本地有效 | 写入`.git/info/exclude` |

常用命令：

| 命令 | 作用 |
| --- | --- |
| `git status --ignored` | 查看被忽略的文件 |
| `git check-ignore -v <file>` | 查看某个文件为什么被忽略 |

最重要的一点是：

> `.gitignore`不是用来忽略所有文件的，它只影响还没有被 Git 跟踪的文件。
