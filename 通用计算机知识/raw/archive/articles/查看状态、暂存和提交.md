# 一、本地操作闭环

Git 本地开发的基本闭环是：查看状态、暂存修改、提交历史。

![[assets/Pasted image 20260722014745.png|600]]

这条流程的重点是：先确认改了什么，再决定哪些内容进入暂存区，最后把暂存区保存为一次提交。

# 二、Git 适合管理什么文件

Git 可以管理文本文件，也可以管理二进制文件，但最擅长的是文本文件。

| 类型 | 示例 | Git 体验 |
|---|---|---|
| 文本文件 | `.md`、`.py`、`.rs`、`.json` | 能精确显示行级差异 |
| 配置文件 | `.yaml`、`.toml`、`.ini` | 适合版本管理 |
| 二进制文件 | `.png`、`.pdf`、`.xlsx` | 通常只能判断文件是否变化 |
| 大文件 | 视频、静态库、设计稿 | 通常考虑 Git LFS |

对于二进制文件，Git 很难展示具体哪一行或哪一块被修改；如果项目有大量大文件，应考虑 Git LFS 或其他资产管理方案。

# 三、使用 `git status`

## 1、普通状态查看

```shell
git status
```

它主要展示当前分支、工作区变化、暂存区变化、未跟踪文件和下一步操作提示。

示例：

```shell
echo "hello" > b.txt
git status
```

![[assets/Pasted image 20260722012951.png|600]]

新文件会出现在：

```text
Untracked files:
        b.txt
```

加入暂存区后：

```shell
git add b.txt
git status
```

![[assets/Pasted image 20260722013020.png|600]]

会出现在：

```text
Changes to be committed:
        new file: b.txt
```

## 2、简洁状态查看

```shell
git status -s
```

简洁状态格式通常是：

```text
XY path
```

| 位置 | 含义 |
|---|---|
| `X` | 暂存区相对最近一次提交的状态 |
| `Y` | 工作区相对暂存区的状态 |

常见输出：

| 输出         | 含义                    |
| ---------- | --------------------- |
| `?? b.txt` | 未跟踪文件                 |
| `A  b.txt` | 新文件已暂存                |
| ` M b.txt` | 工作区有未暂存修改             |
| `M  b.txt` | 修改已暂存                 |
| `MM b.txt` | 同一文件既有已暂存修改，又有新的未暂存修改 |

# 四、使用 `git add`

## 1、暂存指定文件

```shell
git add b.txt
```

`git add` 把工作区中指定路径的当前内容写入暂存区。它可以重复执行，每次都会刷新暂存区中对应文件的内容。

## 2、暂存当前目录范围

```shell
git add .
```

`.` 表示当前目录及其子目录。若在仓库根目录执行，通常会处理整个仓库的变化；若在子目录执行，通常只处理该子目录范围内的变化。

## 3、`git add` 不只是添加新文件

`git add` 的本质是暂存变更，因此它可以处理：

| 变更类型 | 示例 |
|---|---|
| 新增文件 | 新建 `a.txt` 后执行 `git add a.txt` |
| 修改文件 | 修改已跟踪文件后执行 `git add a.txt` |
| 删除文件 | 删除已跟踪文件后执行 `git add a.txt` |

# 五、使用 `git commit`

## 1、创建一次提交

```shell
git commit -m "add b.txt"
```

`git commit` 会把暂存区内容保存为一次新提交。提交信息应简洁说明本次提交做了什么。

## 2、提交前检查暂存区

提交前通常先执行：

```shell
git status
git diff --staged
```

| 命令 | 作用 |
|---|---|
| `git status` | 查看哪些内容已经暂存 |
| `git diff --staged` | 查看暂存区相对最近一次提交的具体差异 |

这样可以减少漏提交和误提交。

## 3、使用编辑器编写提交信息

不带 `-m` 时：

```shell
git commit
```

Git 会打开默认编辑器。编辑器配置见 [[1、Git 安装与配置|Git 安装与配置]]。

## 4、多行提交信息

可以通过多个 `-m` 写标题和正文：

```shell
git commit -m "add user login page" -m "Create login form and basic validation."
```

实际提交信息会形成：

```text
add user login page

Create login form and basic validation.
```

第一行适合写“做了什么”，正文适合补充“为什么这样做”。

# 六、查看已跟踪文件

## 1、列出 Git 正在跟踪的文件

```shell
git ls-files
```

它列出 Git 索引中记录的文件，通常包括已经提交过的文件和已经加入暂存区的文件。它不同于 `ls`：`ls` 看工作区目录，`git ls-files` 看 Git 当前管理的路径。

## 2、查看索引底层信息

```shell
git ls-files --stage
```

输出中常见字段包括文件模式、对象哈希、阶段编号和路径。普通文件模式常见有：

| 模式       | 含义        |
| -------- | --------- |
| `100644` | 普通文件，不可执行 |
| `100755` | 普通文件，可执行  |
| `120000` | 符号链接      |
| `160000` | Git 子模块   |
对于`100644`：

- `100`为文件类型，这里是普通文件
- `644`是文件权限，即`rw-r--r--`

## 3、查看未跟踪且未被忽略的文件

```shell
git ls-files --others --exclude-standard
```

它会列出未被 Git 跟踪、且没有被标准忽略规则排除的文件。忽略规则见 [[8、忽略规则文件|忽略规则文件]]。

两个参数的含义是：

| 参数 | 含义 |
|---|---|
| `--others` | 列出不在 Git 索引里的“其他文件”，也就是还没有被 Git 跟踪的文件 |
| `--exclude-standard` | 使用 Git 的标准忽略规则，把 `.gitignore`、`.git/info/exclude` 和全局 ignore 配置匹配到的文件排除掉 |

所以这条命令可以理解为：只列出当前工作区中“未跟踪、且未被忽略”的文件。

# 七、查看提交历史

## 1、完整历史

```shell
git log
```

输出通常包含提交哈希、作者、时间和提交信息。提交哈希很长，日常一般使用前几位短哈希即可，只要在当前仓库中能唯一识别。

![[assets/Pasted image 20260722014546.png|600]]

## 2、简洁历史

```shell
git log --oneline
```

![[assets/Pasted image 20260722014615.png|600]]

更多历史查看方式见 [[9、灵活查看提交历史|灵活查看提交历史]]。

# 八、小结

日常本地提交可以形成固定习惯：

```shell
git status
git add <path>
git diff --staged
git commit -m "message"
git log --oneline -5
```

这套流程把“看清楚、选进去、再提交”连在一起，是后续撤销、改提交和排查历史的基础。
