# 字符编码基础

字符编码解决的核心问题是：**把人类可读的字符转换成计算机可存储和传输的字节数据**。

## 三层概念

| 概念 | 含义 | 示例 |
|---|---|---|
| 字符 | 人类看到的符号 | `A`、`中`、`🙂` |
| 字符集 | 规定有哪些字符，以及每个字符对应哪个编号 | ASCII、Unicode |
| 编码方式 | 规定字符编号如何转换成字节存储 | UTF-8、UTF-16、GBK、Big5 |

字符集回答"有哪些字符、编号是多少"，编码方式回答"这些编号如何变成字节"。

## ASCII

ASCII（American Standard Code for Information Interchange）是面向英文环境的 7 位编码标准，共 128 个字符。

| 范围 | 内容 |
|---|---|
| `0x00` ~ `0x1F` | 控制字符 |
| `0x20` | 空格 |
| `0x21` ~ `0x7E` | 可显示字符 |
| `0x7F` | 删除控制字符 `DEL` |

- 数字 `0~9`：`0x30` ~ `0x39`
- 大写字母 `A~Z`：`0x41` ~ `0x5A`
- 小写字母 `a~z`：`0x61` ~ `0x7A`

**局限**：仅覆盖英文字符，无法表示中文、日文、表情符号等。

## ANSI 与本地编码

`ANSI` 在 Windows 语境中并非固定编码，而是指代**当前系统区域设置对应的本地代码页编码**。

| 地区/语言 | 常见 ANSI 代码页 |
|---|---|
| 简体中文 | `GBK` / `CP936` |
| 繁体中文 | `Big5` / `CP950` |
| 西欧语言 | `Windows-1252` |

### GB2312 / GBK / Big5

| 编码 | 用途 | 关系 |
|---|---|---|
| `GB2312` | 早期简体中文 | 覆盖常用简体汉字 |
| `GBK` | 简体中文 Windows 常见 | 向下兼容 GB2312，收录更多 |
| `Big5` | 繁体中文 | 主要用于繁体中文环境 |

本地编码大多兼容 ASCII（`0x00~0x7F` 范围一致），但超出该范围后解释完全不同。

**核心问题**：同一串字节在不同地区环境中可能被解释成不同字符，不适合跨语言、跨地区、跨系统的文本交换。

## Unicode

Unicode 的目标是**为世界上尽可能多的字符分配统一且唯一的编号**（码点，code point）。

- `U+0041` → `A`
- `U+4E2D` → `中`
- `U+1F642` → `🙂`

**重要区分**：Unicode 本身是字符集，规定了字符与码点的映射，但不等于具体的文件存储格式。码点如何变成字节，需要具体的编码方式来实现，如 [[UTF-8]] 和 [[UTF-16]]。
