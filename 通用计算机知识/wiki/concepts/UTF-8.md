# UTF-8

UTF-8 是目前最常用的 Unicode 编码方式。核心特点是：**使用 1~4 个字节表示一个 Unicode 字符，并且兼容 ASCII**。

## 编码长度

| Unicode 码点范围 | UTF-8 字节数 |
|---|---|
| `U+0000` ~ `U+007F` | 1 字节 |
| `U+0080` ~ `U+07FF` | 2 字节 |
| `U+0800` ~ `U+FFFF` | 3 字节 |
| `U+10000` ~ `U+10FFFF` | 4 字节 |

ASCII 范围内的字符在 UTF-8 中与 ASCII 完全一致。

## 字节格式

| 字节数 | 二进制格式 |
|---|---|
| 1 字节 | `0xxxxxxx` |
| 2 字节 | `110xxxxx 10xxxxxx` |
| 3 字节 | `1110xxxx 10xxxxxx 10xxxxxx` |
| 4 字节 | `11110xxx 10xxxxxx 10xxxxxx 10xxxxxx` |

- 1 字节字符以 `0` 开头
- 多字节字符的首字节用连续 `1` 的个数表示总字节数
- 后续字节都以 `10` 开头

这种设计使 UTF-8 具有较好的**自同步能力**：即使中间丢失或损坏某个字节，也较容易找到下一个合法字符的起始位置。

## 编码示例

字符 `中` 的 Unicode 码点为 `U+4E2D`，二进制：`01001110 00101101`。

位于 `U+0800~U+FFFF`，需 3 字节。按格式填充：

```
11100100 10111000 10101101
```

即十六进制 `E4 B8 AD`。

## 字节序

UTF-8 的编码单位是单字节，**不存在字节序问题**。没有 `UTF-8 LE` 或 `UTF-8 BE` 的说法。

## BOM

UTF-8 文件也可能带 BOM（`EF BB BF`），但并非必须。

| 形式 | 说明 |
|---|---|
| UTF-8 无 BOM | 更常见，适合跨平台、代码文件、配置文件 |
| UTF-8 with BOM | 某些 Windows 软件可能生成或依赖 |

在编程和配置文件场景中，推荐统一使用 **UTF-8 without BOM**，避免某些程序将 BOM 误当成文件开头的真实字符。

## 优势

- **兼容 ASCII**：英文文本不浪费空间
- **无字节序问题**：单字节为单位
- **自同步能力较好**：字节错位后较易恢复
- **跨平台通用**：互联网和文本文件的事实标准

## 与 UTF-16 对比

相比 [[UTF-16]]，UTF-8 没有字节序问题，ASCII 兼容性好，空间效率更优，因此成为现代文本文件和网络传输的主流选择。
