# Git 版本控制系统

Git 是分布式版本控制系统（Distributed Version Control System）。它将项目文件在不同时间点的状态保存为可追溯的提交（commit），由 Git 管理的目录称为仓库（repository 或 repo）。

## 核心价值

| 能力 | 用途 |
|---|---|
| 版本记录 | 保留文件变化与提交历史 |
| 差异比较 | 比较文件、提交或分支之间的差异 |
| 回退与恢复 | 回到历史提交，或从其中恢复内容 |
| 分支管理 | 在彼此独立的开发线上并行工作 |
| 协作 | 通过远程仓库交换提交并协同开发 |

可以把一次提交理解为项目在某个时刻的快照。历史查看、分支切换与协作等日常操作，都是围绕这些快照组织的。

## 仓库起点

新的本地项目可用 `git init` 初始化；已有远程项目可用 `git clone` 连同其版本历史一起获取。两种方式都会得到 Git 仓库，但后者还会将克隆来源设为默认远程别名 `origin`。具体步骤与验证方式见 [[Git 仓库创建与验证]]。

## 本地提交模型

Git 的本地提交不是把工作区文件直接写入历史，而是先把下一次提交要包含的内容放进暂存区，再由暂存区生成提交。工作区、暂存区和本地仓库之间的关系，以及 `git status`、`git diff` 的状态判断方式，见 [[Git 工作区域与文件状态]]；完整的查看状态、暂存、检查差异、提交和回看历史流程见 [[Git 本地提交流程]]。

## 使用前的基础设置

首次使用应配置提交身份、为新仓库选定默认初始分支，并设置 Git 需要编辑提交信息时使用的编辑器。配置有 `system`、`global`、`local` 和可选的 `worktree` 等作用域；当前仓库的 `local` 设置通常会覆盖用户级的 `global` 设置。

具体安装、配置与排错步骤见 [[Git 安装与首次配置]]。
