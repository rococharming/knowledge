# Git 忽略规则

本文介绍 [[Git]] 中如何用 `.gitignore` 让 Git 默认忽略某些文件，以及查看忽略是否生效、停止跟踪已提交文件、本地忽略文件等用法。

## 核心内容

### 为什么需要忽略

工作区里有些文件不该交给 Git 管理（编译产物、依赖目录、日志、本地敏感配置），它们会让 `git status` 噪音变大，且容易被 `git add .` 误提交。解决思路是写忽略规则，而非反复手动删除。

### .gitignore 基本用法

`.gitignore` 放在项目根目录，**本身需要提交到仓库**（团队共享）。常见规则：

| 规则 | 含义 |
|------|------|
| `*.log` | 忽略所有 `.log` 文件 |
| `dist/` | 忽略目录 |
| `.env` | 忽略具体文件（敏感配置，可提交 `.env.example` 作示例） |
| `!important.log` | `!` 取反，取消忽略某文件 |

详见 [[Gitignore]]。

### 查看忽略是否生效

| 命令 | 作用 |
|------|------|
| `git status --ignored` | 列出被忽略的文件 |
| `git check-ignore -v <file>` | 查看某文件为什么被忽略（显示来源文件、行号、匹配规则） |

### 已跟踪文件不会被忽略

`.gitignore` **只影响未跟踪文件**。已跟踪文件即使加入 `.gitignore`，Git 仍继续追踪。停止跟踪需 `git rm --cached <file>`（保留工作区文件），配合 `.gitignore` + 提交完成。

详见 [[Gitignore]] 的「停止跟踪已提交的文件」一节。

### .git/info/exclude 本地忽略

| 文件 | 适用 | 是否提交 |
|------|------|----------|
| `.gitignore` | 团队共享的项目规则 | 提交 |
| `.git/info/exclude` | 只对自己电脑有效的本地规则 | 不提交 |
