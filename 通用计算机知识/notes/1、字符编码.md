# 一、概述

字符编码解决的是一个核心问题：**如何把人类可读的字符，转换成计算机可以存储和传输的字节数据**。

计算机底层只能处理0和1的二进制数据。文本中的字母、数字、标点、汉字、表情符号等，最终都必须转换成字节序列，才能保存到文件、通过网络传输，或者被程序读取。

字符编码相关概念容易混淆，主要是因为这里至少涉及三层含义：

|概念|含义|示例|
|---|---|---|
|字符|人类看到的符号|`A`、`中`、`🙂`|
|字符集 / 符号集|规定有哪些字符，以及每个字符对应哪个编号|ASCII、Unicode|
|编码方式|规定字符编号如何转换成字节存储|UTF-8、UTF-16、GBK、Big5|
> 字符集规定“有哪些字符，每个字符编号是多少”，编码方式规定“这些编号如何变成字节”。

例如字符 `中` 在 Unicode 中的码点是 `U+4E2D`，但它在不同编码方式下的字节表示不同：

|编码方式|字节表示|
|---|---|
|UTF-8|`E4 B8 AD`|
|UTF-16 BE|`4E 2D`|
|UTF-16 LE|`2D 4E`|
|GBK|`D6 D0`|
所以，讨论字符编码时不能只说“这是Unicode”，还要说明具体使用的`UTF-8`、`UTF-16`，还是其他编码方式。



# 二、ASCII编码

## 1、ASCII 的基本定位

`ASCII` 是 `American Standard Code for Information Interchange` 的缩写，即“美国信息交换标准代码”。

ASCII 是早期面向英文环境设计的一套字符编码标准，主要用于表示：

- 英文字母
- 数字
- 英文标点
- 控制字符

ASCII使用7位二进制表示字符，因此最多可以表示 `2^7 = 128`个字符，编号范围是`0x00 ~ 0x7F`。

虽然ASCII只需要7位，但在现代计算机中，**数据通常按字节处理**，所以一个ASCII字符一般存放在一个字节中，其中最高位为0。


## 2、ASCII 码表的范围划分

ASCII 的 128 个字符可以大致分为控制字符和可显示字符：

| 范围              | 内容           |
| --------------- | ------------ |
| `0x00` ~ `0x1F` | 控制字符         |
| `0x20`          | 空格           |
| `0x21` ~ `0x7E` | 可显示字符        |
| `0x7F`          | 删除控制字符 `DEL` |
 `0x20` 是空格，虽然在屏幕上看不见，但它属于文本中的实际字符。

`0x7F` 是 `DEL`，即删除控制字符。它来源于早期纸带、电传打字机等设备环境，用于表示删除或擦除某个位置上的字符。现代文本处理里很少直接使用它，但它仍然保留在 ASCII 表中，属于历史遗留控制字符。

其中：

- 数字`0 ~ 9`的ASCII码为`0x30 ~ 0x39`
- 大写英文字母`A ~ Z`的ASCII码为`0x41 ~ 0x5A`
- 小写英文字母`a ~ z`的ASCII码为`0x61 ~ 0x7A`


## 3、ASCII 的局限

ASCII 只覆盖英文环境中常见的字符，无法表示中文、日文、韩文、希腊字母、数学符号、表情符号等大量字符。因此，随着计算机在不同语言环境中普及，ASCII 不再够用，各地区开始设计自己的扩展编码方案。


# 三、ANSI和本地编码

## 1、ANSI的实际含义

在字符编码语境中，`ANSI`这个词比较容易误解。

严格来说，`ANSI` 是美国国家标准协会的名称，不是某一种具体编码。但在 Windows 语境中，很多软件把 `ANSI` 作为一个习惯说法，用于指代**当前系统区域设置所对应的本地代码页编码**。

也就是说，`ANSI`不是一个固定编码，而是一个依赖于系统语言和地区设置的编码别名。

例如：

| 地区 / 语言环境    | 常见 ANSI 代码页      |
| ------------ | ---------------- |
| 简体中文 Windows | `GBK` / `CP936`  |
| 繁体中文 Windows | `Big5` / `CP950` |
| 西欧语言 Windows | `Windows-1252`   |
所以，同一个“ANSI 文件”，在不同语言环境下可能会用不同编码解释。


## 2、ANSI与ASCII的关系

很多本地编码都兼容`ASCII`。也就是说，对于`0x00 ~ 0x7F`范围内的字节，它们和ASCII的含义保持一致。

例如，在 GBK 中，`0x41`仍然表示`A`，`0x30`仍然表示`0`，`0x20`仍然表示空格。

但超过`ASCII`范围之后，不同编码的解释可能就完全不同：

> ANSI对应的是某个本地代码页，不同代码页的编码规则不同，有些是单字节编码，有些是多字节编码。

对于简体中文环境GBK，ASCII字符1字节，汉字通常2字节。


## 3、GB2312、GBK、BIG5

中文环境中常见的本地编码包括`GB2312`、`GBK`以及`BIG5`。

|编码|主要用途|关系|
|---|---|---|
|`GB2312`|早期简体中文编码|覆盖常用简体汉字|
|`GBK`|简体中文 Windows 常见编码|向下兼容 GB2312，收录字符更多|
|`Big5`|繁体中文常见编码|主要用于繁体中文环境|
例如字符`中`，GBK编码的字节表示为`D6 D0`。

## 4、ANSI的主要问题

ANSI / 本地编码最大的问题：**同一串字节在不同地区环境中可能被解释成不同字符**。

例如，一个在简体中文 Windows 下用 GBK 保存的文本，如果拿到繁体中文或西欧语言环境中按其他代码页打开，就可能出现乱码。

乱码的本质通常是：

> 写入文件时使用了一种编码，读取文件时却使用了另一种编码。

因此，ANSI不适合跨语言、跨地区、跨系统的文本交换。


# 四、Unicode

## 1、Unicode的基本定位

为了解决各地区编码不统一的问题，`Unicode`出现了。

Unicode的目标是：

> 为世界上尽可能多的字符分配统一且唯一的编号

这个编号通常称为**码点**，英文是`code point`。

示例：

- `U+0x41`   ->   `A`
- `U+4E2D`   ->  `中`
- `U+1F642` -> `🙂`


## 2、Unicode不是具体的存储方式

需要特别注意：

> Unicode 本身主要是字符集 / 编码字符集，不等于某一种具体的文件存储格式。

Unicode规定了字符对应的码点，但这些码点如何变成字节，还需要具体的编码方式来实现。

常见的Unicode编码方式包括：

|编码方式|特点|
|---|---|
|`UTF-8`|变长编码，使用 1 ~ 4 字节，互联网和文本文件中最常见|
|`UTF-16`|变长编码，使用 2 或 4 字节，内部会涉及字节序问题|
|`UTF-32`|固定 4 字节编码，简单但非常浪费空间|

# 五、UTF-16

## 1、UTF-16的基本特点

`UTF-16` 是 Unicode 的一种编码方式。它不是简单地“所有字符都用 2 字节表示”。更准确地说：

> UTF-16使用16位编码单元。常见字符通常用2字节表示，超出基本多文种平面的字符需要4字节表示。

Unicode 中的字符可以分布在不同范围。早期常用字符大多位于 `BMP`，即基本多文种平面，范围是`U+0000 ~ U+FFFF`。

这些字符在`UTF-16`中通常用2字节表示。

但一些字符，例如很多表情符号、古文字、较少见字符，码点超过 `U+FFFF`，UTF-16 需要使用一对代理项，即 `surrogate pair`，总共 4 字节表示。

所以，**UTF-16 也是一种变长编码**，只不过它的基本单位是 16 位。


## 2、UTF-16 的字节序

因为 UTF-16 的基本编码单元是 2 字节，所以它涉及字节序问题。

同一个16位数值，在内存或文件中可以有两种存放顺序：

|名称|含义|
|---|---|
|`UTF-16 BE`|Big Endian，大端序，高字节在前|
|`UTF-16 LE`|Little Endian，小端序，低字节在前|

例如字符 `A` 的 Unicode 码点是 `U+0041`。

| 编码方式      | 字节表示    |
| --------- | ------- |
| UTF-16 BE | `00 41` |
| UTF-16 LE | `41 00` |

字符 `中` 的 Unicode 码点是 `U+4E2D`。

| 编码方式      | 字节表示    |
| --------- | ------- |
| UTF-16 BE | `4E 2D` |
| UTF-16 LE | `2D 4E` |

## 3、BOM与UTF-16文件识别

`BOM`是`Byte Order Mark`的缩写，即字节序标记。

在UTF-16文件开头，常见BOM如下：

| 编码        | BOM     |
| --------- | ------- |
| UTF-16 LE | `FF FE` |
| UTF-16 BE | `FE FF` |

BOM 的作用是告诉读取程序：这个文件使用的是 UTF-16，并且字节序是大端还是小端。

例如：

```text
FF FE 41 00
```

通常可以解释为：UTF-16 LE 编码的 A。

需要注意：

> BOM 是文件层面的标记，不是每个字符都有的内容。


## 4、UTF-16的问题

UTF-16的主要问题包括：

- 字节序问题：需要区分 `UTF-16 LE`还是`UTF-16 BE`。
- ASCII空间浪费：英文字符也要占2字节
- 与C字符串不友好：ASCII字符在UTF-16中通常包含00字节，容易与C风格的字符串结束符搞混
- 不是所有字符都 2 字节：超过 `U+FFFF` 的字符需要 4 字节，容易造成误解
- 容错性较差：如果字节错位，后续内容可能较难恢复解析

所以，UTF-16 在一些系统内部和历史平台中仍然常见，但现代文本文件和网络传输中，更多使用 UTF-8。


# 六、UTF-8

## 1、UTF-8的基本定位

`UTF-8`是目前最常用的`Unicode`编码方式。它的核心特点是：

> 使用 1 ~ 4 个字节表示一个Unicode字符，并且兼容ASCII。

UTF-8 的编码长度大致如下：

| Unicode 码点范围           | UTF-8 字节数 |
| ---------------------- | --------: |
| `U+0000` ~ `U+007F`    |      1 字节 |
| `U+0080` ~ `U+07FF`    |      2 字节 |
| `U+0800` ~ `U+FFFF`    |      3 字节 |
| `U+10000` ~ `U+10FFFF` |      4 字节 |
ASCII 范围内的字符，在 UTF-8 中和 ASCII 完全一致。

## 2、UTF-8的字节格式

UTF-8是变长编码，不同长度的字符有不同的字节格式。

|字节数|二进制格式|
|---|---|
|1 字节|`0xxxxxxx`|
|2 字节|`110xxxxx 10xxxxxx`|
|3 字节|`1110xxxx 10xxxxxx 10xxxxxx`|
|4 字节|`11110xxx 10xxxxxx 10xxxxxx 10xxxxxx`|

- 1字节字符以`0`开头
- 多字节字符的首字节用连续的`1`表示总字节数
- 后续字节都以`10`开头

例如：

```text
1110xxxx 10xxxxxx 10xxxxxx
```

表示这是一个3字节的UTF-8字符。

这种设计使得UTF-8具有较好的**自同步能力**。即使中间丢失或损坏了某个字节，程序也比较容易找到下一个合法字符的起始位置。


## 3、UTF-8编码过程示例

以字符`中`为例，其`Unicode`码点是`U+4E2D`。

二进制表示为：`01001110 00101101`

根据UTF-8的编码规则，`U+4E2D`位于`U+0800~U+FFFF`，因此编码的字节数为3字节。

填充为：

```text
11100100 10111000 10101101
```

转换成十六进制：

```text
E4 B8 AD
```

所以，字符 `中` 的 UTF-8 编码是`E4 B8 AD`。


## 4、UTF-8的字节序

UTF-8 的编码单位是单字节，因此不像 UTF-16 那样需要区分大端序和小端序。

例如字符 `中` 的 UTF-8 字节是：

```text
E4 B8 AD
```

它在文件中就是按这个顺序存储：

```text
低地址 ─────────────▶ 高地址
 E4       B8       AD
```

不需要写成 `AD B8 E4`，也不存在 `UTF-8 LE` 或 `UTF-8 BE` 这种常规说法。


## 5、UTF-8 BOM

UTF-8文件也可能带BOM，但这不是必须的。

UTF-8 BOM 是：

```text
EF BB BF
```

UTF-8 BOM 的作用主要是帮助某些程序识别文件编码，但由于 UTF-8 本身没有字节序问题，所以 BOM 对 UTF-8 来说并不是必需的。

常见情况是：

| 形式             | 说明                    |
| -------------- | --------------------- |
| UTF-8 无 BOM    | 更常见，尤其适合跨平台、代码文件、配置文件 |
| UTF-8 with BOM | 某些 Windows 软件可能生成或依赖  |
在编程和配置文件场景中，通常更推荐使用：

```text
UTF-8 without BOM
```

因为有些程序会把 BOM 当成文件开头的真实字符处理，从而导致解析问题。


## 6、UTF-8的优势

UTF-8 成为主流编码，主要因为它同时满足了几个重要需求：

- 兼容ASCII，节省英文文本空间
- 无字节序问题
- 自同步能力较好
- 跨平台通用
