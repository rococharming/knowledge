# 一、文件管理

文件管理是指在电脑上创建、命名、移动、搜索、删除和组织文件的过程。对日常使用来说，它决定你能不能快速找到资料；对开发来说，它决定项目是否容易维护、协作和部署。

文件管理的核心不是记住某个按钮在哪里，而是理解三个问题：

- **文件放在哪里**：路径和文件夹结构是否清楚。
- **文件叫什么**：文件名是否能表达用途。
- **文件属于哪一类**：扩展名是否能让程序正确识别和打开。

这些能力建立在 [[1、计算机基础概览|计算机基础]] 的存储和开发工具基础之上：磁盘负责长期保存文件，文件管理器负责让用户以可视化方式管理这些文件。

# 二、文件管理器

## 1、核心职责

文件管理器是操作系统提供的可视化工具，用来浏览、搜索和管理文件与文件夹。

| 系统 | 默认文件管理器 | 常见用途 |
|---|---|---|
| Windows | File Explorer | 浏览文件夹、搜索文件、复制、移动、删除、固定常用位置 |
| macOS | Finder | 浏览本地和远程文件、预览文件、使用标签和智能文件夹组织内容 |

文件管理器可以理解成“文件系统的地图”。真实文件保存在磁盘上，文件管理器提供路径、图标、侧边栏、搜索框、右键菜单等界面，让用户更容易操作它们。

## 2、路径与侧边栏

文件夹也常被称为目录（directory）。目录是一种容器，用来保存文件和其他目录。多个目录一层套一层，就形成路径。

示例：

```text
Documents/
└── web-practice/
    ├── index.html
    └── css/
        └── main.css
```

这里的 `Documents/web-practice/css/main.css` 就是一条路径，表示 `main.css` 位于 `css` 文件夹中，而 `css` 又位于 `web-practice` 文件夹中。

Windows 的 File Explorer 和 macOS 的 Finder 都有侧边栏，用来快速进入常用位置，例如桌面、文档、下载、最近使用、收藏文件夹或标签。侧边栏本质上是“快捷入口”，不是文件真正只能存在的地方。

# 三、基本操作

## 1、创建与命名

创建文件和文件夹时，先确认当前位置。因为新建对象通常会出现在当前打开的文件夹里。

| 操作 | Windows | macOS |
|---|---|---|
| 创建文件夹 | File Explorer 的 New / 右键 New Folder | Finder 中右键 New Folder |
| 创建文件 | 可在 File Explorer 中 New，也可在应用内创建 | 通常先在应用内创建，再保存到指定位置 |
| 重命名 | Rename / 右键 Rename / <kbd>F2</kbd> | 选中文件名后改名，或右键 Rename |
| 保存文件 | 由具体应用完成 | 常用 <kbd>Command</kbd> + <kbd>S</kbd> |

需要注意的是，macOS 的 Finder 默认不直接提供“新建任意文件”的入口。创建文本、图片、文档等文件时，通常先打开对应应用，再通过保存对话框选择文件名和位置。

## 2、移动与复制

移动和复制都用于把文件放到另一个位置，但结果不同：

| 操作 | 含义 | 结果 |
|---|---|---|
| 复制 | 保留原文件，再生成一份副本 | 原位置和新位置各有一份 |
| 移动 | 把文件从原位置转移到新位置 | 原位置不再保留 |
| 删除 | 把文件移入回收站或废纸篓 | 仍可恢复，直到清空 |

Windows 中常见移动方式是“剪切 → 粘贴”，也可以拖拽到目标文件夹。macOS Finder 中拖拽到目标位置可以移动；如果用快捷键，可以先 <kbd>Command</kbd> + <kbd>C</kbd> 复制，再到目标文件夹使用 <kbd>Command</kbd> + <kbd>Option</kbd> + <kbd>V</kbd> 完成移动。

> 删除文件后，通常只是进入回收站或废纸篓。只有清空回收站、清空废纸篓，或选择立即删除，文件才会更接近永久删除。

## 3、搜索文件

搜索适合在“不确定文件具体放在哪里”时使用。更好的习惯是：能通过目录结构找到的文件，就靠目录；目录太大或忘记位置时，再用搜索。

| 系统 | 搜索入口 | 适合场景 |
|---|---|---|
| Windows | 任务栏搜索、File Explorer 搜索框 | 按文件名、关键词、文档类型搜索 |
| macOS | Spotlight、Finder 搜索、Recents | 全局搜索、最近打开文件、按类型或关键词查找 |

搜索范围会影响速度和结果。只在当前文件夹搜索通常更快；从整台电脑搜索更全面，但可能更慢。云盘同步目录还可能混入本地文件和云端文件，需要留意文件是否已经下载到本机。

# 四、文件命名

文件名是给人和程序同时看的。好的文件名应该让人能猜出用途，也能被工具稳定处理。

## 1、描述清楚

像 `index1234.html`、`file-1!@.html` 这样的名字很难维护，因为它们不能说明文件内容。更好的命名应该直接表达用途：

| 不推荐 | 推荐 | 原因 |
|---|---|---|
| `index1234.html` | `about-us.html` | 能看出这是关于我们页面 |
| `file-1!@.html` | `contact.html` | 避免无意义数字和特殊符号 |
| `new page.html` | `new-page.html` | 避免空格，便于 URL 和命令行处理 |

Web 项目中常用小写字母和连字符：

```text
about-us.html
main.css
product-card.js
```

这样做的好处是简单、清楚、跨系统更稳定，也更适合作为 URL 的一部分。

## 2、遵循约定

`index.html` 是一个特殊且常见的文件名，通常表示网站或某个目录的默认入口页。访问一个目录时，服务器经常会默认寻找里面的 `index.html`。

示例：

```text
site/
├── index.html
└── about.html
```

这里的 `index.html` 通常代表首页，`about.html` 代表关于页面。

不同语言和团队可能有自己的命名约定。学习新技术时，应优先看官方文档、项目已有文件和团队风格指南，而不是把一种命名规则套到所有地方。

# 五、目录组织

目录组织的目标是让“同类文件放在一起，不同职责能分开”。一个清楚的目录结构能减少查找成本，也能让其他人更快理解项目。

## 1、根目录

根目录是一个项目的最外层目录，也就是观察项目结构时的起点。在目录树中，常用一个点 `.` 表示当前项目根目录。

示例：

```text
.
├── assets/
│   ├── images/
│   │   ├── logo.png
│   │   ├── banner.jpg
│   │   └── icons.svg
│   └── fonts/
│       ├── custom-font.woff
│       └── custom-font.woff2
├── css/
│   ├── main.css
│   ├── about.css
│   └── contact.css
├── index.html
├── about.html
├── contact.html
└── README.md
```

在这个结构里，`assets/` 放项目资源，`css/` 放样式文件，根目录下的 HTML 文件表示不同页面，`README.md` 放项目说明。

## 2、按职责分组

常见 Web 项目可以先按职责粗分：

| 位置 | 放什么 | 示例 |
|---|---|---|
| `assets/images/` | 图片资源 | logo、banner、图标 |
| `assets/fonts/` | 字体资源 | `.woff`、`.woff2` |
| `css/` | 样式文件 | `main.css`、`about.css` |
| 根目录 | 页面入口和项目说明 | `index.html`、`README.md` |

这只是入门示例，不是唯一标准。随着项目变复杂，可能会出现 `js/`、`src/`、`components/`、`public/`、`tests/` 等目录。判断目录是否合理，可以问一句：未来看到这个文件名时，能不能快速猜到它应该放在哪里？

# 六、文件类型

文件类型通常通过扩展名识别。扩展名是文件名末尾的后缀，例如 `.html`、`.css`、`.js`。它帮助操作系统、编辑器、浏览器和构建工具判断文件应该如何打开和处理。

## 1、网页核心文件

| 类型 | 扩展名 | 职责 |
|---|---|---|
| HTML | `.html` | 定义网页结构和内容 |
| CSS | `.css` | 定义网页样式 |
| JavaScript | `.js` | 添加交互和逻辑 |

可以用一个简单关系理解：

```text
HTML：页面有什么
CSS：页面长什么样
JavaScript：页面能做什么
```

## 2、媒体与资源

| 类型 | 扩展名 | 适合用途 |
|---|---|---|
| JPEG | `.jpg` / `.jpeg` | 照片，文件较小但有损压缩 |
| PNG | `.png` | 图标、截图、需要透明背景的图片 |
| GIF | `.gif` | 简单动画，颜色数量有限 |
| SVG | `.svg` | 矢量图标和可缩放图形 |
| MP3 | `.mp3` | 压缩音频 |
| MP4 | `.mp4` | 常见视频 |
| WebM | `.webm` | Web 友好的开放视频格式 |
| WOFF / WOFF2 | `.woff` / `.woff2` | Web 字体 |
| ZIP | `.zip` | 打包多个文件或文件夹 |
| Markdown | `.md` / `.markdown` | README、文档和说明文件 |

图片格式选择时可以先记住：照片常用 JPEG，透明图和截图常用 PNG，图标和可缩放图形优先考虑 SVG，网页字体优先使用 WOFF2。

# 七、整理原则

文件管理的最终目标是降低混乱，而不是追求复杂结构。入门阶段可以先遵循三条原则：

- **名字能说明用途**：避免无意义数字、空格和特殊符号。
- **位置能说明职责**：图片、样式、页面、文档分开放。
- **约定优先于个人喜好**：项目已有结构、官方文档和团队规范优先。

当文件很少时，不必提前创建很多目录；当文件开始变多、查找变慢、同类文件混在一起时，再把它们归类。好的组织方式应该帮助你工作，而不是增加额外负担。
