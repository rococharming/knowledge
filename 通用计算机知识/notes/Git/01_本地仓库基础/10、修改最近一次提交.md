# 一、为什么需要修改最近一次提交

完成一次提交后，可能马上发现：

- 提交信息写错了或者不够清楚
- 漏提了一个文件
- 还有一处小修改应该属于这次提交

如果它是当前分支的最近一次提交，并且还没有被其他人基于它继续开发，可以使用：

```shell
git commit --amend
```

`amend` 表示修正。它不是直接编辑原提交，而是根据当前暂存区和新的提交信息，创建一个新提交来替换原来的最近提交。

```text
修改前：A -- B
修改后：A -- B'
```

`B` 和 `B'` 是两个不同的提交，因此提交哈希会变化。

# 二、只修改提交信息

如果只是最近一次提交的信息写错了，可以执行：

```shell
git commit --amend -m "new message"
```

例如：

```shell
git commit --amend -m "add .gitignore rules"
```

执行后，原来的提交信息会被替换，同时生成新的提交哈希。

如果提交信息较长，可以不使用 `-m`：

```shell
git commit --amend
```

Git 会打开默认编辑器，在其中修改标题和详细说明。如果希望 Git 默认使用 VS Code，可以配置：

```shell
git config --global core.editor "code --wait"
```

Git 配置的作用域和优先级见 [[1、Git的安装与配置]]。

# 三、把遗漏内容补进最近提交

如果刚提交完就发现漏了文件或修改，先把内容加入暂存区：

```shell
git add <file>
```

然后执行：

```shell
git commit --amend --no-edit
```

`--no-edit` 表示沿用原提交信息。

例如：

```shell
echo "missing note" > missing.txt
git add missing.txt
git commit --amend --no-edit
```

> [!important] `amend` 使用的仍然是暂存区
> `git commit --amend` 会用“原提交的父提交 + 当前暂存区快照”创建替代提交。执行前应先用 `git status` 和 `git diff --staged` 检查将要写入提交的内容。

# 四、同时修改内容和提交信息

先修改文件并加入暂存区：

```shell
git add <file>
```

再修改提交信息：

```shell
git commit --amend -m "new message"
```

也可以执行 `git commit --amend` 打开编辑器。新提交会同时包含当前暂存区快照和新的提交信息。

# 五、为什么提交哈希会改变

Git 提交对象不只包含文件快照，还包含：

- 父提交
- 作者和提交者信息
- 时间信息
- 提交信息
- 指向文件快照的信息

修改提交信息或文件快照后，提交对象的内容发生变化，哈希也会随之改变。这就是为什么 `amend` 属于重写历史。

# 六、什么时候不要使用 amend

可以使用 `amend` 的典型情况：

- 它是最近一次提交
- 提交还只存在于本地
- 没有其他人基于旧提交继续开发

不应随意使用 `amend` 的情况：

- 提交已经推送到远程仓库
- 其他人可能已经拉取或基于该提交开发

`amend` 已推送的提交后，普通 `git push` 通常会被拒绝，因为本地和远程的历史已经分叉。虽然可以强制推送，但这可能覆盖其他人的工作。

> [!warning] 不要随意重写共享历史
> 本地、未共享的最近提交可以使用 `amend`。对已共享的提交，通常应使用 `git revert` 新增反向提交，而不是改写旧历史。

# 七、操作流程

```text
最近一次提交需要修正
  │
  ├─ 只改提交信息
  │    └─ git commit --amend -m "new message"
  │
  ├─ 只补充文件或修改
  │    └─ git add <file>
  │       git commit --amend --no-edit
  │
  └─ 内容和提交信息都要改
       └─ git add <file>
          git commit --amend -m "new message"
```
