# 一、什么时候需要修改最近一次提交

提交完成后，可能马上发现提交信息写错、漏加文件，或者还有一处小修改本应属于这次提交。如果它是当前分支的最近一次提交，并且还没有被其他人基于它继续开发，可以使用：

```shell
git commit --amend
```

`amend` 表示修正。它不是原地编辑旧提交，而是创建一个新提交替换最近提交：

```text
修改前：A -- B
修改后：A -- B'
```

`B` 和 `B'` 是两个不同提交，因此提交哈希会变化。

# 二、只修改提交信息

如果只是提交信息写错：

```shell
git commit --amend -m "new message"
```

例如：

```shell
git commit --amend -m "add .gitignore rules"
```

如果提交信息较长，可以打开编辑器修改：

```shell
git commit --amend
```

默认编辑器配置见 [[1、Git 安装与配置|Git 安装与配置]]。

# 三、把遗漏内容补进最近提交

如果漏提交了文件或小修改，先暂存遗漏内容：

```shell
git add <file>
```

然后沿用原提交信息：

```shell
git commit --amend --no-edit
```

示例：

```shell
echo "missing note" > missing.txt
git add missing.txt
git commit --amend --no-edit
```

> [!important] `amend` 使用当前暂存区
> 执行前应先用 `git status` 和 `git diff --staged` 检查暂存区，因为新的替代提交会基于当前暂存区快照生成。

# 四、同时修改内容和提交信息

先修改文件并暂存：

```shell
git add <file>
```

再指定新的提交信息：

```shell
git commit --amend -m "new message"
```

也可以不带 `-m` 打开编辑器：

```shell
git commit --amend
```

这样会同时修改提交内容和提交信息。

# 五、为什么提交哈希会改变

Git 提交对象不只包含文件快照，还包含父提交、作者、提交者、时间、提交信息等内容。

只要提交信息或文件快照发生变化，提交对象的内容就变了，哈希也会随之改变。因此 `amend` 属于重写历史。

# 六、什么时候不要使用 `amend`

适合使用 `amend` 的情况：

- 它是最近一次提交。
- 提交还只存在于本地。
- 没有其他人基于旧提交继续开发。

不适合随意使用的情况：

- 提交已经推送到远程仓库。
- 其他人可能已经拉取或基于它开发。
- 该提交已经进入共享分支的协作历史。

> [!warning] 不要随意重写共享历史
> 对本地、未共享的最近提交，可以使用 `amend`。对已共享提交，通常应使用 `git revert` 新增反向提交，而不是改写旧历史。

# 七、操作选择

```text
最近一次提交需要修正
  │
  ├─ 只改提交信息
  │    └─ git commit --amend -m "new message"
  │
  ├─ 只补充文件或修改
  │    └─ git add <file>
  │       git commit --amend --no-edit
  │
  └─ 内容和提交信息都要改
       └─ git add <file>
          git commit --amend -m "new message"
```

# 八、小结

`git commit --amend` 解决的是“最近一次本地提交需要修正”的问题。它会生成新提交并改变哈希，因此使用前要确认这个提交还没有成为共享历史。
