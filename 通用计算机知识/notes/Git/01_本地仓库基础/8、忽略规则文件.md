# 一、为什么需要忽略规则

真实项目里，并不是所有出现在工作区的文件都应该交给 Git 管理。

常见不适合提交的文件包括：

| 类型 | 示例 | 原因 |
|---|---|---|
| 编译产物 | `dist/`、`build/`、`target/` | 可重新生成 |
| 依赖目录 | `node_modules/` | 文件多、体积大、可重新安装 |
| 日志文件 | `*.log` | 运行时临时生成 |
| 系统文件 | `.DS_Store` | 与个人电脑环境有关 |
| 本地密钥 | `.env` | 可能包含敏感信息 |

忽略规则的作用是让这些未跟踪文件不再干扰 `git status`，也避免被普通的 `git add .` 误加入暂存区。

# 二、`.gitignore`

## 1、基本作用

`.gitignore` 通常放在项目根目录，用来记录项目共享的忽略规则。

示例：

```gitignore
.DS_Store
*.log
dist/
node_modules/
.env
```

`.gitignore` 本身通常应该提交到仓库，因为它是团队共享的项目规则。

## 2、忽略某类文件

```gitignore
*.log
```

表示忽略所有以 `.log` 结尾的文件，例如 `app.log`、`error.log`。

## 3、忽略目录

```gitignore
dist/
build/
node_modules/
```

目录规则适合编译产物和依赖目录。

## 4、忽略具体文件

```gitignore
.env
```

`.env` 往往保存本地数据库密码、API key 等敏感配置。项目如果需要说明环境变量，可以提交 `.env.example`，但真实 `.env` 应忽略。

## 5、取消忽略

`!` 可以对前面的规则取反：

```gitignore
*.log
!important.log
```

含义是忽略所有 `.log` 文件，但保留 `important.log` 可见。

# 三、查看忽略是否生效

## 1、显示被忽略文件

默认 `git status` 不显示被忽略文件。可以执行：

```shell
git status --ignored
```

如果 `app.log` 被忽略，输出中可能出现：

```text
Ignored files:
        app.log
```

## 2、定位忽略来源

```shell
git check-ignore -v app.log
```

输出可能类似：

```text
.gitignore:1:*.log    app.log
```

这表示 `app.log` 被 `.gitignore` 第 1 行的 `*.log` 规则忽略。

# 四、已跟踪文件不会被忽略

`.gitignore` 最容易误解的一点是：

> `.gitignore` 只影响未跟踪文件。

如果 `config.json` 已经被 Git 跟踪，后来再把它写入 `.gitignore`，Git 仍会继续跟踪它的修改。

如果要让 Git 停止跟踪但保留本地文件：

```shell
git rm --cached config.json
```

完整流程通常是：

```shell
echo "config.json" >> .gitignore
git rm --cached config.json
git add .gitignore
git commit -m "stop tracking config.json"
```

`git rm --cached` 的作用见 [[7、删除和重命名文件|删除和重命名文件]]。

# 五、本地忽略：`.git/info/exclude`

除了 `.gitignore`，Git 还有当前仓库本地忽略文件：

```text
.git/info/exclude
```

它的语法和 `.gitignore` 类似，但不会提交到仓库。

| 文件 | 适合规则 | 是否提交 |
|---|---|---|
| `.gitignore` | 项目共享规则 | 通常提交 |
| `.git/info/exclude` | 只和自己电脑有关的本地规则 | 不提交 |

例如，个人临时测试文件 `local-test.txt` 只想在当前仓库忽略，就可以写入 `.git/info/exclude`。

# 六、小结

| 场景 | 处理方式 |
|---|---|
| 未跟踪临时文件不想显示 | 写入 `.gitignore` |
| 文件已经被 Git 跟踪，但以后不想跟踪 | `git rm --cached <file>` |
| 团队共享忽略规则 | 写入 `.gitignore` |
| 个人本地忽略规则 | 写入 `.git/info/exclude` |
| 不确定为什么被忽略 | `git check-ignore -v <file>` |

最重要的边界是：`.gitignore` 不是取消跟踪工具，它只影响 Git 还没有跟踪的文件。
