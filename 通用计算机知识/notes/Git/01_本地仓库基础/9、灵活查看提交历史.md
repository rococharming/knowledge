# 一、提交历史查询的目标

`git log` 能查看提交历史，但项目做久之后，只看完整日志往往不够。实际排查问题时，常见问题包括：

- 最近几次提交是什么。
- 某次提交改了哪些文件。
- 某次提交具体改了哪些行。
- 某个文件的历史如何变化。
- 某一行最后是谁改的。

这篇笔记把这些问题对应到命令。

# 二、只看最近几次提交

```shell
git log --oneline -3
```

示例输出：

```text
64829c9 update a.txt
5714062 add b.txt
6b3ef19 add a.txt
```

`-3` 表示只显示最近 3 条提交。只看最近一次可以写：

```shell
git log --oneline -1
```

# 三、查看提交影响了哪些文件

```shell
git log --stat
```

`--stat` 会在提交信息下面显示文件级修改统计：

```text
a.txt | 2 ++
1 file changed, 2 insertions(+)
```

它适合快速判断“这次提交影响范围有多大”，但不展示每一行具体怎么改。

只看最近一次统计：

```shell
git log --stat -1
```

如果要观察多个分支之间的分叉关系，可以使用 `git log --oneline --graph --decorate --all`，分支场景中的读图方法见 [[1、Git 分支的基本概念与操作|Git 分支的基本概念与操作]]。

# 四、查看提交的具体修改

```shell
git log -p
```

`-p` 表示 patch，会把每次提交对应的 diff 一起显示出来。

只看最近一次：

```shell
git log -p -1
```

diff 标记与 [[5、查看修改内容|查看修改内容]] 中的规则一致：`+` 是新增，`-` 是删除。

# 五、查看某个文件的历史

## 1、只看某个文件相关提交

```shell
git log --oneline -- a.txt
```

`--` 用于分隔 Git 参数和文件路径。

## 2、查看某个文件每次提交的具体改动

```shell
git log -p -- a.txt
```

这会把输出限制在 `a.txt` 相关的变化上。

## 3、追踪重命名前后的历史

```shell
git log --follow -- b.txt
```

`--follow` 会尝试沿着单个文件的重命名前后继续追踪历史。

> [!note] `--follow` 的适用范围
> `--follow` 主要用于单个文件路径，不适合一次跟踪多个路径。

# 六、查看某次提交详情

`git show` 用于查看一次提交的提交信息和具体改动：

```shell
git show HEAD
git show 64829c9
```

只看统计：

```shell
git show --stat HEAD
```

只看某次提交中某个文件的变化：

```shell
git show HEAD -- a.txt
```

# 七、查看某一行是谁改的

```shell
git blame a.txt
```

`git blame` 会显示文件中每一行最后一次由哪次提交修改。输出通常包含提交哈希、作者、时间、行号和当前行内容。

只看行号范围：

```shell
git blame -L 1,5 a.txt
```

看到某行对应的提交后，可以继续查看提交详情：

```shell
git show <commit>
```

> [!tip] `git blame` 的真正用途
> 它不是用来追责，而是用来找到某行代码背后的提交，再结合提交信息理解当时为什么这样写。

# 八、命令速查

| 想解决的问题 | 命令 |
|---|---|
| 只看最近几次提交 | `git log --oneline -3` |
| 查看提交影响了哪些文件 | `git log --stat` |
| 查看提交具体改了什么 | `git log -p` |
| 只看某个文件历史 | `git log --oneline -- a.txt` |
| 追踪文件重命名前后的历史 | `git log --follow -- b.txt` |
| 查看某次提交详情 | `git show HEAD` |
| 查看某个文件在某次提交中的变化 | `git show HEAD -- a.txt` |
| 查看某一行最后是谁改的 | `git blame a.txt` |

# 九、小结

历史查询可以先粗后细：先用 `git log --oneline` 定位提交，再用 `--stat` 看影响范围，最后用 `git show` 或 `git log -p` 看具体 diff。

如果发现最近一次提交需要修正，继续看 [[10、修改最近一次提交|修改最近一次提交]]。
