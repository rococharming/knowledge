# 一、概述

前面已经学过：

```shell
git log
git log --oneline
```

它们都可以查看提交历史。

但是项目做久之后，提交会越来越多，只看完整的`git log`并不方便。

实际排查问题时，经常会有这些需求：

- 只看最近几次提交
- 查看某次提交改了哪些文件
- 查看某次提交具体改了什么
- 只看某个文件的提交历史
- 查看某一行最后是谁改的

这一篇可以理解为：

> 提交已经发生之后，怎么更灵活地回头查看历史。

它和前面几篇的关系是：

| 场景 | 常用命令 |
| --- | --- |
| 提交前看当前修改 | `git diff`、`git diff --staged` |
| 提交后看某次提交 | `git show` |
| 提交后看一串历史 | `git log` |
| 追踪某一行来源 | `git blame` |

# 二、只看最近几次提交

如果提交很多，只想看最近几次，可以加上数量限制。

例如，只看最近 3 次提交：

```shell
git log --oneline -3
```

输出可能类似：

```text
64829c9 update a.txt
5714062 add b.txt
6b3ef19 add a.txt
```

这里的`-3`表示只显示最近 3 条提交。

如果只想看最近 1 次提交，可以写：

```shell
git log --oneline -1
```

可以理解为：

```text
git log --oneline   ->  用一行显示一条提交
-3                   ->  只显示最近 3 条
```

# 三、查看提交影响了哪些文件

如果想知道每次提交改了哪些文件，但暂时不关心每一行具体怎么改，可以使用：

```shell
git log --stat
```

`--stat`会在提交信息下面显示文件修改统计。

输出可能类似：

```text
a.txt | 2 ++
1 file changed, 2 insertions(+)
```

含义是：

| 输出 | 含义 |
| --- | --- |
| `a.txt` | 修改了`a.txt` |
| `2 ++` | 这个文件新增了 2 行 |
| `1 file changed` | 一共改了 1 个文件 |
| `2 insertions(+)` | 一共新增了 2 行 |

如果只想看最近一次提交的统计，可以执行：

```shell
git log --stat -1
```

需要注意：

> `git log --stat`只显示文件级别统计，不显示每一行具体怎么改。

# 四、查看提交的具体修改

如果想看每次提交具体改了哪些内容，可以使用：

```shell
git log -p
```

`-p`表示 patch，也就是补丁。

它会把每次提交对应的 diff 一起显示出来。

如果只看最近一次提交的具体修改，可以执行：

```shell
git log -p -1
```

输出中可能看到类似内容：

```diff
+new line
-old line
```

含义是：

| 标记 | 含义 |
| --- | --- |
| `+` | 新增内容 |
| `-` | 删除内容 |

这和前面学习`git diff`时看到的 diff 格式是一致的。

区别在于：

| 命令 | 查看对象 |
| --- | --- |
| `git diff` | 当前工作区或暂存区里的修改 |
| `git log -p` | 已经提交到历史里的修改 |

`git log -p`的输出可能很长，适合排查具体问题时使用。

# 五、查看某个文件的历史

如果只关心某个文件相关的提交，可以在命令后面指定文件路径。

例如，只看`a.txt`相关的提交：

```shell
git log --oneline -- a.txt
```

这里的`--`用于分隔 Git 参数和文件路径。

可以理解为：

```text
git log --oneline   ->  查看提交历史
-- a.txt            ->  只看 a.txt 这个文件相关的提交
```

如果想看`a.txt`每次提交的具体改动，可以执行：

```shell
git log -p -- a.txt
```

这样输出会只围绕`a.txt`展开，不会把其他文件的改动一起显示出来。

前面学过重命名文件。假设`a.txt`后来改名成了`lesson-a.txt`，如果想尽量沿着重命名前后的历史继续看，可以使用：

```shell
git log --follow -- lesson-a.txt
```

`--follow`表示在查看单个文件历史时，尝试追踪文件重命名前后的历史。

需要注意：

> `--follow`主要用于单个文件路径，不适合一次跟多个文件一起用。

# 六、查看某次提交详情

前面已经用过`git show`。

它用于查看某一次提交的详细信息，包括提交信息和具体改动。

查看当前最新提交：

```shell
git show HEAD
```

查看某个提交哈希：

```shell
git show 64829c9
```

只看统计信息：

```shell
git show --stat HEAD
```

只看某次提交中某个文件的变化：

```shell
git show HEAD -- a.txt
```

这里也使用了`--`分隔提交参数和文件路径。

可以简单理解为：

| 命令 | 作用 |
| --- | --- |
| `git log --stat -1` | 从提交历史里看最近一次提交的统计 |
| `git show --stat HEAD` | 直接查看`HEAD`这次提交的统计 |
| `git show HEAD -- a.txt` | 只看`HEAD`这次提交里`a.txt`的变化 |

# 七、查看某一行是谁改的

如果想知道文件中某一行最后是谁改的，可以使用：

```shell
git blame a.txt
```

它会显示`a.txt`中每一行最后一次是由哪次提交修改的。

输出通常包含：

| 内容 | 说明 |
| --- | --- |
| 提交哈希 | 这一行最后一次修改来自哪次提交 |
| 作者 | 谁提交了这次修改 |
| 时间 | 这次修改发生的时间 |
| 行号 | 当前行在文件中的位置 |
| 当前行内容 | 文件里的具体内容 |

如果只想查看某个行号范围，可以使用`-L`。

例如，只看`a.txt`第 1 行到第 5 行：

```shell
git blame -L 1,5 a.txt
```

看到某一行对应的提交哈希后，如果还想继续看这次提交具体改了什么，可以再执行：

```shell
git show <commit>
```

需要注意：

> `git blame`不是用来甩锅的，它主要用于追踪上下文，理解代码为什么这样写。

# 八、常用组合

查看提交历史时，可以按问题选择命令：

| 想解决的问题 | 命令 |
| --- | --- |
| 只看最近几次提交 | `git log --oneline -3` |
| 查看提交影响了哪些文件 | `git log --stat` |
| 查看提交具体改了什么 | `git log -p` |
| 只看某个文件的提交历史 | `git log --oneline -- a.txt` |
| 尝试追踪文件重命名前后的历史 | `git log --follow -- lesson-a.txt` |
| 查看某次提交详情 | `git show HEAD` |
| 查看某次提交中某个文件的变化 | `git show HEAD -- a.txt` |
| 查看某一行是谁改的 | `git blame a.txt` |

# 九、小结

可以简单记成：

| 命令 | 关注点 |
| --- | --- |
| `git log` | 一串提交历史 |
| `git log --stat` | 每次提交改了哪些文件 |
| `git log -p` | 每次提交具体改了哪些行 |
| `git log -- <file>` | 某个文件相关的提交 |
| `git show` | 某一次提交的详情 |
| `git blame` | 某一行最后是谁改的 |

这一篇的核心是：

> 历史不是只能从头到尾看，可以按提交数量、文件、具体改动、单行来源去看。
