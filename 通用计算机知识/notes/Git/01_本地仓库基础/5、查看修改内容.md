
# 一、概述

`git status`可以告诉我们哪些文件发生了变化，但不会展示文件内部具体改了什么。

例如，`git status`可能只显示：

```shell
modified: a.txt
```

这只能说明`a.txt`被修改了，但无法直接知道新增了哪一行、删除了哪一行、修改了哪一行，或者暂存区中准备提交的内容是不是自己想要的。

因此，在实际工程中，提交前通常会先查看修改内容。一个比较好的习惯是：

```shell
git status
git diff
git diff --staged
git commit
```

含义分别是：

| 命令                  | 作用             |
| ------------------- | -------------- |
| `git status`        | 先看哪些文件发生了变化    |
| `git diff`          | 查看工作区中还没有暂存的修改 |
| `git diff --staged` | 查看暂存区中准备提交的修改  |
| `git commit`        | 确认无误后提交        |

# 二、git diff

## 1、git diff 命令

`git diff`用于查看工作区相对暂存区的差异。

例如，某个文件`c.txt`先前已经通过`git add`暂存，现在工作区又修改了它但还没有执行`git add`。此时执行：

```shell
git diff
```

就能看到这次修改的具体内容：

![[Pasted image 20260611214043.png|200]]

其中：

| 内容                              | 含义                                            |
| ------------------------------- | --------------------------------------------- |
| `diff --git a/c.txt b/c.txt`    | Git 正在比较 `c.txt` 的两个版本                        |
| `index ce01362..5e073a9 100644` | 文件内容对象从 `ce01362` 变为 `5e073a9`，文件模式是 `100644` |
| `--- a/c.txt`                   | 旧版本的 `c.txt`                                  |
| `+++ b/c.txt`                   | 新版本的 `c.txt`                                  |
| `@@ -1 +1,2 @@`                 | 变更块的行号范围                                      |
| `hello`                         | 上下文行，旧版本和新版本都存在                               |
| `+new line`                     | 新版本新增的一行                                      |

注意，`+`表示新增，`-`表示删除。

`@@ -1 +1,2 @@`表示：

| 片段     | 含义                 |
| ------ | ------------------ |
| `-1`   | 旧版本从第 1 行开始，显示 1 行 |
| `+1,2` | 新版本从第 1 行开始，显示 2 行 |

如果只想查看某个文件的未暂存修改，可以在命令后面指定文件名：

```shell
git diff c.txt
```

更严谨的写法是：

```shell
git diff -- c.txt
```

这里的`--`用于告诉 Git：后面的内容是文件路径。

当文件名和分支名、参数名可能混淆时，使用`--`更安全。

`git diff`主要适合查看文本文件的变化。对于图片、压缩包、音视频等二进制文件，Git 通常只能告诉你文件发生了变化，不能像文本一样展示具体哪一行被修改。

## 2、git diff --staged

`git diff --staged`用于查看暂存区相对最近一次提交之间的差异。

```shell
git diff --staged
```

也可以写成：

```shell
git diff --cached
```

这两个命令在这里的含义基本相同。

例如，修改`c.txt`文件暂存之后，执行`git diff --staged`：

![[Pasted image 20260611215537.png|200]]

`--- /dev/null`表示最近一次提交并没有`c.txt`文件，因此`c.txt`是新增的。

## 3、HEAD 的含义

`HEAD`表示当前所在的位置。

在多数日常场景中，可以先把`HEAD`理解为：

> 当前分支上的最新一次提交。

例如，当前分支最新一次提交是`5714062`，那么`HEAD`就指向这次提交。

一些常见写法：

| 写法       | 含义            |
| -------- | ------------- |
| `HEAD`   | 当前所在的提交       |
| `HEAD~1` | 当前提交的上一次提交    |
| `HEAD~2` | 当前提交的上上一次提交   |

## 4、git diff HEAD

`git diff HEAD`查看的是工作区 + 暂存区整体相对于`HEAD`最新提交的整体差异。

例如，新建`c.txt`写入内容，先加入到暂存区，然后又继续修改`c.txt`，但不暂存。此时执行：

```shell
git diff HEAD
```

结果：

![[Pasted image 20260611220248.png|200]]

看到的是工作区和暂存区的整体修改相对于最新提交的差异。

## 5、对比

| 命令                  | 比较范围                | 主要用途        |
| ------------------- | ------------------- | ----------- |
| `git diff`          | 工作区 vs 暂存区          | 查看还没有暂存的修改  |
| `git diff --staged` | 暂存区 vs 最近一次提交       | 查看准备提交的修改   |
| `git diff HEAD`     | 工作区 + 暂存区 vs 最近一次提交 | 查看当前所有未提交修改 |

## 6、查看两次提交之间的差异

`git diff`也可以用来比较两次提交之间的差异。

基本形式：

```shell
git diff <commit1> <commit2>
```

例如：

```shell
git diff HEAD~1 HEAD
```

表示查看从上一次提交到当前提交之间发生了什么变化。

示例：

![[Pasted image 20260611222010.png|200]]

图中表示相比上一次提交，最新提交在`b.txt`文件新增了两行内容。

也可以使用提交哈希：

```shell
git diff 6b3ef19 5714062
```

## 7、查看修改摘要

如果只想快速知道哪些文件改了，每个文件大致改了多少行，可以使用`--stat`。

查看未暂存修改摘要：

```shell
git diff --stat
```

结果：

![[Pasted image 20260611222853.png|200]]

`c.txt | 1 +`表示文件`c.txt`发生了变化，`1`表示这个文件一共有 1 行变化，`+`表示这一行是新增内容。

查看已暂存修改摘要：

```shell
git diff --staged --stat
```

查看全部未提交修改摘要：

```shell
git diff HEAD --stat
```

# 三、git show

`git show`用于查看某一次提交的详细信息，包括提交信息和具体改动。

基本形式：

```shell
git show <commit>
```

例如：

```shell
git show HEAD
```

表示查看当前最新提交的信息，以及最新提交和其父提交的差异。

![[Pasted image 20260611231635.png|400]]

可以把`git show HEAD`理解为`git log` + `git diff`的结合。

如果只想查看提交摘要，不想看具体`diff`，可以加上`--stat`参数：

```shell
git show --stat HEAD
```

结果：

![[Pasted image 20260611231613.png|400]]

如果只想查看某次提交中某个文件的变化，可以写：

```shell
git show HEAD -- c.txt
```
