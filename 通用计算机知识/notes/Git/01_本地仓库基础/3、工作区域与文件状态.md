# 一、Git 本地提交模型

Git 本地提交不是把工作区文件直接写入历史，而是先把要提交的内容放进暂存区，再由暂存区生成提交。

```text
工作区
  │ git add
  ▼
暂存区
  │ git commit
  ▼
本地仓库
```

这条链路解释了一个关键事实：

> `git commit` 提交的是暂存区内容，不是工作区里的全部文件。

# 二、三个工作区域

## 1、工作区

工作区（Working Tree / Working Directory）就是日常编辑的项目目录。除了 `.git` 目录以外，普通项目文件通常都属于工作区。

在工作区中可以新建、修改、删除、移动或重命名文件。Git 能检测这些变化，但不会自动把它们写入提交历史。

## 2、暂存区

暂存区（Staging Area / Index）保存“下一次提交要包含的内容”。执行：

```shell
git add a.txt
```

Git 会把 `a.txt` 当前这一刻的内容写入暂存区。

这里容易误解：`git add` 暂存的是内容快照，不只是文件名。如果暂存后继续修改同一个文件，新修改仍留在工作区，需要再次执行 `git add` 才会进入本次提交。

## 3、本地仓库

本地仓库保存已经提交的历史记录，数据主要位于 `.git` 目录。执行：

```shell
git commit -m "add a.txt"
```

Git 会把暂存区内容保存为一次新的提交。

# 三、文件状态分类

Git 中文件状态分为两大类：

| 状态 | 含义 |
|---|---|
| `Untracked` | 未跟踪，文件还没有被 Git 纳入管理 |
| `Tracked` | 已跟踪，文件已经被 Git 纳入管理 |

已跟踪文件又可以继续分为：

| 状态 | 含义 |
|---|---|
| `Unmodified` | 内容与最近一次提交一致 |
| `Modified` | 工作区内容发生变化 |
| `Staged` | 修改已加入暂存区，等待提交 |

基本流转如下：

```text
新建文件
  ▼
Untracked
  │ git add
  ▼
Staged
  │ git commit
  ▼
Unmodified
  │ 修改文件
  ▼
Modified
  │ git add
  ▼
Staged
```

# 四、常见状态场景

## 1、未跟踪文件

```shell
echo "hello" > a.txt
git status
```

新文件还没有被 Git 管理时，会显示在 `Untracked files` 中。此时它只存在于工作区。

## 2、已暂存文件

```shell
git add a.txt
git status
```

文件进入暂存区后，会显示在 `Changes to be committed` 中。即使它还没有提交，也已经不再是未跟踪状态。

## 3、同一文件同时有暂存和未暂存修改

```shell
git add a.txt
echo "new line" >> a.txt
git status
```

这时同一个文件可能同时出现在两个区域：

| 输出区域 | 含义 |
|---|---|
| `Changes to be committed` | 暂存区里已有一版内容 |
| `Changes not staged for commit` | 工作区里又产生了新修改 |

如果直接提交，提交进去的是暂存区那一版，不包含后续未暂存修改。

## 4、工作区干净

提交后再次查看状态：

```shell
git commit -m "add a.txt"
git status
```

如果没有新修改，会看到：

```text
nothing to commit, working tree clean
```

这表示工作区和暂存区都没有待处理内容。

# 五、状态检查与差异查看

## 1、`git status`

`git status` 回答两个问题：

- 工作区有哪些变化。
- 暂存区有哪些变化。

常见输出区域：

| 输出 | 含义 |
|---|---|
| `Untracked files` | 未跟踪文件 |
| `Changes not staged for commit` | 工作区有修改，但还没暂存 |
| `Changes to be committed` | 暂存区有内容，等待提交 |
| `working tree clean` | 工作区和暂存区都干净 |

## 2、`git diff`

```shell
git diff
```

查看工作区相对于暂存区的差异，也就是还没有暂存的修改。

## 3、`git diff --staged`

```shell
git diff --staged
```

查看暂存区相对于最近一次提交的差异，也就是下一次提交准备包含的内容。等价写法是：

```shell
git diff --cached
```

差异查看的更多用法见 [[5、查看修改内容|查看修改内容]]。

# 六、`.git` 中的对应结构

## 1、`index` 对应暂存区

`.git/index` 是暂存区的底层文件。首次执行 `git add` 后，Git 会把待提交内容记录到这个索引中。

## 2、`objects/` 对应对象数据库

`.git/objects/` 保存 Git 对象：

| 对象 | 说明 |
|---|---|
| `blob` | 文件内容 |
| `tree` | 目录结构 |
| `commit` | 提交对象 |
| `tag` | 标签对象 |

## 3、`HEAD` 与 `refs/`

`.git/HEAD` 表示当前检出位置。正常位于分支上时，它通常指向某个分支引用：

```text
ref: refs/heads/main
```

`.git/refs/` 保存分支、标签、远程跟踪分支等引用。

# 七、小结

理解工作区、暂存区、本地仓库之后，Git 的大部分本地命令都能归位：`git add` 把工作区内容放入暂存区，`git commit` 把暂存区内容写入历史，`git status` 和 `git diff` 用来检查这两个区域之间的差异。
