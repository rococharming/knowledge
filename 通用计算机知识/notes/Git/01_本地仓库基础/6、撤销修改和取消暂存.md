# 一、先判断要撤销什么

Git 中的撤销操作要先分清两个问题：撤销的是工作区还是暂存区，是否保留已经写下的文件内容。

| 需求 | 常用命令 | 是否保留工作区内容 |
|---|---|---|
| 已暂存，但暂时不想提交 | `git restore --staged <file>` | 保留 |
| 未暂存修改写错了，想丢弃 | `git restore <file>` | 不保留 |
| 新建未跟踪文件不想要 | `rm <file>` | 不保留 |

> [!warning] 先看 diff 再丢弃
> `git restore <file>` 会丢弃未暂存修改。执行前建议先用 `git diff -- <file>` 确认这些内容确实不需要。

# 二、取消暂存：`git restore --staged`

## 1、基本用法

假设修改 `d.txt` 后已经暂存：

```shell
git add d.txt
```

现在想把它从暂存区拿出来，但保留文件内容：

```shell
git restore --staged d.txt
```

这个命令的效果是：

| 区域 | 结果 |
|---|---|
| 暂存区 | 取消暂存 |
| 工作区 | 文件内容继续保留 |

可以理解为：这次先不提交 `d.txt`，但写过的内容还留在文件里。

## 2、状态变化

新文件暂存后可能显示：

```text
A  d.txt
```

取消暂存后可能变为：

```text
?? d.txt
```

这表示 `d.txt` 已经从暂存区退回工作区，成为未跟踪文件。

# 三、丢弃工作区修改：`git restore`

## 1、丢弃已跟踪文件的未暂存修改

如果 `d.txt` 已被 Git 跟踪，后来又在工作区中写错了，可以执行：

```shell
git diff -- d.txt
git restore d.txt
```

`git restore d.txt` 会把工作区中的 `d.txt` 恢复到暂存区或最近一次提交中的状态。

## 2、删除未跟踪文件

如果 `d.txt` 是新建的未跟踪文件，Git 没有历史版本可恢复。想丢弃它，本质上就是删除文件：

```shell
rm d.txt
```

这类文件通常会在 `git status -s` 中显示为：

```text
?? d.txt
```

# 四、同一文件同时有已暂存和未暂存修改

假设先修改并暂存：

```shell
git add d.txt
```

随后又继续修改同一个文件，但没有再次暂存。此时：

```shell
git status -s
```

可能显示：

```text
MM d.txt
```

含义是：

| 区域 | 内容 |
|---|---|
| 暂存区 | 第一次修改 |
| 工作区 | 第二次未暂存修改 |

如果执行：

```shell
git restore d.txt
```

只会丢弃工作区后续修改，暂存区中的第一次修改仍然保留。

如果执行：

```shell
git restore --staged d.txt
```

会取消暂存区中的修改，但工作区内容仍保留。

# 五、常用场景对比

| 场景 | 命令 | 结果 |
|---|---|---|
| 已经暂存，但暂时不想提交 | `git restore --staged d.txt` | 修改留在工作区 |
| 修改错了，想丢弃未暂存修改 | `git restore d.txt` | 未暂存修改被丢弃 |
| `MM` 文件只想丢弃第二次修改 | `git restore d.txt` | 保留暂存区修改 |
| `MM` 文件只想取消暂存 | `git restore --staged d.txt` | 保留工作区当前内容 |

# 六、小结

`--staged` 处理暂存区，不带 `--staged` 处理工作区。只要记住这条边界，就不容易把“取消暂存”和“丢弃内容”混在一起。
