# 一、从快照到对象

Git 把一次提交保存为对象之间的关联，而不是保存一串文件操作。理解这些对象后，工作区、暂存区、分支和历史命令就有了统一的底层解释。

## 1、对象类型

Git 的对象数据库通常位于 `.git/objects/`，核心对象包括：

| 对象 | 保存内容 | 作用 |
|---|---|---|
| `blob` | 一个文件的内容 | 表示文件内容，不包含文件名 |
| `tree` | 目录条目 | 将文件名、模式与 `blob` 或子树关联 |
| `commit` | 一次提交的元数据 | 指向根 `tree`、父提交、作者与提交信息 |
| `tag` | 带注释的标签对象 | 为指定对象附加名称和说明 |

一次提交通过 `tree` 连接到整棵目录树；两个版本内容相同的文件可以复用同一个 `blob`。这也是 Git 以内容为中心保存快照的原因。

## 2、暂存区的位置

暂存区在底层通常由 `.git/index` 表示。执行 `git add` 时，Git 会更新索引中对应路径要指向的内容；执行 `git commit` 时，再根据索引生成新的目录树和提交对象。

这正是 [[通用计算机知识/notes/Git/01_本地仓库基础/3、工作区域与文件状态|工作区域与文件状态]] 中“提交的是暂存区内容”的底层对应。

# 二、引用与 HEAD

## 1、分支是引用

分支不是一份项目副本，而是指向某个提交的可移动引用。本地分支通常可理解为保存在 `.git/refs/heads/` 下的名字，例如 `main` 指向最新提交。

创建提交后，当前分支会移动到新提交；删除分支通常删除的是这个名字，不会立即销毁它曾指向的提交。分支的操作方式见 [[通用计算机知识/notes/Git/02_分支管理/1、Git 分支的基本概念与操作|Git 分支的基本概念与操作]]。

## 2、HEAD 的角色

`HEAD` 表示当前检出位置。正常位于分支上时，它通常指向分支引用：

```text
ref: refs/heads/main
```

因此可以把当前位置读成 `HEAD → main → 某次提交`。如果 `HEAD` 直接指向提交而不是分支，就处于 Detached HEAD 状态。

# 三、用原理解释操作

## 1、为什么 `amend` 会改变哈希

提交对象包含根目录树、父提交、作者、提交者、时间与提交信息。修改其中任一部分都会产生新的对象，所以 `git commit --amend` 会用新提交替换当前分支的指向。

## 2、为什么 `reflog` 能救援

`reset` 只是移动分支引用，原提交不会立刻消失。`reflog` 记录本地 `HEAD` 和分支引用的移动轨迹，因此常可在误操作后找到旧提交并先创建救援分支。具体步骤见 [[通用计算机知识/notes/Git/01_本地仓库基础/11、撤销提交与恢复历史|重置本地提交与恢复历史]]。

# 四、后续

对象、引用和 `HEAD` 是理解分支合并、变基、标签与远程跟踪分支的共同基础。日常使用中不需要手动编辑 `.git` 内的文件；优先通过 Git 命令操作，再用这些原理解释结果。
