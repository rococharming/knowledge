# 一、先判断要撤销什么

Git 中的撤销操作要先分清两个问题：撤销的是工作区还是暂存区，是否保留已经写下的文件内容。

| 需求 | 常用命令 | 是否保留工作区内容 |
|---|---|---|
| 已暂存，但暂时不想提交 | `git restore --staged <file>` | 保留 |
| 未暂存修改写错了，想丢弃 | `git restore <file>` | 不保留 |
| 新建未跟踪文件不想要 | `rm <file>` | 不保留 |

![[assets/restore-and-unstage-generated.png|600]]

> [!warning] 先看 diff 再丢弃
> `git restore <file>` 会丢弃未暂存修改。执行前建议先用 `git diff -- <file>` 确认这些内容确实不需要。

# 二、当前起点

第 5 篇结束后，`third line` 已经进入暂存区，但还没有提交：

```text
M  note.txt
```

短状态的两列要分开读：

| 列 | 状态 | 含义 |
|---|---|---|
| 第一列 | `M` | 暂存区里有已暂存修改 |
| 第二列 | 空 | 工作区没有额外未暂存修改 |

当前的暂存修改是：

```diff
+third line
```

这篇的目标是先把 `third line` 从暂存区退回工作区，再在确认不要它之后丢弃工作区修改。

# 三、取消暂存

## 1、基本用法

如果 `note.txt` 的修改已经暂存，但暂时不想让它进入下一次提交，可以执行：

```shell
git restore --staged note.txt
```

这个命令的效果是：

| 区域 | 结果 |
|---|---|
| 暂存区 | 取消暂存 |
| 工作区 | 文件内容继续保留 |

可以理解为：这次先不提交 `note.txt`，但写过的内容还留在文件里。

## 2、状态变化

第 5 篇留下的状态是：

```text
M  note.txt
```

取消暂存后会变成：

```text
 M note.txt
```

这表示 `third line` 已经不在暂存区，而是退回工作区。此时 `git diff --staged -- note.txt` 没有输出，`git diff -- note.txt` 可以看到 `+third line`。

# 四、丢弃修改

## 1、丢弃已跟踪文件的未暂存修改

如果确认工作区里的 `third line` 不需要，可以执行：

```shell
git diff -- note.txt
git restore note.txt
```

`git restore note.txt` 会把工作区中的 `note.txt` 恢复到暂存区或最近一次提交中的状态。本篇场景中，`third line` 会被丢弃，文件回到最近一次提交中的两行内容。

检查文件内容：

```shell
cat note.txt
```

应只剩：

```text
first line
second line
```

## 2、删除未跟踪文件

如果某个文件是新建的未跟踪文件，Git 没有历史版本可恢复。想丢弃它，本质上就是删除文件：

```shell
rm <file>
```

这类文件通常会在 `git status -s` 中显示为：

```text
?? <file>
```

# 五、混合状态

假设先修改并暂存：

```shell
git add note.txt
```

随后又继续修改同一个文件，但没有再次暂存。此时：

```shell
git status -s
```

可能显示：

```text
MM note.txt
```

含义是：

| 区域 | 内容 |
|---|---|
| 暂存区 | 第一次修改 |
| 工作区 | 第二次未暂存修改 |

如果执行：

```shell
git restore note.txt
```

只会丢弃工作区后续修改，暂存区中的第一次修改仍然保留。

如果执行：

```shell
git restore --staged note.txt
```

会取消暂存区中的修改，但工作区内容仍保留。

# 六、常用场景

| 场景 | 命令 | 结果 |
|---|---|---|
| 已经暂存，但暂时不想提交 | `git restore --staged note.txt` | 修改留在工作区 |
| 修改错了，想丢弃未暂存修改 | `git restore note.txt` | 未暂存修改被丢弃 |
| `MM` 文件只想丢弃第二次修改 | `git restore note.txt` | 保留暂存区修改 |
| `MM` 文件只想取消暂存 | `git restore --staged note.txt` | 保留工作区当前内容 |

更短的心智模型：

```text
--staged 影响暂存区
不带 --staged 影响工作区
```

# 七、本地练习

起点：继续使用上一课结束后的本地仓库，当前应看到 `M  note.txt`。

```shell
git status -s
git diff --staged -- note.txt
git restore --staged note.txt
git status -s
git diff -- note.txt
git restore note.txt
git status -s
cat note.txt
```

检查目标：

| 检查项 | 期待结果 |
|---|---|
| 起点 `git status -s` | `M  note.txt` |
| `git diff --staged -- note.txt` | 能看到 `+third line` |
| 取消暂存后 `git status -s` | ` M note.txt` |
| `git diff -- note.txt` | 能看到 `+third line` |
| `git restore note.txt` 后 `git status -s` | 没有输出 |
| `cat note.txt` | 只有 `first line` 和 `second line` |

本课目标状态：仓库回到 clean，`note.txt` 回到最近一次提交中的两行内容，没有创建新提交。

# 八、小结

`--staged` 处理暂存区，不带 `--staged` 处理工作区。只要记住这条边界，就不容易把“取消暂存”和“丢弃内容”混在一起。

如果要撤销已经形成的提交，先看 [[通用计算机知识/notes/Git/04_撤销、恢复与历史整理/1、撤销前的三问诊断|撤销前的三问诊断]]，确认改动是否已经提交、是否已经共享。
