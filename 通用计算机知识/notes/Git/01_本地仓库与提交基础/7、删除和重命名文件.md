# 一、删除和重命名的核心区别

在 Git 仓库中，删除和重命名都可以用系统命令完成，也可以用 Git 命令完成。

![[assets/remove-and-rename-generated.png|600]]

| 操作 | 系统命令 | Git 命令 | 区别 |
|---|---|---|---|
| 删除文件 | `rm <file>` | `git rm <file>` | `git rm` 会自动暂存删除 |
| 重命名文件 | `mv <old> <new>` | `git mv <old> <new>` | `git mv` 会自动暂存重命名 |

可以先记成：

> `rm` / `mv` 只改工作区；`git rm` / `git mv` 改工作区并同步更新暂存区。

换成 [[3、工作区域与文件状态|工作区、暂存区和提交历史]] 的模型：

| 动作 | 工作区 | 暂存区 |
|---|---|---|
| `rm` | 变了 | 没变 |
| `rm` 后 `git add -A` | 变了 | 更新了 |
| `git rm` | 变了 | 更新了 |
| `mv` | 变了 | 没变 |
| `mv` 后 `git add -A` | 变了 | 更新了 |
| `git mv` | 变了 | 更新了 |

# 二、当前起点

第 6 篇结束后，仓库应处于 clean，`note.txt` 回到最近一次提交中的两行内容：

```text
first line
second line
```

本篇会先创建一个临时 tracked 文件 `scratch.txt`，用于安全练习删除；然后把 `note.txt` 改名为 `daily-note.txt`。这样删除和改名都有具体对象，不会破坏前面已经建立好的主线。

# 三、删除文件

## 1、使用 `rm`

先创建并提交一个临时文件，让它成为 Git 已经跟踪的文件：

```shell
printf "scratch\n" > scratch.txt
git add scratch.txt
git commit -m "Add scratch file"
```

普通 `rm` 是操作系统命令，只会从工作区删除文件：

```shell
rm scratch.txt
git status -s
```

对于已跟踪文件，Git 会在状态中显示删除：

```text
 D scratch.txt
```

这里的 `D` 在第二列，表示工作区删除了文件，但删除记录还没有暂存。

如果要把删除操作纳入下一次提交：

```shell
git add -A
git status -s
```

状态会变成：

```text
D  scratch.txt
```

这里的 `D` 在第一列，表示删除记录已经进入暂存区。

## 2、使用 `git rm`

如果还没有删除文件，也可以直接使用 `git rm`：

```shell
git rm scratch.txt
git status -s
```

它相当于：

```shell
rm scratch.txt
git add -A
```

执行后，简洁状态可能显示：

```text
D  scratch.txt
```

所以 `git rm scratch.txt` 可以理解为“删除 tracked 文件，并把删除放进下一次提交草稿”。

## 3、停止跟踪但保留文件

如果只是想让 Git 不再跟踪某个文件，但保留工作区文件：

```shell
git rm --cached <file>
```

这常用于“文件已经被提交过，后来才发现应该被 `.gitignore` 忽略”的场景。忽略规则见 [[8、忽略规则文件|忽略规则文件]]。

# 四、恢复误删

## 1、恢复未暂存的 `rm`

如果只是执行了：

```shell
rm scratch.txt
```

且还没暂存删除，可以恢复：

```shell
git restore scratch.txt
```

## 2、恢复已暂存的 `git rm`

如果执行的是：

```shell
git rm scratch.txt
```

需要先取消暂存，再恢复工作区文件：

```shell
git restore --staged scratch.txt
git restore scratch.txt
```

这与 [[6、撤销修改和取消暂存|取消暂存和恢复工作区]] 的规则一致。

# 五、重命名文件

## 1、使用 `mv`

```shell
mv note.txt daily-note.txt
git status -s
```

`mv` 只操作工作区。Git 可能先看到：

```text
 D note.txt
?? daily-note.txt
```

表示旧文件被删除，新文件还未跟踪。暂存后：

```shell
git add -A
git status -s
```

Git 可能识别为：

```text
R  note.txt -> daily-note.txt
```

Git 本质上不是永久保存“重命名动作”，而是在比较前后快照时根据内容相似度识别新路径是否像旧路径改名而来。如果改名同时大幅改内容，Git 可能显示为删除旧文件、增加新文件。

## 2、使用 `git mv`

```shell
git mv note.txt daily-note.txt
git status -s
```

它相当于：

```shell
mv note.txt daily-note.txt
git add -A
```

执行后重命名变化已经暂存，下一次提交会记录这个路径变化。

# 六、提交检查

删除和重命名属于路径变化，提交前用摘要比直接看完整 diff 更清楚：

```shell
git status -s
git diff --staged --summary
```

如果本篇练习同时删除 `scratch.txt` 并重命名 `note.txt`，状态中应能看到删除和 rename，摘要中也会显示对应路径变化。

最后提交：

```shell
git commit -m "Rename note and remove scratch"
git status -s
```

提交后没有输出，表示仓库回到 clean。

# 七、恢复重命名

## 1、未暂存的重命名

如果只是执行了 `mv`，可以直接改回：

```shell
mv daily-note.txt note.txt
```

## 2、已暂存的重命名

如果重命名已经暂存，可以先取消暂存，再恢复：

```shell
git restore --staged note.txt daily-note.txt
rm daily-note.txt
git restore note.txt
```

含义是：先撤销暂存区里的重命名记录，再删除新路径，最后从 Git 中恢复旧路径。

# 八、常见误区

## 1、对未跟踪文件用 `git rm`

untracked 文件还没有进入 Git 管理，通常直接用普通删除命令即可。`git rm` 主要用于已经被 Git 跟踪的文件。

## 2、以为 `git mv` 是唯一改名方式

普通 `mv` 加 `git add -A` 也能记录路径变化。初学阶段优先用 `git mv`，是因为动作更清楚，中间状态更少。

## 3、忘记提交路径变化

`git rm` 和 `git mv` 会把路径变化放进暂存区，但真正写进历史仍然需要 `git commit`。

## 4、分不清 ` D` 和 `D `

| 状态 | 含义 |
|---|---|
| ` D scratch.txt` | 工作区删除了，暂存区还没记录 |
| `D  scratch.txt` | 删除已经进入暂存区 |

# 九、本地练习

起点：继续使用上一课结束后的本地仓库，当前应为 clean，`note.txt` 只有 `first line` 和 `second line` 两行。

```shell
git status -s
printf "scratch\n" > scratch.txt
git add scratch.txt
git commit -m "Add scratch file"
rm scratch.txt
git status -s
git restore scratch.txt
git rm scratch.txt
git status -s
mv note.txt daily-note.txt
git status -s
mv daily-note.txt note.txt
git mv note.txt daily-note.txt
git status -s
git diff --staged --summary
git commit -m "Rename note and remove scratch"
git status -s
```

检查目标：

| 检查项 | 期待结果 |
|---|---|
| 起点 `git status -s` | 没有输出 |
| 普通 `rm scratch.txt` 后 | 看到 ` D scratch.txt` |
| `git rm scratch.txt` 后 | 看到 `D  scratch.txt` |
| 普通 `mv note.txt daily-note.txt` 后 | 看到旧路径删除和新路径未跟踪 |
| `git mv note.txt daily-note.txt` 后 | rename 已进入暂存区 |
| `git diff --staged --summary` | 能看到删除和重命名摘要 |
| 最后 `git status -s` | 没有输出 |

本课目标状态：仓库 clean，`note.txt` 已改名为 `daily-note.txt`，`scratch.txt` 已被删除。

# 十、小结

| 场景 | 推荐命令 |
|---|---|
| 删除并立刻纳入下一次提交 | `git rm <file>` |
| 只在工作区删除，稍后再决定 | `rm <file>` |
| 停止跟踪但保留本地文件 | `git rm --cached <file>` |
| 重命名并立刻纳入下一次提交 | `git mv <old> <new>` |
| 重命名后还想继续编辑再暂存 | `mv <old> <new>` 后再 `git add -A` |

判断命令是否“安全”的关键，是看它是否同时改变暂存区。只改工作区的操作更容易回头检查；已经暂存的操作则要用 `git restore --staged` 先退回。
