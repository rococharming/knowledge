# 一、为什么要查看修改内容

`git status` 只能告诉我们哪些文件发生了变化，不能展示文件内部具体改了什么。提交前查看 diff，可以避免把调试代码、误删内容或无关修改带进历史。

推荐检查顺序：

```shell
git status
git diff
git diff --staged
git commit
```

| 命令 | 作用 |
|---|---|
| `git status` | 看哪些文件发生变化 |
| `git diff` | 看工作区中还没有暂存的修改 |
| `git diff --staged` | 看暂存区中准备提交的修改 |
| `git commit` | 确认无误后提交 |

# 二、理解 diff 输出

`git diff` 的输出通常类似：

```diff
diff --git a/note.txt b/note.txt
index ce01362..5e073a9 100644
--- a/note.txt
+++ b/note.txt
@@ -1,2 +1,3 @@
 first line
 second line
+third line
```

常见字段：

| 内容 | 含义 |
|---|---|
| `diff --git a/note.txt b/note.txt` | Git 正在比较同一路径的两个版本 |
| `index ... 100644` | 内容对象变化和文件模式 |
| `--- a/note.txt` | 旧版本 |
| `+++ b/note.txt` | 新版本 |
| `@@ -1,2 +1,3 @@` | 变更块的行号范围 |
| `+third line` | 新版本新增的一行 |

在 diff 中，`+` 表示新增，`-` 表示删除，未带符号的行是上下文。

# 三、常用差异命令

## 1、查看未暂存修改

```shell
git diff
```

它比较的是工作区和暂存区：工作区比暂存区多了什么还没加入下一次提交。

只看某个文件：

```shell
git diff -- note.txt
```

`--` 用来分隔 Git 参数和文件路径，文件名可能与分支名或参数混淆时更安全。

## 2、查看已暂存修改

```shell
git diff --staged
```

它比较的是暂存区和最近一次提交：下一次提交准备写入什么。

等价写法：

```shell
git diff --cached
```

## 3、查看全部未提交修改

```shell
git diff HEAD
```

它比较的是“工作区 + 暂存区整体”和 `HEAD`。日常可以把 `HEAD` 先理解为当前分支的最新提交。

常见相对写法：

| 写法 | 含义 |
|---|---|
| `HEAD` | 当前提交 |
| `HEAD~1` | 当前提交的上一次提交 |
| `HEAD~2` | 当前提交的上上一次提交 |

# 四、比较提交之间的差异

## 1、比较两个提交

```shell
git diff <commit1> <commit2>
```

示例：

```shell
git diff HEAD~1 HEAD
```

表示查看从上一次提交到当前提交之间发生了什么。

也可以使用提交哈希：

```shell
git diff 6b3ef19 5714062
```

## 2、查看修改摘要

如果只想快速知道哪些文件变了、每个文件大致改了多少行：

```shell
git diff --stat
git diff --staged --stat
git diff HEAD --stat
```

`--stat` 适合先扫范围，再决定是否查看完整 diff。

# 五、查看某次提交详情

## 1、使用 `git show`

`git show` 查看一次提交的提交信息和具体改动：

```shell
git show HEAD
git show <commit>
```

可以把 `git show HEAD` 理解为 `git log` 和 `git diff` 的结合。

## 2、只看统计信息

```shell
git show --stat HEAD
```

## 3、只看提交中某个文件的变化

```shell
git show HEAD -- note.txt
```

提交历史的更多查询方式见 [[9、灵活查看提交历史|灵活查看提交历史]]。

# 六、本地练习

起点：继续使用上一课提交后的本地仓库，当前应为 clean。

```shell
git status -s
printf "third line\n" >> note.txt
git status -s
git diff -- note.txt
git add note.txt
git diff -- note.txt
git diff --staged -- note.txt
```

检查目标：

| 检查项 | 期待结果 |
|---|---|
| 第一次 `git status -s` | 没有输出 |
| 追加第三行后 `git status -s` | 看到 ` M note.txt` |
| `git diff -- note.txt` | 看到 `+third line` |
| `git add note.txt` 后的 `git diff -- note.txt` | 没有输出 |
| `git diff --staged -- note.txt` | 看到 `+third line` |

本课结束时暂时不要提交。目标状态是：`third line` 已经暂存，但还没进入提交历史。下一课会用这个状态学习取消暂存和撤销修改。

# 七、小结

差异查看要先分清比较范围：

| 命令 | 比较范围 | 主要用途 |
|---|---|---|
| `git diff` | 工作区 vs 暂存区 | 查看还没暂存的修改 |
| `git diff --staged` | 暂存区 vs 最近一次提交 | 查看准备提交的修改 |
| `git diff HEAD` | 工作区 + 暂存区 vs 最新提交 | 查看全部未提交修改 |
| `git diff A B` | 提交 A vs 提交 B | 比较历史提交 |
| `git show <commit>` | 某次提交及其父提交 | 查看提交详情 |

提交前至少看一次 `git diff --staged`，这是防止误提交最有效的习惯之一。
