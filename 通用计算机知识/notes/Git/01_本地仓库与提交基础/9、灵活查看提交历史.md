# 一、提交历史查询的目标

`git log` 能查看提交历史，但项目做久之后，只看完整日志看不过来。实际排查问题时，会有如下需求：

- 最近几次提交是什么。
- 某次提交改了哪些文件。
- 某次提交具体改了哪些行。
- 某个文件的历史如何变化。
- 某一行最后是谁改的。

# 二、最小模型

每个提交都记录一份项目快照，并指向自己的 parent，也就是上一次提交。`git log` 默认从当前 `HEAD` 开始，沿着 parent 往回显示历史。

![[assets/view-history-generated.png|600]]

| 概念 | 含义 |
|---|---|
| `HEAD` | 当前所在提交 |
| parent | 当前提交的上一个提交 |
| commit id | 提交对象的名字，常用短哈希显示 |
| message | 人类可读的提交意图 |

因此，同一个仓库里，切到不同分支后，`HEAD` 可能不同，默认看到的历史也可能不同。分支视角见 [[通用计算机知识/notes/Git/1、Git 分支的基本概念与操作|Git 分支的基本概念与操作]]。

# 三、快速浏览：git log --oneline

```shell
git log --oneline --decorate --max-count=6
```

示例输出：

```text
fc86c12 (HEAD -> main) Add ignore rules
5d89ea2 Rename note and remove scratch
8b44f0d Add scratch file
ee56325 Add note file
```

命令片段拆开看：

| 片段 | 作用 |
|---|---|
| `--oneline` | 每个提交显示一行，适合快速扫读 |
| `--decorate` | 显示 `HEAD`、分支名、标签等引用 |
| `--max-count=6` | 最多显示 6 条提交，不改变历史 |

`--max-count=6`  只是限制显示数量，不会删除旧提交。

示例中的 `(HEAD -> main)` 表示当前站在这个提交上，`main` 分支也指向这个提交。

查看最近几次也可以写：

```shell
git log --oneline -n 3
```

表示查看最近3次提交。

或者也可以简写：

```shell
git log --oneline -3
```

只看某个文件相关提交：

```shell
git log --oneline -- daily-note.txt
```

`--` 用于分隔 Git 参数和文件路径。

# 四、影响范围：git log --stat

```shell
git log --stat
```

`--stat` 会在提交信息下面显示文件级修改统计：

```text
fc86c12 (HEAD -> main) Add ignore rules
 .gitignore | 2 ++
 1 file changed, 2 insertions(+)

5d89ea2 Rename note and remove scratch
 note.txt => daily-note.txt | 0
 scratch.txt                | 1 -
 2 files changed, 1 deletion(-)
```

它适合快速判断“这次提交影响范围有多大”，但不展示每一行具体怎么改。

# 五、具体修改：git log -p / git show

```shell
git log -p
```

`-p` 表示 patch，会把每次提交对应的 diff 一起显示出来。

默认情况下，`git log -p`会显示所有提交。

如果只看最近一次，可以使用：

```shell
git log -p -1
```

diff 标记与 [[5、查看修改内容|查看修改内容]] 中的规则一致：`+` 是新增，`-` 是删除。

查看某个文件每次提交的具体改动

```shell
git log -p -- daily-note.txt
```

这会把输出限制在 `daily-note.txt` 相关的变化上。


`git show` 也用于查看提交的提交信息和具体改动，但它需要查看的是某个单次提交：

```shell
git show
```

默认情况下，它查看的是 HEAD 提交。等价于：

```shell
git show HEAD
```

如需查看某个具体提交，可用：

```shell
git show 64829c9
```

只看统计（类似于 git log --stat）：

```shell
git show --stat HEAD
```

只看某次提交中某个文件的变化：

```shell
git show HEAD -- daily-note.txt
```


# 六、追踪重命名前后的历史

`--follow`参数会尝试沿着单个文件的重命名前后继续追踪历史。

例如，对于`daily-note.txt`，如果不加`--follow`，只能看到其重命名后的历史：

```shell
git log -p -- daily-note.txt
```

![[assets/Pasted image 20260725134429.png|400]]

但使用`--follow`：

```shell
git log -p --follow -- daily-note.txt
```

![[assets/Pasted image 20260725134602.png|600]]

还能追踪到其重命名前`note.txt`的改动。

> [!note] `--follow` 的适用范围
> `--follow` 主要用于单个文件路径，不适合一次跟踪多个路径。


# 七、逐行追踪

`git blame` 会显示文件中每一行最后一次由哪次提交修改。输出通常包含提交哈希、作者、时间、行号和当前行内容。

```shell
git blame daily-note.txt
```

![[assets/Pasted image 20260725134751.png|600]]

只看行号范围：

```shell
git blame -L 1,5 daily-note.txt
```

看到某行对应的提交后，可以继续查看提交详情：

```shell
git show <commit>
```

> [!tip] `git blame` 的真正用途
> 它不是用来追责，而是用来找到某行代码背后的提交，再结合提交信息理解当时为什么这样写。

# 八、本地练习

起点：继续使用上一课结束后的本地仓库。本课只读历史，不修改文件，仓库应保持 clean。

```shell
git status -s
git log --oneline --decorate --max-count=6
git log --stat --max-count=3
git show --stat HEAD
git log --oneline -- daily-note.txt
```

检查目标：

| 检查项 | 期待结果 |
|---|---|
| `git status -s` | 没有输出 |
| `git log --oneline --decorate --max-count=6` | 能指出哪一行是当前提交 |
| `git log --stat --max-count=3` | 能读出最近几次提交影响了哪些文件 |
| `git show --stat HEAD` | 能放大查看当前提交的文件统计 |
| `git log --oneline -- daily-note.txt` | 只显示和该路径有关的历史 |

本课目标状态：仓库仍然 clean；你能根据问题选择 `log`、`log --stat`、`show` 或路径历史视图。


# 九、命令速查

| 想解决的问题 | 命令 |
|---|---|
| 只看最近几次提交 | `git log --oneline --decorate --max-count=6` |
| 查看提交影响了哪些文件 | `git log --stat --max-count=3` |
| 查看提交具体改了什么 | `git log -p` |
| 只看某个文件历史 | `git log --oneline -- daily-note.txt` |
| 追踪文件重命名前后的历史 | `git log --follow -- daily-note.txt` |
| 查看某次提交详情 | `git show HEAD` |
| 查看某个文件在某次提交中的变化 | `git show HEAD -- daily-note.txt` |
| 查看某一行最后是谁改的 | `git blame daily-note.txt` |

# 十、小结

历史查询可以先粗后细：先用 `git log --oneline` 定位提交，再用 `--stat` 看影响范围，最后用 `git show` 或 `git log -p` 看具体 diff。

如果发现最近一次提交需要修正，继续看 [[10、修改最近一次提交|修改最近一次提交]]。
