# 一、日常循环

Git 本地基本功不是记住某一条命令，而是形成一条可反复执行、可诊断的循环。每一轮从 clean 出发，做改动，检查，选择性暂存，提交，回看，再回到 clean。

![[assets/local-repo-daily-loop-generated.png|600]]

最小模型：

```text
clean -> edit -> status -> diff -> add -> diff --staged -> commit -> log/show -> clean
```

换成心法就是：

```text
先观察，再选择，再提交，最后回看。
```

这条循环把 [[3、工作区域与文件状态|工作区域]]、[[4、查看状态、暂存和提交|状态与提交]]、[[5、查看修改内容|diff]]、[[11、提交前检查清单|提交前检查]] 和 [[12、最小可读提交|最小可读提交]] 串成日常动作。

# 二、循环步骤

## 1、观察

一轮改动最好从 clean 开始：

```shell
git status -s
```

没有输出，表示 working tree 和 index 都是干净的。开始编辑后，再看范围和内容：

```shell
git status -s
git diff
```

`git status -s` 回答“哪些路径变了”，`git diff` 回答“working tree 里还没暂存的内容是什么”。

## 2、选择

确认本轮改动的意图后，把目标路径放进 index：

```shell
git add <path>
git diff --staged
```

`git add <path>` 表示选择本次提交要包含的路径；`git diff --staged` 是提交前最关键的一眼，它展示下一次提交会保存什么。

如果这轮改动里有多个意图，应按 [[12、最小可读提交|最小可读提交]] 的原则拆开，而不是直接把所有文件塞进同一个提交。

## 3、提交

确认暂存区内容后，把 index 写成新的 commit：

```shell
git commit -m "Summarize the intent"
```

提交信息应说明这次改动的意图，而不是机械列出文件名。一个写不清楚的 message，常常说明改动范围还需要再拆。

## 4、回看

提交不是循环终点。提交后要回看历史和最新提交：

```shell
git log --oneline --decorate --max-count=3
git show --stat HEAD
git status -s
```

`git log` 确认最新提交信息和历史位置；`git show --stat HEAD` 确认最新提交动了哪些文件；最后的 `git status -s` 确认回到 clean。

# 三、clean

clean 不是形式主义，也不是催你把所有东西立刻提交。它的意义是让每一轮结束时状态清楚，下一轮不会混进旧改动。

| clean 意味着 | 价值 |
|---|---|
| working tree 没有未保存改动 | 不容易把旧改动混进新任务 |
| index 里没有待提交内容 | 下一次提交从清楚起点开始 |
| 最新 commit 已经可回看 | 历史可诊断 |

如果改动还没想清楚，可以继续编辑；如果改动已经形成一个清楚意图，就通过提交把它固定下来。关键是不要长期停在“自己也说不清哪些内容该提交”的混合状态。

# 四、卡住诊断

## 1、状态定位

卡住时先别猜，先问“文件现在在哪里”：

| 问题 | 命令 |
|---|---|
| 不知道文件在哪个状态 | `git status -s` |
| 不知道 working tree 改了什么 | `git diff` |
| 不知道 index 里有什么 | `git diff --staged` |
| 暂存错了 | `git restore --staged <path>` |

`git status -s` 是诊断入口；`git diff` 和 `git diff --staged` 分别对应 working tree 与 index。

## 2、历史确认

已经提交后，用历史命令回看：

| 问题 | 命令 |
|---|---|
| 不知道最近提交是什么 | `git log --oneline --decorate --max-count=3` |
| 不知道最近提交动了什么文件 | `git show --stat HEAD` |
| 想看最近提交的具体内容 | `git show HEAD` |

回看不是多余步骤。它能及时发现 message 不清楚、文件夹带错误或统计不符合预期的问题。

# 五、本地练习

起点：继续使用上一课结束后的本地仓库。上一课完成后，仓库应为 clean，最新提交信息是 `Clarify practice repository purpose`。

先确认当前状态和最近历史：

```shell
git status -s
git log --oneline --decorate --max-count=4
```

用编辑器打开 `daily-note.txt`，在末尾新增一行：

```text
Completed the local repository daily loop.
```

完整走一遍本地循环：

```shell
git status -s
git diff
git add daily-note.txt
git diff --staged
git commit -m "Complete local repository daily loop"
git log --oneline --decorate --max-count=4
git show --stat HEAD
git status -s
```

检查目标：

| 检查项 | 期待结果 |
|---|---|
| 最新提交 | `Complete local repository daily loop` |
| 最新提交统计 | `daily-note.txt` 有 1 行新增 |
| 最后 `git status -s` | 没有输出 |

本课目标状态：新增一个 `Complete local repository daily loop` 提交；仓库回到 clean；第一单元的本地基本功闭环完成。

# 六、小结

Git 的本地基本功，是让每一次改动都能被看见、被选择、被解释、被回看。

从这一轮开始，遇到混乱状态时先回到四个问题：现在有哪些路径变了，working tree 里改了什么，index 里准备提交什么，最近提交实际保存了什么。下一步进入分支、合并与历史演进，学习 `branch`、`HEAD`、`merge` 和 conflict。
