# 一、为什么需要忽略规则

真实项目里，并不是所有出现在工作区的文件都应该交给 Git 管理。

常见不适合提交的文件包括：

| 类型   | 示例                         | 原因            |
| ---- | -------------------------- | ------------- |
| 编译产物 | `dist/`、`build/`、`target/` | 可重新生成         |
| 依赖目录 | `node_modules/`            | 文件多、体积大、可重新安装 |
| 日志文件 | `*.log`                    | 运行时临时生成       |
| 系统文件 | `.DS_Store`                | 与个人电脑环境有关     |
| 本地密钥 | `.env`                     | 可能包含敏感信息      |

忽略规则的作用是让这些未跟踪文件不再干扰 `git status`，也避免被普通的 `git add .` 误加入暂存区。

# 二、两类规则

忽略规则分两类：项目共享规则放进 `.gitignore`，个人本地规则放进 `.git/info/exclude`。判断标准是“这条规则是不是应该影响团队里的其他人”。

![[assets/Pasted image 20260724012358.png|600]]

| 文件 | 是否提交 | 适合规则 |
|---|---|---|
| `.gitignore` | 通常提交 | 团队都不该提交的文件，例如日志、缓存目录、构建产物 |
| `.git/info/exclude` | 不提交 | 只影响自己的文件，例如个人实验文件、本机临时笔记 |

可以先记成：

```text
团队共享规则写 .gitignore
个人本地规则写 .git/info/exclude
```

# 三、`.gitignore`

## 1、基本作用

`.gitignore` 通常放在项目根目录，用来记录项目共享的忽略规则。

示例：

```gitignore
.DS_Store
*.log
dist/
node_modules/
.env
```

`.gitignore` 本身通常应该提交到仓库，因为它是团队共享的项目规则。

## 2、忽略某类文件

```gitignore
*.log
```

表示忽略所有以 `.log` 结尾的文件，例如 `debug.log`。

## 3、忽略目录

```gitignore
dist/
build/
node_modules/
```

目录规则适合编译产物和依赖目录。

## 4、忽略具体文件

```gitignore
.env
```

`.env` 往往保存本地数据库密码、API key 等敏感配置。项目如果需要说明环境变量，可以提交 `.env.example`，但真实 `.env` 应忽略。

## 5、取消忽略

`!` 可以对前面的规则取反：

```gitignore
*.log
!important.log
```

含义是忽略所有 `.log` 文件，但保留 `important.log` 可见。

# 四、规则写法

忽略规则一行写一条。常见写法如下：

| 规则 | 匹配什么 | 不匹配什么 |
|---|---|---|
| `*.log` | 任意位置的 `.log` 文件，例如 `debug.log` | `debug.txt` |
| `tmp/` | 名为 `tmp` 的目录及其中内容 | `tmp.txt` |
| `/dist/` | 仓库根目录下的 `dist/` | `src/dist/` |
| `build/*.tmp` | `build/` 下一层的 `.tmp` 文件 | `build/cache/a.tmp` |
| `!keep.log` | 把 `keep.log` 从前面的忽略规则中排除出来 | 不能恢复父目录已经被忽略的文件 |
| `# note` | 注释，方便解释规则为什么存在 | 不会匹配文件 |

本篇练习只用最常见的两条：

```gitignore
*.log
tmp/
```

先把“日志文件”和“缓存目录”读准，比一次背完整套语法更重要。

# 五、查看生效

## 1、显示被忽略文件

默认 `git status` 不显示被忽略文件。可以执行：

```shell
git status --ignored
```

如果 `debug.log` 被忽略，输出中可能出现：

```text
Ignored files:
        debug.log
```

## 2、定位忽略来源

```shell
git check-ignore -v debug.log
```

输出可能类似：

```text
.gitignore:1:*.log    debug.log
```

这表示 `debug.log` 被 `.gitignore` 第 1 行的 `*.log` 规则忽略。

# 六、已跟踪文件

`.gitignore` 最容易误解的一点是：

> `.gitignore` 只影响未跟踪文件。

如果 `debug.log` 已经被 Git 跟踪，后来再把它写入 `.gitignore`，Git 仍会继续跟踪它的修改。

如果要让 Git 停止跟踪但保留本地文件：

```shell
git rm --cached debug.log
```

完整流程通常是：

```shell
echo "*.log" >> .gitignore
git rm --cached debug.log
git add .gitignore
git commit -m "Stop tracking debug log"
```

`git rm --cached` 的作用见 [[7、删除和重命名文件|删除和重命名文件]]。

# 七、本地忽略

除了 `.gitignore`，Git 还有当前仓库本地忽略文件：

```text
.git/info/exclude
```

它的语法和 `.gitignore` 类似，但不会提交到仓库。

| 文件 | 适合规则 | 是否提交 |
|---|---|---|
| `.gitignore` | 项目共享规则 | 通常提交 |
| `.git/info/exclude` | 只和自己电脑有关的本地规则 | 不提交 |

例如，个人临时测试文件 `local-only.txt` 只想在当前仓库忽略，就可以写入 `.git/info/exclude`。

# 八、本地练习

起点：继续使用上一课结束后的本地仓库，当前应为 clean，并且 `note.txt` 已改名为 `daily-note.txt`。

先制造项目级噪音：

```shell
git status -s
printf "debug\n" > debug.log
mkdir -p tmp
printf "cache\n" > tmp/cache.txt
git status -s
```

此时应看到：

```text
?? debug.log
?? tmp/
```

创建 `.gitignore`，写入：

```gitignore
*.log
tmp/
```

保存后检查：

```shell
git status -s
```

此时应只看到：

```text
?? .gitignore
```

再创建只属于自己的本地临时文件：

```shell
printf "my local scratch\n" > local-only.txt
git status -s
```

此时会看到：

```text
?? .gitignore
?? local-only.txt
```

打开 `.git/info/exclude`，在文件末尾新增：

```gitignore
local-only.txt
```

保存后再次检查并提交共享规则：

```shell
git status -s
git add .gitignore
git commit -m "Add ignore rules"
git status -s
```

检查目标：

| 检查项 | 期待结果 |
|---|---|
| 最后 `git status -s` | 没有输出 |
| `.gitignore` | 已提交，包含 `*.log` 和 `tmp/` |
| `.git/info/exclude` | 本地保留，包含 `local-only.txt` |
| 磁盘文件 | `debug.log`、`tmp/cache.txt`、`local-only.txt` 仍存在 |

本课目标状态：`.gitignore` 已提交；本地忽略规则留在 `.git/info/exclude`；日志、缓存和本地临时文件仍在磁盘上，但不再干扰状态输出。

# 九、小结

| 场景 | 处理方式 |
|---|---|
| 未跟踪临时文件不想显示 | 写入 `.gitignore` |
| 文件已经被 Git 跟踪，但以后不想跟踪 | `git rm --cached <file>` |
| 团队共享忽略规则 | 写入 `.gitignore` |
| 个人本地忽略规则 | 写入 `.git/info/exclude` |
| 不确定为什么被忽略 | `git check-ignore -v <file>` |

最重要的边界是：`.gitignore` 不是取消跟踪工具，它只影响 Git 还没有跟踪的文件。
