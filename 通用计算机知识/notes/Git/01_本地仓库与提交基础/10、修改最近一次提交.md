# 一、amend

提交完成后，可能马上发现提交信息写错、漏加文件，或者还有一处小修改本应属于这次提交。如果它是当前分支的最近一次提交，并且还没有共享给别人，可以使用：

```shell
git commit --amend
```

`amend` 的核心不是“补一个新提交”，而是“用一个新提交替换最近一次提交”。

![[assets/amend-last-commit-generated.png|600]]

最小模型：

```text
修改前：A -- B -- C
修改后：A -- B -- C'
```

`C` 和 `C'` 是两个不同提交，因此 amend 后 commit id 会变化。这不是异常，而是 Git 重新生成提交对象的结果。

使用 `amend` 前先问三件事：

| 问题 | 为什么要问 |
|---|---|
| 我要改的是最近一次提交吗 | `--amend` 只适合修正最顶端的提交 |
| 它还没有 push 或分享给别人吗 | 已共享历史不要随意重写 |
| 我检查过暂存区了吗 | 新提交会使用当前暂存区内容 |

可以压缩成一句话：

```text
最近一次 + 未共享 + 已检查暂存区 = 可以 amend
```

> [!warning] 不要随意重写共享历史
> 对本地、未共享的最近提交，可以使用 `amend`。对已共享提交，通常应使用 `git revert` 新增反向提交，而不是改写旧历史。

# 二、常用操作

## 1、补充内容

如果漏提交了文件或小修改，先暂存遗漏内容，并检查暂存区：

```shell
git add <path>
git diff --staged
```

确认无误后，沿用原提交信息：

```shell
git commit --amend --no-edit
```

示例：上一课提交 `.gitignore` 后，又发现还应该忽略 `.tmp` 文件：

```shell
echo "*.tmp" >> .gitignore
git add .gitignore
git diff --staged
git commit --amend --no-edit
```

`--no-edit` 表示沿用原提交信息，不打开编辑器。

> [!important] `amend` 使用当前暂存区
> 执行前应先用 `git status` 和 `git diff --staged` 检查暂存区，因为新的替代提交会基于当前暂存区快照生成。

## 2、修改信息

如果内容已经正确，只是最近一次提交信息不够清楚，可以直接改 message：

```shell
git commit --amend -m "Add shared ignore rules"
```

如果提交信息较长，也可以打开编辑器修改：

```shell
git commit --amend
```

默认编辑器配置见 [[1、Git 安装与配置|Git 安装与配置]]。

## 3、同时修改

内容和提交信息都要改时，先暂存新内容，再指定新的提交信息：

```shell
git add <path>
git diff --staged
git commit --amend -m "new message"
```

这样会同时修改最近提交的内容和提交信息。

## 4、改完检查

amend 后至少检查三件事：

```shell
git log --oneline --decorate --max-count=3
git show --stat HEAD
git status -s
```

| 检查 | 期待 |
|---|---|
| `git log` | 最新 message 是你想要的，且最新哈希已经变化 |
| `git show --stat HEAD` | 文件统计包含你补进去的内容 |
| `git status -s` | 没有输出，表示 clean |

## 5、操作选择

```text
最近一次提交需要修正
  │
  ├─ 只改提交信息
  │    └─ git commit --amend -m "new message"
  │
  ├─ 只补充文件或修改
  │    └─ git add <path>
  │       git diff --staged
  │       git commit --amend --no-edit
  │
  └─ 内容和提交信息都要改
       └─ git add <path>
          git diff --staged
          git commit --amend -m "new message"
```

# 三、本地练习

起点：继续使用上一课结束后的本地仓库。第 9 篇只读历史，因此当前应为 clean。

先查看当前最近提交：

```shell
git status -s
git log --oneline --decorate --max-count=3
```

给上一课的 `.gitignore` 补一条遗漏规则：

```gitignore
*.tmp
```

保存后检查并暂存：

```shell
git status -s
git add .gitignore
git diff --staged
```

把遗漏规则补进最近一次提交，但沿用原提交信息：

```shell
git commit --amend --no-edit
git log --oneline --decorate --max-count=3
```

然后把最近提交信息改得更清楚：

```shell
git commit --amend -m "Add shared ignore rules"
git show --stat HEAD
git status -s
```

检查目标：

| 检查项 | 期待结果 |
|---|---|
| `.gitignore` | 包含 `*.log`、`tmp/`、`*.tmp` |
| 最新提交信息 | `Add shared ignore rules` |
| 最新提交统计 | `.gitignore` 有 3 行 |
| `git status -s` | 没有输出 |

本课目标状态：`.gitignore` 的遗漏规则已补进最近一次提交；最新提交信息更清楚；仓库仍然 clean。

# 四、小结

`git commit --amend` 解决的是“最近一次本地提交需要修正”的问题。它会生成新提交并改变哈希，因此使用前要确认这个提交还没有成为共享历史。
