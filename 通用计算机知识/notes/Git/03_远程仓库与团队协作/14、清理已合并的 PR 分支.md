# 一、分支清理

PR 合并后，feature 分支通常可以清理。清理前先确认 PR 已 merged、本地 `main` 已经与 `origin/main` 对齐，再分别处理 GitHub 上的远程分支、本地远程跟踪分支和本地分支。

核心模型是：

```text
PR merged
main 已经包含 feature 改动
远程 feature 分支可以删除
本地远程跟踪分支需要刷新
本地 feature 分支可以安全删除
```

删除已合并分支名通常不是删除历史。分支名只是指向提交的入口；当 `main` 已经包含 feature 改动后，删除 `feature/pr-practice` 这个名字通常只是清理入口，不会把 `main` 里的提交删掉。

# 二、三种名字

## 1、位置区别

清理 PR 分支时，最容易混淆的是三个长得相似的名字：

| 名字 | 在哪里 | 清理方式 |
|---|---|---|
| `feature/pr-practice` | 本地分支 | `git branch -d feature/pr-practice` |
| `origin/feature/pr-practice` | 本地远程跟踪分支 | `git fetch --prune origin` 后刷新 |
| GitHub 上的 `feature/pr-practice` | 远程仓库分支 | GitHub 页面 `Delete branch`，或 `git push origin --delete feature/pr-practice` |

这三者不是同一个东西。GitHub 上的远程分支删掉后，本地的 `origin/feature/pr-practice` 记录可能还留着；本地 feature 分支也不会自动消失。

## 2、清理顺序

推荐顺序是：

```text
先确认 main 对齐
再清理 GitHub 远程 feature 分支
再 prune 本地远程跟踪分支
最后删除本地 feature 分支
```

这个顺序能降低误删风险，也能让每一步的结果更容易观察。

# 三、前置确认

## 1、PR 与 main

清理前先确认：

| 检查项 | 为什么 |
|---|---|
| PR 已 merged | 没合并就删除分支，会让继续协作变麻烦 |
| 本地 `main` 已与 `origin/main` 对齐 | 先确认本地看见了合并结果 |
| 当前不在要删除的本地分支上 | Git 不允许删除当前所在分支 |
| `git branch -d` 能成功 | `-d` 会保护未合并分支 |

本地状态应类似：

```shell
git status -sb
```

```text
## main...origin/main
```

## 2、同步 main

如果还不在 `main`，先切回并同步：

```shell
git switch main
git fetch origin
git pull --ff-only
```

再次确认：

```shell
git status -sb
```

```text
## main...origin/main
```

# 四、远程分支

## 1、页面删除

打开已经 merged 的 PR。GitHub 通常会显示 `Delete branch` 按钮。

页面操作顺序：

1. 确认 PR 状态是 merged。
2. 确认要删除的是 `feature/pr-practice`，不是 `main`。
3. 点击 `Delete branch`。
4. 确认页面显示分支已删除或可恢复。

命令行也能删除远程分支：

```shell
git push origin --delete feature/pr-practice
```

学习阶段优先用 GitHub 页面按钮，因为页面能同时展示 PR merged 状态和删除目标，更不容易删错。

## 2、自动删除

GitHub 可以配置 PR 合并后自动删除 head branch。对应设置通常在：

```text
Settings -> Pull Requests -> Automatically delete head branches
```

中文理解是：

```text
PR 合入后，自动删除这个 PR 的来源分支。
```

需要注意：

| 情况 | 含义 |
|---|---|
| 需要仓库管理员权限 | 普通协作者不一定能改这个设置 |
| 自动删除的是 head branch | 也就是 PR 来源分支，例如 `feature/pr-practice` |
| 不会删除 base branch | `main` 不会因为这个设置被删除 |
| 受保护分支或规则可能阻止删除 | 如果 head branch 受保护，可能不会自动删除 |
| 只影响 GitHub 远程分支 | 本地分支和本地 `origin/*` 记录仍要自己处理 |

如果仓库已经开启自动删除，PR 合并后远程 `feature/pr-practice` 可能已经消失。此时远程删除步骤变成确认它已经被删除。

# 五、本地清理

## 1、刷新远程跟踪分支

GitHub 上的远程分支删除后，本地保存的 `origin/feature/pr-practice` 记录可能还没刷新。此时要清理的是本地过期记录：

```shell
git fetch --prune origin
```

这个命令可以拆开理解：

| 部分 | 作用 |
|---|---|
| `git fetch origin` | 从名为 `origin` 的远程拿回最新分支信息 |
| `--prune` | 删除本地已经过期的 `origin/*` 远程跟踪分支记录 |

注意：`--prune` 不会删除 GitHub 上的真实分支。GitHub 上的分支要先通过页面按钮或 `git push origin --delete ...` 删除。

查看远程跟踪分支：

```shell
git branch -r
```

`-r` 是 remote 的意思，只列出本地保存的远程跟踪分支。远程 feature 分支已删除并 prune 成功后，通常只会看到类似：

```text
  origin/HEAD -> origin/main
  origin/main
```

如果仍然看到 `origin/feature/pr-practice`，常见原因是 GitHub 上的分支其实还没删，或者还没有成功执行 `git fetch --prune origin`。

## 2、删除本地分支

先确认当前站在 `main`：

```shell
git status -sb
```

再查看哪些本地分支已经合并到当前 `main`：

```shell
git branch --merged
```

`git branch --merged` 按当前 `HEAD` 判断。因为现在站在 `main`，它回答的是：哪些本地分支的提交已经能从 `main` 走到。

如果列表里有：

```text
  feature/pr-practice
* main
```

说明本地 Git 认为这个分支已经合并到当前 `main`。这时可以安全删除本地分支名：

```shell
git branch -d feature/pr-practice
```

`git branch -d` 的 `-d` 是 delete。它是带保护的删除：如果 Git 认为这个分支还没有合并到当前分支，它会拒绝删除。

# 六、练习流程

## 1、GitHub 页面

打开已经 merged 的 PR，逐项确认：

1. PR 状态是 merged。
2. 远程 feature 分支是 `feature/pr-practice`。
3. 如果仓库启用了 `Automatically delete head branches`，确认 `feature/pr-practice` 已经自动删除。
4. 如果没有自动删除，找到 `Delete branch`。
5. 确认按钮指向的是 `feature/pr-practice`。
6. 点击 `Delete branch` 删除远程 feature 分支。

完成后，GitHub 上的远程 feature 分支应该已经删除，或者页面显示它可恢复。

## 2、本地终端

回到本地仓库：

```shell
cd path/to/practice-repo
git status -sb
git fetch --prune origin
git branch -r
git branch --merged
git branch -d feature/pr-practice
git branch
git status -sb
```

期待结果：

| 检查项 | 期待结果 |
|---|---|
| GitHub PR | merged |
| GitHub feature 分支 | 已删除，或页面提示可恢复 |
| `origin/feature/pr-practice` | `fetch --prune` 后不再显示 |
| 本地 `feature/pr-practice` | 用 `git branch -d` 删除 |
| 当前分支 | `main` |
| 工作区 | clean |

# 七、风险边界

## 1、不要默认 -D

如果 `git branch -d feature/pr-practice` 拒绝删除，可能看到：

```text
error: The branch 'feature/pr-practice' is not fully merged.
If you are sure you want to delete it, run 'git branch -D feature/pr-practice'.
```

这表示 Git 认为该分支还没有完全合并到当前分支。先停下，不要把 `-D` 当默认选择。

`git branch -D feature/pr-practice` 是强制删除本地分支名。它不会删除远程分支，也不会直接删除提交对象，但可能让你失去一个还没合并工作的入口。

可以先运行：

```shell
git branch --merged
git log --oneline --decorate --graph --all --max-count=12
```

确认原因后再决定。

## 2、常见误区

| 误区 | 更准确的理解 |
|---|---|
| 自动删除会清理本地分支 | `Automatically delete head branches` 只处理 GitHub 上的 head branch |
| 删除分支等于删除历史 | 删除已合并分支名通常不会删除 `main` 里的提交 |
| 未 merged 也清理 | 未合并分支可能还有未进入 `main` 的改动 |
| 看到 `origin/feature` 还在就以为 GitHub 没删 | 本地远程跟踪分支可能是旧记录，先 `fetch --prune` |
| `git branch -d` 失败就立刻用 `-D` | `-d` 失败是在提醒你先诊断合并关系 |

清理分支的关键是分清“远程分支、本地远程跟踪分支、本地分支”。它衔接 [[13、合并 PR 并同步本地 main|合并 PR 后同步 main]]：先确认 `main` 已经包含改动，再清理不再需要的分支入口。
