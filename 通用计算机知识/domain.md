# 通用计算机知识 领域规则

## 领域概述

操作系统、计算机网络、数据结构与算法、计算机组成原理等通用计算机科学基础知识

## 分类体系

wiki 页面按以下子目录组织：

- `summaries/` — 单篇来源摘要（某篇文章、某节课程的知识点提炼）
- `entities/` — 实体页面（算法、协议、工具、硬件、人物）
- `concepts/` — 概念页面（进程调度、TCP 握手、B+ 树、缓存一致性等核心概念）
- `comparisons/` — 对比分析（如 TCP vs UDP、BFS vs DFS、乐观锁 vs 悲观锁）
- `overviews/` — 领域概览（如计算机网络体系结构总览、操作系统内核概览）
- `syntheses/` — 综合结论与最佳实践（如面试题总结、系统设计模式）
- `recipes/` — 可复用方法、操作指南（如 GDB 调试流程、性能分析步骤）

## 标签体系

领域初始标签（统一使用英文，便于检索和 Dataview 查询）。标签是动态扩展的——以下只是种子标签，LLM 在 ingest 时会根据素材内容自动补充：

- `#operating-system` — 操作系统（进程、线程、内存管理、文件系统、调度算法）
- `#network` — 计算机网络（协议、模型、传输、安全）
- `#data-structure` — 数据结构（数组、链表、树、图、哈希表）
- `#algorithm` — 算法（排序、搜索、动态规划、贪心、回溯）
- `#computer-architecture` — 计算机组成原理（CPU、缓存、指令集、流水线）
- `#database` — 数据库（SQL、索引、事务、存储引擎、查询优化）
- `#distributed-system` — 分布式系统（一致性、共识算法、CAP、微服务）

**标签添加原则**：
- 初始标签作为 ingest 时的参考基准
- 当素材涉及新的子主题时，自动创建新标签
- 定期 review 标签使用情况，合并过于细分的标签

## qmd 配置

- collection 名称：`knowledge-通用计算机知识`
- collection root：`通用计算机知识/wiki`
- collection 注册：由 `qmd_sync.py` 根据 Git 根目录与 collection root 幂等同步；本机配置不写入仓库

## 特殊约定

- **术语处理**：英文术语首次出现时标注全称和中文翻译，如 Round-Robin Scheduling（轮转调度）。后续使用英文简称即可。
- **复杂度标注**：算法页面必须标注时间复杂度和空间复杂度，使用标准 Big-O 表示法。
- **图示偏好**：数据结构、算法流程、网络协议交互等复杂概念优先使用 ASCII 图或 canvas 图示，放在 `assets/` 目录并在页面中嵌入。
- **跨领域引用**：该领域内容常与 Rust、Python、前后端等领域交叉。涉及具体语言实现时，使用 `[[Rust/xxx]]` 或 `[[Python/xxx]]` 链接指向对应领域页面，保持通用知识与具体实现的分离。
