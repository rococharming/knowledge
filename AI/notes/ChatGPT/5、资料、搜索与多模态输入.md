# 一、上下文来源

ChatGPT 的结果不仅取决于提示词，也取决于它实际获得了哪些资料。常见上下文来源包括：

| 来源 | 适合的场景 | 持续范围 |
|---|---|---|
| 当前消息中的文字 | 简短背景和一次性资料 | 当前 Chat |
| 当前消息的附件 | 单次分析、比较或转换 | 当前 Chat |
| Project Sources | 多个 Chat 共同使用的资料 | 当前 Project |
| 本地文件夹 | 直接读取或修改电脑文件 | 当前本地 Project |
| Web Search | 需要最新公开信息 | 当前任务 |
| Plugin | 云盘、邮件、日历等外部服务 | 取决于授权和当前 Chat |

选择上下文时应遵循“够用即可”：资料过少会导致猜测，资料过多则会增加噪声，让真正重要的信息不突出。

# 二、文件

## 1、附加文件

可以向 Chat 添加文档、演示文稿、表格、PDF、图片和数据文件。适合让 ChatGPT：

- 总结或比较文件
- 提取结构化信息
- 查找矛盾和缺失项
- 清理或重组数据
- 把现有材料转换成新的交付物

附加文件时，要说明文件的角色。

示例：

```text
附件 A 是当前有效的需求，附件 B 是旧版设计，只用于理解背景。
请比较两者并列出真正发生变化的条目，不要把 B 中已删除的需求带入结论。
```

## 2、复用资料

文件只服务于当前请求时，直接附加到 Chat；多个 Chat 都要使用时，把文件加入 Project Sources；需要直接操作电脑中的整套文件时，使用本地 Project。

如果资料含有密钥、个人信息或公司敏感数据，应先确认组织策略和 ChatGPT 的数据访问范围，再决定是否提供。

# 三、Web Search

## 1、使用时机

任务依赖新闻、版本、价格、政策、日程或其他可能变化的信息时，应要求 ChatGPT 使用 Web Search。

示例：

```text
搜索 OpenAI 官方文档，确认 ChatGPT App 当前支持哪些桌面操作能力。
只使用官方来源，并在关键结论旁附链接。
```

ChatGPT 的第一方 Web Search 会把搜索活动和其他工具调用一起记录在 Chat 中。搜索结果和网页内容都属于外部输入，仍然需要检查来源质量。

## 2、核对结果

搜索完成后，应重点核对：

- 来源是否真的支持对应结论
- 发布日期和事件发生日期是否被混淆
- 是否使用了过时页面
- 关键数字和引用是否来自原始来源
- 网页内容是否可能包含诱导工具执行的提示注入

Web Search 负责查找信息；[[8、浏览器与计算机操作|Browser]] 还可以打开网页、查看页面状态并执行交互操作，两者不是同一个能力。

# 四、图片

## 1、图片输入

当任务依赖视觉信息时，可以附加截图、照片、架构图或设计稿。根据官方 [Image inputs](https://learn.chatgpt.com/docs/image-inputs) 指南，提示中应同时说明：

- 图片是什么
- 哪个区域最重要
- 希望 ChatGPT 完成什么
- 哪些内容不能改变

示例：

```text
第一张图是当前页面，第二张图是设计稿。
比较导航栏的间距和字体，只列出视觉差异，不推测业务逻辑。
```

## 2、Appshot

Appshot 是 ChatGPT 对桌面应用窗口获取的视觉上下文。它不仅可能包含可见画面，也可能包含窗口的辅助功能文字，包括当前滚动区域之外的内容。

使用 Appshot 前应关闭或遮挡敏感窗口，并确认 macOS 的 Screen Recording 与 Accessibility 权限是否符合当前任务需要。

## 3、图片生成

图片输入用于 **理解现有图片**；Image Generation 用于 **创建或编辑图片**。

生成图片时，说明用途、主体、构图、风格和必须保持的约束。编辑现有图片时，应明确“修改什么”和“保持什么不变”。

示例：

```text
为一篇新员工入职指南生成简洁的编辑插画。
画面是一位员工在桌面整理项目资料，使用柔和自然光和克制配色。
不要出现文字、Logo 或未来科技元素。
```

# 五、Voice

## 1、语音对话

ChatGPT Voice 可以在桌面 App 的 Chat、Work 和 Codex 中进行实时语音交流。它适合：

- 口头梳理思路
- 在任务运行时询问进度
- 追加条件或改变方向
- 协调多个较长任务

Voice Chat 需要从一个新的空白 Chat 或 Task 开始。第一次使用时，App 会请求麦克风权限；macOS 上使用屏幕上下文还可能请求 Screen Recording 和 Accessibility 权限。

## 2、语音听写

Voice Chat 是持续的实时对话；Voice Dictation 只把语音转换成输入区中的文字，发送前仍可编辑。

| 需求 | 选择 |
|---|---|
| 想持续用语音交流和控制任务 | Voice Chat |
| 只是不想键盘输入提示词 | Voice Dictation |

默认听写快捷键是 <kbd>Ctrl</kbd> + <kbd>Shift</kbd> + <kbd>D</kbd>。

# 六、选择方法

遇到一项资料任务时，可以按下面的顺序判断：

1. 信息是否已经在当前对话中？如果是，直接引用当前内容。
2. 是否只需使用少量文件一次？如果是，附加到当前 Chat。
3. 是否需要多个 Chat 重复使用？如果是，加入 Project Sources。
4. 是否依赖当前公开信息？如果是，使用 Web Search。
5. 是否需要登录后的外部服务？如果是，使用 [[9、Plugins 与外部服务|Plugin]]。
6. 是否需要直接查看或操作网页和桌面应用？如果是，使用 Browser 或 Computer Use。

知识工作实践可以从下面的提示开始：

```text
使用 Project 中的三份访谈记录总结主要用户问题，
再搜索最新官方资料核对产品能力。
把每条结论标记为“来自访谈”或“来自官方资料”，
暂时不要生成最终报告。
```

资料确认完成后，再进入 [[6、使用 Work 完成交付物|Work]] 生成可审阅的成果。
