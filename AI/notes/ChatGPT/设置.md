# 一、设置

ChatGPT 设置是管理账号、界面、个性化、外部连接和本地执行权限的地方。它不会直接改变模型“聪不聪明”，但会改变 ChatGPT 能看到什么、能操作什么、默认怎样回复，以及哪些动作需要先确认。

截至 2026-07-31，新版 ChatGPT 桌面 App 把 Chat、Work 和 Codex 放在同一个应用中：ChatGPT 工作区包含 Chat 和 Work，Codex 仍是单独的开发工作区。因此设置也分成三类：

| 分类 | 主要管理什么 |
|---|---|
| 个人 | 账号、界面、语言、语音、个性化、快捷键和计费 |
| 集成 | 插件、浏览器、电脑操控和外部服务权限 |
| 编码 | Codex 的钩子、连接、Git、环境和 Worktree |

设置项会随账号套餐、地区、工作区策略、操作系统和 App 版本变化。如果某个选项没有出现，通常先检查版本、登录账号、工作区权限和所在工作模式。

# 二、个人

## 1、常规

常规页处理 App 的基础行为，特别是权限模式和桌面使用习惯。

| 选项 | 作用 |
|---|---|
| 默认权限 | 控制 ChatGPT 默认能否读取、编辑当前工作空间文件，以及遇到额外访问时是否需要请求批准 |
| 自动审核 | 让 ChatGPT 自动审查部分额外权限请求，减少手动确认 |
| 完全访问权限 | 允许 ChatGPT 在运行时更自由地访问文件和网络，风险明显更高 |
| 默认文件打开目标 | 选择打开文件或文件夹时默认使用哪个编辑器，例如 VS Code |
| 语言 | 设置 App 界面语言，常见选项包括自动检测和具体语言 |
| 在菜单栏中显示 | 主窗口关闭后，是否继续在 macOS 菜单栏保留 ChatGPT |
| 底部面板 | 是否在应用底部显示 Terminal 等底部面板控件 |
| 默认终端位置 | 选择终端和环境操作默认出现在底部还是右侧 |
| 运行时防止系统休眠 | ChatGPT 执行任务时，让电脑保持唤醒状态 |

其中最重要的是权限。默认权限适合日常工作；自动审核适合边界清楚、可以承受少量误判的任务；完全访问权限只适合隔离环境或明确需要跨目录、联网执行的任务。

## 2、个人资料

个人资料用于管理账号展示信息，例如姓名、头像、个人标识或工作区身份。它影响别人如何识别你，也可能影响共享、协作和组织工作区中的显示方式。

个人资料不是 Custom Instructions。前者是账号身份信息，后者是告诉 ChatGPT 如何理解你和如何回复你。

## 3、外观

外观页控制视觉体验。常见设置包括主题和强调色：

| 选项 | 作用 |
|---|---|
| 主题 | 跟随系统、浅色或深色 |
| 强调色 | 改变对话气泡、语音按钮和高亮等界面元素颜色 |

外观设置通常只影响当前设备或当前平台。例如 Web 上设置的主题，不一定会同步到移动端。

## 4、语音

语音页控制 ChatGPT 的语音体验。语音不是单纯的朗读功能，而是让用户用说话方式和 ChatGPT 对话。

| 选项 | 作用 |
|---|---|
| Voice 类型 | 在 Live、Advanced 或 Standard 等语音体验之间切换，具体可见项取决于账号和版本 |
| 主语言 | 指定或自动检测语音输入语言，提高听写和识别稳定性 |
| 声音 | 选择 ChatGPT 回复时使用的声音 |
| 后台对话 | 允许语音对话在切换 App 或锁屏后继续一段时间 |
| 独立语音模式 | 在普通聊天内使用语音，或进入单独的全屏语音体验 |

Live 更接近自然对话，支持边听边说和更自然的打断；Advanced 保留部分移动端能力；Standard 更像先转写再回答的轮流对话。实际可选项会受到套餐、地区、工作区和版本影响。

## 5、配置

配置页通常用于管理 App 的高级偏好和本地配置入口。对普通 Chat 用户来说，它很少需要调整；对 Codex 或本地 Work 用户来说，它可能关联到本机配置、默认工作方式或调试入口。

如果不确定某个配置项的含义，应先保持默认值。配置类选项通常影响面较广，改动前要确认它是当前任务真正需要的。

## 6、个性化

个性化决定 ChatGPT 如何把长期偏好带入新对话。它与 [[10、个性化与记忆|个性化与记忆]] 关系最密切。

| 选项 | 作用 |
|---|---|
| Custom Instructions | 明确告诉 ChatGPT 你希望它知道什么、怎样回复 |
| Personality | 选择默认表达风格，例如更友好或更务实 |
| Characteristics | 调整回复特征，例如简洁程度、语气、格式和表情使用 |
| Memory | 允许 ChatGPT 引用保存的记忆或历史对话综合出的背景 |
| Memory 管理 | 查看、刷新、编辑、删除或关闭记忆 |

Custom Instructions 适合写稳定偏好，例如默认语言、输出风格和个人背景。Memory 适合让 ChatGPT 从长期使用中记住有用信息。项目规则、代码风格和必须遵守的约束，仍应写入 Project Instructions 或本地项目文档。

## 7、宠物

宠物是桌面 App 的轻量陪伴和界面装饰类设置。它通常不影响模型能力、权限、上下文或计费。

如果目标是提高工作效率，宠物设置可以按个人喜好处理；如果目标是控制数据访问、任务风险或输出质量，应优先检查权限、个性化、插件和 Codex 设置。

## 8、键盘快捷键

键盘快捷键用于快速打开 ChatGPT、切换窗口、启动语音、打开浏览器或执行常用动作。

常见用途包括：

- 打开 Chat Bar 或新建聊天
- 停止生成
- 打开内置 Browser
- 分享屏幕或当前窗口
- 聚焦、隐藏或切换面板

快捷键可以提高桌面使用效率，但也可能与编辑器、终端或系统快捷键冲突。出现误触时，应先到这里搜索并重新绑定。

## 9、使用情况和计费

使用情况和计费用于查看当前套餐、用量、限制、账单和升级入口。

需要区分不同类型的用量：

| 用量 | 说明 |
|---|---|
| 普通 Chat | 与聊天、图片、文件、语音等普通能力相关 |
| Work / Codex | 长任务、代码任务、云端任务等通常共用 agentic usage 或信用池 |
| Voice | 普通语音和 Work / Codex 中的语音可能按不同规则计量 |
| 插件和外部服务 | 还可能受第三方服务自己的配额和权限限制 |

达到限制后，可能需要等待重置、升级套餐、购买额外额度或缩小任务范围。

## 10、账户

账户页用于管理登录状态、账号信息、安全入口和退出登录。

常见操作包括：

- 查看当前登录账号
- 管理订阅或跳转到账户页面
- 切换工作区
- 退出登录
- 删除账号或进入相关数据控制入口

如果多个 ChatGPT App、Web、CLI 或插件同时使用不同账号，先在账户页确认当前身份，再处理权限和计费问题。

# 三、集成

## 1、智能快照

智能快照用于管理 App 在执行任务时可引用的上下文快照。它更像“当下状态”的辅助记录，适合让 ChatGPT 理解当前窗口、任务现场或可见上下文。

这类能力通常和隐私边界关系很近：开启前要确认它会记录什么、保存多久、哪些任务能引用，以及是否可以清除。不同版本中该页的命名和细节可能变化，应以当前设置说明为准。

## 2、插件

插件是 ChatGPT 和 Codex 的可安装能力包。一个插件可以包含：

- Skill：可复用的工作规则和流程
- App：连接外部服务和数据
- App template：供工作区管理员创建或配置应用

插件页用于浏览、安装、连接、断开或管理权限。连接插件时，需要检查：

| 检查项 | 原因 |
|---|---|
| 提供者 | 确认插件来自可信来源 |
| 读取范围 | 知道它能看哪些文件、仓库、邮件或频道 |
| 操作范围 | 区分只读、可创建、可修改和可发送 |
| 审批策略 | 确认哪些动作会先问你 |
| 第三方权限 | ChatGPT 不能绕过外部系统原本的账号权限 |

插件权限会受到个人账号、工作区角色、地区和套餐影响。某个插件可见，不代表它一定能连接或执行所有动作。

## 3、浏览器

浏览器设置管理桌面 App 的内置 Browser。它与普通 Web Search 不同：Web Search 查找公开信息，Browser 打开网页并在页面上交互。

| 选项 | 作用 |
|---|---|
| 允许网站 | 管理 ChatGPT 可以访问的网站 |
| 阻止网站 | 管理不允许 ChatGPT 使用的网站 |
| 浏览器数据 | 清除 Cookie、登录状态和浏览历史 |
| 下载位置 | 管理文件下载位置 |
| 开发者模式 | 在需要前端调试时，允许更深的浏览器检查能力 |

内置 Browser 使用自己的浏览器状态，不会自动共享日常 Chrome 的 Cookie、标签页或扩展。任务需要当前 Chrome 登录态时，应使用 Chrome 扩展；希望隔离账号状态时，应使用内置 Browser。

## 4、电脑操控

电脑操控允许 ChatGPT 查看并操作本机桌面应用，适合没有专用接口、必须通过图形界面完成的任务。它通常需要系统级权限，例如屏幕录制、辅助功能或自动化权限。

电脑操控的风险高于普通文本处理，因为它可能点击按钮、输入内容或读取屏幕。因此应遵循三个原则：

- 只在确实需要 GUI 操作时开启。
- 任务开始前关闭或遮挡无关敏感窗口。
- 涉及发送、购买、删除、提交等动作时要求先确认。

有关 Browser 和 Computer Use 的区别，参考 [[8、浏览器与计算机操作|浏览器与计算机操作]]。

# 四、编码

## 1、钩子

钩子用于在 Codex 工作流的特定节点自动运行命令或检查。例如开始任务前准备环境、修改后运行格式化、测试前生成文件，或结束时收集结果。

钩子适合稳定、低风险、可重复的动作。不要把会删除数据、发布版本、推送代码或修改外部系统的动作直接放入自动钩子。

## 2、连接

连接页管理 Codex 使用的外部开发服务和远程能力，例如代码托管、远程主机、MCP Server、插件依赖或账号授权。

连接成功只表示 ChatGPT 具备调用入口；实际能读写什么，还取决于外部服务账号权限、工作区策略和当前任务授权。

## 3、Git

Git 设置影响 Codex 如何理解和操作代码仓库。它通常与当前 Project、分支、工作区状态和 Pull Request 流程有关。

需要重点关注：

- 默认仓库或当前 Primary Folder
- 是否允许创建分支或 Worktree
- 提交作者信息
- Pull Request 相关连接
- 是否需要在提交、推送或创建 PR 前请求确认

本知识库约定不自动执行 `git add`、`git commit`、`git push`。即使 App 中存在相关 Git 设置，也应先展示变更摘要和提交信息，再等待确认。

## 4、环境

环境页管理 Codex 运行任务时使用的本地或远程执行环境。它会影响命令在哪里运行、能访问哪些变量、使用哪个终端或解释器，以及是否允许网络。

常见内容包括：

- 默认 shell 或终端行为
- 环境变量和密钥来源
- 依赖安装方式
- 本地、Worktree 或 Cloud 的默认选择
- 网络和沙盒边界

不要把密钥直接写进普通提示词。需要密钥时，应使用受控的环境变量、凭据管理器或插件授权。

## 5、工作树

工作树设置管理 Codex 使用 Git Worktree 的方式。Worktree 是同一仓库的独立工作目录，适合并行处理不同任务，同时减少互相覆盖的风险。

| 场景 | 是否适合 Worktree |
|---|---|
| 一个任务修改少量文件，当前工作区干净 | 不一定需要 |
| 多个 Codex 任务并行修改同一仓库 | 适合 |
| 当前目录已有未完成改动 | 适合 |
| 任务需要共享同一个本地数据库或服务状态 | 需要额外谨慎 |

Worktree 隔离的是 Git 工作目录，不会自动隔离数据库、缓存、端口、外部服务和生成目录。并行任务仍要检查共享资源冲突。

# 五、已归档

已归档区域用于查看被隐藏或归档的对象，例如过去的 Chat、Project、任务或 Codex 工作。归档通常只是从主要列表中移走，不等于删除。

需要找回旧工作时，先检查已归档；需要永久删除前，确认该内容是否仍包含可复用资料、文件输出或重要操作记录。

# 六、选择顺序

遇到设置问题时，可以按下面顺序定位：

| 问题 | 先看哪里 |
|---|---|
| ChatGPT 为什么答复风格不对 | 个性化、Custom Instructions、Memory |
| 为什么看不到某个功能 | 使用情况和计费、账户、工作区权限、App 版本 |
| 为什么不能读某个文件 | 常规权限、本地 Project、文件系统授权 |
| 为什么不能访问网页 | 浏览器、插件、网络权限、网站允许列表 |
| 为什么不能操作桌面 App | 电脑操控、系统辅助功能和屏幕录制权限 |
| 为什么 Codex 改错目录 | 工作树、Git、环境、Primary Folder |
| 为什么插件不能用 | 插件页、连接页、第三方账号权限 |

设置的核心思路是：先确定任务需要的能力，再只打开对应权限。权限越靠近文件、浏览器、电脑操控、外部服务和 Git 操作，越需要保守。
