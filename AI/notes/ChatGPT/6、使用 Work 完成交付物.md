# 一、Work

`ChatGPT Work` 用于把一项较完整的工作委托给 ChatGPT，并获得可以审阅和继续修改的结果。

Chat 适合解释、讨论和短草稿；Work 更适合：

- 使用多份来源和多个工具
- 需要连续执行多个步骤
- 创建文档、演示文稿、表格或 PDF
- 生成需要反复检查和调整的成果
- 重复、监控或定期更新一项工作

使用 Work 时，重点不是发出更多提示词，而是定义好 **最终成果、资料来源、约束和验收标准**。

# 二、执行位置

## 1、本地执行

选择 **Work locally** 时，任务在当前电脑上运行。适合需要：

- 本地文件夹
- 桌面应用
- 内置 Browser
- Computer Use
- 只能从当前电脑访问的资料

本地任务需要电脑保持开机，并在必要时让 ChatGPT App 继续运行。

## 2、云端执行

当输入区提供 **Cloud** 选项时，可以让 Work 在托管环境中继续执行。适合：

- 关闭 App 后仍需继续的任务
- 希望从 Web 或移动设备继续查看的任务
- 不依赖当前电脑文件和桌面应用的研究
- 定时搜索或检查网站

本地和云端不是质量等级，而是两种执行环境。任务需要本机资源时选择本地；需要脱离本机持续运行时选择云端。

# 三、任务说明

一个适合 Work 的任务通常包含：

1. **Outcome**：最终要得到什么。
2. **Sources**：使用哪些文件、Project Sources 或 Plugins。
3. **Constraints**：范围、语言、格式和禁止事项。
4. **Review criteria**：如何判断结果可以使用。
5. **Approval points**：哪些外部动作必须停下来确认。

示例：

```text
使用 Project 中的用户访谈和产品数据制作一份 10 页中文演示文稿。

结构包括：问题、证据、三个机会点、推荐方案和下一步。
图表中的数字必须来自附件；缺失数据要明确标注，不要估算。
生成后检查每页文字是否溢出、图表标签是否可读，并给出文件路径。
发布或发送给其他人之前必须先征求我的确认。
```

有关任务描述方法，参考 [[3、提问与提供上下文|提问与提供上下文]]。

# 四、文件交付

## 1、创建文件

Work 可以根据任务创建和修改：

- Markdown 和普通文档
- 演示文稿
- 电子表格
- PDF
- HTML
- 图片和其他媒体文件

创建文件时，应说明需要的具体结构。例如表格需要哪些 Sheet、列和图表；演示文稿需要哪些章节、页数和视觉重点。

## 2、预览文件

桌面 App 可以在 Chat 旁边预览生成的文档、演示文稿、表格和 PDF。HTML 文件在支持时还能切换渲染视图与源代码视图。

官方文件预览界面示意：

![[chatgpt-artifact-viewer.webp|700]]

预览的价值是让“文件已经生成”与“文件确实可用”分开。每次交付至少检查：

- 文件能否打开
- 页、Slide 或 Sheet 是否完整
- 文字是否溢出
- 表格和图表是否准确
- 版式和可读性是否符合用途

## 3、批注修改

支持批注时，可以选中预览中的具体区域并要求局部修改。

示例：

```text
把第 4 页图表的纵轴名称改清楚。
保留数据、图表类型和其他页面不变。
```

批注会把选中区域作为上下文，适合在第一版已经接近完成时进行精确调整。

# 五、Sites

`Sites` 用于创建、托管、继续修改和分享网站、Web App 或小游戏。它适合需要可访问 URL、交互界面或持久化数据的成果。

基本流程：

1. 描述受众、用途、核心行为和信息来源。
2. 检查生成内容、交互和数据处理。
3. 通过文字、截图或文件继续修改。
4. 保存一个可部署版本。
5. 确认访问范围后再部署和分享。

> Sites 的每个部署 URL 都是生产部署。只想预览时，应先要求保存版本，不要直接部署。

Sites 与 ChatGPT Project 不同：Project 用于组织 Chat 和上下文；Site 是可重新打开、配置和分享的托管成果。

# 六、Visualizations

`Visualizations` 可以把问题和数据转换成图表、地图、流程图、计算器、模拟器或交互式讲解。

它适合以下情况：

- 调整输入后需要观察结果变化
- 多组数据需要直观比较
- 流程或关系用图比文字更清楚
- 学习内容需要交互式实验

在功能可用时，可以在输入区输入 `@Visualize` 并选择对应 Plugin。提示中应说明：

- 想回答的问题
- 使用的数据
- 合适的图形
- 需要哪些交互控件
- 单位、标签和可访问性要求

如果只需要一个静态关系图，普通图表或 Mermaid 往往更简单；如果需要长期托管、分享 URL 或持久化数据，应使用 Sites。

# 七、知识工作实践

下面用一条任务完成“技术方案调研报告”：

1. 在 [[4、对话与 Projects|Project]] 中准备访谈记录、数据文件和官方资料。
2. 先用 Chat 确认问题、受众和报告结构。
3. 切换到 Work，选择本地或云端执行。
4. 要求生成比较表格和演示文稿。
5. 打开预览，逐页检查事实、结构和布局。
6. 使用批注只修改存在问题的区域。
7. 要求 ChatGPT 报告保存路径和执行过的检查。
8. 需要交互展示时，再生成 Visualization 或 Site。

第一次执行可以使用：

```text
使用这个 Project 中的调研材料完成一份技术方案比较。
先生成包含成本、实现难度、维护风险和适用场景的表格，
再根据表格制作 8 页演示文稿。
所有结论必须能追溯到 Project Sources。
完成后预览两个文件并检查内容与布局，不要发布到外部。
```

任务需要较长时间、定期重复或在后台持续时，再使用 [[11、长期任务与自动化|长期任务与自动化]]。
