# 一、个性化

个性化让 ChatGPT 的表达和工作方式更符合长期偏好。它主要包括：

- Personality
- Custom Instructions
- Memories
- Project 或仓库指令
- Chronicle

这些能力的作用范围不同。表达风格、可选记忆和必须遵守的项目规则不应该混在同一个位置。

# 二、Personality

在 **Settings > Personalization** 中可以选择默认 Personality：

- **Friendly**：沟通更友好、自然。
- **Pragmatic**：表达更直接、务实。
- **None**：不额外应用 Personality 指令。

Personality 改变的是 ChatGPT **如何表达**，不会改变模型本身能做什么，也不能代替事实来源、项目规则或权限设置。

例如，希望回复更简短，应使用 Personality 或 Custom Instructions；希望某个代码库必须运行指定测试，应写入项目文档。

# 三、Custom Instructions

Custom Instructions 用于跨 Chat 持续生效的个人偏好，例如：

```text
默认使用中文。
先给结论，再解释关键原因。
遇到不确定信息时明确说明假设。
代码注释使用英文。
```

在 Codex 中，个人指令会存放在全局 `AGENTS.md` 中。Project 和仓库还可以提供各自的指令。

不要把一次性任务要求写入 Custom Instructions。例如“这次只修改登录页”应放在当前 Chat；否则它可能错误地影响未来任务。

# 四、Memories

## 1、作用

Memories 让 ChatGPT 或 Codex 从过去的工作中带入有用背景，例如：

- 稳定的个人偏好
- 经常重复的工作流
- 项目约定
- 不想每次重新解释的背景

Memory 是辅助回忆层，不是强制规则系统。必须始终生效的团队要求，仍应保存在 Project Instructions、`AGENTS.md` 或仓库文档中。

## 2、两类记忆

ChatGPT App 中需要区分：

| 使用方式 | 记忆来源 |
|---|---|
| Chat 与 ChatGPT Work | ChatGPT 账号和 Workspace 可用的 Memory |
| 本地 Codex | 当前 Codex Host 的本地 Memory |

两者不是同一个存储层。ChatGPT Web 的 Memory 不等同于本地 Codex Memory。

本地 Codex Memory 默认保存在 `~/.codex/memories/`。它属于生成状态，可以查看，但不应把手工编辑内部文件当作主要配置方式。

## 3、控制范围

在桌面 App 的 Codex Chat 中，可以输入 `/memories` 控制：

- 当前 Chat 是否使用已有 Memory
- 当前 Chat 是否参与未来 Memory 的生成

Chat 级选择不会改变全局开关。全局设置位于 **Settings > Personalization**。

不要在 Memory 中保存密码、API Key 或其他密钥。分享 `.codex` 目录前，也应检查其中是否存在不适合公开的记忆内容。

# 五、指令层级

可以按照作用范围选择存放位置：

| 信息 | 合适位置 |
|---|---|
| 只影响当前请求 | 当前提示词 |
| 同一 Project 的多个 Chat 共用 | Project Instructions |
| 当前代码仓库必须遵守 | 仓库 `AGENTS.md` 或项目文档 |
| 所有 Codex 项目都适用的个人规则 | 全局 `AGENTS.md` |
| 有帮助但允许变化的个人背景 | Memories |
| 只改变默认沟通语气 | Personality |

示例：

```text
“这次只修改 README” → 当前提示词
“本项目默认使用 Rust 2024 Edition” → 仓库文档或 AGENTS.md
“我习惯先看流程再看代码” → Custom Instructions 或 Memory
```

这能避免“ChatGPT 好像记得”与“ChatGPT 必须遵守”之间的混淆。

# 六、Chronicle

Chronicle 是 macOS 桌面 App 中的可选研究预览能力。它通过近期屏幕上下文帮助 Codex 生成 Memory，让 Codex 更容易理解你正在查看的内容和常用工作流。

启用时需要：

- Memories 已开启
- macOS Screen Recording 权限
- macOS Accessibility 权限
- 当前账号具备该功能

Chronicle 会提高屏幕内容带来的隐私和提示注入风险。它可能处理截图、OCR 文字、时间信息和本地路径，并消耗额外使用额度。

使用原则：

- 只在明确需要时开启
- 会议或查看敏感内容前暂停
- 不用它记录未经同意的他人通信
- 定期检查生成的 Memory
- 不把 Chronicle 当作读取原文件的替代方案

当 Slack、Google Drive、代码文件或 Pull Request 才是准确来源时，应让 Codex 直接读取对应来源，而不是只依赖屏幕记忆。

# 七、配置实践

可以从一组较小、稳定的个人规则开始：

```text
默认使用中文。
先说明结论和验证结果。
修改文件前先阅读项目约定。
遇到动态事实时优先查官方来源。
```

然后把项目专属规则放到 Project Instructions 或仓库中。执行一段时间后，再观察哪些背景值得进入 Memory。

个性化只影响上下文和工作方式，不会扩大文件、网络或桌面权限。实际能力边界仍由 [[12、权限、设置与故障排查|权限设置]] 决定。
