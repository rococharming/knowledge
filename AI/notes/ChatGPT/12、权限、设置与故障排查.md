# 一、权限模型

ChatGPT App 的权限决定它可以读取、修改和操作什么，以及哪些动作必须先经过确认。

权限不是一个总开关，而是多层边界的组合：

```text
Permission Mode
    ↓
Filesystem 与 Network Sandbox
    ↓
macOS / Windows 系统权限
    ↓
Plugin 和外部服务账号权限
```

即使 ChatGPT 能访问某个 Project，也不代表它可以访问电脑上的所有文件；即使安装了 Plugin，也不代表它可以绕过外部服务的账号权限。

# 二、Permission Mode

根据官方 [Permissions](https://learn.chatgpt.com/docs/permission-modes) 指南，大多数工作应从 **Ask for approval** 开始。

## 1、Ask for approval

ChatGPT 可以在当前 Workspace 中读取和修改文件，并运行常规本地命令；使用网络或越过 Workspace 边界时会请求确认。

适合：

- 日常代码和文档任务
- 希望监督外部访问
- 第一次使用某个工具
- 任务范围还可能变化

## 2、Approve for me

`Approve for me` 在 Settings 中称为 `Auto-review`。它会自动审查额外权限请求，减少人工确认次数。

Auto-review 仍可能判断错误。它适合边界清楚、环境可恢复的任务，不等于所有操作都安全。

## 3、Full access

Full access 允许 ChatGPT 在无需逐次批准的情况下访问更广泛的文件和网络。

这会显著增加：

- 误删或覆盖文件的风险
- 密钥和隐私数据泄漏风险
- 执行意外命令的风险
- 网页提示注入扩大影响的风险

只有在环境隔离、任务边界明确并且具备可靠恢复手段时才考虑使用。

## 4、Custom

Custom 通过 `config.toml` 定义更细的 Sandbox、网络和审批策略，适合需要稳定权限配置的开发环境。

普通使用不需要先编写自定义配置。应先判断 Ask for approval 是否已经满足任务。

# 三、文件与网络

## 1、Filesystem

文件权限应围绕任务需要的最小目录配置：

- Read-only：只分析，不修改。
- Workspace write：可以在当前 Workspace 内修改。
- Additional roots：明确增加其他可访问目录。
- Deny paths：禁止读取特定路径。

附加整个 Home 目录会扩大敏感数据暴露面。任务只需要一个仓库或素材目录时，应只打开该目录。

## 2、Network

网络权限控制 ChatGPT 是否可以：

- 搜索和读取网页
- 下载依赖
- 访问 API
- 连接外部服务
- 向远端 Git 或其他系统写入

“允许网络”不代表“允许所有外部动作”。发送邮件、提交表单、发布网站和推送 Git 仍应根据任务边界单独确认。

# 四、系统权限

macOS 和 Windows 还会在应用层之外控制能力。

| 能力 | 常见系统权限 |
|---|---|
| Voice | Microphone |
| Appshot / Chronicle | Screen Recording |
| Computer Use | Screen Recording、Accessibility |
| Notifications | Notification |
| 本地文件夹 | 文件和目录访问 |

macOS 可以在 **System Settings > Privacy & Security** 中撤销 Screen Recording 或 Accessibility。Windows 还可能受到系统策略、企业管理和沙箱配置限制。

系统权限应按能力分别授予，不需要为了使用普通 Chat 一次性打开所有权限。

# 五、设置

## 1、General

General 包含日常运行行为，例如：

- 多行提示的发送方式
- 本地任务运行时是否阻止休眠
- Follow-up 消息立即 Steering 还是排队
- Permission Mode 是否出现在选择菜单
- Code Review 是否在当前 Chat 或独立 Chat 中运行

## 2、工具设置

- **Browser**：独立 Profile、网站允许列表和下载位置。
- **Computer Use**：可控制的 App 和已授权范围。
- **Plugins**：已安装能力和外部连接。
- **Notifications**：完成、权限和问题提醒。
- **Personalization**：Personality、Custom Instructions、Memories。

## 3、快捷键

使用 <kbd>Cmd</kbd> / <kbd>Ctrl</kbd> + <kbd>,</kbd> 打开 Settings，使用 <kbd>Cmd</kbd> / <kbd>Ctrl</kbd> + <kbd>Shift</kbd> + <kbd>/</kbd> 打开快捷键列表。

快捷键可以搜索、重新绑定或恢复默认值。基础快捷键见 [[2、安装、登录与界面|安装、登录与界面]]。

# 六、故障定位

## 1、确认使用形态

先确认问题发生在哪个 Surface：

- ChatGPT 桌面 App
- ChatGPT Web
- Codex CLI
- Codex IDE Extension

不同 Surface 的功能并不完全一致。例如 Plugins 不用于普通 Chat，内置 Browser 不用于 Codex CLI，Scheduled 管理界面也不在 CLI 中。

## 2、检查账号与工作区

确认：

- 当前登录方式
- 账号是否具备该功能
- Workspace 管理员是否禁用
- Plugin 或 Connector 是否已经完成认证
- 功能是否仍在分阶段开放

不要只因为文档存在，就假设当前账号一定已经显示入口。

## 3、检查 Project

本地任务失败时，检查：

- 打开的是否是正确 Project
- Primary Folder 是否正确
- 文件夹是否仍然存在
- Git 仓库状态是否正常
- Worktree 是否完成初始化
- Setup Script 是否成功
- `AGENTS.md` 和 `.codex` 是否位于正确根目录

Review Pane 展示整个 Git 工作区的变化，不只是 ChatGPT 修改的文件。看到陌生变更时先运行 `git status`，不要直接 Revert。

## 4、检查权限

根据失败动作逐层检查：

1. Permission Mode 是否允许。
2. Sandbox 是否包含目标目录和网络。
3. 系统是否授予对应权限。
4. Plugin 或外部服务是否仍然连接。
5. 网站或 App 是否要求额外确认。

权限不足时，应增加最小必要范围，而不是直接切换 Full access。

## 5、检查运行状态

任务卡住时可以：

- 查看是否在等待审批或回答
- 查看终端和工具错误
- 暂停后恢复 Goal
- 确认电脑是否休眠
- 确认本地 Project 和 App 是否仍在运行
- 重新打开 Chat
- 必要时重启 App

重新运行前先判断上一次操作是否已经部分完成，避免重复发送、创建或修改。

# 七、诊断信息

报告问题时，保留足够但不敏感的信息：

- App 版本
- macOS 或 Windows 版本
- 使用的 Surface 和工作方式
- Project 类型
- Permission Mode
- 完整错误文本
- 复现步骤
- 实际结果与期望结果
- 相关日志时间

不要在截图或日志中公开：

- API Key
- Access Token
- Cookie
- 内部 URL
- 用户数据
- 私有仓库内容

可以使用下面的描述模板：

```text
环境：
- ChatGPT desktop app：
- 操作系统：
- 使用方式：Chat / Work / Codex
- Project：ChatGPT Project / Local / Worktree / Cloud
- Permission Mode：

步骤：
1.
2.
3.

期望：

实际：

错误信息：
```

如果问题涉及 Browser 或 Computer Use，再附上 [[8、浏览器与计算机操作|对应能力]] 的网站、App 和系统权限状态；涉及 Scheduled Task，则同时说明本地或云端执行位置及最近一次运行记录。
