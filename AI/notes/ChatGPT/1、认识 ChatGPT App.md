# 一、简介

`ChatGPT App` 是 ChatGPT 的桌面工作空间。它不只用于一问一答，还能围绕项目组织对话和资料、处理本地文件、调用工具，并持续完成需要多步执行的任务。

![[chatgpt-app-surface.webp|80]]

官方将桌面 App 定位为复杂工作的控制中心：可以同时推进多个项目、检查真实文件、使用浏览器或桌面应用，并让较长的任务在后台继续运行。

![[chatgpt-projects-interface.webp|600]]

与普通聊天网页相比，桌面 App 的关键差异是：它能够把 **对话、项目、本地目录、工具和交付物** 放在同一个工作环境中。

# 二、使用形态

ChatGPT 有多种使用形态，它们共享部分能力，但适合的工作场景不同。

| 形态 | 适合的场景 | 主要特点 |
|---|---|---|
| ChatGPT 桌面 App | 本地文件、复杂任务、多项目并行 | 能连接本地目录、浏览器和桌面应用 |
| ChatGPT Web | 云端聊天与知识工作 | 无需安装，适合跨设备继续任务 |
| Codex CLI | 终端中的代码任务 | 从当前目录读取代码并执行命令 |
| Codex IDE Extension | 编辑器内的代码任务 | 能结合当前工作区、打开文件和选中代码 |

本系列以 **ChatGPT 桌面 App** 为主。Web 端只在行为有明显差异时补充说明；Codex CLI 作为延伸内容，可参考 [[补充资料/1、Codex  CLI|Codex CLI]]。

# 三、工作模式

## 1、Chat

`Chat` 适合通过对话逐步解决问题，例如：

- 解释一个概念
- 搜索最新资料
- 头脑风暴
- 起草或改写文字
- 比较多个选择
- 总结一份文件

Chat 的重点是 **交流与迭代**。第一条提示不需要一次写得完美，可以通过后续消息继续补充背景、纠正方向和调整结果。

## 2、Work

`ChatGPT Work` 适合目标明确、步骤较多、最终需要交付成果的任务，例如：

- 根据资料生成调研报告
- 分析表格并给出结论
- 制作演示文稿
- 创建项目计划
- 生成可预览和修改的文件

Work 的重点不是只返回一段回答，而是把任务推进到 **可检查、可修改、可使用的结果**。桌面 App 中还可以选择本地或云端执行，详见 [[6、使用 Work 完成交付物|使用 Work 完成交付物]]。

## 3、Codex

`Codex` 适合软件开发任务，例如：

- 理解代码库
- 修复 Bug
- 实现功能
- 运行测试
- 查看 Git 变更
- 审查 Pull Request

Codex 会显示更多技术细节，例如终端命令、文件改动和 Diff。它也能处理部分知识工作，但界面和反馈方式更偏向开发流程。

有关 App 内 Codex 的完整流程，参考 [[7、使用 Codex 处理代码项目|使用 Codex 处理代码项目]]。

# 四、选择方式

可以按照任务最终需要的结果来选择：

| 当前目标 | 推荐方式 |
|---|---|
| 想问清楚、讨论或快速起草 | Chat |
| 想得到报告、表格、演示文稿等成品 | Work |
| 想读取、修改或验证代码项目 | Codex |

如果任务还不明确，先用 Chat 梳理问题；目标和验收标准明确后，再切换到 Work 或 Codex。

> Chat、Work 与 Codex 的能力有重叠。选择它们主要是在选择更适合当前任务的界面、工具和结果呈现方式，而不是选择三个完全隔离的产品。

# 五、工作位置

## 1、独立对话

一次性问题可以直接新建 Chat，不必创建 Project。独立对话适合不依赖共享文件、不需要长期维护上下文的任务。

## 2、ChatGPT Project

当多次对话需要共享文件、来源或项目指令时，可以创建 ChatGPT Project。它适合调研、写作、学习和持续维护的知识工作。

## 3、本地 Project

当 ChatGPT 需要直接读取或修改电脑上的文件夹时，可以创建本地 Project 或打开目录。本地 Project 常用于代码库、文档仓库和本地素材集合。

Project 的具体组织方式参考 [[4、对话与 Projects|对话与 Projects]]。

# 六、基本流程

使用 ChatGPT App 完成任务时，可以遵循下面的循环：

1. 明确要得到什么结果。
2. 选择 Chat、Work 或 Codex。
3. 选择独立对话、ChatGPT Project 或本地 Project。
4. 提供必要的文字、文件、图片、网页或外部服务。
5. 检查 ChatGPT 的计划、工具调用和权限请求。
6. 审阅结果并给出针对性修改意见。
7. 验证关键事实、文件内容和实际运行结果。

```text
目标
  ↓
选择 Chat / Work / Codex
  ↓
提供上下文和工具
  ↓
执行与审阅
  ↓
修改与验证
```
