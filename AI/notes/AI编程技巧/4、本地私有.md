# 一、本地私有配置

本地私有配置是指：只服务于自己当前机器和当前工作方式、不应该进入团队 Git 仓库的 AI 编程辅助文件。

在团队项目里，[[2、全局规则|全局规则]]和[[3、项目规则|项目规则]]通常应该保持清晰分层：团队共享的规则放进仓库，个人工具偏好、临时上下文、实验记录和本地工作树配置留在本机。

> 关键判断：凡是“别人 clone 项目后也应该拿到”的内容，才适合提交；凡是“只和我的 Agent、我的工作树、我的临时记录有关”的内容，应放进本地私有配置。

# 二、私有规则

`CLAUDE.local.md` 适合保存个人规则，例如自己使用 Mattpocock Skills 时需要的本地说明、个人偏好的 Agent 行为约束，或只适用于当前机器的操作习惯。

它和团队共享的 `CLAUDE.md` 职责不同：

| 文件 | 适合内容 | 是否提交 |
|---|---|---|
| `CLAUDE.md` | 团队共享的项目规则、目录约定、验证命令、安全边界 | 通常提交 |
| `CLAUDE.local.md` | 个人偏好、本地工具说明、临时上下文、本机路径 | 通常不提交 |

如果执行 `setup-matt-pocock-skills` 初始化项目，可以要求 Agent 把 Mattpocock Skills 的 `Agent Skills` 相关规则写入 `CLAUDE.local.md`，而不是直接写进团队共享的 `CLAUDE.md`。

这样做的好处是：个人可以使用完整的 Skills 工作流，但不会把个人工具配置扩散给整个团队。

# 三、本地忽略

`.gitignore` 是团队共享的忽略规则，会被提交到仓库；`.git/info/exclude` 是当前仓库副本的本地忽略规则，不会被提交。

如果某类文件在团队里也明确“不应该提交”，就适合写进 `.gitignore`。例如 `CLAUDE.local.md` 是个人规则文件，`.claude/worktrees/` 是本地 worktree 目录，它们通常可以直接放进 `.gitignore`。

当某些文件只对自己有用，或者暂时不想把忽略规则写进团队仓库时，再把它们放进 `.git/info/exclude`。

Mattpocock Skills 常见的本地文件包括：

```gitignore
docs/agents/
.scratch/
CONTEXT.md
```

> 注意：`.git/info/exclude` 只影响当前这一份仓库副本。换一台电脑、重新 clone，或者创建新的仓库副本时，需要重新设置。

# 四、工作树继承

worktree 会创建一个新的工作目录。问题是：如果个人规则和 Skills 相关文件没有提交到 Git，新 worktree 默认可能拿不到这些本地文件。

在支持 `.worktreeinclude` 的 Claude 工作流中，可以用它声明“创建 worktree 时也要复制过去”的本地文件：

```text
CLAUDE.local.md
docs/agents/
.scratch/
CONTEXT.md
```

`.worktreeinclude` 本身通常也属于个人配置，因此可以把它加入 `.git/info/exclude`，避免提交到团队仓库。

这套关系可以概括为：

| 需求 | 放在哪里 |
|---|---|
| 团队都要遵守的 Agent 规则 | `CLAUDE.md` |
| 只有自己使用的 Agent 规则 | `CLAUDE.local.md` |
| 只在当前仓库副本忽略的文件 | `.git/info/exclude` |
| 新 worktree 也要带上的本地文件 | `.worktreeinclude` |

# 五、示例文件

下面是一组最小可用示例。真实项目里可以按自己的工具链增删内容，但不要把本机路径、账号信息、密钥或临时任务细节写进团队共享文件。

## 1、`CLAUDE.local.md`

`CLAUDE.local.md` 用来放个人 Agent 规则。它应该说明“我本机希望 Agent 怎么工作”，而不是改写团队项目规则。

示例：

````markdown
## Agent Skills

...

````

## 2、`.gitignore`

`.gitignore` 适合记录团队共同认可的忽略规则。对于本地私有配置，可以把个人规则文件和 Claude 本地 worktree 目录写进去。

示例：

```gitignore
# Local agent rules
CLAUDE.local.md

# Claude local worktrees
.claude/worktrees/
```

这样配置后，团队成员都可以在本机保留自己的 `CLAUDE.local.md`，同时避免把 Claude 创建的本地 worktree 目录提交进仓库。

## 3、`.git/info/exclude`

`.git/info/exclude` 是当前仓库副本自己的忽略规则，语法和 `.gitignore` 基本一致，但不会被提交。

示例：

```gitignore
# Local agent workspace
docs/agents/
.scratch/
CONTEXT.md

# Local worktree support
.worktreeinclude
```

这样配置后，这些文件可以留在本机使用，但不会出现在普通的 `git status` 待提交列表里。

## 4、`.worktreeinclude`

`.worktreeinclude` 用来声明创建新 worktree 时希望一并复制过去的本地文件。它适合列出“新工作树也需要，但不应该提交”的个人配置。

示例：

```text
CLAUDE.local.md
docs/agents/
.scratch/
CONTEXT.md
```

这里没有写 `.worktreeinclude` 自己，因为它是控制复制行为的配置文件本身；是否复制它取决于当前工具对 `.worktreeinclude` 的实现。更稳妥的做法是把它留在主工作区，并通过 `.git/info/exclude` 保持本地私有。
