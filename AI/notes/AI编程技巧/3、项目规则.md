每个项目需要各自的项目规则，下面给出一份项目规则模板，可根据具体项目内容补齐模板。

```Markdown
# 项目协作规则

## 项目目标

- 这个项目用于：[这里写项目的核心用途，比如“Rust 命令行工具，用于从文件中搜索指定文本”]
- 主要用户和场景：[比如“开发者在终端中传入关键词和文件路径，快速筛选匹配行”]
- 当前阶段：[比如“学习项目/开发中/测试中/已上线”]
- 暂时不做：[比如“暂不支持正则搜索、暂不支持递归扫描目录、暂不做异步 I/O]

## 目录约定

- 源码目录：[比如 `src/`]
- 测试目录：[比如 `tests/`]
- 文档目录：[比如 `docs/`]
- 临时实验目录：[比如 `tmp/`]
- 禁止随意新增文件的位置：[比如“所有业务代码只能放在 `src/` 下”]

## 开发命令

- 安装依赖：[比如 `cargo add`]
- 构建项目：[比如 `cargo build`]
- 运行项目：[比如 `cargo run`]
- 检查代码：[比如 `cargo check`]
- 代码格式化：[比如 `cargo fmt`]
- 运行测试：[比如 `cargo test`]

## 需要按需阅读的文档

- 项目说明：[比如 `README.md`]  
- API / 模块设计：[比如 `docs/api.md`]   
- 错误处理约定：[比如 `docs/error-handling.md`]  
- 测试规范：[比如 `docs/testing.md`]  
- 发布流程：[比如 `docs/release.md`]
```
