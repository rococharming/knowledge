
# 一、权限系统概述

当 Claude Code 需要执行某些可能影响系统或项目状态的操作时，例如：

- 编辑文件
- 创建、删除或移动文件
- 执行 shell 命令
- 使用网络相关工具

Claude Code 会通过权限系统决定是否执行。

默认情况下，Claude 请求操作，权限系统判断，决定执行/ 询问 / 拒绝。

# 二、权限系统组成

Claude Code 权限系统由两个核心部分组成：权限模式和权限规则。

## 1、权限模式

权限模式决定：

> 当没有明确权限规则处理某个操作时，Claude Code 默认如何处理。

例如，默认是`manual` mode，表示：

- 读取操作通常直接执行
- 需要授权的操作请求用户确认


## 2、权限规则

权限规则用于针对具体工具调用进行控制。

配置：

```json
{
  "permissions": {
    "allow": [],
    "ask": [],
    "deny": []
  }
}
```

三类规则：

| 规则      | 作用         |
| ------- | ---------- |
| `allow` | 允许指定操作自动执行 |
| `ask`   | 要求用户确认     |
| `deny`  | 禁止指定操作     |

规则通常用于补充或限制权限模式。

例如：

允许测试：

```json
{
  "permissions": {
    "allow": [
      "Bash(cargo test)"
    ]
  }
}
```

禁止危险删除：

```json
{
  "permissions": {
    "deny": [
      "Bash(rm -rf *)"
    ]
  }
}
```

# 四、权限模式分类

Claude Code 当前主要权限模式：

| 模式                  | 作用       |
| ------------------- | -------- |
| `default`（`manual`） | 默认人工确认模式 |
| `acceptEdits`       | 自动接受编辑操作 |
| `plan`              | 规划模式     |
| `auto`              | 自动风险判断模式 |
| `dontAsk`           | 非交互拒绝模式  |
| `bypassPermissions` | 绕过普通权限审批 |

## 1、manual 模式

`manual`是 Claude Code 需要人工确认的权限模式。

其核心思想为：

> Claude 可以正常分析项目，但对于需要改变环境状态的操作，会暂停并请求用户确认。

它适合：

- 新项目探索；
- 敏感代码修改；
- 生产环境操作；
- 希望逐步审查 Claude 行为的场景。

在 `manual` 模式下，Claude 通常可以直接执行文件读取、分析类操作。

当 Claude 想执行可能改变项目或系统状态的操作时，会请求确认。例如：

- 修改、创建、删除、移动文件文件
- 执行可能产生副作用的 Shell 命令，如执行`npm install`命令
- 网络相关操作，如下载文件、调用外部服务、上传数据

> Claude Code 的默认权限策略正在向 `auto` 模式迁移。Anthropic 已宣布，从 **2026 年 8 月 14 日起**，部分用户（如 Pro、Max、Team）Claude Code 默认将使用 `auto` 模式，而不是传统 Manual（default）模式。


## 2、acceptEdits 模式

`acceptEdits` 是偏向代码修改场景的权限模式。

其核心思想为：

> Claude 可以直接修改项目文件，而无需逐次请求确认，用户最终通过 `git diff`、代码审查等方式统一检查修改结果。

它适合：

- 日常代码开发；
- Bug 修复；
- 重构代码；
- 批量修改文件。

在 `acceptEdits` 模式下，Claude 可以自动接受文件创建、文件修改等常见文件系统操作，例如`mkdir`、`touch`、`mv`、`cp`。

这些自动批准通常限制在：

- 当前工作目录；
- `additionalDirectories` 配置目录。

但是，`acceptEdits` 并不代表所有操作都自动执行。对于`git push`这类可能产生外部影响的操作，仍然会根据权限规则和其他权限机制处理。


## 3、plan 模式

`plan` 模式用于：

> 先理解代码库、分析问题并制定修改方案，而不是立即修改代码。

它适合：

- 大型功能开发前分析；
- 不熟悉的项目；
- 复杂 Bug 定位；
- 架构设计。

在 `plan` 模式下，Claude 可以：

- 阅读项目文件；
- 搜索代码；
- 分析代码结构；
- 运行只读探索命令。

但是不会直接修改源代码。 

## 4、auto 模式

`auto` 是更加自动化的权限模式。

其核心思想：

> Claude 自动处理大部分权限决策，减少频繁的人工确认，同时通过安全检查阻止高风险操作。

它介于`manual`和`bypassPermissions`之间。

在 `auto` 模式下，Claude 不会对每个工具调用都询问用户，它会有一个安全分类器判断风险，进入决定是否允许执行、阻止还是请求干预。

适合：

- 长时间运行任务；
- 大量代码修改；
- 希望减少权限提示打断的场景。

## 5、dontAsk 模式

`dontAsk` 是非交互权限模式。

其核心思想：

> Claude 不会弹出权限确认，而是只执行已经明确允许的操作。

适合：

- CI 环境；
- 自动化脚本；
- 无人值守任务。

## 6、bypassPermissions 模式

`bypassPermissions` 是权限限制最少的模式。

其核心思想：

> 跳过普通权限审批流程，让 Claude 可以连续执行工具调用。

启动：

```shell
claude --permission-mode bypassPermissions
```

或者：

```shell
claude --dangerously-skip-permissions
```

它适合：

- Docker 容器；
- 虚拟机；
- 临时沙箱环境。

不建议直接用于：

- 个人主机；
- 生产环境；
- 包含密钥和敏感数据的项目。


# 五、权限模式切换

Claude Code 可以通过以下方式切换权限模式：

## 1、会话中切换

使用：

```shell
Shift + Tab
```

循环切换可用模式。

默认可切换的四种模式：

```
Manual
 ↓
acceptEdits
 ↓
plan
 ↓
auto
```

## 2、启动时指定

```shell
claude --permission-mode plan
```

表示进入`plan`模式。

## 3、配置默认模式

用户级：

```
~/.claude/settings.json
```

例如：

```json
{
  "permissions": {
    "defaultMode": "auto"
  }
}
```

> 事实上，执行`/doctor`会推荐我们设置默认模式为`auto`
