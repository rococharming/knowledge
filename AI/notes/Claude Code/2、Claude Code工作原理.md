
# 一、Agentic Loop

当给 `Claude Code`一个任务，它会经历三个阶段：**收集上下文**、**采取行动**、**验证结果**。这几个阶段并不是严格分开的，而是会相互交织。`Claude Code`会在整个过程中使用**工具**：它可能会搜索文件来理解代码，也可能会编辑文件做出修改，还可能会运行测试检查自己的工作。

![[Pasted image 20260521102454.png|800]]

`Agentic Loop`的过程可以理解为：你的提示词触发`Claude`收集上下文，采取行动、验证结果，并在任务完成前不断重复这个过程。你可以在任何时候打断它。

这个循环会根据你的请求自动调整，如果你只是询问代码库中的某个问题，`Claude Code`可能只需要收集上下文。一次 Bug 修复通常会反复经历这三个阶段。一次重构可能需要大量验证。`Claude`会根据上一步得到的信息，判断下一步需要做什么，并把几十个动作串联起来，在过程中不断修正方向。

注意，你也是这个循环的一部分。你可以在任何时候打断`Claude Code`，让它换个方向，提供额外上下文，或者要求它尝试另一种方法。`Claude`可以自主工作，但仍然响应你的输入。

`Agentic Loop`由两个组件驱动：负责推理的`models`、以及负责行动的`tools`。**`Claude Code`是围绕`Claude`模型或第三方模型构建的`agentic harness`：它提供工具、上下文管理和执行环境，把语言模型变成一个具有实际行动能力的编程代理**。


# 二、模型

`Claude Code`使用`Claude`模型理解你的代码，并对任务进行推理。当然，也可以接入第三方模型，参考：[[1、Claude Code入门|Claude Code入门]]。

`Claude` 可以阅读任何语言的代码，理解不同组件之间如何连接，并判断为了实现你的目标需要修改什么。面对复杂任务时，它会把工作拆分成多个步骤，逐步执行，并根据过程中学到的信息调整做法。

Claude Code 提供多个模型，不同模型之间有不同取舍。Sonnet 能很好地处理大多数编程任务。Opus 在复杂架构决策上有更强的推理能力。你可以在会话中使用 `/model` 切换模型，也可以通过 `claude --model <name>` 在启动时指定模型。

当我们说`Claude`选择或`Claude`决定时，实际进行推理的是模型。



# 三、工具

工具让`Claude Code`具备`agentic`能力。如果没有工具，`Claude`只能生成文本回复。有了工具之后，`Claude Code`就可以：读取代码、编辑文件、运行命令、搜索网页，以及与外部服务交互。每一次工具调用都会返回新的信息，这些信息也进入循环，帮助`Claude`做出下一步决策。

`Claude Code`内置工具通常可以分为五类，每一类代表一种不同形式的行动能力。

| 类别   | `Claude`能做什么                       |
| ---- | ---------------------------------- |
| 文件操作 | 读取文件、编辑代码、创建新文件、重命名或重新组织文件         |
| 搜索   | 按模式查找文件、用正则搜索内容、探索代码库              |
| 执行   | 运行shell命令、启动服务、运行测试、使用git          |
| Web  | 搜索网页、获取文档、查找错误信息                   |
| 代码智能 | 在编辑后查看类型错误和警告、跳转到定义、查找引用（需要代码智能插件） |
这些是`Claude Code`的主要能力。除此之外，Claude 还拥有用于生成子代理、向你提问，以及执行其他编排任务的工具。

`Claude Code`会根据你的提示词，以及它在执行过程中学到的信息，选择要使用哪些工具。当你说“修复失败的测试”时，`Claude Code`可能会：

1. 运行测试套件，查看哪些测试失败
2. 阅读错误输出
3. 搜索相关源文件
4. 阅读这些文件，理解代码
5. 编辑文件，修复问题
6. 再次运行测试进行验证

每一次工具调用都会给 Claude 新的信息，从而影响下一步动作。这就是`agentic loop`在实际工作中的体现。


# 四、Claude Code可以访问什么

当你在某个目录中运行 `claude` 时，Claude Code 会获得以下访问能力：

1. 项目目录：当前目录及其子目录中的文件，以及在你授权后访问其他位置的文件。
2. 终端：任何你可以运行的命令：构建工具、git、包管理器、系统工具、脚本等。只要你能从命令行完成，Claude 通常也可以完成。
3. Git状态：当前分支、未提交的改动，以及最近提交历史
4. `CLAUDE.md`：一个`Markdown`文件，用于保存`Claude Code`在每次会话中都应该知道的项目级指令、约定和上下文
5. `Auto Memory`：`Claude Code`在工作过程中自动保存的知识。例如项目模式和你的偏好。每个对话开始时，会加载`Memory.md`的前200行或前25KB内容，以先达到的限制为准。
6. 配置的扩展：用于外部服务的 MCP Servers，用于工作流的 Skill，用于委托任务的 Subagents，以及用于浏览器交互的 Claude in Chrome。

因为 Claude 能看到整个项目，所以它可以**跨文件工作**。当你让 Claude “修复认证 bug” 时，它会搜索相关文件，读取多个文件来理解上下文，进行协调性的修改，运行测试验证修复结果，并在你要求时提交改动。这与只看到当前文件的内联代码助手不同。



# 五、环境与接口

## 1、执行环境

`Claude Code`可以运行在三种环境中，每种环境在代码执行位置上有不同取舍。

### （1）Local

`Local`是在你的本机进行，这是最常见的模式。在终端里进入项目目录，运行：

```shell
claude
```

这时`Claude Code`运行在本机终端，可以访问当前目录下的项目文件，也能调用本机已有的工具。


### （2）Cloud

`Cloud`指在云端虚拟机执行。`Claude Code`的任务执行环境不在本机，而是在`Anthropic`管理的云端虚拟机里。`Claude Code`程序本身也在云端执行。

通过浏览器操作，但代码/命令本身在`Anthropic`的云端环境。

### （3）Remote Control

`Remote Control`表示浏览器控制，本机执行。它不是`Cloud`，而是通过浏览器界面操作`Claude`，但实际代码仍然在本机执行。例如你不想一直盯着终端，或者更喜欢浏览器界面，但又希望 Claude 使用你本地项目、本地依赖、本地工具链，这时 Remote Control 就有意义。



## 2、接口

可以通过终端、桌面应用、IDE 扩展、`claude.ai/code`、Remote Control、Slack 和 CI/CD pipelines 访问 Claude Code。接口决定了你如何看到 Claude、如何与它交互，但底层的`agentic loop`是相同的。



# 六、使用会话

`Claude Code`会在你工作时把对话保存在本地。每条消息、每次工具调用以及每个结果，都会写入`~/.claude/projects/`下的纯文本`JSONL`文件中。这让`Claude Code`支持回退、恢复和分叉对话。在`Claude Code`修改代码之前，它还会对受影响的文件创建快照，方便你在需要时还原。

会话彼此独立。每个新会话都会从一个全新的上下文窗口开始，不包含之前会话的对话历史。`Claude Code`可以通过`auto memory`在不同会话之间持久保存知识，你也可以把自己的持久指令写入`CLAUDE.md`。

每个`Claude Code`对话都是一个会话，并且与当前目录绑定。默认情况下，`/resume` 选择器会显示当前 worktree 中的会话，也可以通过快捷键扩大列表范围，查看其他 worktree 或项目中的会话。

`Claude Code`会看到当前分支中的文件。当你切换分支时，`Claude Code`会看到新分支的文件，但你的对话历史会保持不变。即使切换了分支，`Claude Code`仍然记得你们之前讨论过的内容。

由于会话与目录绑定，你可以使用 git worktrees 运行多个并行的 Claude 会话。git worktree 会为不同分支创建独立目录。

使用 `claude --continue` 或 `claude --resume` 恢复会话时，会以相同的 session ID 重新打开该会话，并把新消息追加到已有对话中。使用 `--fork-session` 或 `/branch` 分叉会话时，会把历史复制到一个新的 session ID 中，原始会话保持不变。


# 七、上下文窗口

`Claude Code`的上下文窗口包含你的历史对话、文件内容、命令输出、`CLAUDE.md`、`auto memory`、已加载的Skills以及系统指令等。

随着工作进行，上下文会逐渐被填满。`Claude Code`会自动压缩上下文，但对话早期的指令可能会丢失。持久规则应该写进`CLAUDE.md`，并且可以运行`/context` 查看当前是什么内容占用了上下文空间。

当上下文接近限制时，Claude Code 会自动管理上下文。它会先清理较旧的工具输出，然后在需要时总结对话。你的请求和关键代码片段会被保留；但对话早期的详细指令可能会丢失。因此，不要依赖对话历史保存长期规则，而应该把持久规则放进 `CLAUDE.md`。

**如果想控制压缩时保留什么内容，可以在 `CLAUDE.md` 中添加 “Compact Instructions” 小节，或者运行带焦点的 `/compact`，例如 `/compact focus on the API changes`**。

如果某个单独文件或工具输出太大，导致每次总结之后上下文又立刻被填满，Claude Code 会在尝试几次后停止自动压缩，并显示错误，而不是无限循环。

运行 `/context` 可以查看当前是什么内容占用了空间。默认情况下，MCP 工具定义会延迟加载，并通过 tool search 按需加载。因此，在 Claude 真正使用某个具体工具之前，通常只有工具名称会占用上下文。运行 `/mcp` 可以查看每个 MCP server 的上下文成本。

Skills 会按需加载。会话开始时，Claude 能看到 skill 的描述，但只有在使用某个 skill 时，完整内容才会加载。

Subagents 拥有自己的全新上下文，与主对话完全分离。它们的工作不会让你的主上下文膨胀。任务完成后，subagent 会返回一份总结。这种隔离机制正是 subagents 能帮助长会话的原因。


#  八、扩展能力概览

`Claude Code`将一个能够对你的代码进行推理的模型，与用于文件操作、搜索、执行命令和访问Web的内置工具结合在一起。内置工具可以覆盖大多数编程任务，但`Claude Code`同时可以额外添加的功能，用来定制`Claude Code`知道什么、连接外部服务、以及自动化工作流。

这些扩展能力如下表所示：

| 功能                    | 作用                                     | 适合什么时候使用                      | 示例                                                                |
| --------------------- | -------------------------------------- | ----------------------------- | ----------------------------------------------------------------- |
| **CLAUDE.md**         | 每次对话都会加载的持久上下文                         | 项目约定、“永远做 X” 这类规则             | “使用 pnpm，不要使用 npm。提交前先运行测试。”                                      |
| **Skill**             | Claude 可以使用的指令、知识和工作流                  | 可复用内容、参考文档、可重复执行的任务           | `/deploy` 运行你的部署检查清单；包含端点模式的 API 文档 skill                         |
| **Subagent**          | 隔离的执行上下文，返回总结后的结果                      | 上下文隔离、并行任务、专门化 worker         | 读取大量文件的研究任务，但只把关键发现返回主对话                                          |
| **Agent teams**       | 协调多个独立的 Claude Code 会话                 | 并行研究、新功能开发、基于不同假设进行调试         | 同时生成多个 reviewer，分别检查安全性、性能和测试                                     |
| **Code intelligence** | 语言服务器提供的导航和诊断能力                        | 类型化语言、大型代码库，以及 grep 太慢或不精确的场景 | 直接跳转到某个符号的定义，而不是阅读整个文件                                            |
| **MCP**               | 连接外部服务                                 | 外部数据或外部动作                     | 查询数据库、发送消息到 Slack、控制浏览器                                           |
| **Hook**              | 由事件触发的脚本、HTTP 请求、prompt 或 subagent     | 必须在每次匹配事件发生时运行的自动化任务          | 每次文件编辑后运行 ESLint                                                  |
| **Plugin**            | 将 skills、hooks、subagents、MCP 等打包成可复用模块 | 需要跨项目复用配置，或对外分发能力时            | \|   \|<br>\|---\|<br>\|一个“前端工程规范插件”，包含 lint hook、构建 skill、部署流程\| |
