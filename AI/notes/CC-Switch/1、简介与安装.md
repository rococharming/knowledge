
# 一、简介

CC Switch 是一款跨平台开源桌面工具，用于集中管理多种 AI 编程工具的供应商和模型接入配置，减少手动编辑各工具 JSON、TOML 或 `.env` 配置的需要。当前官方仓库列出的支持工具包括 Claude Code、Claude Desktop、Codex、Gemini CLI、Grok Build、OpenCode、OpenClaw 和 Hermes Agent。

适合人群：

- 同时使用多个 AI 编程工具的开发者
- 需要在官方渠道、云厂商、第三方服务或自定义 API 端点之间切换的用户
- 希望统一管理 MCP 服务器、Prompts、Skills、会话和用量的用户

核心功能：

- **供应商管理**：提供 50+ 供应商预设，支持官方登录、自定义端点、导入现有配置和一键切换；
- **代理与切换**：支持主界面和系统托盘快速切换；启用本地代理后，还可进行协议转换、热切换、故障转移和供应商健康检查；
- **扩展与数据管理**：统一管理 MCP 服务器、Prompts 和 Skills，浏览或搜索会话，并追踪请求、Token 用量和成本；
- **生效规则**：大多数工具切换后需要重启终端或对应的 CLI；Claude Code 支持供应商数据热切换，通常无需重启。

# 三、添加和切换切换供应商

## 1、供应商概述

CC-Switch 的最核心功能就是添加供应商和切换供应商。

供应商（Provider）是一套完整的 API 配置，包含 供应商名称、API 端点（Base URL）、API 密钥（API Key）、模型四部分，切换供应商本质就是将这套配置自动写入对应  AI Agent的配置文件，无需手动修改。

## 2、添加供应商

CC-Switch 预设了很多供应商，无需我们手动填写 API 端点，比较方便。下面以为`Claude Code`添加 `DeepSeek` 供应商为例，完成核心配置。其他供应商配置流程完全一致。

1. 点击主界面右上角的「+」按钮；

![[assets/Pasted image 20260809113050.png|600]]

2. 在弹出的窗口中的预设供应商中找到`DeepSeek`，如果找不到，可点击右上角的搜索按钮直接搜索。

![[assets/Pasted image 20260809113253.png|600]]

预设会自动填充 API 端点，无需手动输入，下拉可以看到：

![[assets/Pasted image 20260809113440.png|600]]

3. 在 「API Key」输入框，填入 [DeepSeek平台](https://platform.deepseek.com/) API 密钥（密钥需从对应供应商平台获取）

![[assets/Pasted image 20260809113728.png|600]]

如果还没有，需要先创建 API Key。注意创建时需要复制备用，之后无法复制。

> API Key 不可以泄漏给别人，如果泄漏需要删除并重新生成一个！

4. 在模型映射，可以点击右上角「获取模型列表」，然后将 Claude Code 的模型角色映射为 DeepSeek 的实际请求模型。

![[assets/Pasted image 20260809115111.png|600]]

这里可以勾选上 1M 上下文，因为 deepseek-v4-pro 和 deepseek-v4-flash 都支持 1M 上下文。

>勾选 1M 上下文的意思是：向 Claude Code 声明这个映射后的模型支持 100 万 Token 的上下文窗口。默认情况下，Claude Code 按 200 K上下文窗口管理会话，勾选上 1M 则按 1M 上下文来管理会话。

5. 查看实际配置文件

CC Switch 会很句上述配置自动生成`~/.claude/settings.json`文件，如下所示：

![[assets/Pasted image 20260809115255.png|600]]

6. 点击添加即可完成

![[assets/Pasted image 20260809115431.png|600]]


## 3、切换供应商

在主界面的供应商列表中，找到需要启用的供应商，点击其右侧的「启用」切换供应商。

![[assets/Pasted image 20260809115738.png|600]]

也可以在系统托盘快速切换：

![[assets/Pasted image 20260809115918.png|300]]

切换供应商后，应启动对应 Agent 并发送简单指令验证配置是否生效，不同 AI Agent 的验证方式略有差异：

| Agent          | 是否需要重启            |
| -------------- | ----------------- |
| Claude Code    | ❌ 无需重启，支持热重载      |
| Claude Desktop | ✅ 建议重启应用          |
| Codex          | ✅ 需要重启            |
| Gemini CLI     | ❌ 无需重启，每次请求重新读取配置 |
| OpenCode       | ✅ 需要重启            |
| OpenClaw       | ✅ 需要重启            |
| Hermes Agent   | ✅ 建议重启            |
| Grok Build     | ✅ 建议重启            |

## 4、注意事项

- 自定义 API 端点时，应按供应商要求填写 Base URL，并避免无必要的末尾 `/`
- 切换供应商后若配置未生效，先确认对应 Agent 是否需要重启；Claude Code 通常支持热切换，Gemini CLI 每次请求会重新读取配置，而 Codex、OpenCode、OpenClaw 等通常需要重新启动。
- 首次使用 CC Switch 时，会读取并保留受管 Agent 的现有配置，已有配置通常无需手动重新录入。

## 5、多工具独立配置

CC Switch 顶部有对应 AI Agent 的标签页（如 Claude Code、Claude Desktop、Open AI、Gemini等），切换到对应标签页，可为每个工具单独添加供应商，避免配置冲突。

## 1、Skills 管理

CC Switch 的 Skills 管理用于统一管理多个 AI Agent 的 Skill，包括发现、安装、导入、同步、更新、卸载和恢复。

>Skills 管理的核心价值是：一份 Skill 由 CC Switch 统一维护，再按需提供给多个 Agent 使用。

### （1）Skill 的基本结构

Skill 通常是一个目录，核心文件为：

```text
my-skill/
├── SKILL.md
├── scripts/
├── references/
└── assets/
```

其中 `SKILL.md` 是最重要的文件，用于描述 Skill 的用途、触发条件和和执行规则。

CC Switch 在 Skill 仓库中主要通过查找 `SKILL.md` 来识别 Skill，因此一个 GitHub 仓库中可以同时包含多个 Skill。、
