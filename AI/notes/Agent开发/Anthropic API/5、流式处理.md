
# 一、概念

前面像模型发送信息时，通过如下方式：

```python
response = client.messages.create(  
    model=model,  
    max_tokens=800,  
    temperature=0,  
    messages=[  
        {  
            "role": "user",  
            "content": "请写一篇关于大型语言模型流式输出的短文，说明它是什么、为什么有用，以及适合哪些应用场景。"  
        }  
    ],  
)  
  
print("已经收到完整响应！")  
print("========================")  
print(response.content[0].text)
```

使用这种方式，只有在所有内容生成完毕之后才会从 API 获取内容。因此，在完整响应一次性打印出来之前什么也不会显示。这在很多情况下是可以接受的，但在一些场景下强制用户等待整个响应生成，会导致体验很糟糕。

解决的办法是可以使用**流式传输**。流式传输可以让模型生成内容时接收内容，而不必等待整个响应完成完毕。


# 二、使用流式传输

要从 API 获取流式响应，只需要将`stream=True`传递给`client.messages.create`即可。

```python
stream = client.messages.create(  
    model=model,  
    max_tokens=800,  
    temperature=0,  
    messages=[  
        {  
            "role": "user",  
            "content": "请写一篇关于大型语言模型流式输出的短文，说明它是什么、为什么有用，以及适合哪些应用场景。"  
        }  
    ],  
    stream=True  
)  
  
print(stream)
```

此时打印`stream`变量的值：

流对象是生成器对象，它会随着 API 接收到数据，逐个生成服务器发送的事件（SSE）。

因此，我们需要编写代码来遍历流式响应：

```python
for event in stream:
	print(event)
```

最终，从 API 接收到了很多服务器发送的事件。每个流包含按以下顺序排列的一系列事件：

- `RawMessageStartEvent`：一条内容为空的消息
- 一系列内容块，每个内容块包含：
	- 一个`RawContentBlockStartEvent`
	- 一个或多个`RawContentBlockDeltaEvent
	- 一个`RawContentBlockStopEvent`
- 一个或多个`RawMessageDeltaEvent`：表示对最终消息的顶层修改
- 一个最终的`RawMessageStopEvent`

在本次示例中，只有一个内容块。

我们关心的所有实际由模型生成的内容来自`RawContentBlockDeltaEvent`，每个事件都包含一个类型被设置为`content_block_delta`的属性。要实际获取内容本身，需要访问`delta`中的`text`属性。

现在尝试专门打印出生成的内容：

```python
for event in stream:  
    if event.type == "content_block_delta":  
        print(event.delta.text)
```

结果：

但由于Python 的 `print()` 函数默认会换行，因此需要传递两个额外的参数打印流式文本：

- `end=''`：默认情况下，`print()` 函数会在打印的文本末尾添加一个换行符（\n）。通过设置 `end=''`，指定打印的文本后面不应跟随换行符。
- `flush=True`：将`flush`参数设置为`True`，强制立即将输出写入控制台或标准输出，无需等待换行符或缓冲区满。

`RawContentBlockDeltaEvent`是我们所需要关注的，如果想要获取`token`使用情况的信息，则需要查看：

- `RawMessageStartEvent`：包含输入`token`的使用信息
- `RawMessageDeltaEvent`：包含输出`token`的使用信息
