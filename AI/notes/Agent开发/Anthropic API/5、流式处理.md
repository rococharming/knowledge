# 一、概念

前面模型发送信息时，通过如下方式：

```python
response = client.messages.create(  
    model=model,  
    max_tokens=800,  
    temperature=0,  
    messages=[  
        {  
            "role": "user",  
            "content": "请写一篇关于大型语言模型流式输出的短文，说明它是什么、为什么有用，以及适合哪些应用场景。"  
        }  
    ],  
)  
  
print("已经收到完整响应！")  
print("========================")  
print(response.content[0].text)
```

使用这种方式，只有在所有内容生成完毕之后才会从 API 获取内容。因此，在完整响应一次性打印出来之前什么也不会显示。这在很多情况下是可以接受的，但在一些场景下强制用户等待整个响应生成，会导致体验很糟糕。

解决的办法是可以使用**流式传输**。流式传输可以让模型生成内容时接收内容，而不必等待整个响应完成完毕。


# 二、使用流式传输

要从 API 获取流式响应，只需要将`stream=True`传递给`client.messages.create`即可。

```python
stream = client.messages.create(  
    model=model,  
    max_tokens=800,  
    temperature=0,  
    messages=[  
        {  
            "role": "user",  
            "content": "请写一篇关于大型语言模型流式输出的短文，说明它是什么、为什么有用，以及适合哪些应用场景。"  
        }  
    ],  
    stream=True  
)  
  
print(stream)
```

此时打印`stream`变量的值：

流对象是生成器对象，它会随着 API 接收到数据，逐个生成服务器发送的事件（SSE）。

因此，我们需要编写代码来遍历流式响应：

```python
for event in stream:
```

最终，从 API 接收到了很多服务器发送的事件。每个流包含按以下顺序排列的一系列事件：

- `RawMessageStartEvent`：一条内容为空的消息
- 一系列内容块，每个内容块包含：
	- 一个`RawContentBlockStartEvent`
	- 一个或多个`RawContentBlockDeltaEvent
	- 一个`RawContentBlockStopEvent`
- 一个或多个`RawMessageDeltaEvent`：表示对最终消息的顶层修改
- 一个最终的`RawMessageStopEvent`

在本次示例中，只有一个内容块。

我们关心的所有实际由模型生成的内容来自`RawContentBlockDeltaEvent`，每个事件都包含一个类型被设置为`content_block_delta`的属性。要实际获取内容本身，需要访问`delta`中的`text`属性。

现在尝试专门打印出生成的内容：

```python
for event in stream:  
    if event.type == "content_block_delta":  
        print(event.delta.text)
```

结果：

![[Pasted image 20260612095754.png|300]]

但由于Python 的 `print()` 函数默认会换行，因此需要传递两个额外的参数打印流式文本：

- `end=''`：默认情况下，`print()` 函数会在打印的文本末尾添加一个换行符（\n）。通过设置 `end=''`，指定打印的文本后面不应跟随换行符。
- `flush=True`：将`flush`参数设置为`True`，强制立即将输出写入控制台或标准输出，无需等待换行符或缓冲区满。

`RawContentBlockDeltaEvent`是我们所需要关注的，如果想要获取`token`使用情况的信息，则需要查看：

- `RawMessageStartEvent`：包含输入`token`的使用信息
- `RawMessageDeltaEvent`：包含输出`token`的使用信息

# 三、其他流式事件

在处理流时，可能会遇到一些其他类型的事件，例如：

- **Ping事件**：流中可能还包含任意数量的 ping 事件
- **错误事件**：事件流中偶尔也会出现错误事件。例如，在高使用率期间，可能会收到`overloaded_error`，这通常在非流式上下文中对应 HTTP 529 状态码。


# 四、流式处理辅助工具

## 1、client.messages.stream()

`client.messages.stream()`是 Anthropic Python SDK 提供的流式消息辅助接口。

它和直接使用`client.messages.create(..., stream=True)`的区别在于`client.messages.stream()`不只是返回底层事件流，还额外提供一些便捷能力，例如：

- stream.text_stream
- stream.get_final_message()

这些辅助方法可以减少手动处理事件类型、拼接文本、维护最终消息对象的代码。

基本结构如下：

```python
from anthropic import AsyncAnthropic  
from dotenv import load_dotenv  
import os  
import asyncio  
  
load_dotenv()  
  
api_key = os.getenv("ANTHROPIC_API_KEY") or os.getenv("ANTHROPIC_AUTH_TOKEN")  
if not api_key:  
    raise RuntimeError("请设置 ANTHROPIC_AUTH_TOKEN 或 ANTHROPIC_API_KEY 环境变量")  
  
model = os.getenv("MODEL_ID")  
  
client = AsyncAnthropic(  
    base_url=os.getenv("ANTHROPIC_BASE_URL"),  
    api_key=api_key  
)  
  
  
async def streaming_with_helpers():  
    async with client.messages.stream(  
        max_tokens=800,  
        model=model,  
        messages=[  
            {  
                "role": "user",  
                "content": "请写一篇关于大型语言模型流式输出的短文，说明它是什么、为什么有用，以及适合哪些应用场景。"  
            }  
        ],  
    ) as stream:  
        async for text in stream.text_stream:  
            print(text, end="", flush=True)  
  
  
    final_message = await stream.get_final_message()  
    print("\n\nSTREAMING IS DONE. FINAL MESSAGE:")  
    print(final_message.to_json())  
  
  
if __name__ == "__main__":  
    asyncio.run(streaming_with_helpers())
```


## 2、client.text_stream

`stream.text_stream`是一个只包含文本增量的异步迭代器。

如果直接处理底层流事件，需要判断事件类型，例如：

- content_block_delta
- message_delta
- message_stop

而使用`stream.text_stream`时，SDK已经规律出了文本内容，所以可以直接写：

```python
async for text in stream.text_stream:
	print(text, end="", flush=True)
```

这里的 `text` 不是完整回答，而是模型本次流式返回的一小段文本增量。


## 3、get_final_message()

`get_final_message()`用来在流式读取完成后，返回最终累积好的完整`Message`对象。

示例：

```python
final_message = await stream.get_final_message()  
print("\n\nSTREAMING IS DONE. FINAL MESSAGE:")  
print(final_message.to_json())
```

最终消息通常含：

![[Pasted image 20260615145424.png|800]]

其中最常用的是：

|字段|含义|
|---|---|
|`content`|模型最终生成的内容|
|`role`|消息角色，一般是 `assistant`|
|`model`|使用的模型|
|`stop_reason`|生成停止原因|
|`stop_sequence`|如果由停止序列触发，这里会记录对应序列|
|`usage`|token 使用量|
`get_final_message()` 的价值在于：既可以享受流式输出的实时体验，又可以在最后拿到完整结构化结果。


# 五、流式简单聊天程序

示例

```python
from dotenv import load_dotenv  
from anthropic import Anthropic  
import os  
  
  
load_dotenv()  
  
api_key = os.getenv("ANTHROPIC_API_KEY") or os.getenv("ANTHROPIC_AUTH_TOKEN")  
if not api_key:  
    raise RuntimeError("请设置 ANTHROPIC_AUTH_TOKEN 或 ANTHROPIC_API_KEY 环境变量")  
  
client = Anthropic(  
    base_url=os.getenv("ANTHROPIC_BASE_URL"),  
    api_key=api_key,  
)  
  
model = os.getenv("MODEL_ID")  
  
BLUE = "\033[34m"  
GREEN= "\033[32m"  
RESET = "\033[0m"  
  
  
def chat_with_model():  
    print("Welcome to Chatbot!")  
    print("Type 'quit' to exit chat.")  
  
    conversation = []  
  
    while True:  
        user_input = input(f"{GREEN}You:{RESET}")  
  
        if user_input.lower() == "quit":  
            print("Goodbye")  
            break  
  
        conversation.append(  
            {  
                "role": "user",  
                "content": user_input  
            }  
        )  
  
        stream = client.messages.create(  
            model=model,  
            max_tokens=800,  
            temperature=0,  
            messages=conversation,  
            stream=True  
        )  
  
        print(f"{BLUE}Model:{RESET}", end='', flush=True)  
  
        assistant_response = ""  
        for event in stream:  
            if event.type == "content_block_delta":  
                content = event.delta.text  
                print(f"{BLUE}{content}{RESET}", flush=True, end="")  
                assistant_response += content  
  
        print()  # New Line  
  
        conversation.append(  
            {  
                "role": "assistant",  
                "content": assistant_response  
            }  
        )  
  
  
  
if __name__ == "__main__":  
    chat_with_model()
```
