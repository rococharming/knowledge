# 一、api_key 和 auth_token 的区别

使用 Anthropic SDK 需要指定 base_url + api_key 或者 base_url + auth_token的方式。

- base_url 决定请求发往哪个主机
- api_key、auth_token 是两种不同的身份验证方式，走不同的 HTTP 请求头，不能同时设置。

api_key vs auth_token：

| 维度           | `api_key`                              | `auth_token`                                                    |
| ------------ | -------------------------------------- | --------------------------------------------------------------- |
| 请求头          | `x-api-key: <key>`                     | `Authorization: Bearer <token>`                                 |
| 典型来源         | Console 标准 API Key（`sk-ant-api03-...`） | OAuth 令牌（`ant auth login`）或 environment key（`sk-ant-oat01-...`） |
| 常见场景         | 日常开发、服务端调用                             | 自托管沙箱环境、OAuth 登录态                                               |
| 与 `base_url` | 可组合                                    | 可组合                                                             |

三种典型组合：

```python
from anthropic import Anthropic

# 1. 标准 API Key（从环境变量或显式传入）
client = Anthropic(api_key="sk-ant-api03-...")

# 2. 自定义网关/代理 + API Key
client = anthropic.Anthropic(base_url="https://your-gateway.example.com", api_key="sk-ant-api03-...")

# 3. 自托管环境 + OAuth/Environment Token
client = anthropic.Anthropic(base_url="https://your-host.example.com", auth_token="sk-ant-oat01-...")
```

# 二、Message 响应对象

`client.messages.create()`（注意是 `messages` 复数）返回一个 `Message` 对象（非流式调用），可理解为模型这一轮回复的完整快照——既包含生成的内容块列表，也包含为什么停下、用了多少 token 等元信息。

关键字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `response.content` | list | 核心。内容块列表，每个块是 `TextBlock` / `ThinkingBlock` / `ToolUseBlock` 等对象。访问 `.text` 前必须先判断 `.type` |
| `response.stop_reason` | str \| None | 模型为什么停下：`end_turn` / `tool_use` / `pause_turn` / `refusal` / `max_tokens` / `model_context_window_exceeded` |
| `response.usage` | 对象 | token 统计：`input_tokens`、`output_tokens` 等 |
| `response.model` | str | 实际使用的模型字符串 |
| `response.id` | str | 本次消息的唯一 ID |
| `response.role` | str | 固定为 `"assistant"` |
| `response.stop_details` | 对象 | 仅当 `stop_reason == "refusal"` 时存在，含 `category`、`explanation` |

`response.content` 的内容块结构——`content` 是个列表，因为模型一轮回复可能由多个块组成（先思考、再说话、再调工具）。每个块都是带 `type` 字段的对象，常见三种：

```python
# 文本块
TextBlock(type='text', text='模型的回复文字')

# 思考块（开启 thinking 时出现）
ThinkingBlock(type='thinking', thinking='...思考过程...')

# 工具调用块
ToolUseBlock(type='tool_use', id='toolu_xxx', name='get_weather', input={'location': '北京'})
```

关键规范：取文本前必须判 `type`，否则 `ToolUseBlock` 上没有 `.text` 会抛 `AttributeError`：

```python
for block in response.content:
    if block.type == "text":      # 先判断
        print(block.text)
```

`stop_reason` 取值含义：

| 值 | 含义 | agent loop 里怎么处理 |
| --- | --- | --- |
| `end_turn` | 模型自然说完 | 结束循环 |
| `tool_use` | 模型要调工具 | 执行工具 → 结果作为新 user 消息回传 → 继续循环 |
| `pause_turn` | 服务端工具迭代限制 | 重新发送当前对话以继续 |
| `refusal` | 安全分类器拒绝 | 检查 `stop_details`，结束循环 |
| `max_tokens` | 达到输出上限 | 结束循环（输出被截断） |
| `model_context_window_exceeded` | 上下文超限 | 结束循环（需裁剪 history） |
