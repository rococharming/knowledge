# Claude Code 记忆系统

Claude Code 的记忆系统是跨会话持久化上下文的核心基础设施，由**手动维护的持久指令**和**自动积累的项目经验**两部分组成。

## 双轨架构

### CLAUDE.md：事先约定

由用户手动编写，存放稳定、可复用的项目上下文。适合编码规范、测试命令、目录结构、工作流约定等"如果不说每次都要重复解释"的信息。

核心特征：
- **上下文注入**：会话启动时加载到上下文中，与对话内容一起消耗 token
- **多级作用范围**：托管策略 → 用户指令 → 项目指令 → 本地指令，层层叠加
- **向上查找**：从当前目录向根目录查找，所有发现的文件拼接进上下文而非互相覆盖
- **本地隔离**：`CLAUDE.local.md` 适合个人偏好，应加入 `.gitignore`

### Auto Memory：使用中学习

由 Claude Code 自动维护，根据内容价值判断决定是否记录。包括构建命令、调试经验、架构说明、代码风格偏好、工作流习惯等。

核心特征：
- **按需读写**：`MEMORY.md` 索引在启动时加载，主题文件按需读取
- **审计透明**：自动记忆文件是普通 Markdown，可随时查看、修改、删除
- **非强制写入**：不会每次对话后都写入，只保存对未来有帮助的内容

## 互补关系

| 维度 | CLAUDE.md | Auto Memory |
|---|---|---|
| 维护者 | 用户 | Claude Code |
| 内容性质 | 明确规则、事先约定 | 经验积累、使用中学习 |
| 更新频率 | 低频、手动 | 持续、自动 |
| 适合存放 | 编码规范、工作流 | 调试经验、构建命令 |
| 可靠性 | 用户保证 | 模型判断 |

`CLAUDE.md` 负责保证基础行为一致，`auto memory` 负责在持续协作中逐渐适应具体项目和使用者习惯。

## 规则拆分：.claude/rules/

当项目规模变大时，`.claude/rules/` 可将规则按主题拆分为独立文件：

- **无条件加载**：没有 `paths` 的 `YAML frontmatter` 的规则文件，会话启动时加载
- **路径特定**：通过 `paths` 字段限定只在匹配文件时生效，减少无关上下文干扰
- **符号链接支持**：可维护一套公共规则，通过符号链接在多个项目复用

## AGENTS.md 兼容

Claude Code 默认读取 `CLAUDE.md` 而非 `AGENTS.md`。若仓库已为其他编码代理维护 `AGENTS.md`，可在 `CLAUDE.md` 中通过 `@AGENTS.md` 导入，或创建符号链接 `ln -s AGENTS.md CLAUDE.md`（Windows 上更推荐导入方式）。

## 常见问题排查

### Claude Code 没有遵循记忆文件

排查顺序：
1. 运行 `/memory` 确认文件确实被加载
2. 检查文件是否放在当前会话能加载的位置
3. 检查是否存在相互冲突的规则
4. 把模糊指令改成具体、可验证的指令

### /compact 之后指令丢失

- 项目根目录的 `CLAUDE.md` 会在压缩后重新从磁盘读取并注入
- 子目录中的嵌套 `CLAUDE.md` 不会自动重新注入，需后续读取对应文件时才重新加载
- 路径限定规则需当前读取匹配文件时才生效

### CLAUDE.md 过大

建议控制在 200 行以内。过大的处理策略：
- 删除不需要每次会话加载的内容
- 将路径相关规则放到 `.claude/rules/`
- 将多步骤流程改成 `skill`
- 将本地偏好放到 `CLAUDE.local.md`

> 注意：`@path` 导入只改善可维护性，不减少上下文占用，被导入文件仍会在启动时加载。
