# 继承

继承是面向对象的重要原则之一：通过继承，一个类可以使用另一个类已有的属性和方法，减少重复代码并建立清晰的类层次。它是 [[类和对象]] 之上复用与扩展代码的机制，与 [[封装]]、[[多态]] 同为 OOP 核心。整体概览见 [[面向对象]]。

## 基本概念

| 名称 | 其他称呼 | 含义 |
|---|---|---|
| 父类 | 基类、超类 | 提供通用属性和方法的类 |
| 子类 | 派生类 | 继承并扩展父类的类 |

基本语法——把父类写在子类名后的圆括号中：

```python
class Parent:
    pass

class Child(Parent):
    pass
```

继承适合表达"是一种"关系：开发者是一种员工，设计师也是一种员工。仅代码相似但无合理类型关系时，不一定适合继承。

## 单继承与代码复用

一个子类只继承一个直接父类称为单继承。子类未定义的方法会沿继承关系向上查找：

```python
class Animal:
    def __init__(self, name):
        self.name = name

    def introduce(self):
        return f'My name is {self.name}'

class Dog(Animal):
    species = 'dog'

dog = Dog('Jack')
dog.introduce()   # Dog 未定义，沿继承找到 Animal.introduce
```

创建 `Dog('Jack')` 时，Python 找不到 `Dog.__init__()`，便沿继承关系调用 `Animal.__init__()`。把多个类的共同数据和行为上提到父类，子类只写各自特有部分，即可复用。

## 扩展与重写

### 添加成员

子类在继承父类成员基础上，可定义自己的属性和方法（如 `Dog` 新增 `fetch()`）。

### 方法重写

子类定义与父类同名的方法称为**方法重写**。调用时 Python 优先使用子类实现。重写不修改父类，只改变子类对象调用该方法时的行为。

### super()

若想在保留父类行为基础上增加功能，用 `super()` 调用父类方法：

```python
class Dog(Animal):
    def sound(self):
        parent_result = super().sound()
        return f'{parent_result}, then barks: woof!'
```

`super()` 按方法解析顺序（MRO）调用下一个类的方法，比直接写 `Animal.sound(self)` 更灵活，在多继承中尤其重要。

### 扩展初始化方法

子类新增实例属性时，可重写 `__init__()` 再通过 `super().__init__()` 完成父类部分初始化：

```python
class Developer(Employee):
    def __init__(self, name, employee_id, language):
        super().__init__(name, employee_id)   # 初始化父类属性
        self.language = language              # 初始化子类特有属性
```

**注意**：子类重写 `__init__()` 却不调用父类初始化方法，父类定义的实例属性不会被自动创建。

## 继承关系检查

| 函数 | 作用 |
|---|---|
| `isinstance(obj, cls)` | 对象是否属于 `cls` 或其子类 |
| `issubclass(clsA, clsB)` | `clsA` 是否是 `clsB` 的子类 |

```python
issubclass(Dog, Animal)   # True
issubclass(Dog, object)   # True —— 所有类最终继承自 object
```

`dog` 既是 `Dog` 的对象，也可视为 `Animal` 的对象——这是 [[多态]] 的基础。

## 多继承与方法解析顺序

一个子类直接继承多个父类称为多继承，可组合多个父类的功能：

```python
class Frog(Walker, Swimmer):
    pass
```

多个父类有同名方法时，Python 按**方法解析顺序（MRO）**查找，可用 `Cls.mro()` 查看：

```python
class Child(ParentA, ParentB):
    pass

Child.mro()
# [<class 'Child'>, <class 'ParentA'>, <class 'ParentB'>, <class 'object'>]
```

父类在类定义中的排列顺序会影响 MRO。多继承可能增加同名方法、初始化顺序和依赖关系的复杂度，应在确实需要组合多类行为时使用。

## 自定义异常与继承

异常也是对象，常见异常继承自 `Exception`，自定义异常 `class XxxError(Exception)` 本质是定义 `Exception` 子类：

```
BaseException
└── Exception
    ├── ValueError
    ├── TypeError
    ├── LookupError
    │   ├── IndexError
    │   └── KeyError
    └── 自定义异常
```

要点：

- 业务异常应继承 `Exception` 而非 `BaseException`。`KeyboardInterrupt`/`SystemExit` 直接继承 `BaseException`；业务异常若也继承 `BaseException`，`except Exception` 将无法捕获
- 命名用 `Error` 结尾、**PascalCase**
- 既有 `pass` 空类已够保存消息（消息由 `Exception` 处理）；需保存业务数据则重写 `__init__()` 并 `super().__init__(...)`
- 可定义公共异常父类再派生具体异常，调用方既能捕获具体类型，也能用父类统一捕获：

```python
class WalletError(Exception): pass
class InvalidAmountError(WalletError): pass
class InsufficientFundsError(WalletError): pass
```

`except WalletError` 可捕获这两种子类异常。优先捕获具体异常类型，`except Exception` 范围过大。详见 [[异常处理]]。

## 名称改写在继承中的价值

[[封装]] 中的双下划线名称改写，其设计价值主要体现在继承场景：避免子类意外覆盖父类同名成员。父类的 `__data` 改写为 `_Parent__data`，子类的 `__data` 改写为 `_Child__data`，二者是不同属性，互不覆盖。

## 选择原则

- 继承应表达合理的"是一种"类型关系
- 优先复用接口而非依赖具体类型——这让 [[多态]] 成为可能
- 继承可实现多态，但 Python 的鸭子类型也允许无继承关系的类表现多态

合理使用继承减少重复代码，合理使用 [[多态]] 减少类型判断。
