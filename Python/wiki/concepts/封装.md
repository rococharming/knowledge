# 封装

封装是面向对象的重要原则之一：把对象的数据和操作数据的方法组合在一个类中，并通过清晰的接口控制外部代码如何访问和修改对象状态。它是 [[类和对象]] 之上控制"可见性"与"不变式"的机制，与 [[继承]]、[[多态]] 同为 OOP 核心。整体概览见 [[面向对象]]。

## 封装的目的

- 集中检查数据是否合法
- 防止对象进入无效状态
- 隐藏内部实现细节
- 修改内部实现时减少对外部代码的影响

经典模式：把状态存为内部属性，只通过方法暴露受控操作。

```python
class Wallet:
    def __init__(self, balance=0):
        self._balance = balance

    def deposit(self, amount):
        if amount <= 0:
            raise ValueError('Amount must be positive')
        self._balance += amount

    def withdraw(self, amount):
        if amount <= 0:
            raise ValueError('Amount must be positive')
        if amount > self._balance:
            raise ValueError('Insufficient funds')
        self._balance -= amount

    def get_balance(self):
        return self._balance
```

外部通过 `deposit()`/`withdraw()`/`get_balance()` 使用钱包，而非直接操作余额。

## 访问约定

Python 没有强制的访问权限，依靠**命名约定**表达访问意图：

| 写法 | 含义 | 外部可访问 |
|---|---|---|
| `name` | 公共成员，对外接口 | 是 |
| `_name` | 内部成员，约定不外部依赖 | 是（仅约定） |
| `__name` | 触发名称改写 | 原名称不可直接访问 |

### 公共成员

无下划线前缀的属性和方法，构成类对外提供的接口，可正常访问。

### 单下划线前缀

`_name` 表示仅供内部使用。**只是一种命名约定，语法上不阻止外部访问**。它传达：该成员属于内部实现，外部代码不应依赖。

### 双下划线前缀与名称改写

`__name`（不以双下划线结尾）触发**名称改写**：Python 在类内部把 `__name` 改写为 `_ClassName__name`。

```python
class Wallet:
    def __init__(self, balance=0):
        self.__balance = balance

    def get_balance(self):
        return self.__balance

wallet = Wallet(100)
wallet.__balance      # AttributeError: 原名称不可直接访问
wallet._Wallet__balance  # 仍可访问（改写后名称）
```

**关键认知**：名称改写不是绝对私有机制，外部仍可通过改写后名称访问。Python 的封装主要依靠接口设计和命名约定，而非强制访问权限。

双下划线也可用于方法（私有方法），如 `__validate_amount()` 只负责类内部校验，不属于对外接口。

## 名称改写的真实用途

双下划线的主要作用是**避免子类意外覆盖父类同名成员**，而非提供绝对私有：

```python
class Parent:
    def __init__(self):
        self.__data = 'Parent data'   # 改写为 _Parent__data

class Child(Parent):
    def __init__(self):
        super().__init__()
        self.__data = 'Child data'    # 改写为 _Child__data

child = Child()
child.__dict__   # {'_Parent__data': 'Parent data', '_Child__data': 'Child data'}
```

父类与子类的 `__data` 改写为不同名称，互不覆盖。若改用普通属性名 `data`，子类赋值会覆盖父类创建的值。

## 单下划线 vs 双下划线

| 写法 | 含义 | 常见用途 |
|---|---|---|
| `name` | 公共成员 | 对外稳定接口 |
| `_name` | 内部命名约定 | 提醒外部不要直接依赖 |
| `__name` | 触发名称改写 | 避免子类意外覆盖父类成员 |

**一般情况下内部成员用单下划线已足够**。仅当一个类可能被继承、且确需降低子类与父类成员名称冲突风险时，才考虑双下划线。不应仅为模拟其他语言的私有属性而滥用双下划线。

名称改写在 [[继承]] 场景下才体现其设计价值。

## Property：受控的属性访问

Property 让点语法在背后自动调用 Getter/Setter，兼顾点语法简洁性与方法的可控性。

| 装饰器 | 作用 |
|---|---|
| `@property` | 定义 Getter |
| `@属性名.setter` | 定义 Setter（方法名须与属性名相同） |
| `@属性名.deleter` | 定义 Deleter（控制 `del` 行为） |

```python
class Circle:
    def __init__(self, radius):
        self.radius = radius        # 走 Setter，创建时即验证

    @property
    def radius(self):
        return self._radius

    @radius.setter
    def radius(self, value):
        if value <= 0:
            raise ValueError('Radius must be positive')
        self._radius = value

    @property
    def area(self):                 # 只读，动态计算
        return math.pi * self._radius ** 2
```

关键要点：

- 只有 Getter、没有 Setter 的属性是**只读属性**，赋值抛 `AttributeError`
- 属性可在读取时动态计算（如 `area`），不必单独保存
- 在 `__init__()` 中通过属性赋值（`self.radius = radius`），可让对象创建时也走 Setter 验证，保证对象从一开始就有效
- **Setter 内部不能给同名属性赋值**（`self.radius = value`），否则触发自身 Setter 无限递归抛 `RecursionError`；应保存到另一个内部属性（`self._radius`）

| 名称 | 作用 |
|---|---|
| `radius` | 对外公开的属性 |
| `_radius` | 类内部实际保存数据的属性 |

## 方法 vs Property

两者都能隐藏内部实现，适用场景不同：

| 场景 | 推荐 |
|---|---|
| 读取/设置对象的一项数据 | Property |
| 读取时需简单计算 | 只读 Property |
| 执行存款、取款等明确动作 | 普通方法 |
| 操作耗时或产生明显副作用 | 普通方法 |
| 操作需要多个参数 | 普通方法 |

`circle.area` 表示一项数据，适合 Property；`wallet.deposit(100)` 表示一次动作，适合普通方法。

## 封装核心原则

封装不是给所有属性加下划线，而是为对象设计稳定、清晰的公共接口：

- 对外只公开使用对象所需的成员
- 内部实现用单下划线表示不建议外部访问
- 通过方法或 Property 集中执行验证
- 保证对象始终处于有效状态
- 不让外部代码依赖易变的内部细节

良好的封装让外部代码只关心对象能做什么，不必了解内部如何完成。封装常与 [[继承]]、[[多态]] 配合，自定义异常类（继承 `Exception`）也是封装思想在错误处理上的应用，见 [[异常处理]]。
