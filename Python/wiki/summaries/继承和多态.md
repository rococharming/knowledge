# 继承和多态

本文承接 [[类和对象]] 与 [[封装和属性]]，覆盖 OOP 另两大原则 **继承** 与 **多态**，并延伸到多继承、名称改写与自定义异常层次。详细概念见 [[继承]]、[[多态]]、[[封装]]。

## 继承

一个类可使用另一个类已有的属性和方法，减少重复代码并建立类层次。父类（基类/超类）提供通用成员，子类（派生类）继承并扩展。

```python
class Child(Parent):
    pass
```

继承适合表达"是一种"关系（开发者是一种员工）。子类可：

- **添加成员**：在继承基础上定义自己的属性和方法
- **方法重写**：定义与父类同名的方法，调用时优先用子类实现（不修改父类）
- **`super()`**：在保留父类行为基础上增加功能，按方法解析顺序（MRO）查找下一个类的方法，比直接写 `Parent.method(self)` 更灵活
- **扩展 `__init__()`**：通过 `super().__init__(...)` 完成父类部分初始化，再设置子类特有属性。重写 `__init__()` 却不调用父类初始化，父类实例属性不会被自动创建

## 继承关系检查

| 函数 | 作用 |
|---|---|
| `isinstance(obj, cls)` | 对象是否属于 `cls` 或其子类 |
| `issubclass(clsA, clsB)` | `clsA` 是否是 `clsB` 的子类 |

Python 中所有类最终继承自 `object`。

## 自定义异常与继承

异常也是对象，常见异常继承自 `Exception`，`Exception` 又继承自 `BaseException`。自定义异常 `class XxxError(Exception)` 本质是定义 `Exception` 子类。要点：

- 业务异常应继承 `Exception` 而非 `BaseException`——`KeyboardInterrupt`/`SystemExit` 直接继承 `BaseException`，业务异常若也继承 `BaseException`，`except Exception` 将无法捕获
- 命名用 `Error` 结尾、**PascalCase**
- 既有 `pass` 空类已够保存消息（消息由 `Exception` 处理）；需保存业务数据则重写 `__init__()` 并 `super().__init__(...)`
- 可定义公共异常父类再派生具体异常（如 `WalletError` → `InvalidAmountError`/`InsufficientFundsError`），调用方既能捕获具体类型，也能用父类统一捕获

这部分是 [[异常处理]] 自定义异常的进阶扩展。优先捕获具体异常类型，`except Exception` 范围过大。

## 多继承与方法解析顺序

一个子类直接继承多个父类（`class Child(ParentA, ParentB)`），可组合多个父类的功能。多个父类有同名方法时，Python 按方法解析顺序（MRO）查找，可用 `Cls.mro()` 查看。父类在类定义中的排列顺序影响 MRO。多继承增加同名方法、初始化顺序和依赖的复杂度，应在确实需要组合多类行为时使用。

## 多态

多态表示不同类型对象可通过相同接口执行各自行为，外部代码无需为每种对象分别编写调用逻辑。

Python 实现多态的两种方式：

- **鸭子类型**：关注对象能做什么而非属于哪个类。只要对象提供所需方法即可在相同代码中使用，**不要求继承关系**。这是 Python 最常见的方式
- **基于继承**：父类定义统一方法，子类分别重写。Python 根据对象实际类型选择对应实现

多态减少类型判断和重复分支：没有多态时需用 `isinstance` 写多个条件分支；用统一接口后调用代码只写一次，新增类型只要提供该方法通常无需修改调用方。

## 继承与多态的关系

| 概念 | 关注 |
|---|---|
| 继承 | 如何复用和扩展已有类的属性与方法 |
| 多态 | 如何通过相同接口操作不同类型的对象 |

继承可实现多态，但 Python 的鸭子类型允许没有继承关系的类也表现出多态。合理使用继承减少重复代码，合理使用多态减少类型判断。

## 选择原则

- 继承应表达合理的"是一种"类型关系；只是代码相似但无合理类型关系时不一定适合继承
- 优先复用接口而非依赖具体类型，让调用代码依赖统一接口
