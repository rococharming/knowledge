# 封装和属性

面向对象编程（OOP）以对象组织程序，对象包含**属性**（保存数据与状态）和**方法**（定义行为）。OOP 通常包含四个原则：封装、继承、多态、抽象。本文聚焦 **封装** 与 **属性机制**，是 [[类和对象]] 的进阶，相关概念见 [[封装]]、[[继承]]、[[多态]]。

## 封装的基本含义

封装把对象的数据和操作这些数据的方法组合在一个类中，并通过清晰的接口控制外部如何访问和修改对象状态。典型例子是钱包：余额不应被随意修改，存取款必须通过方法完成。

封装的作用：

- 集中检查数据是否合法
- 防止对象进入无效状态
- 隐藏内部实现细节
- 修改内部实现时减少对外部代码的影响

## Python 访问约定

Python 没有强制的访问权限，依靠命名约定表达访问意图：

| 写法 | 含义 | 是否阻止外部访问 |
|---|---|---|
| `name` | 公共成员，对外接口 | 否 |
| `_name` | 内部成员，约定不外部依赖 | 否 |
| `__name` | 触发名称改写 | 改写后原名称不可直接访问 |

单下划线只是约定，语法上仍可访问；双下划线通过名称改写（`__name` → `_ClassName__name`）让原名称外部访问抛 `AttributeError`，但改写后的名称仍可访问。**双下划线的主要作用是避免子类意外覆盖父类同名成员，而非绝对私有**。详见 [[封装]]。

## Getter 与 Setter

Getter 读取属性值，Setter 修改属性值，可在访问/修改时执行验证等额外逻辑。普通方法形式（`get_radius()`/`set_radius()`）不如点语法简洁，Python 通过 Property 让点语法在背后自动调用 Getter/Setter。

## Property 属性

| 装饰器 | 作用 |
|---|---|
| `@property` | 定义 Getter |
| `@属性名.setter` | 定义 Setter（方法名须与属性名相同） |
| `@属性名.deleter` | 定义 Deleter（控制 `del` 行为） |

关键要点：

- 只有 Getter、没有 Setter 的属性是**只读属性**，赋值会抛 `AttributeError`
- 属性可在读取时动态计算（如 `area` 根据 `radius` 算），不必单独保存
- 在 `__init__()` 中通过属性赋值，可让对象创建时也走 Setter 验证，保证对象从一开始就有效
- **Setter 内部不能给同名属性赋值**（`self.radius = value`），否则无限递归抛 `RecursionError`；应保存到另一个内部属性（如 `self._radius`）

## 方法 vs Property

| 场景 | 推荐 |
|---|---|
| 读取/设置对象的一项数据 | Property |
| 读取时需简单计算 | 只读 Property |
| 执行存款、取款等明确动作 | 普通方法 |
| 操作耗时或产生明显副作用 | 普通方法 |
| 操作需要多个参数 | 普通方法 |

## 封装核心原则

封装不是给所有属性加下划线，而是为对象设计稳定、清晰的公共接口：

- 对外只公开使用对象所需的成员
- 内部实现用单下划线表示不建议外部访问
- 通过方法或 Property 集中执行验证
- 保证对象始终处于有效状态
- 不让外部代码依赖易变的内部细节

封装与继承、多态共同构成面向对象的核心机制，整体概览见 [[面向对象]]。
