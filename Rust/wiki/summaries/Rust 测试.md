# Rust 测试

Rust 内置了完整的测试支持，通过 `cargo test` 即可编译并运行项目中的测试代码。测试体系围绕**单元测试**、**集成测试**和**文档测试**三种类型展开，覆盖了从内部实现到公开 API、从代码正确性到文档示例可用性的全方位验证。

## 核心内容概览

### 测试类型

| 测试类型 | 常见位置 | 主要用途 |
|---|---|---|
| 单元测试 | `src` 目录中的源码文件内部 | 测试某个函数、模块或内部实现 |
| 集成测试 | 项目根目录下的 `tests/` 目录 | 像外部用户一样测试库的公开 API |
| 文档测试 | 文档注释中的 Rust 代码块 | 保证文档示例可以编译或运行 |

### 测试函数基本结构

测试函数通过 `#[test]` 属性标记，测试模块通过 `#[cfg(test)]` 条件编译包裹。典型结构如下：

```rust
#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn it_works() {
        assert_eq!(2 + 2, 4);
    }
}
```

### 关键知识点

- **断言宏**：`assert!`、`assert_eq!`、`assert_ne!` 用于判断测试结果；支持自定义失败信息
- **should_panic**：`#[should_panic]` 标记预期会 panic 的测试，可通过 `expected` 精确匹配 panic 信息
- **Result 测试**：测试函数可以返回 `Result<T, E>`，以 `Ok(())` 表示通过、`Err(e)` 表示失败
- **cargo test 参数**：支持并行/顺序执行、名称过滤、显示输出、忽略测试、只编译不运行等控制选项
- **开发依赖**：`[dev-dependencies]` 中放置仅在测试/示例中使用的依赖，如 `pretty_assertions`
- **单元测试**可访问私有函数，**集成测试**只能访问公开 API，**文档测试**验证文档示例的正确性
