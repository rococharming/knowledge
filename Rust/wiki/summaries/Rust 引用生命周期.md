# Rust 引用生命周期

本文系统梳理 Rust 中引用生命周期的核心机制：生命周期用于描述引用有效范围，配合[[所有权系统]]和[[引用与借用]]防止悬垂引用；在函数、结构体和方法中，生命周期标注用于表达多个引用之间的关系，而不是延长任何值实际存在的时间。

## 核心主题

### 生命周期与悬垂引用

生命周期的目标是保证引用在被使用时，其指向的数据仍然有效。若外层引用指向内层作用域中的局部变量，内层变量离开作用域后引用就会悬垂，借用检查器会在编译期拒绝这类代码。相关概念详见[[生命周期]]。

### 函数签名中的生命周期关系

当函数接收多个引用并返回引用时，编译器可能无法判断返回值来自哪个参数。此时需要显式生命周期参数，例如 `fn longest<'a>(x: &'a str, y: &'a str) -> &'a str`，表示返回引用的有效期受两个输入引用中较短者约束。

### 生命周期标注不是延寿

生命周期标注只描述引用之间的关系，不改变任何值的真实作用域。若函数返回局部变量的引用，即使写了生命周期参数也无法通过编译；正确做法通常是返回拥有所有权的值。

### 结构体与方法中的生命周期

结构体若保存引用字段，需要在类型定义中声明生命周期参数，例如 `struct Excerpt<'a> { text: &'a str }`，表示结构体实例不能比字段中的引用活得更久。方法返回结构体内部引用时，常借助[[生命周期省略规则]]减少重复标注。

### 静态生命周期

`'static` 表示引用可存活于整个程序期间。字符串字面量天然具有 `'static` 生命周期，但不应把 `'static` 当作普通生命周期错误的修补手段。
