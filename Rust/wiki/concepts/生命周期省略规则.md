# 生命周期省略规则

生命周期省略规则（lifetime elision rules）是 Rust 编译器在常见引用模式下自动补全生命周期参数的规则。它们让简单函数和方法不必重复书写显式生命周期，同时仍然保持[[生命周期]]检查的安全性。

## 输入与输出生命周期

函数或方法参数中的引用生命周期称为输入生命周期，返回值中的引用生命周期称为输出生命周期。省略规则的作用，就是在函数签名没有显式写出生命周期时，为这些输入和输出引用建立关系。

## 三条常用规则

### 每个引用参数获得自己的生命周期

每个引用参数都会先被分配一个独立生命周期：

```rust
fn foo(x: &str, y: &str)
```

可理解为：

```rust
fn foo<'a, 'b>(x: &'a str, y: &'b str)
```

这一步只处理输入引用，不处理返回值。

### 只有一个输入生命周期时，赋给所有输出引用

如果函数只有一个输入引用生命周期，那么返回引用默认与这个输入引用相关：

```rust
fn first_word(s: &str) -> &str
```

可理解为：

```rust
fn first_word<'a>(s: &'a str) -> &'a str
```

这类函数通常返回参数内部的一部分引用，例如字符串切片。

### 方法中返回引用默认关联 self

如果方法有多个输入生命周期，但其中一个参数是 `&self` 或 `&mut self`，那么所有省略的输出生命周期默认与 `self` 的生命周期相关：

```rust
impl User {
    fn name(&self) -> &str {
        &self.name
    }
}
```

可理解为：

```rust
impl User {
    fn name<'a>(&'a self) -> &'a str {
        &self.name
    }
}
```

这条规则符合方法的常见用途：方法返回的引用通常是从当前对象内部借出的。返回引用存在期间，`self` 也必须保持有效，并继续遵守[[引用与借用]]规则。

## 不能省略的典型场景

如果函数有多个输入引用，又没有 `self`，编译器无法判断返回值与哪个参数相关：

```rust
fn longest(x: &str, y: &str) -> &str
```

此时必须显式标注：

```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str
```

这个签名表示返回引用的有效期不能超过 `x` 和 `y` 中较短的那个。

如果方法实际想返回的引用来自非 `self` 参数，也需要显式标注，避免默认关联到 `self`：

```rust
impl User {
    fn choose<'a>(&self, other: &'a str) -> &'a str {
        other
    }
}
```
