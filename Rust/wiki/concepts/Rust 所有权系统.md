# Rust 所有权系统

Rust 的所有权系统是一套编译期规则，用来决定一个值由谁负责、什么时候失效、什么时候释放资源。它让 Rust 在不依赖垃圾回收、不要求手动释放普通内存的前提下，避免大量内存安全问题。

可以先把它理解成一个资源责任模型：值进入作用域后由某个绑定拥有；值离开作用域时，由当前所有者负责清理；如果所有权被移动给别人，原绑定就不能再继续使用。

## 内存管理路线

常见语言大致有三类内存管理方式：

| 方式 | 代表语言 | 核心特点 | 主要代价 |
|---|---|---|---|
| 垃圾回收 | Java、Python | 运行时追踪不再使用的对象并回收 | 可能有运行时开销、暂停或更高内存占用 |
| 手动管理 | C、C++ | 开发者显式申请和释放内存 | 容易出现泄漏、悬垂指针、二次释放等问题 |
| 编译期所有权 | Rust | 编译器用所有权、借用和生命周期检查资源使用 | 学习和建模成本更高 |

Rust 主要保证的是安全 Rust 代码中的内存安全。使用 `unsafe`、外部 FFI 或写错业务逻辑时，仍然需要开发者承担相应责任。

## 作用域与 Drop

变量的作用域通常由 `{}` 代码块决定。绑定进入作用域后可以使用，离开作用域后绑定失效：

```rust
fn main() {
    {
        let a = 1;
        println!("a: {a}");
    }
    // println!("{a}"); // 编译错误，a 已离开作用域
}
```

Rust 使用 RAII 管理资源：值离开作用域时会自动运行析构逻辑，这个过程通常称为 drop。对只在栈上的简单数据来说，离开作用域后栈空间自然失效；对拥有堆内存、文件句柄、锁等资源的值来说，drop 会释放对应资源。

```rust
fn main() {
    {
        let s = String::from("hello");
    }
    // s 离开作用域，String 持有的堆内存被释放
}
```

## 三条基本规则

Rust 所有权可以先记住三条规则：

1. 每一个值都有一个所有者。
2. 同一时刻，一个值默认只有一个所有者。
3. 当所有者离开作用域，值会被丢弃。

这里的“一个所有者”说的是默认模型。Rust 也能表达共享所有权，但需要通过 `Rc`、`Arc` 等类型显式建模，而不是让多个普通变量都默认拥有同一份资源。

## `String` 的栈与堆

`String` 是理解所有权的典型例子。`String` 值本身在栈上保存指针、长度和容量；真正的 UTF-8 字节内容放在堆上。

图中 `s` 这个绑定拥有栈上的 `String` 结构，而结构里的指针指向堆上的字符串数据。当 `s` 离开作用域时，`String` 的 drop 逻辑会释放它指向的堆缓冲区。

## 移动

对大多数非 `Copy` 类型来说，赋值、函数传参和函数返回默认发生移动。移动会把值的所有权从源绑定转移到目标绑定；移动之后，源绑定在语义上失效。

```rust
fn main() {
    let s1 = String::from("hello");
    let s2 = s1;

    // println!("{s1}"); // 编译错误，s1 已经移动
    println!("{s2}");
}
```

移动 `String` 时，Rust 并不会把堆上的字符串字节重新复制一份。它主要转移栈上的 `String` 结构，也就是指针、长度和容量；堆上的字符串数据仍然是同一份。

![[Image 32.png|600]]

移动前，`s1` 拥有这份 `String` 数据。

![[Image 33.png|600]]

移动后，所有权转移到 `s2`，`s1` 不能再被使用。这样可以避免两个变量都以为自己负责释放同一块堆内存，从而避免二次释放。

## Clone

如果确实需要两份独立数据，应显式调用 `clone`：

```rust
fn main() {
    let s1 = String::from("hello");
    let s2 = s1.clone();

    println!("{s1}");
    println!("{s2}");
}
```

![[Image 35.png|600]]

对 `String` 来说，`clone` 通常会重新分配堆内存并复制字符串内容。因此 Rust 要求显式写出 `clone`，让这类成本在代码里可见。

## Copy 类型

`Copy` 是移动规则的例外。整数、浮点数、布尔值、字符，以及元素全是 `Copy` 的数组和元组，通常可以被隐式复制。赋值后，原绑定仍然可用：

```rust
fn main() {
    let num1: i32 = 36;
    let num2 = num1;

    println!("{num1}");
    println!("{num2}");
}
```

![[Image 36.png|600]]

`i32` 这样的固定大小数值不拥有需要特殊释放的堆资源，因此复制一份值不会制造“谁负责释放资源”的歧义。

拥有需要清理资源的类型通常不能是 `Copy`。例如 `String` 需要在 drop 时释放堆内存，所以它不能被隐式复制出多个所有者。更一般地说，实现了 `Drop` 的类型不能同时实现 `Copy`。

## 函数中的所有权转移

函数传参也可能发生所有权转移。把非 `Copy` 类型传给函数时，所有权通常移动到形参：

```rust
fn main() {
    let s = String::from("hello");

    take_ownership(s);

    // println!("{s}"); // 编译错误，s 已移动
}

fn take_ownership(value: String) {
    println!("{value}");
}
```

函数结束时，形参 `value` 离开作用域，这个 `String` 被 drop。

如果传入的是 `Copy` 类型，函数调用会复制值，原绑定仍然可用：

```rust
fn main() {
    let x = 5;

    makes_copy(x);

    println!("{x}");
}

fn makes_copy(value: i32) {
    println!("{value}");
}
```

函数返回非 `Copy` 值时，所有权会移动给调用者：

```rust
fn gives_ownership() -> String {
    let s = String::from("hello");
    s
}
```

这些规则和 [[Rust 函数、语句与表达式基础]] 的函数参数、返回值语法直接相连：语法决定值如何进入和离开函数边界，所有权规则决定进入和离开时绑定是否仍然可用。

## 控制流中的移动

移动也会受到控制流影响。只要某个值在分支之后可能已经被移动，编译器就会禁止继续使用它：

```rust
fn main() {
    let s = String::from("hello");

    if true {
        consume(s);
    } else {
        consume(s);
    }

    // println!("{s}"); // 编译错误，s 已经可能被移动
}

fn consume(value: String) {
    println!("{value}");
}
```

循环中也不能反复移动同一个非 `Copy` 值：

```rust
fn main() {
    let s = String::from("hello");

    loop {
        consume(s); // 编译错误，第一次循环后 s 已移动
    }
}

fn consume(value: String) {
    println!("{value}");
}
```

如果只是想读取或临时使用一个值，通常应学习借用和引用，而不是每次都转移所有权。

## 学习边界

所有权这一页先聚焦“谁拥有值、移动后谁还能使用、何时释放资源”。后续的引用、切片、生命周期、集合移动、智能指针和共享所有权，都建立在这套基础规则之上。
