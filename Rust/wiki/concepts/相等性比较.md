# 相等性比较

Rust 中的相等比较由 `std::cmp::PartialEq` 和 `std::cmp::Eq` 两个 trait 表示。区分二者的原因是：**并非所有类型都满足严格数学意义上的相等关系**。

## PartialEq

`PartialEq` 表示**部分相等**，支持 `==` 和 `!=` 运算符：

```rust
trait PartialEq<Rhs = Self>
where
    Rhs: ?Sized,
{
    fn eq(&self, other: &Rhs) -> bool;

    fn ne(&self, other: &Rhs) -> bool {
        !self.eq(other)
    }
}
```

与 `Add` 等算术运算符不同，`PartialEq` 使用 **引用接收参数**（`&self`、`&Rhs`），因为比较通常只需读取值，不应消耗所有权。

### 实现要点

只需实现 `eq()` 方法，`ne()` 有默认实现：

```rust
impl<T> PartialEq for Complex<T>
where
    T: PartialEq,
{
    fn eq(&self, other: &Self) -> bool {
        self.re == other.re && self.im == other.im
    }
}
```

实现 `PartialEq` 后即可使用 `assert_eq!` 进行断言测试。

### 派生宏

手动实现 `PartialEq` 通常只是逐字段比较，较为机械。可使用 `#[derive(PartialEq)]` 自动实现：

```rust
#[derive(Debug, Copy, Clone, PartialEq)]
struct Complex<T> {
    re: T,
    im: T,
}
```

编译器自动按字段生成比较逻辑。

## 为什么区分 PartialEq 和 Eq

数学意义上的相等要求满足三条性质：

| 性质 | 说明 |
|------|------|
| 对称性 | 若 `x == y`，则 `y == x` |
| 传递性 | 若 `x == y` 且 `y == z`，则 `x == z` |
| 自反性 | 任意 `x` 满足 `x == x` |

浮点数的 `NaN` 不满足自反性：

```rust
let x = 0.0f64 / 0.0;
assert!(x.is_nan());
assert!(x != x);  // NaN != NaN
```

因此 `f32` 和 `f64` 实现了 `PartialEq`，但**没有实现 `Eq`**。

## Eq

`Eq` 是 `PartialEq` 的语义增强，不新增方法：

```rust
trait Eq: PartialEq<Self> {}
```

实现 `Eq` 意味着承诺：该类型的相等关系满足更严格的数学要求，尤其是**所有值都满足 `x == x`**。

### 实现方式

```rust
impl<T: Eq> Eq for Complex<T> {}
```

更常见的写法是直接派生：

```rust
#[derive(Debug, Copy, Clone, PartialEq, Eq)]
struct Complex<T> {
    re: T,
    im: T,
}
```

### 限制

只有当字段类型也适合实现 `Eq` 时，自定义类型才能派生 `Eq`。包含 `f64` 字段的结构体不能直接派生：

```rust
#[derive(Debug, PartialEq)]
struct Point {
    x: f64,
    y: f64,
}
// 错误：f64 只有 PartialEq，没有 Eq
// #[derive(Eq)]
```

## 对比总结

| trait | 含义 | 对应运算符 | 数学承诺 |
|-------|------|-----------|---------|
| `PartialEq` | 部分相等 | `==`、`!=` | 不要求自反性 |
| `Eq` | 完全相等 | 无新增 | 要求自反性、对称性、传递性 |

这是 Rust 类型系统严谨性的体现：**能比较相等，不代表一定满足完全相等关系**。
