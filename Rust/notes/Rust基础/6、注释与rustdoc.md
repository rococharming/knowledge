# 一、Rust注释分类

注释用于解释代码，帮助人类理解程序逻辑。普通注释在编译时会被编译器忽略，不会影响程序运行。

Rust的注释除了常规代码注释外，还支持**文档注释**。文档注释可以被`rustdoc`工具解析，并生成**API文档**。

Rust注释主要分为三类：

- 行注释
- 块注释
- 文档注释

其中，行注释和块注释主要用于解释代码；文档注释主要用于为`crate`、模块、函数、结构体、枚举、`Trait`等生成文档。

# 二、行注释

行注释（`line comment`）使用`//`开头，从`//`开始到行尾的内容都会被编译器忽略。

行注释适合写简短说明。

示例：

```rust
// 这是一个行注释

let x = 5; // 这是跟在代码后面的行注释
```

行注释也常用于临时屏蔽某一行代码：

```rust
let x = 5;

// println!("{}", x);
```

# 三、块注释

块注释（`block comment`）使用`/* ... */`包裹，它可以跨多行，也可以写在同一行内。

块注释适合临时屏蔽一段代码，或者写较长说明。

示例：

```rust
/*
这是一个块注释。

它可以跨越多行。
*/

let y = 10;

/* 也可以这样写在同一行 */
```

**值得注意的是**：和C/C++不同， Rust块注释**支持嵌套** 。

示例：

```rust
/* 外层注释

    /* 内层注释 */

*/
```

这在调试时很有用。例如要临时注释掉一大段代码，而这段代码内部本身已经包含块注释，Rust 也能正确处理。

# 四、文档注释

当查看 [docs.rs](https://docs.rs/) 或 `rustdoc` 生成的在线 API 文档时，看到的函数说明、结构体说明、示例代码等内容，很多都是通过**文档注释**生成的。

Rust提供了专门的文档注释形式，供`rustdoc`解析并生成**HTML文档**。当执行`cargo doc`时，`Cargo`底层会调用`rustdoc`来生成文档。

文档注释常见分为两类：

- **项文档注释**：用于说明函数、结构体、枚举、Trait、常量、静态变量等项（item）；
- **内部文档注释**：用于说明当前模块或当前`crate`

## 1、项文档注释

`///` 是最常见的文档注释形式，用于为它下方的 item 添加说明。item 可以是：

- 函数
- 结构体
- 枚举
- Trait
- 常量
- 静态变量
- 模块

示例：

```rust
/// `add_one` 会将指定值加 1
///
/// # Examples
///
/// ```
/// # fn add_one(x: i32) -> i32 { x + 1 }
/// let arg = 5;
/// let answer = add_one(arg);
///
/// assert_eq!(6, answer);
/// ```
pub fn add_one(x: i32) -> i32 {
    x + 1
}
```

这里的文档注释会被 `rustdoc` 解析，生成到 API 文档中。

需要注意：文档注释支持`Markdown`语法，例如标题、列表、代码块等。

示例中的`# Examples`会在生成的文档中显示为标题。

文档注释中的 Rust 代码块还可以作为**文档测试**，也就是`doctest`。上面示例中的 `# fn add_one(...)` 是隐藏行：生成文档时不会显示，但运行文档测试时会参与编译。真实项目中也常用隐藏的 `use crate_name::add_one;` 引入被测试项。详见[[Rust/notes/Rust基础/20、测试|测试]]。

被注释的 item 不一定必须是 `pub` 才能写文档注释。只是默认生成公开 API 文档时，非 `pub` 的 item 通常不会显示，除非使用相关参数生成私有项文档。

除了`///`，Rust也支持块式文档注释`/** ... */`。

示例：

```rust
/**
`add_one` 会将指定值加 1。
*/
pub fn add_one(x: i32) -> i32 {
    x + 1
}
```

它的作用和 `///` 类似，都是给后面的 item 添加文档说明。不过实际项目中更常用 `///`，因为它更直观，也更方便逐行维护。

## 2、内部文档注释

`//!` 是内部行文档注释，也叫 inner doc comment。它和`///`的区别是：

- `///`注释的是紧随其后的 item
- `//!`注释的是当前crate本身或所在模块

`//!`通常写在文件顶部，用于说明整个`crate`或模块。

例如，在 `src/lib.rs` 顶部写：

```rust
//! 这是当前 crate 的说明文档。
//!
//! 这个 crate 提供了一些数学工具函数。

pub mod math {
    pub fn add(x: i32, y: i32) -> i32 {
        x + y
    }
}
```

这里的 `//!` 注释的是当前 crate 本身，而不是下面的 `math` 模块。

也可以写在模块内部，用于说明该模块：

```rust
mod math {
    //! 数学工具模块。

    pub fn add(x: i32, y: i32) -> i32 {
        x + y
    }
}
```

在这个例子中，`//! 数学工具模块。` 注释的是 `math` 模块本身。

与`//!`对应的是块式内部文档`/*! ... */`。

示例：

```rust
/*!
这是当前 crate 的说明文档。

可以写多行。
*/

pub fn add(x: i32, y: i32) -> i32 {
    x + y
}
```

它和 `//!` 的作用类似，都是用于给当前模块或 crate 写文档，只是写法不同。

实际项目中，`//!` 更常见。


## 3、查看文档注释

编写好文档注释后，可以在项目目录执行：

```shell
cargo doc
```

这会在项目的 `target/doc` 目录下生成 HTML 文档。

为了方便查看，可以加上 `--open` 参数，生成后自动在浏览器中打开：

```bash
cargo doc --open
```

在生成的文档中：

- `//!` 对应 crate 或模块级别的说明，通常显示在页面顶部；
- `///` 对应具体 item 的说明，例如函数、结构体、枚举、Trait 等；
- 文档注释中的 Markdown 标题、代码块、列表等会被渲染为 HTML 内容。

可以看到定义的函数，例如，点击`add`进入：

文档中常见的一些小标题包括：

- \# Examples：示例用法，最常见
- \# Panics：说明哪些情况可能触发 `panic!`；
- \# Errors：如果函数返回 `Result`，说明可能返回哪些错误；
- \# Safety：如果函数涉及 `unsafe`，说明调用者必须满足哪些安全前提。

这些标题是 Rust 社区常见惯例，不是语法强制要求。

可以使用中文标题，但实际项目中建议遵循团队规范，并保持文档风格一致。
