# 一、迭代器基础

迭代器是一个可以按需产生一系列值的对象。它不要求一次性把所有值都准备好，而是在需要下一个值时，才向前推进下一步。

Rust很多遍历行为都建立在迭代器之上，例如：

| 场景                 | 迭代内容       |
| ------------------ | ---------- |
| 遍历 `Vec<T>`        | 逐个产生元素     |
| 遍历字符串              | 逐个产生字节或字符  |
| 遍历 `HashMap<K, V>` | 逐个产生键值对    |
| 读取标准输入             | 逐行产生输入内容   |
| 处理网络连接             | 逐个产生连接     |
| 接收通道消息             | 逐个产生线程发送的值 |

Rust的`for`循环为迭代器提供了自然语法，但迭代器并不只是为`for`循环服务。它还提高了大量方法，例如`map`（映射）、`filter`（过滤）、`flatten`（展平）、`chain`（链接）、`collect`（收集）、`fold`（折叠）等，可以把一段遍历逻辑组织成清晰的数据处理管道。

例如，计算前`n`个正整数之和：

```rust
fn triangle(n: i32) -> i32 {
    let mut sum = 0;

    for i in 1..=n {
        sum += i;
    }

    sum
}
```

这里的 `1..=n` 是一个范围值，它可以逐个产生从 `1` 到 `n` 的整数，因此可以被 `for` 循环遍历。

同样的逻辑也可以用迭代器消费器`fold`表达：

```rust
fn triangle(n: i32) -> i32 {
    (1..=n).fold(0, |acc, x| acc + x)
}
```

`fold` 从初始值 `0` 开始，每次取出一个元素，把“当前累加值”和“当前元素”传给闭包，闭包返回新的累加值。最后一个累加值就是整个 `fold` 的返回值。

迭代器的核心特点可以概括为：

| 特点    | 含义               |
| ----- | ---------------- |
| 按需产生  | 需要下一个值时才推进       |
| 惰性执行  | 很多适配器本身不会立刻执行    |
| 可组合   | 多个适配器可以链式组合      |
| 零成本抽象 | 编译后通常接近手写循环的性能   |
| 所有权清晰 | 可以按值、共享引用、可变引用遍历 |

# 二、Iterator和IntoIterator

## 1、Iterator特征

所有真正的迭代器类型都实现了`std::iter::Iterator`。它的核心定义可以简化为：

```rust
trait Iterator {
	type Item;
	
	fn next(&mut self) -> Option<Self::Item>;
	
	// 省略大量默认方法
}
```

其中：

| 成员                   | 作用                                       |
| -------------------- | ---------------------------------------- |
| `type Item`          | 迭代器每次产生的元素类型                             |
| `next(&mut self)`    | 推进迭代器并返回下一个元素                            |
| `Option<Self::Item>` | 用 `Some(value)` 表示下一个值，用 `None` 表示当前迭代结束 |
`next()` 使用 `&mut self`，因为迭代器每次向前推进时，内部状态通常都会改变。例如，遍历向量时需要记录当前位置；读取输入流时需要记录已经读到哪里。

手动调用`next()`的例子“

```rust
let mut iter = vec![10, 20, 30].into_iter();

assert_eq!(iter.next(), Some(10));
assert_eq!(iter.next(), Some(20));
assert_eq!(iter.next(), Some(30));
assert_eq!(iter.next(), None);
```

`Iterator` 只要求实现 `next()`。`map`、`filter`、`fold`、`collect` 等大量方法都是基于 `next()` 提供的默认方法。也就是说，只要一个类型实现了 `next()`，它就可以获得整套迭代器方法。


## 2、IntoIterator特征

迭代器是实现了 `Iterator` 特征的值，而可迭代者则是实现了 `IntoIterator` 特征的值。

可迭代者本身不是迭代器类型，但可以调用 `IntoIterator::into_iter()` 方法转换为迭代器，向量、数组、切片、哈希表等类型，均属于可迭代者。

`IntoIterator` 特征的核心简化定义如下：

```rust
trait IntoIterator {
	type Item;
	type IntoIter: Iterator<Item = Self::Item>;
	
	fn into_iter(self) -> Self::IntoIter;
}
```

其中：

| 成员                | 作用            |
| ----------------- | ------------- |
| `Item`            | 转换后迭代器产生的元素类型 |
| `IntoIter`        | 转换后得到的迭代器类型   |
| `into_iter(self)` | 把当前值转换成迭代器    |

很多集合类型本身不是迭代器，但它们可以转换为迭代器，例如`Vec<T>`、数组、切片引用、`HashMap<K, V>`等。

示例：

```rust
let v = vec![1, 2, 3];

let iter = v.into_iter();
```

这里`v`被转换成一个迭代器。对于`Vec<T>`来说，按值调用`into_iter()`会消耗整个`Vec<T>`，并逐个产生其中元素的所有权。

示例：

```rust
let arr = [1, 2, 3]; // 数组

let iter1 = arr.into_iter();

println!("{:?}", arr);

let vec = vec![4, 5, 6]; // 向量

let iter2 = vec.into_iter();

// println!("{:?}", vec); 错误
```

注意：

`[i32; 3]` 这个数组类型实现了 `Copy` （因为 `i32` 是 `Copy` ，且数组在这种情况下也实现 `Copy` ），所以 `arr.into_iter()` 时实际是复制了一个数组值再去生成迭代器，原来的 `arr` 仍然可用。`vec.into_iter()` 会直接移动整个 `Vec` ，因此 `vec` 被消耗了。

`IntoIterator`的重要意义在于：它让一个类型可以出现在`for`循环中。只要某个类型实现了`IntoIterator`，它就可以被`for`遍历。

## 3、for循环的展开形式

Rust 的`for`循环本质上会先调用`into_iter()`，再不断调用`next()`。

例如：

```rust
let v = vec![1, 2, 3];

for element in v {
    println!("{element}");
}
```

可以近似理解为：

```rust
let v = vec![1, 2, 3];

let mut iter = v.into_iter();

while let Some(element) = iter.next() {
    println!("{element}");
}
```

这里 `v` 被按值传入 `into_iter()`，所以 `v` 的所有权被移动，循环之后不能再使用原来的 `v`。

需要注意：`for` 总是对循环对象调用 `IntoIterator::into_iter()`，但不同写法会调用不同的 `IntoIterator` 实现。

```rust
for element in v {
	// 按值遍历，element: T
}

for element in &v {
	// 共享引用遍历，element: &T
}

for element in &mut v {
	// 可变引用遍历，element: &mut T
}
```

例如：

```rust
let v = vec![1, 2, 3];

for element in &v { // element 的类型为 &i32
	println!("{}", element);
}
```

近似理解为：

```rust
let v = vec![1, 2, 3];

let mut iter = (&v).into_iter(); // iter 类型是 Iter<'_, i32>

while let Some(element) = iter.next() { // element 类型为 &i32
	println!("{}", element);
}
```

这里调用的是为 `&Vec<T>` 实现的 `IntoIterator` 。原来的 `v` 仍然可用，因为这里只是借用了它。

再例如：

```rust
let mut v = vec![1, 2, 3];

for element in &mut v { // element 的类型为 &mut i32
	println!("{}", element);
}
```

近似理解为：

```rust
let mut v = vec![1, 2, 3];

let mut iter = (&mut v).into_iter(); // iter 类型是 IterMut<'_, i32>

while let Some(element) = iter.next() { // element 类型为 &mut i32
	println!("{}", element);
}
```

这里调用的是为 `&mut Vec<T>` 实现的 `IntoIterator` 。

`for` 循环总是会对其操作数调用 `into_iter()` ，但 `for` 循环的操作数本身也可以直接是迭代器，例如遍历 `Range` ：

```rust
for i in 0..10 {
	println!("{}", i);
}
```

 `0..10` 本身就是一个迭代器类型 `Range<i32>` ，`for` 依然会对它调用 `into_iter()` 。之所以可行，是因为迭代器本身也实现了`IntoIterator` 。

大致可以理解为：

```rust
impl<I: Iterator> IntoIterator for I {
	type Item = I::Item;
	type IntoIter = I;
	
	fn into_iter(self) -> I {
		self
	}
}
```

因此，可以对一个已经是迭代器的值继续调用 `into_iter()` ，例如：

```rust
let v = vec![1, 2, 3];

let v_iter = v.into_iter().into_iter().into_iter();
```

# 三、创建迭代器的常见入口

## 1、iter()产生共享引用

`iter()`通常用于不可变遍历集合。它不会取得集合所有权，而是逐个产生元素的共享引用。

示例：

```rust
let v = vec![1, 2, 3];

let mut iter = v.iter();

assert_eq!(iter.next(), Some(&1));
assert_eq!(iter.next(), Some(&2));
assert_eq!(iter.next(), Some(&3));
assert_eq!(iter.next(), None);

println!("{v:?}");
```

这里 `iter` 的元素类型是 `&i32`，原来的 `v` 仍然可用。

`iter()` 适合只读取元素、不移动元素、不修改元素的场景。

## 2、iter_mut()产生可变引用

`iter_mut()`用于可变遍历集合。它不会取得集合所有权，而是逐个产生元素的可变引用。

示例：

```rust
let mut v = vec![1, 2, 3];

for element in v.iter_mut() {
    *element *= 10;
}

assert_eq!(v, vec![10, 20, 30]);
```

这里 `element` 的类型是 `&mut i32`，需要通过 `*element` 修改其指向的值。

`iter_mut()` 适合原地修改集合元素的场景。

## 3、into_iter()按调用对象决定遍历方式

`into_iter()`的行为取决于它的接收者是什么。

```rust
let mut v = vec![
    String::from("a"),
    String::from("b"),
];


for item in &v {
    // item: &String
}

for item in &mut v {
    // item: &mut String
}

for item in v {
    // item: String
}
```

等价于：

```rust
for item in (&v).into_iter() {
    // item: &String
}

for item in (&mut v).into_iter()  {
    // item: &mut String
}

for item in v.into_iter() {
    // item: String
}
```

通常建议：

| 需求      | 推荐写法                                               |
| ------- | -------------------------------------------------- |
| 只读遍历    | `for item in v.iter()` 或 `for item in &v`          |
| 原地修改    | `for item in v.iter_mut()`  或 `for item in &mut v` |
| 取得元素所有权 | `for item in v`                                    |

## 4、数组、切片和字符串的遍历入口

数组拥有元素，因此数组可以按值遍历：

```rust
let arr = [1, 2, 3];

for item in arr {
    println!("{item}");
}
```

如果数组元素类型实现了 `Copy`，按值遍历时复制元素，原数组仍然可用：

```rust
let arr = [1, 2, 3];

for item in arr {
    println!("{item}");
}

println!("{arr:?}");
```

但如果数组元素不是 `Copy`，按值遍历会移动元素：

```rust
let arr = [String::from("a"), String::from("b")];

for item in arr {
    println!("{item}");
}

// println!("{arr:?}"); // 错误：arr 已被移动
```

切片本身不拥有元素，因此常见遍历方式是通过引用：

```rust
let v = vec![1, 2, 3];  
let slice = &v[..];  
  
for item in slice {  
	println!("{item}");  
}
```

字符串需要特别注意：`str` 没有通用的 `iter()` 方法，因为字符串可以按不同粒度遍历。

```rust
fn main() {  
    let s = "中文";  
  
    for b in s.bytes() {  
        println!("{b}");  
    }  
  
    for c in s.chars() {  
        println!("{c}");  
    }  
}
```

| `chars()`            | Unicode 标量值 |

| `split_whitespace()` | 按空白分隔出的片段   |

# 四、迭代器适配器

## 1、适配器的概念

当一个值已经是迭代器后，可以继续调用`Iterator`特征提供的许多默认方法，把它转换成另一个迭代器。这类方法称为**迭代器适配器**。

适配器的基本特点是：

| 特点     | 含义              |
| ------ | --------------- |
| 接收旧迭代器 | 通常按值接收 `self`   |
| 返回新迭代器 | 新迭代器包装旧迭代器      |
| 不立即执行  | 单独调用适配器不会立刻处理元素 |
| 可以链式组合 | 多个适配器可以组成数据处理管道 |
例如：

```rust
let iter = (1..=5)
	.map(|x| x * 2)
	.filter(|x| x % 3 == 0);
```

这段代码只是创建了一个新的迭代器，还没有真正开始计算。只有当后续调用 `next()`、`collect()`、`sum()`、`fold()` 等消费器时，整个迭代器链才会开始向前推进。

整个过程可以理解为：

```text
1..=5
  │
  ▼
map：每个元素乘 2
  │
  ▼
filter：只保留能被 3 整除的元素
```

## 2、常用迭代器适配器方法
### （1）map（逐项变换）

`map`用于对迭代器产生的每个元素调用闭包，并把闭包返回值作为新的迭代器的元素。

简化签名可以理解为：

```rust
fn map<B, F>
```

`map` 方法签名可简化理解为：

```text
fn map<B, F>(self, f: F) -> Iterator<Item = B>

where

Self: Sized,

F: FnMut(Self::Item) -> B;
```
说明：

闭包会接收迭代器的条目 `Self::Item`

返回值 `B` 作为新迭代器的条目类型

适配器按值接收 `self` ，因此要求 `Self: Sized` 。

标准库中， `map` 实际返回的是一个专门类型 `std::iter::Map<...>` ，这里用 `Iterator<Item = B>` 便于理解。

示例1：

将向量中的每个元素都转换为它的平方。
```rust
let v1 = vec![1, 2, 3];

let v2 = v1.iter()

.map(|x| x * x ) // x的类型是&i32，这里x * x自动会进行解引用

.collect::<Vec<i32>>();

println!("{:?}",v1);

println!("{:?}",v2);
```
示例2：

逐行遍历文本，并去掉每行前后的空白，返回一个新的修剪过的 `&str` 向量。
```rust
let text = " hello \n world \n i \n love \n rust \n".to_string();

let v: Vec<&str> = text.lines()

.map(str::trim)

.collect();

println!("{:#?}", v);
```
## 3、filter（按条件保留/丢弃）

`filter` 的作用是对迭代器的每个条目调用闭包进行判断：

若闭包返回 `true` ，保留该条目

若闭包返回 `false` ，丢弃该条目

这个判断闭包通常也称为 **谓词（predicate）** 。

`filter` 的签名如下：

```rust
fn filter<F>(self, f: F) -> impl Iterator<Item = Self::Item>

where

Self: Sized,

F: FnMut(&Self::Item) -> bool;
```
说明：

闭包参数是 `&Self::Item`

**新迭代器的产出的条目类型和旧迭代器相同**

只是某些条目被过滤掉了。

🔊

迭代器适配器的两点注意事项：

（1）仅仅在迭代器上调用适配器，只会得到一个新的迭代器， **它本身并不立刻消耗条目**

（2）迭代器适配器是一种 **零成本抽象** ，像 `map` 和 `filter` 等这类方法都是泛型方法，编译器会为具体类型生成专门代码，因此通常不会产生额外抽象开销

示例1：

保留向量中的偶数。
```rust
let v = vec![1, 2, 3, 4, 5];

let mut iter = v.into_iter()

.filter(|x| x % 2 == 0); // 这里x的类型为&i32，x % 2自动解引用

assert_eq!(iter.next(), Some(2));

assert_eq!(iter.next(), Some(4));

assert_eq!(iter.next(), None);
```
需要注意：传给 `filter` 的闭包接收的是 `&Self::Item` 。 **如果原迭代器本身产生的就是引用，那么闭包参数就会变成双重引用** 。

示例2：
```rust
let v = vec![1, 2, 3];

let mut iter = v.iter()

.filter(|x| **x > 1 ); // // x 的类型是 &&i32，因此需要两个 *

assert_eq!(iter.next(), Some(&2));

assert_eq!(iter.next(), Some(&3));
```
通常更清晰的做法是在参数位置结构一层或两层引用：
```rust
let v = vec![1, 2, 3];

let mut iter = v.iter()

.filter(|&x| *x > 1 ); // // x 的类型是 &i32

assert_eq!(iter.next(), Some(&2));

assert_eq!(iter.next(), Some(&3));
```
或者：
```rust
let v = vec![1, 2, 3];

let mut iter = v.iter()

.filter(|&&x| x > 1 ); // // x 的类型是i32

assert_eq!(iter.next(), Some(&2));

assert_eq!(iter.next(), Some(&3));
```
对于一个尚未被消费的迭代器而言， `iter.filter(f).next()` 和 `iter.find(f)` 在效果上是等价的：都会找到第一个使谓词为 `true` 的元素。
## 4、filter_map（过滤映射）

`filter_map` 可以理解为“ `map` + 丢弃部分条目”的组合。与 `map` 不同的是，它的闭包返回的不是 `B` ，而是 `Option<B>` ：

返回 `Some(b)` ：保留该条目，并把它映射为 `b`

返回 `None` ：丢弃该条目

其方法原型可简化为：

```rust
fn filter_map<B, F>(self, f: F) -> impl Iterator<Item = B>

where

Self: Sized,

F: FnMut<Self::Item> -> Option<B>;
```
示例：
```rust
use std::str::FromStr;

fn main() {

let text = "1\nfrond.25 289\n3.1415 estuary\n";

for number in text

.split_whitespace()

.filter_map(|s| f64::from_str(s).ok())

{

println!("{:4.2}", number);

}

}
```
说明：

`f64::from_str()` 尝试将字符串解析为 `f64` ，返回 `Result<f64, ParseFloatError>`

再调用 `ok()` 将 `Result<f64, ParseFloatError>` 变为 `Option<f64>`

解析成功时得到 `Some(v)` ，保留该值

解析失败时得到 `None` ，该条目被过滤掉

上述代码也可以用 `map + filter + map` 实现，但会更繁琐：
```rust
use std::str::FromStr;

fn main() {

let text = "1\nfrond.25 289\n3.1415 estuary\n";

for number in text.split_whitespace() // &str

.map(|s| f64::from_str(s)) // Result<f64, ParseFloatError>

.filter(|res| res.is_ok()) // 只保留Ok

.map(|r| r.unwrap()) // // 解包出 f64

{

println!("{:4.2}", number);

}

}
```
## 5、flatten（展平）

`flatten` 适配器会把“ **迭代器的每一个条目本身又是一个可迭代者** ”的结构，串联成一个连续迭代器。

其签名可以简化为：

```rust
fn flatten(self) -> impl Iterator<Item = <Self::Item as IntoIterator>::Item>

where

Self: Sized,

Self::Item: IntoIterator;
```
也就是说：

旧迭代器的每个条目必须实现 `IntoIterator`

`flatten` 会把这些小序列首尾相接，产生一个连续的大序列

示例：
```rust
// v 的结构为：[[1, 2], [3, 4], [5]]

let v = vec![

vec![1, 2],

vec![3, 4],

vec![5]

];

let v = v.into_iter().flatten().collect::<Vec<i32>>();

println!("{:?}",v);
```
事实上， `Option<T>` 也是一个 **可迭代者** ：

`Some(x)` 看作是一个只包含一个元素的序列

`None` 看作是空序列

因此，对于条目为 `Option<T>` 的迭代器，也可以调用 `flatten` ：
```rust
let v = vec![None, Some("day"), None, Some("one")];

let v2 = v.into_iter().flatten().collect::<Vec<&str>>();

println!("{:?}",v2);
```
结果中只保留了 `Some` 里的值。

同样， `Result<T, E>` 也实现了 `IntoIterator` ：

`Ok(x)` 看作单元素序列

`Err(e)` 看作空序列

因此，对 `Iterator<Item = Result<T, E>>` 调用 `flatten()` ，会自动丢弃所有 `Err` 并产生一个成功值流。
## 6、flat_map（展平映射）

`flat_map` 可以理解为 `map + flatten` 的组合。它会先把 **每个元素映射成一个可迭代者** ，再把这些可迭代者串联成一个连续迭代器。

原型可简化理解为：

```rust
fn flat_map<U, F>(self, f: F) -> impl Iterator<Item = U::Item>

where

Self: Sized,

F: FnMut(Self::Item) -> U,

U: IntoIterator;
```
这里闭包返回的不是单个值，而是一个可迭代者 `U` 。

示例：
```rust
use std::collections::HashMap;

fn main() {
```

## 7、take（取出）和take_while（当...时取出）

`take` 和 `take_while` 的作用是让一个迭代器“提前结束”。

其签名可以简化为：

```rust
fn take(self, n: usize) -> impl Iterator<Item = Self::Item>

where

Self: Sized;

fn take_while<P>(self, predicate: P) -> impl Iterator<Item = Self::Item>

where

Self: Sized,

P: FnMut(&Self::Item) -> bool;
```

示例：

```rust
}
```

## 9、peekable（窥探）

普通迭代器一旦调用 `next()` ，就会把“下一个条目”消耗掉（推进迭代器位置）。但很多场景需要先看一眼再决定怎么操作。例如，解析连续数字字符时，希望遇到第一个非数字字符就停止，但不能把该非数字字符消耗掉，因为后续还要处理它。此时普通的 `next()` 就不够用了，因为当 `next()` 判断出非数字字符，此时该数字字符已经被丢弃了。

在 Rust 中， `peekable` 是 `Iterator` 的一个适配器方法。对任意迭代器调用它后，会返回一个新的 **包装器类型** ：

```text
fn peekable(self) -> std::iter::Peekable<Self>

where

Self: Sized;
```
注意： `Peekable<Self>` 内部持有原迭代器 `Self` ，它本身仍然实现了 `Iterator<Item= Self::Item>` ，但它额外提供了 `peek()` 方法。

`peek()` 方法可以理解为：
```rust
fn peek(&mut self) -> Option<&Self::Item>;
```
其返回含义：

若底层迭代器还有条目：返回 `Some(&next_item)`

若底层迭代器已耗尽：返回 `None`

`peek()` 返回的是引用，因此调用者可以看到下一项，但不会把它移动出来。如果原迭代器本身产生的就是引用，那么 `peek()` 返回的就会是“引用的引用”。

事实上，调用 `peek()` 时，如果底层迭代器还有数据，它 **会从底层迭代器中取出一个条目缓存起来，返回对该缓存条目的引用** 。之后再调用 `next()` 时，会优先吐出缓存中的这个条目。

因此，“ `peek()` 不消耗条目”的本质并不是完全没动底层迭代器，而是 **提前取出后把它存进了** `Peekable` **自己的缓存里** ，让外部表现得像没消耗一样。

示例：
```rust
let iter = vec![1,2,3].into_iter();

let mut iter2 = iter.peekable();

assert_eq!(Some(&1), iter2.peek());

assert_eq!(Some(&1), iter2.peek());

assert_eq!(Some(1), iter2.next());

assert_eq!(Some(&2), iter2.peek());
```
连续调用 `peek()` ，返回都是同一个值的引用，除非显式再调用 `next()` 消耗掉。

使用 `Peekable` 迭代器的典型应用场景就是从字符串中解析出数字：
```rust
use std::iter::Peekable;

fn parse_number<I>(mut tokens: Peekable<I>) -> u32

where I: Iterator<Item = char>

{

let mut n = 0;

loop {

match tokens.peek() {

Some(ch) if ch.is_ascii_digit() => {

n = n * 10 + ch.to_digit(10).unwrap();

tokens.next(); // 真正消耗这个数字字符

}

_ => return n,

}

}

}

fn main() {

let input = "123456789";

let n = parse_number(input.chars().peekable());

println!("{}", n);

}
```
这里的思路是：

● 用 `peek()` 看下一字符是不是数字

● 如果是数字：更新数值，并用 `next()` 真正消费它

● 如果不是数字或已经结束：停止解析，并把这个非数字字符保留在迭代器里，供后续处理
## 10、fuse（保险丝）

`Iterator` 特征并没有规定一旦 `next()` 返回 `None` 后，再次调用 `next()` 必须怎么表现。大多数迭代器会继续返回 `None` ，但并非所有迭代器都如此。

因此，泛型代码不能盲目依赖“返回一次 `None` 后，后续返回永远 `None` ”。为了消除这种不确定性，可使用 `fuse` 适配器方法。该方法会把任意迭代器包装成一个一旦第一次返回 `None` ，后续永远只返回 `None` 的迭代器。

示例：

```rust
struct Test(bool);

impl Iterator for Test {

type Item = &'static str;

fn next(&mut self) -> Option<Self::Item> {

if self.0 {

self.0 = false;

Some("last item")

} else {

self.0 = true;

None

}

}

}

fn main() {

let mut t = Test(true);

assert_eq!(t.next(), Some("last item"));

assert_eq!(t.next(), None);

assert_eq!(t.next(), Some("last item"));

assert_eq!(t.next(), None);

}
```
这里 `test.next()` 的结果是交替出现的，这说明原始迭代器并不是见到 `None` 就永远结束。

可以用 `fuse` 方法修正，其原型如下：
```text
fn fuse(self) -> Fuse<Self>

where

Self: Sized,

{

Fuse::new(self)

}
```
修正的示例代码如下：
```rust
struct Test(bool);

impl Iterator for Test {

type Item = &'static str;

fn next(&mut self) -> Option<Self::Item> {

if self.0 {

self.0 = false;

Some("last item")

} else {

self.0 = true;

None

}

}

}

fn main() {

let mut t = Test(true).fuse();

assert_eq!(t.next(), Some("last item"));

assert_eq!(t.next(), None);

assert_eq!(t.next(), None);

assert_eq!(t.next(), None);

}

`fuse()` 在处理来源不明的迭代器时很有用。与其假定所有迭代器都“行为良好”，不如直接加一个“保险丝”。
```

## 11、可逆迭代器与rev

普通迭代器只能通过 `next()` 从前往后取元素。然而，对于很多容器，例如向量、切片等，其元素天然也可以从后往前取。能做到这一点的迭代器，称为 **双端迭代器（double-ended iterator）** 。

Rust使用 `std::iter::DoubleEndedIterator` 特征描述这种能力，它在 `Iterator` 的基础上额外要求实现：

```rust
trait DoubleEndedIterator: Iterator {

fn next_back(&mut self) -> Option<Self::Item>;

}
```
可以把它想象成两根手指从两端往中间走：

调用 `next()` ：头指针向后一步

调用 `next_back()` ：尾指针向前一步

当两端指针相遇或交错时，说明元素已经取完，之后两边都返回 `None`

示例：
```rust
let v = ["hello", "world", "rust"];

let mut iter = v.into_iter();

assert_eq!(Some("hello"), iter.next());

assert_eq!(Some("rust"), iter.next_back());

assert_eq!(Some("world"), iter.next());

assert_eq!(None, iter.next_back());
```
并不是所有的迭代器都可以实现 `DoubleEndedIterator` 。例如，从通道 `Receiver` 中不断接收其他线程发送的消息，这种迭代器就无法预先知道最后一个元素是什么，因此只能向前 `next()` ，无法 `next_back()` 。

如果迭代器是双端迭代器，那么就可以调用 `rev()` 适配器将其方向反转，原型如下：
```rust
fn rev(self) -> impl Iterator<Item = Self::Item>

where

Self: Sized + DoubleEndedIterator;
```
示例：
```rust
let v = ["hello", "world", "rust"];

let mut iter = v.into_iter().rev(); // 反转

assert_eq!(Some("rust"), iter.next());

assert_eq!(Some("world"), iter.next());

assert_eq!(Some("hello"), iter.next());
```
**很多适配器方法（如** `map` **、** `filter` **等）在应用于双端迭代器后，返回的新迭代器通常仍然是双端迭代器** 。
## 12、inspect（检查）

Rust中常有如下链式写法：

```rust
iter.map(...).filter(...).flat_map(...).collect();
```
当链路很长时，可能想知道：

`map` 之后数据长什么样

`filter` 之后还剩多少

`flat_map` 展开后是不是符合预期

这时如果把流水线拆成多个变量会打断原始结构，而 `inspect()` 正是用来做这种“中途观察”的。

`inspect` 的核心行为是：

对迭代器产生的每个条目，调用一次传入的闭包

但仍然把该条目原封不动地继续传给后续迭代器

它的闭包参数是 `&Item` ，因此适合做“观察型”操作，如打印、调试、断言等，而不会改变迭代结果。

示例：
```rust
let upper_case = "große".chars()

.inspect(|c| println!("before: {:?}", c))

.flat_map(|c| c.to_uppercase())

.inspect(|c| println!("after: {:?}", c))

.collect::<String>();

println!("upper_case: {:?}", upper_case);
```
这里：

● 第一个 `inspect` 打印原始字符

● `flat_map(char::to_uppercase)` 做大写转换

● 第二个 `inspect` 打印转换后的字符流

● 最终 `collect::<String>()` 收集成字符串
## 13、chain（链接）

`chain` （链接）适配器会把一个迭代器追加到另一个迭代器之后，也就是把两个序列首尾连接成一个新序列。

其签名可简化理解为：

```rust
fn chain<U>(self, other: U) -> impl Iterator<Item = Self::Item>

where

Self: Sized,

U: IntoIterator<Item = Self::Item>;
```
注意：参数 `other` 不必已经是迭代器；只要它实现了 `IntoIterator` 且元素和 `Self::Item` 一致，即可作为 `chain` 的右侧输入。

示例：
```rust
let v =(0..4).chain([4, 5, 6])

.collect::<Vec<_>>();

assert_eq!(v, [0, 1, 2, 3, 4, 5, 6]);
```
如果 `chain` 的两个底层迭代器都是双端迭代器，那么结果迭代器通常也仍然是双端的：
```rust
let v =(0..4).chain([4, 5, 6])

.rev()

.collect::<Vec<_>>();

assert_eq!(v, [6, 5, 4, 3, 2, 1, 0]);
```

```text

```
得到的是一个新的迭代器，其条目是二元组：

第一个是 `usize` 类型的索引，从0开始递增

第二个是原迭代器条目

示例：

## 15、zip（拉合）

`zip` 适配器会把两个迭代器并排拉合成一个新的迭代器。新迭代器每次从左右两个底层迭代器各取出一个值，组成一个二元组。

例如，可以把无限范围 `0..`和一个迭代器拉合，得到和 `enumerate` 更一般化的形式。

示例：

```rust
let names = ["Tom", "Jerry", "Bob"];

`zip` 的参数也不一定必须已经是迭代器，只要它是可迭代者即可：
```

## 16、by_ref（按引用）

多数迭代器适配器（如 `map` 、 `take_while` 、 `skip_while` 等）都会取得底层迭代器的所有权。一旦这样做，原来的迭代器变量就被移动走了，不能再继续使用。

但有时想分两段消费一个迭代器：先处理前一段，再继续处理剩余部分。这时候就可以使用 `by_ref()` 方法。

`by_ref` 方法的本质是：返回对当前迭代器的可变借用 `&mut self` ，这样后续适配器拿走的是对迭代器的可变引用，而是迭代器本身。

示例：

```rust
let message = "To: jimb\r\n\

From: id\r\n\

\r\n\

Oooooh, donuts!!\r\n";

let mut lines = message.lines();

println!("Headers");

println!("{}", header);

}

println!("\nBody");

for body in lines {

println!("{}", body);

}

`lines.by_ref()` 借出 `lines` 的可变引用

`takes_while()` 消耗的是这个引用包装的迭代器
```
因此 `lines` 本体没有被移走，还可以继续用于遍历正文部分
## 17、cloned（克隆）和copied（复制）

很多常见迭代器会产生引用，例如：

```rust
let a = ['1', '2', '3'];

let iter = a.iter(); // Item = &char
```
但有时候希望得到的是值本身，而不是引用，这时候就可以使用 `cloned()` 和 `copied()` 。
### （1）cloned

`cloned()` 的语义可以近似理解为：

```text
iter.map(|item| item.clone())
```
也就是说：

输入通常是 `&T`

输出通常是 `T`

要求 `T: Clone`

示例：
```rust
let s1 = vec!["1".to_string(), "2".to_string(), "3".to_string()];

let s2: Vec<String> = s1.iter().cloned().collect();

println!("{:?}", s1);

println!("{:?}", s2);
```
### （2）copied

`copied()` 的思想与 `cloned()` 类似，但要求更严格：元素类型必须实现 `Copy` 。

其语义可以近似理解为：

```text
iter.map(|r| *r)
```
也就是说，它只是从引用中复制出值本身。

示例：
```rust
let v = vec![1, 2, 3];

let v2: Vec<i32> = v.iter().copied().collect();

assert_eq!(v, v2);
```
这里 `i32` 是 `Copy` 类型，因此 `copied()` 只是把 `&i32` 解引用复制为 `i32` 。

需要注意：

所有实现了 `Copy` 的类型也一定实现了 `Clone`

因此 `cloned()` 更通用

但如果条目类型是简单的 `Copy` 类型，那么 `copied()` 往往更明确，也通常更高效
## 18、cycle（循环）

`cycle()` 适配器会把一段有序序列变成一个无限重复的序列。它会保存迭代器的初始状态，并在每次走到结尾时重新从头开始。因此， **调用** `cycle()` **的迭代器类型本身必须实现** `Clone` **，以便在需要时恢复初始状态** 。

示例：

```rust
let dirs = ["North", "East", "South", "West"];

let mut spin = dirs.into_iter().cycle();

assert_eq!(spin.next(), Some("North"));

assert_eq!(spin.next(), Some("East"));

assert_eq!(spin.next(), Some("South"));

assert_eq!(spin.next(), Some("West"));

assert_eq!(spin.next(), Some("North"));

assert_eq!(spin.next(), Some("East"));

assert_eq!(spin.next(), Some("South"));

assert_eq!(spin.next(), Some("West"));
```
# 五、消耗迭代器

## 1、迭代器消费器的概念

前面介绍的大多是“创建迭代器”和“适配迭代器”的方法。而在 `Iterator` 特征中，还有一类方法称为 **消费器（consumer）** 。 **它们会真正消耗迭代器，并计算出一个最终结果，例如数字、集合、布尔值等** 。

这些方法的内部本质都是在不断调用 `next()` ，直到得到所需结果或迭代器结束。

## 2、collect（收集）

`collect()` 是最常见的消费器之一，它会把迭代器产生的条目收集到 **某种目标容器** 中，只要该容器实现了 `FromIterator` 。

示例：

```rust
let v = (1..=5).map(|x| x * x).collect::<Vec<_>>();

assert_eq!(v, vec![1, 4, 9, 16, 25]);

`collect()` **的目标类型往往需要turbofish明确指出，否则编译器无法推断** 。
```
它不仅能收集成 `Vec<T>` ，还常用于：

`String`

`HashMap<K, V>`

`HashSet<T>`

...
## 3、count（计数）

`count()` 会从迭代器中不断提取条目，直到迭代器返回 `None` ，最终返回条目总数。

示例：

```rust
use std::io::prelude::*;

fn main() {

let stdin = std::io::stdin();

println!("{}", stdin.lock().lines().count());

}
```
注意事项：

`std::io::stdin()` 返回的是全局共享的标准输入句柄 `Stdin` ， `lock()` 方法用户获取一个锁定的输入句柄，防止多处同时读取造成混乱

`lines()` 是 `BufRead` 特征的方法，它会返回一个迭代器，该迭代器会产生每一行字符串。需要把 `BufRead` 引入作用域；导入 `use std::io::prelude::*;`也可以，因为其中包含了 `BufRead` 。

当然，对于很多集合类型而言，它们本身就有 `len()` 方法，因此无需为了计数而先构造迭代器再调用 `count()` 。
## 4、sum（求和）和product（乘积）

`sum()` 和 `product()` 分别计算迭代器条目之和与条目之积。它们都是消费器，本质上内部不断调用 `next()` 并累积结果：

`sum()` 从加法单位元开始（例如整数的 `0` ）

`product()` 从乘法单位元开始（例如整数的 `1`)

以 `sum()` 为例，其简化定义如下：

```text
fn sum<S>(self) -> S

where

Self: Sized,

S: Sum<Self::Item>

{

Sum::sum(self)

}
```
说明：

`sum()` 是泛型函数，需要知道最终返回值类型 `S`

返回值类型不一定必须和迭代器条目类型相同

`S: Sum<Self::Item>` 表示： `S` 必须知道如何把一个 `Iterator<Item = Self::Item>` 里的值求和成自己。

`Sum` 特征核心定义可以理解为：
```rust
trait Sum<A = Self>: Sized {

fn sum<I: Iterator<Item = A>>(iter: I) -> Self;

}
```
示例1:
```rust
fn triangle(n: u64) -> u64 {

(1..=n).sum()

}

fn factorial(n: u64) -> u64 {

(1..=n).product()

}

fn main() {

assert_eq!(triangle(3), 6);

assert_eq!(factorial(4), 24);

}
```
示例2：
```rust
fn main() {

let v = vec![1, 2, 3];

let iter = v.iter(); // 迭代器元素类型为&i32

let s = iter.sum::<i32>(); // i32实现了Sum<&i32>

println!("{}", s);

}
```
## 5、min（最小）和max（最大）

`min()` 和 `max()` 会分别返回迭代器中的最小条目和最大条目。它们要求条目类型实现 `std::cmp::Ord` ，这样条目之间才能进行全序比较。

两个方法的返回值都是 `Option<Self::Item>` ，以便在迭代器为空时返回 `None` 。

示例：

```text
assert_eq!([-2, 0, 3, -5, 1].iter().max(), Some(&3));

assert_eq!([-2, 0, 3, -5, 1].iter().min(), Some(&-5));
```
需要注意的是， `f32` 和 `f64` 类型只实现了 `PartialOrd` ，没有实现 `Ord` ，因此不能直接对浮点数迭代器调用 `min()` 和 `max()` 。原因在于浮点数中存在 `NaN` ， **它不满足普通的全序比较规则** 。
## 6、min_by（据...最小）和max_by（据...最大）

`min_by()` 和 `max_by()` 会根据用户提供的比较函数决定“谁更小”或“谁更大”。

以 `max_by()` 为例，其函数原型可以简化为：

```text
fn max_by<F>(self, compare: F) -> Option<Self::Item>

where

Self: Sized,

F: FnMut(&Self::Item, &Self::Item) -> std::cmp::Ordering;
```
比较函数需要返回 `std::cmp::Ordering` ， `Ordering` 是一个枚举类型：
```rust
pub enum Ordering {

Less, // 左值小于右值

Equal, // 左值等于右值

Greater, // 左值大于右值

}
```
示例：
```rust
use std::cmp::Ordering;

fn cmp(lhs: &f64, rhs: &f64) -> Ordering {

lhs.partial_cmp(rhs).unwrap()

}

fn main() {

let numbers = [1.0, 3.0, 2.0];

assert_eq!(numbers.iter().copied().max_by(cmp), Some(3.0));

assert_eq!(numbers.iter().copied().min_by(cmp), Some(1.0));

let numbers = [1.0, 4.0, 2.0, f64::NAN];

// numbers.iter().copied().max_by(cmp); // 会 panic

}
```
这里之所以可能 panic，是因为当参与比较的值中含有 `NaN` 时， `partial_cmp()` 会返回 `None` ， `unwrap()` 就会触发 panic。

因此，对于浮点数：

● 若能保证没有 `NaN` ，可以这样写

● 若不能保证，应该先过滤掉 `NaN`
```rust
assert_eq!(numbers.iter().copied().filter(|x|!x.is_nan()).max_by(cmp), Some(4.0));
```
## 7、min_by_key（据键最小）和max_by_key（据键最大）

有时候不想直接比较条目自身，而是想根据某个键来比较，此时可以使用 `min_by_key()` 和 `max_by_key()` 。

以 `max_by_key()` 为例，其签名可以简化理解为：

```text
fn max_by_key<B: Ord, F>(self, f: F) -> option<Self::Item>

where

Self: Sized,

F: FnMut(&Self::Item) -> B;
```
它们的工作方式是：

对每个条目调用闭包 `f(&item)` 得到一个键 `B`

再用键 `B` 的顺序来决定哪个条目最小或最大

最终返回的仍然是原始条目，而不是键

示例：
```rust
use std::collections::HashMap;

fn main() {

let mut populations = HashMap::new();

populations.insert("Portland", 583_776);

populations.insert("Fossil", 449);

populations.insert("Greenhorn", 2);

populations.insert("Boring", 7_762);

populations.insert("The Dalles", 15_340);

assert_eq!(populations.into_iter().max_by_key(|&(_name, population)| population),

Some(("Portland", 583_776)));

}
```
## 8、对条目序列进行比较

字符串、数组、切片、向量等值本身，通常可以直接使用 `<` 、 `>` 、 `==` 进行比较，前提是其中元素类型实现了对应的特征，例如：

`&str` 的比较按字典序逐字符进行

`Vec<T>` 、 `[T]` 的比较按逐元素字典序进行

示例：

```rust
let v1 = vec![1, 2, 3];

let v2 = vec![1, 2, 4];

assert!(v1 < v2);
```
但迭代器本身不能直接使用这些运算符比较，因为迭代器表示的是按需产生值的过程，而不是一个一次性静态值。为此，Rust迭代器提供了一组专门的方法来比较“条目序列”：

相等比较： `eq` 、 `ne`

有序比较： `lt` 、 `le` 、 `gt` 、 `ge`

直接得到顺序结果： `cmp` 、 `partial_cmp`

这些方法的行为是：从两个迭代器中成对取出条目，按字典序逐个比较，直到分出胜负或结束。

示例：
```rust
let packed_rust = "hello world rust";

let spaced_rust = "hello world rust";

let packed_c = "hello world c";

assert!(packed_rust!= spaced_rust);

assert!(packed_rust.split_whitespace().eq(spaced_rust.split_whitespace()));

assert!(packed_rust.split_whitespace().gt(packed_c.split_whitespace()));
```
## 9、any（任意）和all（全部）

`any()` 和 `all()` 都接受一个闭包，对闭包里的元素逐个判断，并返回 `bool` ：

`any(pred)` ：主要存在至少一个元素使 `pred(element)` 为 `true` ，就返回 `true`

`all(pred)` ：只有当所有元素都使 `pred(element)` 为 `true` ，才返回 `true`

它们都具有短路行为：

`any()` 找到第一个满足条件的元素后立刻停止

`all()` 找到第一个不满足条件的元素后立刻停止

示例：

```rust
let id = "Iterator";

assert!(id.chars().any(char::is_uppercase));

assert!(!id.chars().all(char::is_uppercase));
```
## 10、position（位置）和rposition（右起位置）

`position()` 会针对迭代器的每个条目调用闭包，并返回第一个使闭包返回 `true` 条目的索引。若没找到，返回 `None` 。

示例：

```rust
let s = "hello";

assert_eq!(s.chars().position(|c| c == 'e'), Some(1));

assert_eq!(s.chars().position(|c| c == 'a'), None);

`rposition()` 与之类似，只不过从右侧开始搜索。
```
虽然 `rposition()` 也是 `Iterator` 上的方法，但调用它的类型还必须额外实现：

`DoubleEndedIterator` ：因为要从右往左找

`ExactSizeIterator` ：因为它需要精确知道剩余长度，从而给出正确索引

`ExactSizeIterator` 的定义可简化为：
```rust
trait ExactSizeIterator: Iterator {

fn len(&self) -> usize;

fn is_empty(&self) -> bool;

}
```
注意： `len()` **返回的是当前未被消耗掉的条目数** 。

示例：
```rust
let v = vec![1, 2, 3, 4, 5];

let mut iter = v.iter();

println!("{}", iter.len()); // 5

iter.next();

println!("{}", iter.len()); // 4
```
并不是所有迭代器都能实现 `ExactSizeIterator` 。例如，有些迭代器无法在不额外工作的前提下精确知道还剩多少个条目，因此就不会实现它。

**rposition** 方法示例：
```rust
let s = b"hello";

assert_eq!(s.iter().rposition(|&b| b == b'l'), Some(3));

assert_eq!(s.iter().rposition(|&b| b == b'a'), None);
```
## 11、fold（折叠）和右起折叠（rfold）

`fold()` 是一个非常通用的消费器，用于把某个条目序列累积成某个结果。给定一个初始累加器和闭包， `fold()` 会反复把“当前累加器”和“下一条目”传入闭包，闭包返回的新值再作为新的累加器，继续处理下一个条目。

如果序列为空，则 `fold()` 直接返回初始累加器。

示例：

```rust
let a = [5, 6, 7, 8, 9, 10];

assert_eq!(a.iter().fold(0, |acc, _| acc + 1), 6); // 计数

assert_eq!(a.iter().fold(0, |acc, x| acc + x), 45); // 求和

assert_eq!(a.iter().fold(1, |acc, x| acc * x), 151200); // 乘积

assert_eq!(a.iter().copied().fold(i32::MIN, std::cmp::max), 10); // 求最大值

`rfold()` 与 `fold()` 基本相同，但要求底层迭代器为双端迭代器，它会从后向前处理条目。
```
示例：
```rust
let words = ["hello", "world", "rust"];

assert_eq!(words.iter().rfold(String::new(), |acc, x| acc + x + " "),

"rust world hello ");
```
