# 一、概述

智能指针是一类“像指针一样间接访问数据，但额外承担所有权、资源管理或运行时检查”的类型。

Rust 中最常见的指针形式是**引用**：

```rust
let x = 10;
let r = &x;
```

**引用本质上是对已有数据的借用，不拥有数据**。它的核心语义不是保存地址，而是临时访问某个值，并受借用规则约束。

智能指针与引用又不同，它们通常是结构体类型，除了保存指向数据的指针外，还可能额外保存元数据或管理逻辑。例如，`String`和`Vec<T>`本质上都是智能指针，它们内部都持有指向堆区数据的指针，还额外保存了长度、容量元数据。`String`还保证其内容始终都是合法的UTF-8字节。

智能指针通常会实现一些特殊`Trait`，其中最重要的是：

| Trait      | 作用               |
| ---------- | ---------------- |
| `Deref`    | 让智能指针可以像引用一样解引用  |
| `DerefMut` | 让智能指针支持可变解引用     |
| `Drop`     | 让值离开作用域时自动执行清理逻辑 |
并不是所有智能指针都必须同时实现这些 trait，但很多常见智能指针都依赖它们提供“像引用一样使用”和“自动释放资源”的能力。

# 二、Box\<T>与堆分配

## 1、Box\<T>的基本使用

`Box<T>`是Rust中最基础的**拥有型指针**。它会把数据存储在堆上，而`Box<T>`本身作为一个固定大小的指针值存储在栈上。

示例：

```rust
fn main() {
    let a = Box::new(3);

    println!("{}", a);
    println!("{}", *a + 1);
}
```

这里：

- `Box::new(3)`会在堆上分配一个`i32`
- `a`是一个`Box<i32>`，拥有堆上那个`i32`
- `*a`可以解引用到内部的`i32`
- 当`a`离开作用域时，堆上的`i32`被自动释放

`Box<T>`的核心是提供一层堆分配的间接访问。它本身很轻量，但使用它会带来一次堆分配和一次间接访问。

## 2、较大数据的移动

当一个值较大时，就可以把它放到堆上。这样移动变量时，移动的是栈上的`Box<T>`指针值，而不是直接移动整块大数据。

```rust
fn main() {
	let arr = Box::new([0; 1000]);
	
	println!("{}", arr.len());
	
	let arr2 = arr;
	
	println!("{}", arr2.len());
}
```

`[0; 1000]` 被存储在堆上，`arr` 本身是一个 `Box<[i32; 1000]>`。

执行：

```rust
let arr2 = arr;
```

发生的是所有权移动，不是深拷贝。移动之后，堆上的数组仍然只有一份，`arr` 失效，`arr2` 成为新的所有者。

`Box<T>`不是`Copy`类型，所以这里不是复制智能指针，而是移动所有权。

## 3、递归类型的大小确定

Rust编译器必须在编译期知道每个类型的大小。如果一个类型直接包含自己，编译器就无法确定其大小。

下面的定义无法直接通过编译：

```rust
enum List {
	Cons(i32, List),
	Nil
}
```

原因是`List`里面又直接包含一个`List`：

```text
List
└── Cons(i32, List)
               └── Cons(i32, List)
                              └── ...
```

这种结构会导致类型大小无限递归。

编译器编译报错：

![[Image 76.png|400]]

使用 `Box<T>` 可以打断这种无限递归：

```rust
enum List {  
    Cons(i32, Box<List>),  
    Nil  
}  
  
use crate::List::{Cons, Nil};  
  
  
fn main() {  
    let list = Cons(  
        1,  
        Box::new(Cons(  
            2,  
            Box::new(Cons(  
                3,   
                Box::new(Nil)  
            ))  
        ))  
    );  
}
```

此时 `Cons` 中保存的不是完整的 `List`，而是一个 `Box<List>`。`Box<List>` 本身大小固定，因此 `List` 的大小也可以在编译期确定。

## 4、Trait对象的存放

Trait对象`dyn Trait`表示某个实现了该Trait的具体类型。由于具体类型可能不同，`dyn Trait`本身是动态大小类型，通常需要放在指针后面使用，例如`&dyn Trait`，`&mut dyn Trait`或者`Box<dyn Trait>`。

```rust
trait Draw {  
	fn draw(&self);  
}

struct Button {
	id: u32,
}

impl Draw for Button {  
	fn draw(&self) {  
		println!("Draw Button {}", self.id);  
	}  
}

struct Select {  
	id: u32,  
}  
  
impl Draw for Select {  
	fn draw(&self) {  
		println!("Draw Select {}", self.id);  
	}  
}


fn main() {
	
	let elems: Vec<Box<dyn Draw>> = vec![
		Box::new(Button { id: 1 }),
		Box::new(Select { id: 2 }),
	];
	
	for elem in elems {  
		elem.draw();  
	}

}
```

`Vec<Box<dyn Draw>>` 中的每个元素都是一个 `Box<dyn Draw>`。它们可以指向不同的具体类型，只要这些类型都实现了 `Draw`。

不能直接写成 `Vec<dyn Draw>`，因为 `dyn Draw` 的大小在编译期不可知；而 `Box<dyn Draw>` 的大小固定，所以可以放进 `Vec`。

## 5、智能指针的内存布局

`Box<T>` 在栈只保存一个指向数据的指针，但 `Vec<T>` 和 `String` 在栈上不只是一个指针，还包含长度和容量信息。

例如 `Vec<i32>` 的内存布局如下：

```text
(stack) (heap)

┌───────────────────────┐ ┌───┬───┬───┬───┐

│ ptr │ len=4 │ cap=4 │──→ │ 1 │ 2 │ 3 │ 4 │

└───────────────────────┘ └───┴───┴───┴───┘
```
而 `Vec<Box<i32>>` 则是：
```text
(heap)

(stack) (heap) ┌───┐

┌──────┐ ┌───┐ ┌─→│ 1 │

│ vec2 │──→│B1 │─┘ └───┘

└──────┘ ├───┤ ┌───┐

│B2 │───→│ 2 │

├───┤ └───┘

│B3 │─┐ ┌───┐

├───┤ └─→│ 3 │

│B4 │─┐ └───┘

└───┘ │ ┌───┐

└─→│ 4 │

└───┘
```
示例：
```rust
fn main() {

let v = vec![Box::new(1), Box::new(2)];

let first = &v[0];

let second = &v[1];

let sum = **first + **second;

println!("sum: {}", sum);

}
```
注意：

`first` 和 `second` 的类型是 `&Box<i32>`

这里使用 `&` 借用元素，避免把 `Box<i32>` 从 `Vec` 中移出

`**first` 表示“概念上两次解引用”：

第一次从 `&Box<i32>` 访问到 `Box<i32>`

第二次从 `Box<i32>` 访问到里面的 `i32`
# 三、Deref特征

智能指针与普通结构体的重要区别之一在于：它们常常实现了 `Deref` 和 `Drop` 。其中， `Deref` 允许一个类型在很多场景下表现得像一个引用，从而支持 `解引用` 行为。

## 1、常规引用

常规引用是一个指向某个值的借用。

示例：

```rust
fn main() {

let x = 5;

let y = &x;

assert_eq!(5, x);

assert_eq!(5, *y);

}
```
这里：

`y` 是 `x` 的引用

`*y` 表示沿着引用取到它指向的值

如果写成：
```rust
assert_eq!(5, y);
```
会报错，因为：

`5` 是 `i32`

`y` 是 `&i32`

两者类型不同，不能直接比较。
## 2、像引用一样使用Box<T>

`Box<T>` 可以像普通引用一样，通过 `*` 解引用得到内部的值。

示例：

```rust
let x = Box::new(5);

assert_eq!(5, *x);
```
## 3、实现Deref特征

标准库中， `std::ops::Deref` 的定义如下：

```rust
trait Deref {

type Target =?Sized;

fn deref(&self) -> &Self::Target;

}
```
为了演示 `Deref` 的功能，自定义一个 `MyBox<T>` ：
```rust
struct MyBox<T>(T);

impl<T> MyBox<T>{

fn new(v: T) -> Self {

Self(v)

}

}
```
此时使用它：
```rust
fn main() {

let x = MyBox::new(5);

assert_eq!(5, *x);

}
```
会报错，因为 `MyBox<T>` 没有实现 `Deref` ，所以不能对它使用解引用运算。

为其实现 `Deref` ：
```rust
use std::ops::Deref;

struct MyBox<T>(T);

impl<T> MyBox<T> {

fn new(v: T) -> Self {

Self(v)

}

}

impl<T> Deref for MyBox<T> {

type Target = T;

fn deref(&self) -> &Self::Target {

&self.0

}

}

fn main() {

let x = MyBox::new(5);

assert_eq!(5, *x);

}
```
此时代码即可通过编译。

从概念上讲， `*x` 会调用 `deref()` 取得一个引用，再进行普通解引用。可以近似理解为：
```text
*(x.deref())
```
## 4、函数和方法中的Deref强制转换

Deref强制转换（ **deref coercion** ）是Rust提供的一套便利能力：

**当某个类型实现了** `Deref` **，那么它的引用可以在函数传参、方法调用等场景中，自动转换为目标引用类型** 。

最典型的例子就是 `&String` 自动转换成了 `&str` ，这是因为 `String` 实现了 `Deref<Target=str>` 。

示例：

```rust
fn print_s(s: &str) {

println!("{s}");

}

fn main() {

let s = String::from("hello");

print_s(&s); // 传入&String

}
```
这种Deref强制转换可以持续进行：
```rust
fn print_s(s: &str) {

println!("{}", s);

}

fn main() {

let s = Box::new(String::from("hello"));

print_s(&s); // &Box<String> => &String => &str

}
```
## 5、DerefMut特征

与 `Deref` 特征对应，Rust还提供了 `DerefMut` ，用于支持可变引用的解引用。

`DerefMut` 特征的定义简化如下：

```rust
trait DerefMut: Deref {

fn deref_mut(&mut self) -> &mut Self::Target;

}
```
示例：
```rust
use std::ops::{Deref, DerefMut};

struct MyBox<T>(T);

impl<T> MyBox<T> {

fn new(v: T) -> Self {

Self(v)

}

}

impl<T> Deref for MyBox<T> {

type Target = T;

fn deref(&self) -> &Self::Target {

&self.0

}

}

impl<T> DerefMut for MyBox<T> {

fn deref_mut(&mut self) -> &mut Self::Target {

&mut self.0

}

}

fn main() {

let mut s = MyBox::new(10);

*s = 11; // 修改

}
```
## 6、触发Deref强制转换的三种情况

Rust在函数参、方法调用等上下文中，会根据以下规则自动执行 `Deref强制转换` ：

当 `T: Deref<Target=U>` 时，可以把 `&T` 转换成 `&U`

当 `T: DerefMut<Target = U>` 时，可以把 `&mut T` 转换为 `&mut U`

当 `T: Deref<Target = U>` 时，可以把 `&mut T` 转换为 `&U`

第三种情况表示： **可变引用可以降级为不可变引用** 。

示例：

```rust
fn print(s: &str) {

println!("{}", s);

}

fn main() {

let mut s = String::from("hello");

print(&mut s); // &mut String -> &str

}
```
# 四、Drop 特征

## 1、Drop定义

在C这类没有 GC 的语言中，程序员通常需要手动管理资源释放；一旦忘记释放，就可能造成内存泄漏或其他安全问题。

Rust 采用 **RAII** （资源获取即初始化）的方式管理资源：当一个值离开作用域时，编译器会自动执行清理逻辑。若某个类型希望在销毁时执行自定义逻辑，就可以实现 `Drop` 特征。

因此， `Drop` 的作用是：

在值生命周期结束时自动执行清理代码

典型场景包括：关闭文件、释放堆内存、断开连接、打印日志等

在标准库中， `Drop` 特征定义如下：

```rust
trait Drop {

fn drop(&mut self);

}
```
只需要实现一个方法： **当值即将被销毁时，Rust 会自动调用该方法** 。
## 2、实现Drop

示例：

```rust
struct Foo {

data: String,

}

impl Drop for Foo {

fn drop(&mut self) {

println!("Drop Foo with data: {}", self.data);

}

}

fn main() {

let _f = Foo {

data: "Hello".to_string(),

};

println!("created Foo");

}
```

## 3、Drop的顺序

示例：

```rust
struct HasDrop1;

struct HasDrop2;

impl Drop for HasDrop1 {

fn drop(&mut self) {

println!("Drop HasDrop1");

}

}

impl Drop for HasDrop2 {

fn drop(&mut self) {

println!("Drop HasDrop2");

}

}

struct HasTwoDrops {

one: HasDrop1,

two: HasDrop2,

}

impl Drop for HasTwoDrops {

fn drop(&mut self) {

println!("Drop HasTwoDrops")

}

}

struct Foo {

data: String,

}

impl Drop for Foo {

fn drop(&mut self) {

println!("Drop Foo with data: {}", self.data);

}
```
结果：

结论：

**局部变量级别：** 按照创建的顺序 **逆序** drop

结构体字段级别：字段会按照 **定义顺序** 依次drop

注意：如果一个类型实现了 `Drop` ，会先执行自己的drop，然后在自动去drop它的字段。
## 4、没有实现 Drop 的结构体

即使不给结构体手动实现 `Drop` ，它的字段依然会在离开作用域时自动被清理。

例如，去掉下面这段代码：

```rust
impl Drop for HasTwoDrops {

fn drop(&mut self) {

println!("Drop HasTwoDrops");

}

}
```
此时：

`HasTwoDrops` 自己不会打印任何东西

但它内部的 `one` 和 `two` 仍然会被自动销毁

Rust编译器会为类型生成必要的 `drop glue` （析构逻辑），自动递归清理它的字段。
## 5、手动回收

**Rust不允许手动直接调用** `drop()` **方法** ，原因是 `Drop::drop(&mut self)` 接收的是一个 **可变借用** 。如果允许手动调用，那么值在销毁后，原变量仍然还在作用域，可能继续被访问，这将破坏Rust的安全保证。

示例：

```rust
struct Foo {

data: String,

}

impl Drop for Foo {

fn drop(&mut self) {

println!("Drop Foo with data = {}", self.data);

}

}

fn main() {

let foo = Foo {

data: String::from("Hello"),

};

// foo.drop(); // 报错

}
```
**正确做法是使用标准库中的** `drop` **函数：**
```rust
pub fn drop<T>(_x: T) {}
```
它本质上是一个空实现，但它会接收参数的所有权，因此参数_x在函数结束时离开作用域，于是Rust自动析构它。
```rust
struct Foo {

data: String,

}

impl Drop for Foo {

fn drop(&mut self) {

println!("Drop Foo with data = {}", self.data);

}

}

fn main() {

let foo = Foo {

data: String::from("Hello"),

};

drop(foo);

}
```
说明： `drop(foo)` 的本质是把 `foo` 的所有权转移给 `drop` 函数，调用后， `foo` 不再可用。
# 五、Rc<T>

## 1、引用计数机制

Rust的所有权规则要求： **一个值在任意时刻只能有一个所有者** 。这在大多数情况下没有问题，但在某些数据结构中，会希望多个地方共同拥有同一份数据：

图数据结构中，多个边可能指向相同的节点。只有当节点没有边指向时，才做清理释放工作。

多线程场景下，多个线程希望持有同一个数据。但受限于Rust引用的安全机制，无法做到。

为了解决这些场景的需求，Rust在所有权机制之外又引入了额外的措施来简化相应地实现：通过 **引用计数的机制** ，允许同一份数据在同一时刻拥有多个所有者。具体来说：

记录当前有多少个所有者

当引用计数归零时，才释放底层数据

Rust中提供了两种引用计数智能指针：

`Rc<T>` ： **单线程** 引用计数

`Arc<T>` ： **多线程** 引用计数（原子引用计数）

由于两者的接口几乎完全相同，只是适用场景不同，这里主要介绍 `Rc<T>` 。

## 2、Rc<T>的使用

`Rc` 是Reference Counting（引用计数）的缩写。当一个值需要在同一线程内被多个地方共同拥有时，可以使用 `Rc<T>` 。

示例1：

```rust
let a = Rc::new(String::from("Hello"));

let b = Rc::clone(&a);

assert_eq!(Rc::strong_count(&a), 2);

assert_eq!(Rc::strong_count(&a), Rc::strong_count(&b));
```
说明：

`Rc::new(s)` 创建一个新的引用计数智能指针，指向底层的 `String` 数据值

`Rc::clone(&a)` 不会深拷贝底层字符串，只会让引用计数加1，也可以写成 `a.clone()` 。但需要你注意的是，这里的clone语义与一般clone语义完全不同。

`Rc::strong_count(&a)` 可以查看当前强引用数量。

`Rc` 不在 prelude 预导入模块中，需要手动导入： `use std::rc::Rc`

示例2：
```rust
struct Owner {

name: String,

}

struct Gadget {

id: u32,

owner: Rc<Owner>,

}

fn main() {

let owner = Rc::new(Owner {

name: "Tom".to_string()

});

let g1 = Gadget{

id: 1,

owner: Rc::clone(&owner)

};

let g2 = Gadget{

id: 2,

owner: Rc::clone(&owner)

};

drop(owner);

println!("Gadget {} owned by {}", g1.id, g1.owner.name);

println!("Gadget {} owned by {}", g2.id, g2.owner.name);

}
```
说明：

`owner` 、 `g1.owner` 和 `g2.owner` 共同拥有同一个 `Owner`

即使 `owner` 被提前 `drop` ，只要还有其他 `Rc` 存在，底层数据就不会释放

`Rc<T>` 实现了 `Deref` ，因此可以直接写 `g1.owner.name`
## 3、Rc<T>只提供共享访问

`Rc<T>` 是一个 **共享所有权** 的智能指针，它允许多个所有者共同拥有同一份数据。但 **默认情况下，只能通过共享引用访问访问内部值，无法直接修改内部数据** 。

示例

```rust
let mut a = Rc::new(String::from("Hello"));

let b = Rc::clone(&a);

a.push_str(" world"); // 错误
```
说明：

这里a可以直接调用 `push_str` ，是因为 `Rc` 也实现了 `Deref` 特征，这里会进行Deref coercion。

`a.push_str(" world")` 的直接原因是 `Rc<T>` 只实现了 `Deref<Target = T>` ，没有实现 `DerefMut`

因此只能共享访问 `Rc` 指向的数据，不可以修改
## 4、Rc<T>注意事项

`Rc<T>` 适用于单线程

`RC<T>` 允许多个所有者共享同一个值，但默认只提供共享访问，不能直接修改内部值。若要修改，通常需要搭配内部可变性类型使用，例如 `RefCell<T>`

多线程场景下使用 `Arc<T>` ，不要使用 `Rc<T>` 。

# 六、Cell<T>和RefCell<T>

## 1、内部可变性

Rust默认遵循这条规则：

要修改数据，必须拿到 `&mut T`

如果只有 `&T` ，那么就不能修改

这能在编译期保证安全。

但有些场景下，在只有 `&self` 的不可变引用前提下，却仍然希望修改对象内部的某个字段。这就是 **内部可变性（interior mutability）** 。

**内部可变性允许通过不可变引用修改内部数据** ，但安全检查会转移到特定机制上。

Rust标准库里最常见的两个内部可变性工具就是 `Cell<T>` 和 `RefCell<T>` 。

## 2、Cell<T>

### （1）问题引入

`Cell<T>` 用于实现内部可变性。它解决的问题是：当手里只有不可变引用 `&self` / `&T` 时，仍然想修改内部的某个值。

例如：

```rust
struct Counter {

counter: i32,

}

impl Counter {

fn increment(&self) {

self.counter += 1; // 报错

}

}
```
由于 `increment()` 的参数是 `&self` ，因此无法修改修改 `self.counter` 。

这里当然可以将参数修改为 `&mut self` ：
```rust
struct Counter {

count: i32,

}

impl Counter {

fn increment(&mut self) {

self.count += 1;

}

}

fn main() {

let mut c = Counter { count: 0 };

c.increment();

println!("{}", c.count);

}
```
这就是最自然、最推荐的写法。

但是，有些场景下，不能使用 `&mut self` ，Trait、API、设计约束已经固定成了 `&self` 。例如：
```rust
trait Messenger {

fn send(&self, msg: &str);

}
```
这个Trait规定死了：方法签名就是 `&self` ，不是 `&mut self` 。

假如在实现它的时候，想顺手记录调用了几次，那么就麻烦了：
```rust
struct MyMessenger {

count: usize,

}

impl Messenger for MyMessenger {

fn send(&self, msg: &str) {

self.count += 1; // 错误

println!("{}", msg);

}

}
```
因为 `send` 只有 `&self` 。

这时候 `Cell` 就派上用场了：
```rust
use std::cell::Cell;

trait Messenger {

fn send(&self, msg: &str);

}

struct MyMessenger {

count: Cell<usize>,

}

impl Messenger for MyMessenger {

fn send(&self, msg: &str) {

self.count.set(self.count.get() + 1);

println!("send {} times: {}", self.count.get(), msg);

}

}
```
说明：

整个 `MyMessenger` 对外仍然是“不可变借用”

但 `count` 这个字段允许内部修改
### （2）常用API

`Cell::new()` ： 创建一个 `Cell<T>`

`get()` ：取出内部值，要求 `T: Copy`

`set(v)` ：直接覆盖内部值

`replace(v)` ：替换新值，并返回旧值

`into_inner()` ：消费掉 `Cell<T>` ，拿出内部值

### （3）使用场景

`Cell<T>` 适合简单类型，如整型、布尔类型、字符型等其他 `Copy` 类型。核心特征是值比较小，改动方式主要是整体替换。

因为 `Cell<T>` 最舒服的模式是：

```rust
let old = cell.get();

cell.set(f(old));
```
但 `Cell<T>` 不适合复杂类型，特别是没有实现 `Copy` 的类型，例如：
```rust
use std::cell::Cell;

fn main() {

let c = Cell::new(vec![1, 2, 3]);

}

`Cell` 中存放了一个 `Vec<String>` ，但无法通过 `c.get()` 获取，更不能写类似 `c.get().push(4)` 的代码，因为 `Vec<T>` 不是 `Copy` ， `Cell<T>` 也不会把 `&mut Vec<_>` 借出来。
```
如果你想 `push` 、 `insert` 、遍历、改某个元素，一般应该用 `RefCell<T>` 。
## 3、RefCell<T>

### （1）RefCell<T>与Cell<T>的区别

`RefCell<T>` 也是 Rust 里实现 **内部可变性** 的工具，它解决的问题是：当手里只有 `&self` / `&T` 时，仍然想修改内部数据，而且这个数据 **不是简单值** ，而是需要“ **借引用操作** ”的复杂数据。

它和 `Cell<T>` 的核心区别是：

`Cell<T>` 不借引用，靠整体取值和整体替换

`RefCell<T>` 可以借引用，但借用规则从编译期检查改到运行时检查

也就是说， `RefCell<T>` 更像是：普通借用规则还在，只是从编译期检查，变成了运行时检查。

### （2）RefCell<T>核心机制

`RefCell<T>` 允许你：

`borrow()` ：拿不可变借用

`borrow_mut()` ：拿可变借用

但它会在运行时检查借用是否合法。

规则与普通借用本质一样：

可以有多个不可变借用或者一个可变借用

不能同时有多个可变借用

不能同时既有不可变借用又有可变借用

如果违反，程序会panic。

### （3）常用API

`RefCell::new()` ：创建一个新的 `RefCell<T>`

`borrow()` ：不可变借用，返回的类型不是普通 `&T` ，而是 `Ref<T>` ，但是用起来很像不可变引用。

`borrow_mut()` ：可变借用，返回的类型不是普通 `&mut T` ，而是 `RefMut<T>` ，但像 `&mut T` 一样使用。

`into_inner()` ：消费 `RefCell<T>` ，直接拿到内部值

示例：

```rust
use std::cell::RefCell;

struct Logger {

logs: RefCell<Vec<String>>,

}

impl Logger {

fn log(&self, msg: String) {

self.logs.borrow_mut().push(msg);

}

fn show(&self) {

for log in self.logs.borrow().iter() {

println!("{}", log);

}

}

}
```
### （4）Rc + RefCell的组合使用

在Rust中，一个非常常见的组合是：

`Rc<T>` ：允许同一个值有多个所有者

`RefCell` ：提供内部可变性，外部值不可变，但其内部字段可变。

将它们组合在一起就是：多个地方共同拥有同一份数据，且允许在运行时对值进行修改。

示例：

```rust
use std::cell::RefCell;

use std::rc::Rc;

fn main() {

let s = Rc::new(RefCell::new(String::from("Hello")));

let s2 = Rc::clone(&s);

s.borrow_mut().push_str(", world");

println!("{}", s.borrow());

println!("{}", s2.borrow());

}
```
