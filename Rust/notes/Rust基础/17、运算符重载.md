# 一、运算符重载简介

Rust 中许多运算符并不是独立的特殊语法，而是建立在`Trait`之上的统一接口。

例如：

| 表达式        | 对应 trait               | 方法调用形式                |
| ---------- | ---------------------- | --------------------- |
| `x + y`    | `std::ops::Add`        | `x.add(y)`            |
| `-x`       | `std::ops::Neg`        | `x.neg()`             |
| `x == y`   | `std::cmp::PartialEq`  | `x.eq(&y)`            |
| `x < y`    | `std::cmp::PartialOrd` | `x.lt(&y)`            |
| `a[i]`     | `std::ops::Index`      | `*a.index(i)`         |
| `a[i] = v` | `std::ops::IndexMut`   | `*a.index_mut(i) = v` |

为自定义类型实现对应`Trait`，就可以让这个类型支持相应运算符。

例如定义一个复数类型`Complex`：

```rust
#[derive(Clone, Copy, Debug)]
struct Complex<T> {
	/// 复数的实部
	re: T,
	/// 复数的虚部
	im: T,
}
```

如果希望它像普通数值一样参与运算：

```rust
z = z * z + c;
```

就需要为`Complex<T>`实现`Add`、`Mul`等对应`Trait`。

Rust 运算符重载几个重要边界：

1. 不能自定义新运算符，只能实现Rust已经支持的运算符trait
2. 运算符行为受类型系统约束，参数类型和返回类型都由trait实现定义
3. 与所有权系统一致，有些trait按值接收，有些trait按引用接收
4. 不是所有的运算符都能重载，借用（`&`）、赋值（`=`）、短路逻辑（`||`、`&&`）、错误传播（`?`）运算符不可随意改写

运算符重载不是为了让语法“炫技”，而是让自定义类型在保持类型安全的前提下拥有自然的使用方式。

# 二、一元运算符

一元运算符只作用于一个操作数。Rust中常见的可重载一元运算符主要是`-`、`!`。

| trait           | 表达式  | 等效方法      | 说明        |
| --------------- | ---- | --------- | --------- |
| `std::ops::Neg` | `-x` | `x.neg()` | 一元负号      |
| `std::ops::Not` | `!x` | `x.not()` | 逻辑取反或按位取反 |

解引用运算符`*`虽然也受`Deref`、`DerefMut`影响，但它通常属于智能指针和自动解引用的主题，不放在本篇展开。

`Neg`和`Not`的简化定义如下：

```rust
trait Neg {
	type Output;
	
	fn neg(self) -> Self::Output;
}

trait Not {
	type Output;
	
	fn not(self) -> Self::Output;
}
```

这里有两个关键点：

| 设计点           | 说明               |
| ------------- | ---------------- |
| `type Output` | 运算结果类型由关联类型指定    |
| `self`        | 默认按值接收操作数，可能消耗原值 |

例如，为复数实现一元负号：

```rust
use std::ops::Neg;  
  
#[derive(Debug,Clone,Copy)]  
struct Complex<T> {  
    /// 实部  
    re: T,  
    /// 虚部  
    im: T  
}  
  
impl<T> Neg for Complex<T>  
where  
    T: Neg<Output = T>  
{  
    type Output = Self;  
  
    fn neg(self)-> Self::Output {  
        Self {  
            re: -self.re,  
            im: -self.im  
        }  
    }  
}  
  
  
fn main() {  
    let c = Complex { re: 3, im: -4 };  
  
    println!("{:?}", c);  
    println!("{:?}", -c);  
}
```

这里的泛型约束是必要的：

```rust
T: Neg<Output = T>
```

它表示字段类型 `T` 本身必须支持一元负号，并且取负后的结果仍然是 `T`。

需要注意，`Output` 不一定必须是 `Self`。虽然很多类型会返回自身类型，但 trait 设计上允许返回其他类型。

`!`在Rust中同时有两种常见含义：

| 类型     | `!x` 的含义 |
| ------ | -------- |
| `bool` | 逻辑取反     |
| 整数     | 按位取反     |
例如：

```rust
fn main() {
    let a = true;
    let b = 0b1010u8;

    println!("{}", !a);
    println!("{:04b}", !b);
}
```

Rust 没有像某些语言那样区分 `!` 和 `~`，而是用同一个 `Not` trait 表达这两类操作。

# 三、二元算术运算符和按位运算符

## 1、概述

二元运算符作用于两个操作数，是最常见的运算符重载场景。

| 类别    | Trait                                                                                                     | 表达式                                          | 等效方法                                                             |
| ----- | --------------------------------------------------------------------------------------------------------- | -------------------------------------------- | ---------------------------------------------------------------- |
| 算术运算符 | `std::ops::Add`<br>`std::ops::Sub`<br>`std::ops::Mul`<br>`std::ops::Div`<br>`std::ops::Rem`               | x + y<br>x - y<br>x * y<br>x / y<br>x % y    | x.add(y)<br>x.sub(y)<br>x.mul(y)<br>x.div(y)<br>x.rem(y)         |
| 按位运算符 | `std::ops::BitAnd`<br>`std::ops::BitOr`  <br>`std::ops::BitXor`  <br>`std::ops::Shl`  <br>`std::ops::Shr` | x & y<br>x \| y<br>x ^ y<br>x << y<br>x >> y | x.bitand(y)<br>x.bitor(y)<br>x.bitxor(y)<br>x.shl(y)<br>x.shr(y) |

本篇主要以`Add`为例介绍。

## 2、Add的核心结构

`std::ops::Add`的简化定义如下：

```rust
trait Add<Rhs = Self> {
	type Output;
	
	fn add(self, rhs: Rhs) -> Self::Output;
}
```

这段定义包含三个关键点：

| 组成                       | 说明                        |
| ------------------------ | ------------------------- |
| `Rhs = Self`             | 右操作数类型默认是自身类型             |
| `type Output`            | 运算结果类型由关联类型指定             |
| `fn add(self, rhs: Rhs)` | 左操作数按值接收，右操作数类型由 `Rhs` 决定 |

`Add<Rhs = Self>` 表示，如果没有额外指定右操作数类型，就默认执行同类型相加。

例如：

```rust
impl Add for Complex<i32> {
    type Output = Self;

    fn add(self, rhs: Self) -> Self::Output {
        Self {
            re: self.re + rhs.re,
            im: self.im + rhs.im,
        }
    }
}
```

这个实现表示：

```rust
Complex<i32> + Complex<i32> -> Complex<i32>
```

## 3、泛型类型的同类型相加

```rust
use std::ops::Add;

#[derive(Debug, Copy, Clone)]
struct Complex<T> {
    re: T,
    im: T,
}

impl<T> Add for Complex<T>
where
    T: Add<Output = T>,
{
    type Output = Self;

    fn add(self, rhs: Self) -> Self::Output {
        Self {
            re: self.re + rhs.re,
            im: self.im + rhs.im,
        }
    }
}

fn main() {
    let c1 = Complex { re: 1, im: 2 };
    let c2 = Complex { re: 3, im: 4 };

    let c3 = c1 + c2;

    println!("{:?}", c3);
}
```

这里的约束是：

```rust
T: Add<Output = T>
```

表示：

```rust
只要 T + T -> T 成立，就可以让 Complex<T> + Complex<T> -> Complex<T> 成立。
```

## 4、左右操作数不同类型的情况

`Add` 的右操作数类型可以自定义，因此左右操作数不一定必须是同一种类型。

代码示例：

```rust
use std::ops::Add;

#[derive(Debug, Copy, Clone, PartialEq)]
struct Complex<T> {
    re: T,
    im: T,
}

impl<L, R> Add<Complex<R>> for Complex<L>
where
    L: Add<R>,
{
    type Output = Complex<L::Output>;

    fn add(self, rhs: Complex<R>) -> Self::Output {
        Complex {
            re: self.re + rhs.re,
            im: self.im + rhs.im,
        }
    }
}
```

这个实现表示：

```rust
Complex<L> + Complex<R> -> Complex<L::Output>
```

也就是说，只要 `L + R` 是合法的，就可以让 `Complex<L>` 和 `Complex<R>` 相加。

例如，如果存在：

```rust
L + R -> X
```

那么就可以得到：

```rust
Complex<L> + Complex<R> -> Complex<X>
```

这种写法类型系统上完全成立，但实际工程中要谨慎使用。过于灵活的跨类型运算容易让 API 变复杂，除非确实有明确需求。

# 四、复合赋值运算符

## 1、概述

复合赋值运算符包括 `+=`、`-=`、`*=`、`/=` 等。它们表示在原值基础上进行运算，并把结果写回左操作数。例如 `x += y` 相当于 `x = x + y` 。

| 类别      | Trait                                                                                                                                   | 表达式                                               | 等效方法                                                                                                |
| ------- | --------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| 算术赋值运算符 | `std::ops::AddAssign`<br>`std::ops::SubAssign`<br>`std::ops::MulAssign`<br>`std::ops::DivAssign`<br>`std::ops::RemAssign`               | x += y<br>x -= y<br>x \*= y<br>x /= y<br>x %= y   | x.add_assign(y)<br>x.sub_assign(y)<br>x.mul_assign(y)<br>x.div_assign(y)<br>x.rem_assign(y)         |
| 按位赋值运算符 | `std::ops::BitAndAssign`<br>`std::ops::BitOrAssign`  <br>`std::ops::BitXorAssign`  <br>`std::ops::ShlAssign`  <br>`std::ops::ShrAssign` | x &= y<br>x \|= y<br>x ^= y<br>x <<= y<br>x >>= y | x.bitand_assign(y)<br>x.bitor_assign(y)<br>x.bitxor_assign(y)<br>x.shl_assign(y)<br>x.shr_assign(y) |
本篇主要以`AddAssign`为例介绍。

## 2、AddAssign核心结构

`AddAssign` 的简化定义如下：

```rust
trait AddAssign<Rhs = Self> {
	fn add_assign(&mut self, rhs: Rhs);
}
```

与 `Add` 不同，`AddAssign` 没有 `Output` 关联类型，因为它的目标是直接修改左操作数。

例如：

```rust
use std::ops::AddAssign;

#[derive(Debug, Copy, Clone)]
struct Complex<T> {
    re: T,
    im: T,
}

impl<T> AddAssign for Complex<T>
where
    T: AddAssign,
{
    fn add_assign(&mut self, rhs: Self) {
        self.re += rhs.re;
        self.im += rhs.im;
    }
}

fn main() {
    let mut c1 = Complex { re: 1, im: 2 };
    let c2 = Complex { re: 3, im: 4 };

    c1 += c2;

    println!("{:?}", c1);
}
```

左操作数必须是可变的：

```rust
let mut c1 = Complex { re: 1, im: 2 };
```

否则 `c1 += c2` 无法修改 `c1`。

复合赋值表达式本身的结果类型是 `()`：

```rust
fn main() {
	
	let mut x = 1;
	
	let result = {
		x += 2;
	}

    println!("{:?}", result);
}
```

这里 `result` 的类型是 `()`，不是赋值后的 `x`。

# 五、相等性比较

## 1、概述

Rust 中的相等比较主要由`PartialEq`和`Eq`表示。

| trait       | 含义   | 对应运算符                      |
| ----------- | ---- | -------------------------- |
| `PartialEq` | 部分相等 | `==`、`!=`                  |
| `Eq`        | 完全相等 | 无新增运算符，是 `PartialEq` 的语义增强 |

`std::cmp::PartialEq` 表示 **部分相等**

`std::cmp::Eq` 表示 **完全相等**

这是Rust中一个非常重要但也非常容易混淆的点。之所以要区分两者，是因为并不是所有类型都满足严格意义上的数学相等关系。

## 2、PartialEq

`PartialEq`的简化定义如下：

```rust
trait PartialEq<Rhs = Self> 
where
	Rhs: ?Sized,
{
	fn eq(&self, other: &Rhs) -> bool;
	
	fn ne(&self, other: &Rhs) -> bool {
		!self.eq(other)
	}
}
```

与 `Add` 不同，`PartialEq` 使用引用接收参数：

```rust
fn eq(&self, other: &Rhs) -> bool
```

这是因为比较通常只需要读取值，不应该消耗所有权。

例如：

```rust
fn main() {
    let a = String::from("hello");
    let b = String::from("world");

    println!("{}", a == b);

    println!("{}", a);
    println!("{}", b);
}
```

比较完成后，`a` 和 `b` 仍然可用。

为自定义类型实现`PartialEq`时，只需要实现`eq()`方法即可，因为`ne()`有默认实现。

为 `Complex<T>` 实现 `PartialEq`：

```rust
impl<T> PartialEq for Complex<T>
where
    T: PartialEq,
{
    fn eq(&self, other: &Self) -> bool {
        self.re == other.re && self.im == other.im
    }
}
```

两个复数相等，当且仅当实部和虚部都相等。

实现了 `PartialEq` 特征，就可以使用 `assert_eq!`对两个 `Complex` 值进行断言了：

```rust
#[cfg(test)]  
mod tests {  
    use super::*;  
  
    #[test]  
    fn complex_partialeq() {  
        let c1 = Complex { re: 1, im: 2 };  
        let c2 = Complex { re: 1, im: 2 };  
  
        assert_eq!(c1, c2);  
    }  
}
```

> 为自定义类型手动实现`PartialEq`比较枯燥，因为无非就是比较各个字段值。
由于相等性是一个常见的操作，可以使用派生属性宏`#[derive(PartialEq)]`为自定义类型自动实现 `PartialEq` 。

示例：

```rust
#[derive(Debug, Copy, Clone, PartialEq)]
struct Complex<T> {
	re: T,
	im: T,
}
```

编译器自动按字段生成比较逻辑。

## 3、部分相等和完全相等

`PartialEq`表示部分相等。它之所以不是直接叫`Eq`，是因为**并不是所有类型都满足严格的相等关系**。

数学意义上的相等通常要求：

- **对称性：** 如果 `x == y` ，则 `y == x`
- **传递性：** 如果 `x == y` 且 `y == z` ，则 `x == z`
- **自反性：** 任意 `x` 都应该满足 `x == x`

然而，并不是所有类型都满足上述三个性质，例如浮点数的`NaN`就不满足自反性：

```rust
fn main() {
    let x = 0.0f64 / 0.0;

    assert!(x.is_nan());
    assert!(x != x);
}
```

`0.0f64 / 0.0`得到的是 `NaN` ，并且 `x == x` 是 `false` ，所以浮点数不满足自反性。

因此，`f32` 和 `f64` 实现了 `PartialEq`，但没有实现 `Eq`。

这也是 Rust 类型系统严谨的地方：能比较相等，不代表一定满足完全相等关系。

## 4、Eq作为更强的语义承诺

`Eq`的简化定义如下：

```rust
trait Eq: PartialEq<Self> {}
```

`Eq` 不新增方法，它只是对 `PartialEq` 的语义增强。

如果一个类型实现了 `Eq`，就表示这个类型的相等关系满足更严格的要求，尤其是所有值都应该满足`x == x`。

为 `Complex<T>` 实现 `Eq`：

```rust
#[derive(Debug, PartialEq)]
struct Complex<T> {
    re: T,
    im: T,
}

impl<T: Eq> Eq for Complex<T> {}
```

更常见的写法是直接派生：

```rust
#[derive(Debug, Copy, Clone, PartialEq, Eq)]
struct Complex<T> {
    re: T,
    im: T,
}
```

不过，只有当字段类型本身也适合实现 `Eq` 时，自定义类型才应该实现 `Eq`。

例如，如果结构体中包含 `f64` 字段，就不能直接派生 `Eq`：

```rust
#[derive(Debug, PartialEq)]
struct Point {
    x: f64,
    y: f64,
}
```

因为 `f64` 只有 `PartialEq`，没有 `Eq`。

# 六、有序性比较

## 1、概述

Rust 的大小比较主要由 `PartialOrd` 和 `Ord` 表示。

| trait        | 含义   | 对应运算符                       |
| ------------ | ---- | --------------------------- |
| `PartialOrd` | 部分有序 | `<`、`>`、`<=`、`>=`           |
| `Ord`        | 全序   | 无新增运算符，是 `PartialOrd` 的语义增强 |

它们和相等比较之间的关系：

| 相等关系        | 有序关系         |
| ----------- | ------------ |
| `PartialEq` | `PartialOrd` |
| `Eq`        | `Ord`        |


## 2、PartialOrd

`PartialOrd`的简化定义如下：

```rust
use std::cmp::Ordering;

trait PartialOrd<Rhs = Self>: PartialEq<Rhs>
where 
	Rhs: ?Sized,
{
	fn partial_cmp(&self, other: &Rhs) -> Option<Ordering>;
	
	fn lt(&self, other: &Rhs) -> bool {
		self.partial_cmp(other) == Some(Ordering::Less)
	}
	
	fn le(&self, other: &Rhs) -> bool {
		matches!(
			self.partial_cmp(other),
			Some(Ordering::Less | Ordering::Equal)
		)
	}
	
	fn gt(&self, other: &Rhs) -> bool {
		self.partial_cmp(other) == Some(Ordering::Greater)
	}
	
	fn ge(&self, other: &Rhs) -> bool {
		matches!(
			self.partial_cmp(other),
			Some(Ordering::Greater | Ordering::Equal)
		)
	}
	
}
```

> `PartialOrd<Rhs = Self>`扩展了`PartialEq<Rhs>`，只有可以比较相等性的类型才能比较有序性。

`PartialOrd` 中必须自行实现的唯一方法是 `partial_cmp` ：

```rust
fn partial_cmp(&self, other: &Rhs) -> Option<Ordering>;
```

其返回类型是`Option<Ordering>`，`Ordering`枚举定义如下：

```rust
enum Ordering {
	Less,       // self < other
	Equal,      // self == other
	Greater,    // self > other
}
```

返回值的含义如下：

| 返回值                       | 含义              |
| ------------------------- | --------------- |
| `Some(Ordering::Less)`    | `self < other`  |
| `Some(Ordering::Equal)`   | `self == other` |
| `Some(Ordering::Greater)` | `self > other`  |
| `None`                    | 两者无法比较顺序        |
之所以返回 `Option<Ordering>`，是因为不是所有值之间都能比较出顺序。

例如，浮点数中的 `NaN` 与任何值都无法形成正常顺序。

## 3、区间类型的部分有序

区间是理解 `PartialOrd` 的典型例子。

考虑一个区间类型，表示左闭右开区间： `[lower, upper)`

```rust
#[derive(Debug, PartialEq)]
struct Interval<T> {
	lower: T,
	upper: T
}
```

区间不一定总能比较大小：

- `[10, 20)` 与 `[20, 40)` ：前者小于后者

- `[20, 30)` 与 `[10, 20)` ：前者大于后者

- `[10, 20)` 与 `[10, 20)` ：相等

- `[10, 30)` 与 `[20, 40)` ：重叠，无法比较大小

为 `Interval<T>` 实现 `PartialOrd` ：

```rust
use std::cmp::Ordering;

#[derive(Debug, PartialEq)]
struct Interval<T> {
	lower: T,
	upper: T,
}

impl<T: PartialOrd> PartialOrd for Interval<T> {
	fn partial_cmp(&self, other: &Self) -> Option<Ordering> {
		if self == other {
			Some(Ordering::Equal)
		} else if self.upper <= other.lower {
			Some(Ordering::Less)
		} else if self.lower >= other.upper {
			Some(Ordering::Greater)
		} else {
			None
		}
	}
}

fn main() {

	assert!(Interval { lower: 10, upper: 20 } == Interval { lower: 10, upper: 20 });

	assert!(Interval { lower: 10, upper: 20 } < Interval { lower: 20, upper: 40 });

	assert!(Interval { lower: 20, upper: 40 } > Interval { lower: 10, upper: 20 });

	assert!(!(Interval { lower: 10, upper: 20 } < Interval { lower: 10, upper: 30 }));

}
```

最后一个断言中，两个区间发生重叠，`partial_cmp` 返回 `None`，因此 `<` 返回 `false`。

## 4、Ord

如果任意两个值之间都能比较出确定顺序，就可以实现 `Ord`。

`Ord`的简化定义如下：

```rust
use std::cmp::Ordering;

trait Ord: Eq + PartialEq<Self> {
	fn cmp(&self, other: &Self) -> Ordering;  
}
```

与 `partial_cmp` 不同，`cmp` 不返回 `Option<Ordering>`，而是直接返回 `Ordering`。而且，`Ord`通常只定义在同一种类型之间的比较上，而`PartialOrd`更宽松，允许跨类型比较，所以 `Ord` 没有指定泛型参数 。

很多排序接口依赖`Ord`：

```rust
fn main() {
	let mut v = vec![10, 30, 20];
	
	v.sort();
	
	println!("{:?}", v);
}
```

输出为升序：

```text
[10, 20, 30]
```

如果需要自定义排序规则，可以使用 `sort_by`：

```rust
fn main() {
    let mut v = vec![10, 30, 20];

    v.sort_by(|a, b| b.cmp(a));

    println!("{:?}", v);
}
```

输出：

```text
[30, 20, 10]
```

`sort_by`接收一个比较器，形式上可以理解为：

```rust
FnMut(&T, &T) -> Ordering;
```

比较器返回值含义如下：

| 返回值                 | 含义               |
| ------------------- | ---------------- |
| `Ordering::Less`    | 第一个参数应该排在第二个参数前面 |
| `Ordering::Equal`   | 两者顺序相同           |
| `Ordering::Greater` | 第一个参数应该排在第二个参数后面 |
正常升序是：

```rust
a.cmp(b)
```

降序可以写成：

```rust
b.cmp(a)
```

## 5、Reverse反转排序顺序

`std::cmp::Reverse<T>`是一个包装类型，用于反转原本的比较顺序。它最常见的用途就是把默认升序变成降序。

`Reverse` 的简化版本定义如下：

```rust
use std::cmp::Ordering;

struct Reverse<T>(T);     // 包装类型

impl<T: PartialOrd> PartialOrd for Reverse<T> {
	fn partial_cmp(&self, other: &Reverse<T>) -> Option<Ordering> {
		other.0.partial_cmp(&self.0)
	}
}

impl<T: Ord> Ord for Reverse<T> {
	fn cmp(&self, other: &Reverse<T>) -> Ordering {
		other.0.cmp(&self.0)
	}
}
```

原本比较是`self.0.partial_cmp(&other.0)`和`self.0.cmp(&other.0)`，`Reverse<T>`改成`other.0.partial_cmp(&self.0)`和`other.0.cmp(&self.0)`。

因此排序方向被反转。

示例：

```rust
use std::cmp::Reverse;

fn main() {
	let mut v = vec![40, 10, 30, 20, 50];
	v.sort_by_key(|x| Reverse(*x));
	println!("{:?}", v);
}
```

# 七、索引运算符

## 1、概述

Rust支持类似数组、切片那样的索引语法：`a[i]`。

如果要让自定义类型支持这种语法，需要实现：

|trait|作用|
|---|---|
|`std::ops::Index`|只读索引|
|`std::ops::IndexMut`|可变索引|

## 2、Index与只读索引

`Index`的简化定义如下：

```rust
trait Index<Idx> {
	type Output: ?Sized;
	
	fn index(&self, index: Idx) -> &Self::Output;
}

```

其中：

|组成|说明|
|---|---|
|`Idx`|索引参数类型|
|`Output`|索引结果类型|
|`index(&self, index: Idx)`|返回索引结果的共享引用|

表达式`a[i]`在只读上下文通常可以理解为：

```rust
*a.index(i)
```

`Index`的索引参数不一定是`usize`。

例如切片既支持单个元素索引，也支持范围索引：

```rust
fn main() {
	let v = vec![1, 2, 3, 4, 5];
	
	let slice = &v[..];
	
	let x = slice[0];
	let y = &slice[1..4];
	
	println!("{}", x);  
	println!("{:?}", y);
}
```

这背后分别对应：

| 表达式           | 对应实现                 |
| ------------- | -------------------- |
| `slice[0]`    | `Index<usize>`       |
| `slice[1..4]` | `Index<Range<usize>>` |
`HashMap`也支持只读索引：

```rust
use std::collections::HashMap;

fn main() {
    let mut scores = HashMap::new();

    scores.insert("Tom", 90);
    scores.insert("Bob", 80);

    assert_eq!(scores["Tom"], 90);
    assert_eq!(scores["Bob"], 80);
}
```

不过需要注意，`HashMap` 的索引访问要求键必须存在。如果键不存在，会发生 panic：

```rust
// 如果 "Jack" 不存在，这里会 panic
// scores["Jack"];
```

因此在不确定键是否存在时，更推荐使用 `get`：

```rust
if let Some(score) = scores.get("Jack") {
	println!("{}", score);
}
```

## 3、IndexMut与可变引用

`IndexMut`的简化定义如下：

```rust
trait IndexMut<Idx>: Index<Idx> {
	fn index_mut(&mut self, index: Idx) -> &mut Self::Output;
}
```

它继承自 `Index`，表示：如果一个类型支持可变索引，它也必须支持只读索引。

表达式`a[i]`在可变上下文通常可以理解为：

```rust
*a.index_mut(i);
```

例如：

```rust
fn main() {
    let mut v = vec!["hello".to_string(), "hi".to_string()];

    v[0].push_str(", world");

    println!("{:?}", v);
}
```

`IndexMut` 必须返回某个已经存在的值的可变引用：`&mut Self::Output`。

这带来一个限制：它不适合“索引不存在时自动创建元素”的场景。

例如，`HashMap`没有实现`IndexMut`，所以不能这样写：

```rust
// 错误：HashMap 不支持这种可变索引赋值
// scores["Jack"] = 70;
```

原因是 `index_mut` 必须返回一个已经存在的值的 `&mut` 引用。如果键不存在，就没有现成的值可以返回。

对于`HashMap`，应该使用`insert`或`entry`：

```rust
use std::collections::HashMap;

fn main() {
	let mut scores = HashMap::new();
	
	scores.insert("Jack", 70);
	
	*scores.entry("Tom").or_insert(0) += 10;
	
	println!("{:?}", scores);
}
```



# 八、不可重载的运算符

Rust 对运算符重载有明确边界。只有一部分运算符对应标准库 trait，可以通过实现 trait 自定义行为；另一部分运算符属于语言核心语义，不能由用户重载。

## 1、短路逻辑运算符

`&&` 和 `||` 不能重载，因为它们不仅是普通计算，还包含短路求值。

```rust
a && b
```

如果 `a` 是 `false`，`b` 不会被求值。

```rust
a || b
```

如果 `a` 是 `true`，`b` 不会被求值。

这种控制流语义不能交给用户自定义，否则会破坏语言行为的可预测性。

## 2、错误传播运算符

`?`不能作为普通运算符重载。它用于错误传播，例如：

```rust
fn read_text(path: &str) -> std::io::Result<String> {
    let text = std::fs::read_to_string(path)?;
    Ok(text)
}
```

`?` 更接近 Rust 内建的控制流机制，而不是普通的 trait 运算符。

它背后确实涉及标准库中的转换机制，但普通用户不能像实现 `Add` 那样自由重载 `?`。

## 3、范围运算符

`..`和`..=`不能重载。

它们用于构造范围值：

```rust
let r1 = 1..5;  
let r2 = 1..=5;
```

它们本质上是：

```rust
let r1 = Range { start: 1, end: 5 };
let r2 = RangeInclusive { start: 1, end: 5 };
```

`..`**和**`..=` 运算符也不能重载，它们的作用是直接构造表示边界范围的结构体值。例如 `a..b` 等价于构造结构体值 `Range {start: a, end: b}` 。

## 4、借用运算符

借用运算符 `&` 不能重载：

```rust
let r = &value;
```

它始终表示创建引用，是所有权和借用系统的一部分。

## 5、赋值运算符

赋值运算符 `=` 也不能重载：

```rust
x = y;
```

它始终表示把右侧值赋给左侧位置，必要时发生移动，或者在类型实现 `Copy` 时发生复制。


## 6、函数调用运算符

函数调用语法也不能像 C++ 那样随意重载：

```rust
obj()
```

在稳定 Rust 中，普通自定义类型不能通过手动实现调用运算符来让自己像函数一样被调用。

如果需要一个可调用的值，通常直接闭包、函数或者实现了 `Fn` 、 `FnMut` 、 `FnOnce` 相关调用能力的类型。
