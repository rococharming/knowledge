# 一、闭包的基本形式

## 1、闭包表达式

闭包（Closure）是一种**匿名函数表达式**。它可以赋值给变量，也可以作为参数传递给函数。闭包在 [[Rust/notes/Rust基础/22、迭代器|迭代器]] 的 `map`、`filter`、`fold` 中非常常见。

闭包使用`||`定义参数列表，后面跟闭包体；在多线程里还经常配合 `move` 把捕获值转入新线程，见 [[Rust/notes/Rust进阶/多线程编程/1、多线程编程基础|多线程编程基础]]：

```rust
fn main() {  
    let add_one = |x| x + 1;  
    assert_eq!(add_one(1), 2);  
}
```

其中：

| 部分         | 含义     |
| ---------- | ------ |
| \|x\|      | 闭包参数列表 |
| x + 1      | 闭包体    |
| add_one(2) | 调用闭包   |

如果闭包体只有一个表达式，可以省略`{}`：

```rust
let add_one = |x| { x + 1 };
```

如果闭包体有多条语句，可以使用代码块：

```rust
let print_and_add = |x| {
	println!("x = {x}");
	x + 1
};

assert_eq!(print_and_add(2), 3);
```

闭包的最后一个表达式就是返回值。


## 2、闭包的类型推断

普通函数的类型参数和返回值类型通常需要显式标注：

```rust
fn add_one(x: i32) -> i32 {  
	x + 1  
}
```

闭包通常用于局部场景，编译器可以通过上下文推断参数类型和返回值类型，所以很多时候可以省略类型注解：

```rust
let add_one = |x| x + 1;
```

也可以显式写出类型：

```rust
let add_one = |x: i32| -> i32 { x + 1 };
```

下面几种写法含义接近：

```rust
fn  add_one_v1(x: i32) -> i32 { 
	x + 1 
}

let add_one_v2 = |x: i32| -> i32 { x + 1 };
let add_one_v3 = |x| { x + 1 };
let add_one_v4 = |x|  x + 1 ;
```

闭包虽然可以省略类型，但类型必须能被推断出来。闭包的参数类型一旦根据使用场景确定下来，之后就不能再换成其他类型。

示例：

```rust
fn main() {
    let identity = |x| x;

    let s = identity(String::from("hello"));

    // 错误：identity 的参数类型已经被推断为 String
    // let n = identity(1);
}
```

这里第一次调用时，编译器把 `identity` 推断为接收 `String` 并返回 `String` 的闭包，所以后面不能再用 `i32` 调用它。


# 二、闭包捕获环境

## 1、闭包与普通函数的区别

闭包与普通函数最重要的区别是：**闭包可以捕获定义位置周围作用域中的变量**。

普通函数不能直接捕获外部局部变量：

```rust
fn main() {
	let x = 10;
	
	fn add_x(y: i32) -> i32 {
		y + x
	}
} 
```

闭包可以：

```rust
fn main() {  
    let x = 10;  
    let add_x = |y| y + x;  
    println!("{}", add_x(5));  
}
```

这里`x`不是闭包参数，但闭包体中可以使用`x`。这是因为闭包在定义时捕获了外部环境中的`x`。

闭包之所以能做到这一点，是因为它不只是“一段代码”，还可以保存它所捕获的环境数据。

**编译器会根据闭包体中如何使用外部变量，决定捕获共享引用、可变引用，还是直接获取所有权。**


## 2、不可变借用捕获

如果闭包只是读取外部变量，编译器通常以不可变借用的方式捕获。

```rust
fn main() {  
  
    let s = String::from("hello");  
  
    println!("Before defining closure: {s}");  
  
    let closure = || {  
        println!("In closure: {s}");  
    };  
  
    println!("Before calling closure: {s}");  
  
    closure();  
  
    println!("After calling closure: {s}");  
}
```

输出：

```text
Before defining closure: hello
Before calling closure: hello
In closure: hello
After calling closure: hello
```

闭包体中只是打印 `s`，没有修改 `s`，也没有消耗 `s` 的所有权。因此闭包只需要保存 `s` 的不可变引用。

所以在定义闭包之后，仍然可以继续读取 `s`：

```rust
println!("Before calling closure: {s}");
```

因为这只是再次对 `s` 进行不可变借用，而 Rust 允许同时存在多个不可变引用。


## 3、可变借用捕获

如果闭包内部要修改外部变量，编译器通常以可变借用的方式捕获。

```rust
fn main() {
    let mut s = String::from("hello");

    println!("Before defining closure: {s}");

    let mut closure = || {
        s.push_str(" world");
        println!("In closure: {s}");
    };

    // println!("Before calling closure: {s}"); // 错误

    closure();

    println!("After calling closure: {s}");
}
```

`s.push_str(" world")` 需要可变访问 `s`，所以闭包会持有对 `s` 的可变借用。

闭包绑定本身也要声明为 `mut`：

```rust
let mut closure = || {
    s.push_str(" world");
};
```

原因是调用这个闭包时，会可变地使用闭包自身。闭包内部保存着对`s`的可变借用，执行闭包会通过这个可变借用修改`s`。

在闭包定义之后、调用之前，下面这句不能写：

```rust
println!("Before calling closure: {s}");
```

因为闭包已经持有了对 `s` 的可变借用。同一时间不能再创建其他借用。

闭包调用结束后，如果可变借用不再被使用，就可以重新使用 `s`：

```rust
closure();

println!("After calling closure: {s}");
```


## 4、所有权捕获

如果闭包体会消耗外部变量，编译器必须让闭包获取该变量的所有权。

```rust
fn main() {
    let s = String::from("hello");

    println!("Before defining closure: {s}");

    let closure = || {
        println!("In closure: {s}");
        drop(s);
    };

    // println!("Before calling closure: {s}"); // 错误

    closure();

    // println!("After calling closure: {s}"); // 错误
}
```

`drop(s)` 会消耗 `s` 的所有权。因此闭包必须把 `s` 移入闭包内部。

从闭包定义完成开始，外部的 `s` 就不能再使用了。


## 5、move闭包

`move`闭包可以强制闭包获取所使用环境变量的所有权。

语法是在参数列表前加上 `move`：

```rust
fn main() {
    let s = String::from("hello");

    let closure = move || {
        println!("In closure: {s}");
    };

    // println!("{s}"); // 错误

    closure();
}
```

`move` 常见于线程、异步任务、回调存储等场景。因为这些场景中，闭包可能在当前作用域结束之后才运行，所以不能借用即将失效的局部变量。

需要注意：`move`只影响捕获方式，不直接决定闭包只能调用一次。

```rust
fn main() {
    let s = String::from("hello");

    let closure = move || {
        println!("{s}");
    };

    closure();
    closure();
}
```

这段代码可以运行。虽然 `s` 被移动进闭包，但闭包体只是读取 `s`，没有把 `s` 再从闭包内部移走，所以闭包仍然可以多次调用。

如果闭包体中消耗了 `s`，就只能调用一次：

```rust
fn main() {
    let s = String::from("hello");

    let closure = move || {
        drop(s);
    };

    closure();

    // closure(); // 错误
}
```


# 三、闭包的底层模型

定义闭包时，编译器会为它生成一个匿名类型。这个类型无法直接写出来，但可以近似理解为一个保存环境数据的结构体。

例如：

```rust
let x = 10;

let add_x = |y| y + x;
```

可以近似理解为：

```rust
struct AddX<'a>  {
	x: &'a i32,
}

impl<'a> AddX<'a> {
	fn call(&self, y) {
		y + *self.x
	}
}
```

这只是帮助理解的简化模型，不是编译器真实生成的代码。

闭包本质上包含两部分：

| 部分      | 作用            |
| ------- | ------------- |
| 捕获的环境数据 | 保存外部变量的引用或所有权 |
| 调用能力    | 让闭包可以像函数一样被调用 |

# 四、FnOnce、FnMut和Fn

## 1、三种调用Trait的关系

闭包会根据闭包体的行为，自动实现`FnOnce`、`FnMut`、`Fn`中的一个或多个`Trait`。

所有闭包至少实现`FnOnce`；如果闭包不会把值移出闭包体，还可以实现`FnMut`；如果闭包既不会移出捕获值，也不会修改捕获值，还可以实现`Fn`。

三者关系如下：

```text
Fn
│
▼
FnMut
│
▼
FnOnce
```

也就是说：

| 闭包实现     | 同时也实现                |
| -------- | -------------------- |
| `Fn`     | `FnMut`、`FnOnce`     |
| `FnMut`  | `FnOnce`             |
| `FnOnce` | 不一定实现 `FnMut` 或 `Fn` |

需要区分两个角度：

| 角度        | 说明                           |
| --------- | ---------------------------- |
| 对闭包自身来说   | 实现 `Fn` 的闭包能力最强，因为它可以反复、共享调用 |
| 对函数参数约束来说 | `Fn` 约束最严格，`FnOnce` 约束最宽松    |
例如：

```rust
fn call_once<F>(f: F)
where
	F: FnOnce(),
{
	f();
}
```

`FnOnce`作为参数约束时最宽松，因为`Fn`、`FnMut`、`FnOnce`闭包都可以传进去。

```rust
fn call_fn<F>(f: F)
where
	F: Fn()
{
	f();  
	f();	
}
```

`Fn` 作为参数约束时最严格，因为它要求闭包调用时不能修改内部状态，也不能移出捕获值。


## 2、FnOnce闭包

只实现了`FnOnce`的闭包只能调用一次。

如果闭包调用时把捕获的值从闭包内部移走，那么闭包只能调用一次。

```rust
fn call_once<F>(f: F)
where
    F: FnOnce(),
{
    f();

    // f(); // 错误：f 已经在第一次调用时被消耗
}

fn main() {
    let s = String::from("hello");

    call_once(move || {
        println!("{s}");
        drop(s);
    });
}
```

这里 `drop(s)` 会消耗闭包内部的 `s`，所以这个闭包只能调用一次，闭包只实现了`FnOnce`。

以 `FnOnce` 为参数的函数可以接收三类闭包：

```rust
fn call_once<F>(f: F)
where
    F: FnOnce(),
{
    f();
}

fn main() {
    let s1 = String::from("hello");
	
	// FnOnce
    call_once(move || {
        drop(s1);
    });

    let mut s2 = String::from("hello");
	
	// FnMut
    call_once(|| {
        s2.push_str(" world");
    });

    let s3 = String::from("hello");
	
	// Fn
    call_once(|| {
        println!("{s3}");
    });
}
```

因为 `Fn` 和 `FnMut` 都可以向下满足 `FnOnce` 约束。

## 3、FnMut闭包

`FnMut` 表示闭包调用时需要可变地使用闭包自身。

常见情况是：闭包内部会修改捕获的外部变量。

```rust
fn call_mut<F>(mut f: F)
where
    F: FnMut(),
{
    f();
    f();
}

fn main() {
    let mut s = String::from("hello");

    call_mut(|| {
        s.push_str("!");
        println!("{s}");
    });
}
```

`call_mut`的参数需要写成`mut f: F`，因为调用 `FnMut` 闭包时，需要可变地调用闭包本身。

以 `FnMut` 为参数的函数可以接收 `FnMut` 和 `Fn` 闭包，但不能接收只能调用一次的 `FnOnce` 闭包。

## 4、Fn 闭包

`Fn` 表示闭包调用时只需要不可变地使用闭包自身。

这种闭包不会修改捕获状态，也不会移出捕获值。

```rust
fn call_fn<F>(f: F)
where
    F: Fn(),
{
    f();
    f();
}

fn main() {
    let s = String::from("hello");

    call_fn(|| {
        println!("{s}");
    });
}
```

`Fn` 闭包可以多次调用，也不要求闭包变量本身是 `mut`。


## 5、捕获方式和调用Trait

闭包捕获变量的方式和闭包实现的调用`Trait`有关，但不是同一个问题。

闭包捕获环境时，关注的是“闭包如何保存外部变量”：

| 捕获方式  | 含义             |
| ----- | -------------- |
| 不可变借用 | 闭包保存外部变量的共享引用  |
| 可变借用  | 闭包保存外部变量的可变引用  |
| 获取所有权 | 闭包把外部变量移动进自己内部 |

闭包实现 `FnOnce`、`FnMut`、`Fn` 时，关注的是“闭包调用时如何使用自己内部保存的值”：

| 调用 Trait | 调用方式        | 含义            |
| -------- | ----------- | ------------- |
| `FnOnce` | `self`      | 调用时消耗闭包本身     |
| `FnMut`  | `&mut self` | 调用时可能修改闭包内部状态 |
| `Fn`     | `&self`     | 调用时只需要不可变访问闭包 |
所以，不能简单记成：

```
不可变借用 = Fn
可变借用 = FnMut
获取所有权 = FnOnce
```

这种说法只适合作为常见情况，不是严格规则。

例如，一个 `move` 闭包按所有权捕获变量，但如果闭包体只是读取这个变量，它仍然可以实现 `Fn`：

```rust
fn call_fn<F>(f: F)
where
    F: Fn(),
{
    f();
    f();
}

fn main() {
    let s = String::from("hello");

    call_fn(move || {
        println!("{s}");
    });
}
```

这里 `s` 被移动进闭包，但闭包调用时没有修改 `s`，也没有移出 `s`，所以这个闭包仍然可以满足 `Fn` 约束。

# 五、函数指针与闭包类型

## 1、函数指针类型

普通函数也可以像值一样传递。

```rust
fn add_one(x: i32) -> i32 {
    x + 1
}

fn main() {
    let f = add_one;

    let result = f(1);

    println!("{result}");
}
```

普通函数项可以被转换为函数指针。函数指针类型写作：

```rust
fn(i32) -> i32
```

可以把函数指针作为参数：

```rust
fn apply(f: fn(i32) -> i32, arg: i32) -> i32 {
    f(arg)
}

fn add_one(x: i32) -> i32 {
    x + 1
}

fn main() {
    let result = apply(add_one, 5);

    println!("{result}");
}
```

这里 `apply` 接收的是函数指针 `fn(i32) -> i32`。

## 2、闭包的独立匿名类型

闭包虽然可以像函数一样调用，但闭包的类型不是简单的 `fn(i32) -> i32`。

```rust
fn main() {
    let add_one = |x| x + 1;

    let result = add_one(1);

    println!("{result}");
}
```

`add_one` 的真实类型是编译器生成的匿名类型。每个闭包都有自己独一无二的类型，即使两个闭包的参数和返回值完全相同，它们的类型也不同。

```rust
let c1 = |x: i32| x + 1;
let c2 = |x: i32| x + 1;
```

`c1` 和 `c2` 是两个不同的闭包类型。

**没有捕获环境的闭包可以强制转换为函数指针**：

```rust
fn apply(f: fn(i32) -> i32, arg: i32) -> i32 {
    f(arg)
}

fn main() {
    let add_one = |x| x + 1;

    let result = apply(add_one, 1);

    println!("{result}");
}
```

**捕获环境的闭包不能转换为函数指针**：

```rust
fn apply(f: fn(i32) -> i32, arg: i32) -> i32 {
    f(arg)
}

fn main() {
    let base = 10;

    let add_base = |x| x + base;

    // 错误：add_base 捕获了 base，不能转换为 fn(i32) -> i32
    // let result = apply(add_base, 1);
}
```

原因是函数指针只保存代码地址，不保存环境；而捕获环境的闭包需要保存外部变量。

## 3、使用泛型接收闭包

如果希望函数既能接收普通函数，也能接收闭包，通常使用泛型和 `Fn` / `FnMut` / `FnOnce` 约束。

```rust
fn apply<F>(f: F, arg: i32) -> i32
where
    F: Fn(i32) -> i32,
{
    f(arg)
}

fn add_one(x: i32) -> i32 {
    x + 1
}

fn main() {
    let result1 = apply(add_one, 1);

    let base = 10;
    let result2 = apply(|x| x + base, 1);

    println!("{result1}");
    println!("{result2}");
}
```

也可以写成 `impl Trait`：

```rust
fn apply(f: impl Fn(i32) -> i32, arg: i32) -> i32 {
    f(arg)
}
```

选择哪种调用 `Trait`，取决于函数内部如何使用回调：

|函数内部行为|参数约束|
|---|---|
|只调用一次，可能消耗闭包|`FnOnce`|
|可能多次调用，并允许修改闭包状态|`FnMut`|
|可能多次调用，且只读使用闭包|`Fn`|

# 六、闭包的Copy和Clone

闭包能否`Copy`和`Clone`，取决于它捕获的内容能否`Copy`和`Clone`。

闭包可以近似理解成一个捕获内容的结构体，所以规则和结构体类似：

| 捕获内容                  | 闭包是否可能 `Copy` / `Clone` |
| --------------------- | ----------------------- |
| 没有捕获内容                | 通常可以 `Copy`、`Clone`     |
| 只捕获共享引用               | 通常可以 `Copy`、`Clone`     |
| 捕获可变引用                | 通常不能 `Copy`、`Clone`     |
| `move` 捕获的值都能 `Copy`  | 闭包通常可以 `Copy`           |
| `move` 捕获的值都能 `Clone` | 闭包通常可以 `Clone`          |

一个不修改变量的非 `move` 闭包只持有共享引用，这些引用既能 `Clone` 也能 `Copy` ，所以闭包也能 `Clone` 和 `Copy` 。

```rust
fn main() {
    let x = 1;

    let add_x = |y| y + x;

    let add_x_copy = add_x;

    let result = add_x_copy(add_x(1));

    println!("{result}");
}
```

一个会修改值的非 `move` 闭包持有可变引用，可变引用既不能 `Copy` 也不能 `Clone` ，所以闭包也不能 `Copy` 和 `Clone` ：

```rust
fn main() {
    let mut x = 1;

    let add_to_x = |y| {
        x += y;
        x
    };

    let mut moved = add_to_x;

    // 错误：add_to_x 已经被移动
    // let a = add_to_x(1);

    let b = moved(1);

    println!("{b}");
    println!("{x}");
}
```

闭包修改了 `x`，因此捕获了 `x` 的可变引用。可变引用不能 `Copy`，所以 `let mut moved = add_to_x;` 是移动闭包，而不是复制闭包。

对于 `move` 闭包，如果其捕获的内容都能 `Copy` ，那么闭包就能 `Copy` ；如果其捕获的内容都能 `Clone` ，那么闭包就能 `Clone` 。

```rust
fn main() {
    let greeting = String::from("hello ");

    let greet = move |name: &str| {
        println!("{greeting}{name}");
    };

    greet.clone()("Tom");
    greet.clone()("Jerry");
}
```

`String` 实现了 `Clone`，所以这个闭包也可以被克隆。

如果闭包内部会修改捕获的 `String`，克隆出来的闭包会各自拥有一份独立的 `String`：

```rust
fn main() {
    let mut greeting = String::from("hello ");

    let greet = move |name: &str| {
        greeting.push_str(name);
        println!("{greeting}");
    };

    greet.clone()("Tom");
    greet.clone()("Jerry");
}
```

`.clone()(...)` 的意思是：先克隆闭包，然后立刻调用克隆出来的闭包


# 七、闭包作为回调

## 1、立即调用的回调

回调就是由调用者传入一段逻辑，函数或库在合适的时候调用这段逻辑。

最简单的回调是传入后可立即调用：

```rust
fn run_task<F>(name: &str, callback: F) -> String
where
    F: Fn(&str) -> String,
{
    callback(name)
}

fn main() {
    let greeting = run_task("Tom", |name| format!("Hello, {name}"));

    println!("{greeting}");
}
```

这里：

| 角色                                  | 作用       |
| ----------------------------------- | -------- |
| `run_task`                          | 接收并调用回调  |
| `callback`                          | 调用者传入的逻辑 |
| `\|name\| format!("Hello, {name}")` | 具体闭包     |

## 2、存储回调时的泛型限制

如果只保存一种闭包类型，可以使用泛型：

```rust
use std::collections::HashMap;

struct CommandDispatcher<C>
where
    C: Fn(&str) -> String,
{
    commands: HashMap<String, C>,
}

impl<C> CommandDispatcher<C>
where
    C: Fn(&str) -> String,
{
    fn new() -> Self {
        Self {
            commands: HashMap::new(),
        }
    }

    fn add_command(&mut self, command: &str, callback: C) {
        self.commands.insert(command.to_string(), callback);
    }
}
```

注册一条命令没有问题：

```rust
fn main() {
    let mut dispatcher = CommandDispatcher::new();

    dispatcher.add_command("hello", |name| {
        format!("你好, {name}!")
    });
}
```

但注册第二条命令会出问题：

```rust
fn main() {
    let mut dispatcher = CommandDispatcher::new();

    dispatcher.add_command("hello", |name| {
        format!("你好, {name}!")
    });

    dispatcher.add_command("bye", |name| {
        format!("再见, {name}!")
    });
}
```

原因是：每个闭包都有独立的匿名类型。

即使两个闭包都满足 `Fn(&str) -> String`，它们仍然是两个不同的具体类型。而 `HashMap<String, C>` 要求所有值都是同一个具体类型 `C`。


## 3、使用 Trait Object 存储不同闭包

如果要在同一个集合中存储多个类型的不同闭包，可以使用`Box<dyn Fn(...) -> ...>`。

```rust
use std::collections::HashMap;

type BoxedCallback = Box<dyn Fn(&str) -> String>;

struct CommandDispatcher {
    commands: HashMap<String, BoxedCallback>,
}

impl CommandDispatcher {
    fn new() -> Self {
        Self {
            commands: HashMap::new(),
        }
    }

    fn add_command<C>(&mut self, command: &str, callback: C)
    where
        C: Fn(&str) -> String + 'static,
    {
        self.commands
            .insert(command.to_string(), Box::new(callback));
    }

    fn run(&self, command: &str, arg: &str) -> String {
        match self.commands.get(command) {
            Some(callback) => callback(arg),
            None => format!("未知的命令: {command}"),
        }
    }
}

fn main() {
    let mut dispatcher = CommandDispatcher::new();

    dispatcher.add_command("hello", |name| {
        format!("你好, {name}!")
    });

    dispatcher.add_command("bye", |name| {
        format!("再见, {name}!")
    });

    println!("{}", dispatcher.run("hello", "Tom"));
    println!("{}", dispatcher.run("bye", "Tom"));
    println!("{}", dispatcher.run("unknown", "Tom"));
}
```

| 写法                                | 含义                               |
| --------------------------------- | -------------------------------- |
| `dyn Fn(&str) -> String`          | 一个实现了 `Fn(&str) -> String` 的动态类型 |
| `Box<dyn Fn(&str) -> String>`     | 把不同闭包装箱，统一成同一种类型                 |
| `HashMap<String, BoxedCallback>`  | 可以保存多个不同闭包                       |
| `C: Fn(&str) -> String + 'static` | 传入的闭包可以被长期保存                     |
`'static`表示闭包不能借用很快失效的局部变量。因为闭包会被存进 `CommandDispatcher`，以后才可能被调用。

下面这种写法会出问题：

```rust
fn main() {
    let prefix = String::from("你好");

    let mut dispatcher = CommandDispatcher::new();

    dispatcher.add_command("hello", |name| {
        format!("{prefix}, {name}!")
    });
}
```

闭包借用了局部变量 `prefix`，但 `dispatcher` 可能比这个借用活得更久。可以使用 `move` 把 `prefix` 移入闭包：

```rust
fn main() {
    let prefix = String::from("你好");

    let mut dispatcher = CommandDispatcher::new();

    dispatcher.add_command("hello", move |name| {
        format!("{prefix}, {name}!")
    });

    println!("{}", dispatcher.run("hello", "Tom"));
}
```

这也是 `move` 闭包在回调存储场景中非常常见的原因。

## 4、函数指针版本的回调存储

如果回调不需要捕获环境，也可以使用函数指针，避免 `Box` 和动态分发。

```rust
use std::collections::HashMap;

struct CommandDispatcher {
    commands: HashMap<String, fn(&str) -> String>,
}

impl CommandDispatcher {
    fn new() -> Self {
        Self {
            commands: HashMap::new(),
        }
    }

    fn add_command(&mut self, command: &str, callback: fn(&str) -> String) {
        self.commands.insert(command.to_string(), callback);
    }

    fn run(&self, command: &str, arg: &str) -> String {
        match self.commands.get(command) {
            Some(callback) => callback(arg),
            None => format!("未知的命令: {command}"),
        }
    }
}

fn hello(name: &str) -> String {
    format!("你好, {name}!")
}

fn bye(name: &str) -> String {
    format!("再见, {name}!")
}

fn main() {
    let mut dispatcher = CommandDispatcher::new();

    dispatcher.add_command("hello", hello);
    dispatcher.add_command("bye", bye);

    println!("{}", dispatcher.run("hello", "Tom"));
    println!("{}", dispatcher.run("bye", "Tom"));
}
```

没有捕获环境的闭包也可以传给 `fn(&str) -> String`：

```rust
dispatcher.add_command("hello", |name| format!("你好, {name}!"));
```

但捕获环境的闭包不行：

```rust
let prefix = String::from("你好");

// 错误：捕获了 prefix，不能转换为函数指针
// dispatcher.add_command("hello", |name| format!("{prefix}, {name}!"));
```

函数指针适合简单、无状态的回调；`Box<dyn Fn>` 适合需要捕获环境、并且要存储多种不同闭包的场景。


# 八、闭包在排序中的使用

## 1、sort 与 Ord 约束

如果想对整数向量排序，可以直接用`sort()`方法。

```rust
fn main() {
    let mut numbers = vec![3, 1, 4, 2];

    numbers.sort();

    println!("{numbers:?}");
}
```

`sort`要求元素类型实现`Ord`：

```rust
impl<T> [T] {
	pub fn sort(&mut self)
	where
		T: Ord
	{
		// ... 
	}
}
```

对于自定义类型，如果没有实现 `Ord`，就不能直接调用 `sort()`：

```rust
struct Person {
    name: String,
    age: u8,
}

fn main() {
    let mut people = vec![
        Person {
            name: "Tom".to_string(),
            age: 25,
        },
        Person {
            name: "Bob".to_string(),
            age: 30,
        },
        Person {
            name: "Alice".to_string(),
            age: 27,
        },
    ];

    people.sort();
}
```

报错原因是：`Person` 没有实现 `Ord`，而 `sort()` 要求 `T: Ord`。

可以通过派生宏为 `Person` 自动实现排序相关 `Trait`：

```rust
#[derive(Debug, Ord, PartialOrd, Eq, PartialEq)]
struct Person {
    name: String,
    age: u8,
}
```

但自动派生的比较规则会按照字段声明顺序进行字典序比较。上面的结构体会先比较 `name`，如果 `name` 相同，再比较 `age`。

如果只想按照 `age` 排序，直接派生 `Ord` 就不合适。

## 2、sort_by_key与闭包

按字段排序可以使用 `sort_by_key()`。它的核心思想是：把每个元素映射成一个可排序的 `key`，然后根据这个 `key` 排序。

`sort_by_key()` 接收一个闭包，闭包参数是当前元素的引用，返回值是用于排序的键；这个键需要实现 `Ord`。标准库中 `sort_by_key` 的约束包含 `F: FnMut(&T) -> K` 和 `K: Ord`。

可以先写一个普通函数作为排序规则：

```rust
#[derive(Debug)]
struct Person {
    name: String,
    age: u8,
}

fn age_key(p: &Person) -> u8 {
    p.age
}

fn main() {
    let mut people = vec![
        Person {
            name: "Tom".to_string(),
            age: 25,
        },
        Person {
            name: "Bob".to_string(),
            age: 30,
        },
        Person {
            name: "Alice".to_string(),
            age: 27,
        },
    ];

    people.sort_by_key(age_key);

    println!("{people:#?}");
}
```

也可以直接使用闭包：

```rust
people.sort_by_key(|p| p.age);
```

这里的 `|p| p.age` 接收一个 `Person` 的引用 `p`，返回 `p.age` 作为排序键。

如果想按照年龄降序排序，推荐使用`std::cmp::Reverse`：

```rust
use std::cmp::Reverse;

people.sort_by_key(|p| Reverse(p.age));
```

`Reverse(p.age)` 会把原本的升序比较反转成降序比较。
