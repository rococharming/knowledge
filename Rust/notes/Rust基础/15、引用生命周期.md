# 一、生命周期的基本概念

生命周期（lifetime）是 Rust 中描述引用有效范围的机制。

在[[Rust/notes/Rust基础/14、泛型|泛型]]中，泛型参数可以让代码适用于多种类型。生命周期也可以看作一种特殊的泛型参数：它不描述“值是什么类型”，而是描述“引用在多长时间内有效”。

引用本身不拥有数据，所以 Rust 必须保证：

> 一个引用被使用时，它指向的数据一定还没有被释放。

大部分时候，生命周期不需要手动写出来。编译器可以根据引用的创建位置、最后一次使用位置和被引用数据的作用域自动推断。

但当一个函数接收多个引用，并且返回值也是引用时，编译器有时无法判断返回值到底和哪个参数有关。这时就需要显式生命周期标注，把多个引用之间的关系写在函数签名里。

需要注意：

**生命周期标注不会延长任何值的生命周期，它只是在类型层面描述多个引用之间的有效期关系。**


# 二、悬垂引用

生命周期最直接的目标，是避免**悬垂引用**（dangling reference）。

悬垂引用：引用还存在，但它指向的数据已经被释放。

示例：

```rust
fn main() {
    let r;

    {
        let x = 5;
        r = &x;
    }

    println!("{r}");
}
```

这段代码无法通过编译：

![[assets/Pasted image 20260717100243.png|400]]

原因是：

- `x` 定义在内部作用域中
- `r` 定义在外部作用域中
- 当内部作用域结束时，`x` 被释放
- 但外部作用域中的 `r` 还想继续引用 `x`

如果 Rust 允许这段代码，`r` 就会指向一个已经失效的值。

所以编译器提示：

```text
`x` does not live long enough
```

即`x` 活得不够久，不能被一个更外层的引用继续使用。

可以把这段代码的生命周期关系理解为：

```rust
fn main() {
    let r;                // ----------+-- r 的作用域
                          //           |
    {                     //           |
        let x = 5;        // ---+-- x 的作用域
        r = &x;           //    |
    }                     // ---+
                          //           |
    println!("{r}");      // 这里 r 仍然要用
}                         // ----------+
```

`x` 的作用域比 `r` 短，所以 `r` 不能引用 `x` 后再离开内部作用域继续使用。

如果把被引用的数据放到外层作用域，就可以编译：

```rust
fn main() {
    let x = 5;
    let r = &x;

    println!("{r}");
}
```

这里 `x` 比 `r` 活得更久，所以 `r` 在被使用时总是有效的。


# 三、借用检查器

Rust 编译器中负责检查引用是否有效的工具，叫做借用检查器（borrow checker）。

借用检查器会同时检查两类规则：

1. 借用规则
2. 生命周期规则

[[Rust/notes/Rust基础/8、引用和切片|引用和切片]]中已经见过借用规则：

- 同一时间可以有多个共享引用
- 同一时间只能有一个可变引用
- 可变引用存在时，不能同时使用其他引用访问同一个值

生命周期规则关注的是另一件事：

> 引用的有效范围不能超过被引用数据的有效范围。

因此，**生命周期不是一种运行时机制**。它不会在运行时记录引用是否有效，也不会带来额外性能开销。**它是在编译期完成的静态检查**。


# 四、生命周期标注语法

生命周期参数以单引号开头，通常使用短小的小写名称，例如 `'a`。

常见写法如下：

```rust
&i32        // 普通共享引用
&'a i32     // 带有生命周期标注的共享引用
&'a mut i32 // 带有生命周期标注的可变引用
```

`'a` 本身没有特殊含义，只是一个名字。它真正表达的是：哪些引用拥有同一个生命周期关系。

例如：

```rust
fn demo<'a>(x: &'a str) -> &'a str {
    x
}
```

这里的意思不是“让 `x` 活得更久”，而是：

> 返回值引用的有效期，不能超过参数 `x` 所引用数据的有效期。

生命周期参数和类型泛型参数一样，需要先声明再使用。声明位置在函数名后面的尖括号中：

```rust
fn function_name<'a>(param: &'a str) -> &'a str {
    param
}
```

如果同时有类型泛型参数和生命周期参数，它们写在同一个尖括号里：

```rust
fn demo<'a, T>(value: &'a T) -> &'a T {
    value
}
```


# 五、函数中的生命周期

生命周期最常见的显式使用场景，是函数参数和返回值都是引用；例如 [[Rust/notes/项目/01_minigrep/4、搜索功能、环境变量与输出流|搜索功能、环境变量与输出流]] 中的 `search` 返回来自 `contents` 的 `&str`。

假设要写一个函数，接收两个字符串切片，返回较长的那个：

```rust
fn longest(x: &str, y: &str) -> &str {
    if x.len() > y.len() {
        x
    } else {
        y
    }
}
```

这段代码不能编译：

![[assets/Pasted image 20260717101321.png|800]]

编译器提示：缺少生命周期标注。

这里的关键问题是：返回值可能引用`x`，也可能引用`y`，Rust 不知道返回引用的生命周期应该和谁绑定。

`x`和`y`可能来自两个不同的字符串，生命周期也可能不同。因此编译器无法自动确定：

- 返回值跟`x`一样久?
- 还是跟`y`一样久？

由于函数签名没有说明这个关系，编译器无法安全地判断返回引用是否有效。

举个反例。假如 Rust 擅自认为：返回值的生命周期只跟`x`绑定。

相当于：

```rust
fn longest<'a>(x: &'a str, y: &str) -> &'a str
```

这也意味着：返回值的引用只需满足不超过`x`的生命周期即可。

但如果是下面这种情况：

```rust
fn main() {
    let x = String::from("abc");
    let result;

    {
        let y = String::from("abcdefgh");

        result = longest(&x, &y);
        // y 更长，所以 result 实际引用的是 y
    } // y 在这里被释放

    println!("{result}"); // result 已经指向被释放的 y
}
```

执行过程是：

![[assets/Pasted image 20260717103223.png|600]]

所以返回值不能简单地和`x`绑定。

正确写法是显式标注生命周期：

```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() {
        x
    } else {
        y
    }
}
```

这个签名表达的是：

> `x`、`y` 和返回值之间存在同一个生命周期关系 `'a`。返回值的有效期不能超过 `x` 和 `y` 中较短的那个。

示例：

```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() {
        x
    } else {
        y
    }
}

fn main() {
    let s1 = String::from("rust language");

    {
        let s2 = String::from("rust");
        let result = longest(s1.as_str(), s2.as_str());

        println!("{result}");
    }
}
```

这段代码可以编译，因为 `result` 只在 `s2` 的作用域内使用。即使 `s1` 活得更久，返回值也最多只能被认为和较短的 `s2` 一样久。

如果把 `result` 的使用放到内部作用域外，就会出错：

```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() {
        x
    } else {
        y
    }
}

fn main() {
    let s1 = String::from("rust language");
    let result;

    {
        let s2 = String::from("rust");
        result = longest(s1.as_str(), s2.as_str());
    }

    println!("{result}");
}
```

虽然从人的角度看，`"rust language"` 更长，`result` 实际会引用 `s1`。但编译器不会根据字符串内容来推断分支结果。

函数签名告诉编译器：返回值可能来自 `x`，也可能来自 `y`，所以返回值必须受到两个参数中较短生命周期的限制。`s2` 离开作用域后，`result` 就不能再使用。


# 六、生命周期标注描述的是关系

生命周期标注应该根据函数真实返回了什么来写。

如果函数总是返回第一个参数，那么第二个参数的生命周期就不需要和返回值关联：

```rust
fn first<'a>(x: &'a str, y: &str) -> &'a str {
    println!("ignored: {y}");
    x
}
```

这里的返回值只来自 `x`，所以返回值和 `x` 使用同一个生命周期 `'a`。参数 `y` 只是临时读取，不参与返回值的生命周期关系。

反过来，如果返回值引用的是函数内部创建的局部变量，无论怎么写生命周期都不行：

```rust
fn wrong<'a>() -> &'a str {
    let s = String::from("temporary");
    s.as_str()
}
```

这段代码不能编译，原因是 `s` 在函数结束时就会被释放，返回 `s.as_str()` 会产生悬垂引用。

生命周期标注并不能把局部变量变成长寿命变量。遇到这种情况，通常应该返回拥有所有权的类型：

```rust
fn right() -> String {
    String::from("temporary")
}
```

可以这样记：

> 返回引用时，这个引用通常必须来自某个输入引用；如果它来自函数内部创建的数据，就应该返回拥有所有权的值。


# 七、结构体中的引用字段

如果结构体字段保存的是引用，就需要为结构体声明生命周期参数，用来描述：

> 结构体中的引用，与被引用数据之间的生命周期关系。

示例：

```rust
struct Excerpt<'a> {
    text: &'a str,
}

fn main() {
    let article = String::from("Rust is fast. Rust is safe.");
    let first_sentence = article.split('.').next().unwrap();

    let excerpt = Excerpt {
        text: first_sentence,
    };

    println!("{}", excerpt.text);
}
```

这里存在引用关系：

```
excerpt.text
   │
   ▼
article 中的字符串数据
```

`Excerpt<'a>` 中的`'a`表示：

```rust
text: &'a str
```

`text`引用的字符串数据，在生命周期`'a`内必须保持有效。

因此，编译器会保证：

> 只要`excerpt`还会被使用，它内部的`text`就不能成为无效引用。

也可以通俗地理解为：`excerpt`只是借用字符串，它不能在原字符串失效后继续使用。

例如，下面的代码无法通过编译：

```rust
struct Excerpt<'a> {
    text: &'a str,
}

fn main() {

    let excerpt;

    {
        let article = String::from("Rust is fast.");

        excerpt = Excerpt {
            text: &article,
        }
    } // article 在这里被释放


    println!("{}", excerpt.text);
}
```

离开内部作用域后，`article` 已经被释放。如果继续使用 `excerpt.text`，就会产生悬垂引用，因此 Rust 会在编译阶段阻止这种情况。

如果结构体直接拥有字符串数据，就不需要生命周期参数：

```rust
struct OwnedExcerpt {
    text: String,
}
```

所以可以简单区分：

- 字段是 `String`：结构体拥有字符串
- 字段是 `&str`：结构体只是借用字符串，因此需要生命周期约束


# 八、生命周期省略规则

虽然每个引用都有生命周期，但很多情况下不需要显式标注，因为 Rust 会根据固定规则自动补全。

例如：

```rust
fn first_word(s: &str) -> &str {
    match s.find(' ') {
        Some(index) => &s[..index],
        None => s,
    }
}
```

完整形式相当于：

```rust
fn first_word<'a>(s: &'a str) -> &'a str {
    match s.find(' ') {
        Some(index) => &s[..index],
        None => s,
    }
}
```

这表示：返回值引用的数据来自 `s`，因此返回引用不能比 `s` 有效得更久。

原因是 Rust 有生命周期省略规则。它们不是程序员必须主动遵守的规则，而是编译器在特定模式下自动补全生命周期的规则。

## 1、规则一：每个引用参数都有独立生命周期

例如：

```rust
fn compare(x: &str, y: &str)
```

编译器会理解为：

```rust
fn compare<'a, 'b>(x: &'a str, y: &'b str)
```

`x` 和 `y` 可能来自不同的数据，因此不能默认它们的生命周期相同。


## 2、规则二：只有一个输入引用时，输出引用与它关联

例如：

```rust
fn first_word(s: &str) -> &str
```

因为只有一个引用参数，所以编译器可以推导出：

```rust
fn first_word<'a>(s: &'a str) -> &'a str
```

因此这种情况可以省略生命周期标注。

但多个输入引用时，可能无法推导，例如：

```rust
fn longest<'a, 'b>(x: &'a str, y: &'b str) -> &str
```

编译器会先将两个参数视为不同的生命周期：

```rust
fn longest<'a, 'b>(x: &'a str, y: &'b str) -> &str
```

但返回值可能来自 `x`，也可能来自 `y`，编译器无法判断返回引用应该与谁关联，因此需要显式标注：

```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() {
        x
    } else {
        y
    }
}
```

这表示返回引用的使用范围不能超过 `x` 和 `y` 共同有效的范围。

## 3、规则三：方法返回引用时，默认与 `self` 关联

如果为带生命周期参数的结构体实现方法，需要在 `impl` 后声明生命周期，并在结构体名称后使用：

```rust
struct Excerpt<'a> {
    text: &'a str,
}

impl<'a> Excerpt<'a> {
    fn len(&self) -> usize {
        self.text.len()
    }
}
```

这里的：

```rust
impl<'a> Excerpt<'a>
```

和泛型类型中的：

```rust
impl<T> Point<T>
```

作用类似：先声明参数，再指定为哪种结构体实现方法。

需要注意，这里的`'a`描述的是：`Excerpt`中`text`引用与它所引用的字符串之间的关系。

如果方法返回结构体内部的引用，可以利用生命周期省略规则：

```rust
impl<'a> Excerpt<'a> {
    fn get_text(&self) -> &str {
        self.text
    }
}
```

因为方法参数中存在 `&self`，所以返回值省略的生命周期会默认与 `self` 的借用生命周期关联。

完整形式可以理解为：

```rust
impl<'a> Excerpt<'a> {
    fn get_text<'b>(&'b self) -> &'b str {
        self.text
    }
}
```

这里有两个不同的生命周期：

- `'a`：`text`所引用字符串的生命周期
- `'b`：本次借用`self`的生命周期

返回值使用`'b`，表示：

> 只要对`self`的这次借用仍然有效，返回的引用就可以继续使用。

之所以默认与 `self` 关联，是因为方法返回引用时，最常见的情况就是返回对象内部的数据，例如：

```rust
fn get_text(&self) -> &str
fn name(&self) -> &str
fn first(&self) -> &Item
```

这些返回值通常都来自 `self`。因此 Rust 将其定义为一条固定的省略规则，让常见的访问方法不必反复书写生命周期。

需要注意，编译器并不是分析函数体后才得出这个结论，而是直接根据方法签名应用规则。

如果返回值实际来自其他参数，就需要显式标注生命周期关系。

# 九、静态生命周期

`'static` 是一个特殊生命周期，表示引用在整个程序运行期间都有效。

字符串字面量天然具有 `'static` 生命周期：

```rust
let s: &'static str = "hello";
```

原因是字符串字面量存放在程序的二进制文件中，程序运行期间一直可用。

但不要把 `'static` 当作解决生命周期报错的万能办法。

如果编译器提示你考虑 `'static`，真正的问题通常是：

- 返回了局部变量的引用
- 引用之间的生命周期关系写错了
- 某个值活得不够久

这时应该优先修正数据的所有权关系或生命周期关系，而不是强行把引用标成 `'static`。
