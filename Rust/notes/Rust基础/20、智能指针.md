# 一、概述

智能指针是一类“像指针一样间接访问数据，但额外承担所有权、资源管理或运行时检查”的类型。

Rust 中最常见的指针形式是**引用**：

```rust
let x = 10;
let r = &x;
```

**引用本质上是对已有数据的借用，不拥有数据**。它的核心语义不是保存地址，而是临时访问某个值，并受借用规则约束。

智能指针与引用又不同，它们通常是结构体类型，除了保存指向数据的指针外，还可能额外保存元数据或管理逻辑。例如，`String`和`Vec<T>`本质上都是智能指针，它们内部都持有指向堆区数据的指针，还额外保存了长度、容量元数据。`String`还保证其内容始终都是合法的UTF-8字节。

智能指针通常会实现一些特殊`Trait`，其中最重要的是：

| Trait      | 作用               |
| ---------- | ---------------- |
| `Deref`    | 让智能指针可以像引用一样解引用  |
| `DerefMut` | 让智能指针支持可变解引用     |
| `Drop`     | 让值离开作用域时自动执行清理逻辑 |
并不是所有智能指针都必须同时实现这些 Trait，但很多常见智能指针都依赖它们提供”像引用一样使用”和”自动释放资源”的能力。

# 二、Box\<T>与堆分配

## 1、Box\<T>的基本使用

`Box<T>`是Rust中最基础的**拥有型指针**。它会把数据存储在堆上，而`Box<T>`本身作为一个固定大小的指针值存储在栈上。

示例：

```rust
fn main() {
    let a = Box::new(3);

    println!("{}", a);
    println!("{}", *a + 1);
}
```

这里：

- `Box::new(3)`会在堆上分配一个`i32`
- `a`是一个`Box<i32>`，拥有堆上那个`i32`
- `*a`可以解引用到内部的`i32`
- 当`a`离开作用域时，堆上的`i32`被自动释放

`Box<T>`的核心是提供一层堆分配的间接访问。它本身很轻量，但使用它会带来一次堆分配和一次间接访问。

## 2、较大数据的移动

当一个值较大时，就可以把它放到堆上。这样移动变量时，移动的是栈上的`Box<T>`指针值，而不是直接移动整块大数据。

```rust
fn main() {
	let arr = Box::new([0; 1000]);
	
	println!("{}", arr.len());
	
	let arr2 = arr;
	
	println!("{}", arr2.len());
}
```

`[0; 1000]` 被存储在堆上，`arr` 本身是一个 `Box<[i32; 1000]>`。

执行：

```rust
let arr2 = arr;
```

发生的是所有权移动，不是深拷贝。移动之后，堆上的数组仍然只有一份，`arr` 失效，`arr2` 成为新的所有者。

`Box<T>`不是`Copy`类型，所以这里不是复制智能指针，而是移动所有权。

## 3、递归类型的大小确定

Rust编译器必须在编译期知道每个类型的大小。如果一个类型直接包含自己，编译器就无法确定其大小。

下面的定义无法直接通过编译：

```rust
enum List {
	Cons(i32, List),
	Nil
}
```

原因是`List`里面又直接包含一个`List`：

```text
List
└── Cons(i32, List)
               └── Cons(i32, List)
                              └── ...
```

这种结构会导致类型大小无限递归。

编译器编译报错：

![[assets/Image 76.png|400]]

使用 `Box<T>` 可以打断这种无限递归：

```rust
enum List {  
    Cons(i32, Box<List>),  
    Nil  
}  
  
use crate::List::{Cons, Nil};  
  
  
fn main() {  
    let list = Cons(  
        1,  
        Box::new(Cons(  
            2,  
            Box::new(Cons(  
                3,   
                Box::new(Nil)  
            ))  
        ))  
    );  
}
```

此时 `Cons` 中保存的不是完整的 `List`，而是一个 `Box<List>`。`Box<List>` 本身大小固定，因此 `List` 的大小也可以在编译期确定。

## 4、Trait对象的存放

Trait对象`dyn Trait`表示某个实现了该Trait的具体类型。由于具体类型可能不同，`dyn Trait`本身是动态大小类型，通常需要放在指针后面使用，例如`&dyn Trait`，`&mut dyn Trait`或者`Box<dyn Trait>`。

```rust
trait Draw {  
	fn draw(&self);  
}

struct Button {
	id: u32,
}

impl Draw for Button {  
	fn draw(&self) {  
		println!("Draw Button {}", self.id);  
	}  
}

struct Select {  
	id: u32,  
}  
  
impl Draw for Select {  
	fn draw(&self) {  
		println!("Draw Select {}", self.id);  
	}  
}


fn main() {
	
	let elems: Vec<Box<dyn Draw>> = vec![
		Box::new(Button { id: 1 }),
		Box::new(Select { id: 2 }),
	];
	
	for elem in elems {  
		elem.draw();  
	}

}
```

`Vec<Box<dyn Draw>>` 中的每个元素都是一个 `Box<dyn Draw>`。它们可以指向不同的具体类型，只要这些类型都实现了 `Draw`。

不能直接写成 `Vec<dyn Draw>`，因为 `dyn Draw` 的大小在编译期不可知；而 `Box<dyn Draw>` 的大小固定，所以可以放进 `Vec`。

# 三、Deref与DerefMut

## 1、普通引用的解引用

普通引用可以通过`*`访问它指向的值：

```rust
fn main() {
    let x = 5;
    let y = &x;

    assert_eq!(5, x);
    assert_eq!(5, *y);
}
```

`y` 是 `&i32`，`*y` 表示访问引用指向的 `i32`。

如果写成：

```rust
assert_eq!(5, y);
```

会报错，因为 `5` 是 `i32`，而 `y` 是 `&i32`，两者类型不同。

## 2、Box\<T>的解引用

`Box<T>`实现了`Deref`，因此可以像普通引用一样解引用。`Deref` 的作用就是让智能指针在很多场景下可以像引用一样使用。

示例：

```rust
fn main() {
    let x = Box::new(5);

    assert_eq!(5, *x);
}
```

这里 `*x` 会访问 `Box<i32>` 内部的 `i32`。

## 3、自定义类型实现Deref

`Deref`特征的核心形式可以简化理解为：

```rust
trait Deref {
	type Target = ?Sized;
	
	fn deref(&self) -> &Self::Target;
}
```

`Target` 表示解引用后得到的目标类型。

可以自定义一个`MyBox<T>`类型：

```rust
struct MyBox<T>(T);

impl<T> MyBox<T> {
    fn new(value: T) -> Self {
        Self(value)
    }
}
```

此时不能直接对 `MyBox<T>` 使用 `*`：

```rust
fn main() {
    let x = MyBox::new(5);

    assert_eq!(5, *x); // 错误
}
```

编译报错：

![[assets/Pasted image 20260609143251.png|400]]

因为 `MyBox<T>` 还没有实现 `Deref`。

为`MyBox<T>`实现`Deref`：

```rust
use std::ops::Deref;  
  
struct MyBox<T>(T);  
  
impl<T> MyBox<T> {  
    fn new(value: T) -> Self {  
        Self(value)  
    }  
}  
  
impl<T> Deref for MyBox<T> {  
    type Target = T;  
  
    fn deref(&self) -> &Self::Target {  
        &self.0  
    }  
}  
  
fn main() {  
    let x = MyBox::new(5);  
  
    assert_eq!(5, *x);  
}
```

从概念上看，`*x` 会先调用 `deref()` 得到引用，再对引用进行普通解引用：

```text
*(x.deref())
```

实际代码中不需要手动写成这种形式，编译器会做必要的转换。

## 4、Deref强制转换

`Deref`强制转换（deref coercion）允许某些引用类型在函数传参、方法调用等场景中自动转换为目标引用类型。

最常见的例子是`&String`自动转换为`&str`：

```rust
fn print_s(s: &str) {
	println!("{s}");
}

fn main() {
	let s = String::from("hello");  
	  
	print_s(&s);	
}
```

`print_s`需要的参数类型是`&str`，但实际传入的`&s`类型是`&String`。这段代码之所以能通过编译，是因为`String`实现了`Deref<Target = str>`，而Rust会在函数传参时自动应用`Deref`强制转换。

可以把它理解为编译器自动帮你做了类似下面的事情：

```rust
print_s(s.deref());
```

不过实际写代码时不需要手动调用 `deref()`。只要函数需要 `&str`，而你传入的是 `&String`，编译器就会尝试把 `&String` 转换成 `&str`。

这种转换可以连续发生：

```rust
fn print_s(s: &str) {
    println!("{s}");
}

fn main() {
    let s = Box::new(String::from("hello"));

    print_s(&s);
}
```

转换过程可以理解为：

```rust
&Box<String> -> &String -> &str
```

## 5、自定义类型实现DerefMut

`DerefMut`用于支持可变解引用。它建立在`Deref`之上：

```rust
trait DerefMut: Deref {
	fn deref_mut(&mut self) -> &mut Self::Target;
}
```

示例：

```rust
use std::ops::{Deref, DerefMut};  
  
struct MyBox<T>(T);  
  
impl<T> MyBox<T> {  
    fn new(value: T) -> Self {  
        Self(value)  
    }  
}  
  
impl<T> Deref for MyBox<T> {  
    type Target = T;  
  
    fn deref(&self) -> &Self::Target {  
        &self.0  
    }  
}  
  
impl<T> DerefMut for MyBox<T> {  
    fn deref_mut(&mut self) -> &mut Self::Target {  
        &mut self.0  
    }  
}  
  
fn main() {  
    let mut x = MyBox::new(10);  
  
    *x += 1;  
  
    assert_eq!(11, *x);  
}
```

如果只实现`Deref`，只能通过共享引用访问内部值；如果还实现`DerefMut`，才能通过可变引用修改内部值。

## 6、Deref强制转换规则

Rust 在函数传参和方法调用中会自动应用以下转换：

| 条件                        | 可转换形式                | 含义          |
| ------------------------- | -------------------- | ----------- |
| `T: Deref<Target = U>`    | `&T` -> `&U`         | 共享引用转换      |
| `T: DerefMut<Target = U>` | `&mut T` -> `&mut U` | 可变引用转换      |
| `T: Deref<Target = U>`    | `&mut T` -> `&U`     | 可变引用降级为共享引用 |

第三种情况表示：可变引用可以临时作为共享引用使用。

示例：

```rust
fn print(s: &str) {
    println!("{s}");
}

fn main() {
    let mut s = String::from("hello");

    print(&mut s);
}
```

这里 `&mut String` 可以转换为 `&str`，因为 `String` 可以解引用到 `str`，并且可变引用可以降级为共享引用。

# 四、Drop 与自动清理

## 1、Drop的作用

`Drop`用于定义值离开作用域时要执行的清理逻辑。Rust没有垃圾回收器，而是通过所有权和作用域自动管理资源。

当一个值离开作用域时，Rust会自动调用对应的析构逻辑。如果类型实现了`Drop`，就会先执行用户定义的`drop`方法，然后继续清理它的字段。

`Drop` 的定义如下：

```rust
trait Drop {
	fn drop(&mut self);
}
```

只需要实现`drop()`。

示例：

```rust
struct Foo {
    data: String,
}

impl Drop for Foo {
    fn drop(&mut self) {
        println!("Drop Foo with data: {}", self.data);
    }
}

fn main() {
    let _foo = Foo {
        data: String::from("Hello"),
    };

    println!("created Foo");
}
```

结果：

![[assets/Image 77.png|200]]

`drop` 会在 `_foo` 离开作用域时自动调用。

## 2、局部变量的drop顺序

局部变量会按照创建顺序的逆序被销毁。

示例：

```rust
struct HasDrop(&'static str);

impl Drop for HasDrop {
    fn drop(&mut self) {
        println!("drop {}", self.0);
    }
}

fn main() {
    let _a = HasDrop("a");
    let _b = HasDrop("b");

    println!("end of main");
}
```

输出：

```text
end of main
drop b
drop a
```

`_b` 后创建，所以先销毁；`_a` 先创建，所以后销毁。


## 3、结构体字段的drop顺序

结构体字段会在结构体自身的`drop`方法执行之后，按照字段定义顺序被销毁。

示例：

```rust
struct Field(&'static str);

impl Drop for Field {
    fn drop(&mut self) {
        println!("drop field {}", self.0);
    }
}

struct Container {
    first: Field,
    second: Field,
}

impl Drop for Container {
    fn drop(&mut self) {
        println!("drop container");
    }
}

fn main() {
    let _container = Container {
        first: Field("first"),
        second: Field("second"),
    };

    println!("end of main");
}
```

输出：

```text
end of main
drop container
drop field first
drop field second
```

顺序是：

```text
Container::drop
Field(first)::drop
Field(second)::drop
```

即使 `Container` 没有实现 `Drop`，它的字段仍然会被自动清理。Rust 会生成必要的析构逻辑，也就是常说的 `drop glue`。

## 4、提前释放值

Rust 不允许直接手动调用 `Drop::drop`：

```rust
// foo.drop(); // 错误
```

原因是 `Drop::drop(&mut self)` 只是接收一个可变借用。如果允许直接调用，调用后原变量仍然在作用域中，看起来仍然可以继续使用，这会破坏 Rust 的安全模型。

如果希望提前释放值，正确方式是调用标准库函数 `std::mem::drop`，通常直接写成 `drop(value)`。

`std::mem::drop` 本质是一个空实现：

```rust
fn drop<T>(_x: T) { }
```

它将值移动进函数内，函数结束后，参数离开作用域，于是触发析构。

示例：

```rust
struct Foo {
    data: String,
}

impl Drop for Foo {
    fn drop(&mut self) {
        println!("Drop Foo with data: {}", self.data);
    }
}

fn main() {
    let foo = Foo {
        data: String::from("Hello"),
    };

    drop(foo);

    // println!("{}", foo.data); // 错误，foo 已经被移动
}
```

# 五、Rc\<T>与共享所有权

## 1、引用计数机制

Rust默认要求**一个值在同一时刻只能有一个所有者**。但有些数据结构中，确实需要多个地方共同拥有同一份数据。

例如：

- 多个组件共享同一个配置对象
- 多个节点引用同一个只读状态
- 图结构中多个边指向同一个节点
- 多个对象需要共同延长某个值的生命周期

这类场景可以使用引用计数。

`Rc<T>`是共享所有权智能指针，RC是Reference Counted的缩写，用于**单线程**场景下的共享所有权。它会记录当前有多少个`Rc`指向同一份数据，当强引用计数归零时，底层数据才被释放。

## 2、Rc\<T>的基本使用

示例：

```rust
use std::rc::Rc;

fn main() {
    let a = Rc::new(String::from("Hello"));
    let b = Rc::clone(&a);

    assert_eq!(Rc::strong_count(&a), 2);
    assert_eq!(Rc::strong_count(&a), Rc::strong_count(&b));
}
```

这里：

- `Rc::new(...)` 创建一份引用计数管理的数据
- `Rc::clone(&a)` 不会深拷贝底层字符串，只会增加引用计数
- `Rc::strong_count(&a)` 可以查看强引用数量

虽然也可以写 `a.clone()`，但在使用 `Rc<T>` 时通常更推荐写 `Rc::clone(&a)`，这样能清楚表达“增加引用计数”，而不是“深拷贝数据”。

`Rc<T>` 不在 prelude 预导入模块中，需要手动导入：

```rust
use std::rc::Rc;
```


## 3、多个对象共享同一份数据

```rust
use std::rc::Rc;

struct Owner {
    name: String,
}

struct Gadget {
    id: u32,
    owner: Rc<Owner>,
}

fn main() {
    let owner = Rc::new(Owner {
        name: String::from("Tom"),
    });

    let g1 = Gadget {
        id: 1,
        owner: Rc::clone(&owner),
    };

    let g2 = Gadget {
        id: 2,
        owner: Rc::clone(&owner),
    };

    drop(owner);

    println!("Gadget {} owned by {}", g1.id, g1.owner.name);
    println!("Gadget {} owned by {}", g2.id, g2.owner.name);
}
```

`owner`、`g1.owner`、`g2.owner` 曾经共同拥有同一个 `Owner`。

即使提前执行 `drop(owner)`，底层的 `Owner` 也不会立即销毁，因为 `g1.owner` 和 `g2.owner` 仍然持有强引用。

> g1.owner是`Rc<Owner>`类型，实现了`Deref`，编译器看到g1.owner.name时，发现g1.owner没有`name`字段，会自动解引用。

## 4、Rc\<T>只提供共享访问

`Rc<T>` 允许多个所有者共享同一个值，但默认只能提供共享访问，不能直接修改内部值。

示例

```rust
use std::rc::Rc;

fn main() {
    let a = Rc::new(String::from("Hello"));
    let b = Rc::clone(&a);

    // a.push_str(" world"); // 错误
}
```

这里不能调用 `push_str`，因为修改 `String` 需要 `&mut String`，而 `Rc<T>` 只实现了 `Deref<Target = T>`，没有实现 `DerefMut`。

原因很直接：如果多个`Rc`同时指向同一份数据，Rust不能随便允许其中一个所有者拿到可变引用，否则会破坏“多个共享引用不能和可变引用同时存在”的规则。

如果需要多个“所有者 + 可修改”，通常会组合使用：

```rust
Rc<RefCell<T>>
```

## 5、Rc\<T>的适用边界

`Rc<T>` 只能用于单线程场景。它的引用计数更新不是原子操作，因此不能安全地在线程间共享。

多线程场景应该使用`Arc<T>`。

`Arc<T>` 是原子引用计数，适合在线程之间共享所有权。

但 `Arc<T>` 也只解决“共享所有权”，不自动解决“可变访问”。如果要在线程间共享并修改数据，通常还需要组合：

```rust
Arc<Mutex<T>>
Arc<RwLock<T>>
```

# 六、内部可变性

## 1、内部可变性的基本概念

Rust默认遵循一条核心规则：要修改数据，通常必须拿到`&mut T`。

如果只有 `&T`，一般不能修改内部数据。

但在有些场景中，外部只能拿到共享引用，却仍然需要修改对象内部的某个字段，例如：

- 缓存计算结果
- 记录调用次数
- 测试中记录发送过的消息
- 某些Trait方法签名中固定为`&self`
- 多个所有者共享数据后仍需要局部修改

这类能力称为内部可变性。

内部可变性不是绕过Rust安全规则，而是把检查方式转移到特定类型内部。`Cell<T>`和`RefCell<T>`是标准库中最常见的两个内部可变性工具。


## 2、内部可变性的检查方式

普通引用的借用规则主要在编译期检查，而`RefCell<T>`会在运行时追踪借用状态。也就是说，`RefCell<T>`仍然遵守借用规则，只是把错误从编译期推迟到了运行时。

常见内部可变性类型的差异如下：

| 类型           | 检查方式             | 适合场景      |
| ------------ | ---------------- | --------- |
| `Cell<T>`    | 不借出引用，通过整体替换实现修改 | 简单`Copy`值 |
| `RefCell<T>` | 运行时检查借用规则        | 复杂数据结构    |
| `Mutex<T>`   | 运行时加锁            | 多线程共享修改   |
| `RwLock<T>`  | 运行时读写锁           | 多线程多读少写   |


## 3、Cell\<T>与简单值替换

### （1）Cell\<T>解决的问题

`Cell<T>`适合保存简单值，并在只有`&self`的情况下修改这个值。

假设有一个计数器：

```rust
struct Counter {
	count: i32,
}

impl Counter {
	fn increment(&self) {
		self.count += 1; // 错误
	}
}
```

`increment` 接收的是 `&self`，所以不能直接修改 `self.count`。

最自然的写法是改成`&mut self`：

```rust
struct Counter {
    count: i32,
}

impl Counter {
    fn increment(&mut self) {
        self.count += 1;
    }
}

fn main() {
    let mut counter = Counter { count: 0 };

    counter.increment();

    println!("{}", counter.count);
}
```

但有些时候，方法签名不能改。例如 Trait 已经规定方法只能接收`&self`：

```rust
trait Messenger {
    fn send(&self, msg: &str);
}
```

如果实现这个 trait 时想记录调用次数：

```rust
struct MyMessenger {
	count: usize,
}

impl Messenger for MyMessenger {

	fn send(&self, msg: &str) {
		self.count += 1; // 错误
		println!("{}", msg);
	}
}
```

因为 `send` 方法是 `&self` ，不能修改其`count`字段。

这时候可以使用`Cell<T>`：

```rust
use std::cell::Cell;

trait Messenger {
    fn send(&self, msg: &str);
}

struct MyMessenger {
    count: Cell<usize>,
}

impl MyMessenger {
    fn new() -> Self {
        Self {
            count: Cell::new(0),
        }
    }
}

impl Messenger for MyMessenger {
    fn send(&self, msg: &str) {
        self.count.set(self.count.get() + 1);

        println!("send {} times: {}", self.count.get(), msg);
    }
}

fn main() {
    let messenger = MyMessenger::new();

    messenger.send("hello");
    messenger.send("world");
}
```

这里 `send` 接收的是 `&self`，但 `count` 字段仍然可以被修改。


### （2）Cell\<T>的常用方法

|方法|作用|
|---|---|
|`Cell::new(value)`|创建一个 `Cell<T>`|
|`get()`|复制取出内部值，要求 `T: Copy`|
|`set(value)`|覆盖内部值|
|`replace(value)`|替换内部值，并返回旧值|
|`into_inner()`|消费 `Cell<T>`，取出内部值|

`Cell<T>` 最常见的使用模式是：

```rust
let old = cell.get();

cell.set(old + 1);
```


### （3）适用场景

`Cell<T>` 更适合简单的 `Copy` 类型，例如：

- `bool`
- `usize`
- `i32`
- `char`
- 小型枚举

对于复杂类型，`Cell<T>` 通常不如 `RefCell<T>` 方便。

例如：

```rust
use std::cell::Cell;

fn main() {
    let c = Cell::new(vec![1, 2, 3]);

    // c.get();          // 错误，Vec<i32> 不是 Copy
    // c.get().push(4);  // 错误，不能这样借出可变引用
}
```

`Cell<T>` 的核心思路是“整体取值、整体替换”，而不是借出 `&mut T` 让你修改内部结构。

如果需要对内部的 `Vec<T>` 执行 `push`、`insert`、遍历、修改元素等操作，通常应该使用 `RefCell<T>`。

## 3、RefCell\<T>与运行时借用检查

### （1）RefCell\<T>的基本作用

`RefCell<T>`也是内部可变性工具。它适合在只有`&self`或`&T`的情况下，对内部复杂数据进行借用操作。

它和`Cell<T>`的区别是：

| 类型           | 核心方式      | 适合数据        |
| ------------ | --------- | ----------- |
| `Cell<T>`    | 整体取值、整体替换 | 简单 `Copy` 值 |
| `RefCell<T>` | 运行时借用检查   | 复杂数据结构      |

`RefCell<T>`允许调用：

| 方法             | 返回类型        | 作用                    |
| -------------- | ----------- | --------------------- |
| `borrow()`     | `Ref<T>`    | 获取不可变借用               |
| `borrow_mut()` | `RefMut<T>` | 获取可变借用                |
| `into_inner()` | `T`         | 消费 `RefCell<T>`，取出内部值 |
`Ref<T>` 和 `RefMut<T>` 不是普通的 `&T` / `&mut T`，但使用体验非常接近。

### （2）RefCell\<T>的基本使用

```rust
use std::cell::RefCell;

struct Logger {
    logs: RefCell<Vec<String>>,
}

impl Logger {
    fn new() -> Self {
        Self {
            logs: RefCell::new(Vec::new()),
        }
    }

    fn log(&self, msg: String) {
        self.logs.borrow_mut().push(msg);
    }

    fn show(&self) {
        for log in self.logs.borrow().iter() {
            println!("{log}");
        }
    }
}

fn main() {
    let logger = Logger::new();

    logger.log(String::from("start"));
    logger.log(String::from("running"));

    logger.show();
}
```

`log` 方法只接收 `&self`，但仍然可以通过 `borrow_mut()` 修改内部的 `Vec<String>`。


### （3）RefCell\<T>的借用规则

`RefCell<T>`仍然遵守 Rust 的借用规则，只是检查时机从编译期变成运行时。违反规则时，程序会在运行时`panic`。

规则仍然是：

|借用状态|是否允许|
|---|---|
|多个不可变借用|允许|
|一个可变借用|允许|
|多个可变借用|不允许|
|不可变借用和可变借用同时存在|不允许|
示例：

```rust
use std::cell::RefCell;

fn main() {
    let value = RefCell::new(String::from("hello"));

    let r1 = value.borrow();
    let r2 = value.borrow();

    println!("{r1}, {r2}");

    // let r3 = value.borrow_mut(); // 如果 r1/r2 仍然存活，这里会 panic
}
```

如果确实需要可变借用，要确保前面的不可变借用已经结束：

```rust
use std::cell::RefCell;

fn main() {
    let value = RefCell::new(String::from("hello"));

    {
        let r1 = value.borrow();
        println!("{r1}");
    }

    value.borrow_mut().push_str(", world");

    println!("{}", value.borrow());
}
```

这里通过额外的作用域让 `r1` 提前释放，之后再进行可变借用。

# 七、Rc\<RefCell\<T>>的组合

## 1、组合方式

`Rc<T>`和`RefCell<T>`经常组合使用：

| 类型               | 提供能力                |
| ---------------- | ------------------- |
| `Rc<T>`          | 多个所有者共享同一份数据        |
| `RefCell<T>`     | 在运行时检查借用规则，并允许内部可变性 |
| `Rc<RefCell<T>>` | 多个所有者共享同一份可修改数据     |

`Rc<T>`负责共享所有权，`RefCell<T>`负责运行时可变借用。这个组合常用于单线程场景下的共享可变数据。

## 2、基本示例

```rust
use std::cell::RefCell;  
use std::rc::Rc;  
  
fn main() {  
    let s1 = Rc::new(RefCell::new(String::from("hello")));  
    let s2 = Rc::clone(&s1);  
  
    s1.borrow_mut().push_str(", world");  
  
    println!("{}", s1.borrow());  
    println!("{}", s2.borrow());  
}
```

这里：

- `s1` 和 `s2` 共同拥有同一个 `RefCell<String>`
- `Rc` 负责共享所有权
- `RefCell` 负责运行时借用检查
- `borrow_mut()` 可以修改内部字符串

## 3、使用边界

`Rc<RefCell<T>>` 很灵活，但也要谨慎使用。

它会把一部分错误从编译期推迟到运行时。如果借用关系设计混乱，程序可能在运行时 `panic`。

因此，能用普通所有权和普通借用解决的问题，不要优先使用 `Rc<RefCell<T>>`。它更适合那些确实需要“单线程共享所有权 + 内部可变性”的场景。
