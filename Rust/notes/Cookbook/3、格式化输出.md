# 一、概述

Rust 的格式化输出由 `std::fmt` 体系提供，最常见入口是 `println!`、`print!` 和 `format!` 等宏。日志字段中的 `%` / `?` 也是同一套格式化能力，见 [[Rust/notes/Cookbook/2、Rust日志系统|Rust日志系统]]。

格式化字符串中的 `{}` 是占位符。编译器会在编译期检查格式化字符串和参数是否匹配，因此 Rust 的格式化输出比普通字符串拼接更安全。

常见形式：

```rust
fn main() {
    println!("Hello");
    println!("Hello, {}!", "world");
    println!("The number is {}", 1);
    println!("{:?}", (3, 4));
    println!("{value}", value = 4);
    println!("{} {}", 1, 2);
    println!("{:04}", 42);
}
```

结果：

![[assets/Pasted image 20260707224545.png|200]]

需要注意：

- 第一个参数必须是格式化字符串字面量，不能直接传入运行时构造出来的 `String`。
- `{}` 默认使用 `Display` 格式化。
- `{:?}` 使用 `Debug` 格式化，主要用于调试。
- 格式化字符串中的 `{` 和 `}` 本身需要写成 `{{` 和 `}}`。

# 二、常用格式化宏

## 1、输出到标准输出

| 宏 | 输出位置 | 是否换行 | 返回值 |
| --- | --- | --- | --- |
| `print!` | stdout | 否 | `()` |
| `println!` | stdout | 是 | `()` |
| `format!` | 内存中的 `String` | 不涉及 | `String` |

示例：

```rust
fn main() {
    let name = "Rust";

    print!("Hello, ");
    println!("{name}!");

    let message = format!("Hello, {name}!");
    println!("{}", message);
}
```

输出：

```text
Hello, Rust!
Hello, Rust!
```

`format!` 不会输出到终端，而是生成一个新的 `String`。当需要构造错误信息、日志内容、文件内容或 UI 文本时，通常使用 `format!`。

## 2、输出到标准错误

| 宏 | 输出位置 | 是否换行 |
| --- | --- | --- |
| `eprint!` | stderr | 否 |
| `eprintln!` | stderr | 是 |

示例：

```rust
fn main() {
    eprintln!("failed to read config file");
}
```

命令行程序中，普通结果通常写入 stdout，错误信息、诊断信息和进度信息通常写入 stderr。

## 3、写入已有缓冲区

除了直接打印和创建 `String`，还可以用 `write!`、`writeln!` 写入已有目标。

写入 `String` 时使用 `std::fmt::Write`：

```rust
use std::fmt::Write;

fn main() -> std::fmt::Result {
    let mut output = String::new();

    write!(&mut output, "name: {}", "Ferris")?;
    writeln!(&mut output, ", lang: {}", "Rust")?;

    print!("{}", output);
    Ok(())
}
```

写入文件、网络流、标准输出锁等 I/O 目标时使用 `std::io::Write`。两者宏名相同，但背后的 trait 不同。

# 三、`Display` 与 `Debug`

## 1、两种最常见的格式

| 占位符 | 依赖 trait | 用途 |
| --- | --- | --- |
| `{}` | `std::fmt::Display` | 面向用户的可读输出 |
| `{:?}` | `std::fmt::Debug` | 面向开发者的调试输出 |
| `{:#?}` | `std::fmt::Debug` | 更易读的多行调试输出 |

示例：

```rust
#[derive(Debug)]
struct Person {
    name: String,
    age: u8,
}

fn main() {
    let p = Person {
        name: String::from("Alice"),
        age: 18,
    };

    println!("{:?}", p);
    println!("{:#?}", p);
}
```

自定义结构体可以通过 `#[derive(Debug)]` 派生 `Debug`。但 `Display` 不能自动派生，因为面向用户的输出格式往往需要人工设计。

## 2、为自定义类型实现 `Display`

```rust
use std::fmt;

struct Person {
    name: String,
    age: u8,
}

impl fmt::Display for Person {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        write!(f, "{} ({})", self.name, self.age)
    }
}

fn main() {
    let p = Person {
        name: String::from("Alice"),
        age: 18,
    };

    println!("{}", p);
}
```

这段代码的核心不是 `println!` 本身，而是给 `Person` 实现了 `std::fmt::Display` 这个 trait。`Display` 可以粗略理解为“这个类型知道如何把自己写成面向用户的文本”。

`Display` 的关键方法签名是：

```rust
fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result
```

其中：

| 参数 | 含义 |
| --- | --- |
| `&self` | 当前要被格式化的值，例如这里的 `p` |
| `f` | 格式化宏创建并传入的写入上下文 |
| `fmt::Result` | 格式化是否成功，底层是 `Result<(), fmt::Error>` |

`Formatter` 不是最终输出字符串，也不是 stdout。它更像是格式化过程中的“中间写入器”和“格式选项容器”：

- 它知道调用方传入了哪些格式控制参数，例如宽度、对齐、精度、是否使用 alternate 格式。
- 它提供写入接口，让 `fmt` 方法把文本写入当前格式化目标。
- 它屏蔽了最终目标差异：目标可能是 `println!` 的标准输出，也可能是 `format!` 创建的 `String`，还可能是 `write!` 写入的缓冲区。

所以 `fmt` 方法里通常写：

```rust
write!(f, "{} ({})", self.name, self.age)
```

这表示：把 `Person` 的显示文本继续写入 `Formatter` 管理的目标中。这里的 `write!` 不会直接打印到终端，而是把内容交还给当前格式化流程。

`println!("{}", p);` 背后的逻辑可以这样理解：

1. `println!` 解析格式化字符串，发现 `{}` 需要使用 `Display`。
2. 编译器检查 `p` 的类型 `Person` 是否实现了 `std::fmt::Display`。
3. 检查通过后，格式化流程会调用 `Person` 的 `fmt` 方法。
4. `fmt` 方法通过 `write!(f, ...)` 把 `Alice (18)` 写入传入的 `Formatter`。
5. `println!` 把格式化完成的内容写入 stdout，并追加换行。

可以把它类比为下面这种关系：

```text
println!("{}", p)
        │
        │ `{}` 要求 Display
        ▼
<Person as Display>::fmt(&p, formatter)
        │
        │ write!(formatter, "{} ({})", ...)
        ▼
Alice (18)
        │
        ▼
stdout + 换行
```

这里不建议在 `fmt` 内部先 `format!` 出一个 `String` 再写出去，因为那会多一次字符串分配。直接 `write!(f, ...)` 可以把内容写入已有的格式化上下文，更符合 `std::fmt` 的零额外分配倾向。

## 3、用 newtype 包装外部类型

Rust 的孤儿规则不允许直接为“外部类型”实现“外部 trait”。例如不能直接为 `Vec<i32>` 实现 `Display`，因为 `Vec` 和 `Display` 都来自标准库。

解决方式是定义一个本地包装类型：

```rust
use std::fmt;

struct Numbers(Vec<i32>);

impl fmt::Display for Numbers {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        write!(f, "{:?}", self.0)
    }
}

fn main() {
    let numbers = Numbers(vec![1, 2, 3]);
    println!("{}", numbers);
}
```

这种只有一层包装的本地类型通常称为 newtype。

# 四、参数引用方式

## 1、按顺序引用

默认情况下，占位符按参数顺序消耗后续参数：

```rust
fn main() {
    println!("{} {}", "hello", "world");
}
```

## 2、按位置引用

位置参数从 `0` 开始：

```rust
fn main() {
    println!("{1} {0}", "world", "hello");
    println!("{0}, this is {1}. {1}, this is {0}.", "Alice", "Bob");
}
```

显式位置参数适合复用同一个值，或者在翻译文本中调整参数顺序。

## 3、按名称引用

```rust
fn main() {
    println!("{name} is {age} years old", name = "Alice", age = 18);
}
```

具名参数必须放在普通位置参数之后：

```rust
fn main() {
    println!("{name} {}", 18, name = "Alice");
}
```

## 4、捕获当前作用域变量

Rust 1.58 起，格式化字符串可以直接捕获当前作用域中的变量：

```rust
fn main() {
    let name = "Alice";
    let score = 98;

    println!("{name}: {score}");
}
```

它只能捕获标识符变量，不能直接捕获任意表达式。如果要输出表达式结果，可以先绑定变量：

```rust
fn main() {
    let value = 40 + 2;
    println!("{value}");
}
```

# 五、宽度、填充与对齐

## 1、宽度

宽度表示格式化结果至少占多少个显示位置。不足时会填充空格；超过宽度时不会截断。

```rust
fn main() {
    println!("|{:5}|", "x");
    println!("|{:5}|", 42);
}
```

默认行为：

- 字符串通常左对齐。
- 数字通常右对齐。

## 2、对齐

| 写法 | 含义 |
| --- | --- |
| `{:<5}` | 左对齐，宽度 5 |
| `{:>5}` | 右对齐，宽度 5 |
| `{:^5}` | 居中对齐，宽度 5 |

示例：

```rust
fn main() {
    println!("|{:<5}|", "x");
    println!("|{:>5}|", "x");
    println!("|{:^5}|", "x");
}
```

## 3、自定义填充字符

填充字符写在对齐符号前面：

```rust
fn main() {
    println!("|{:*<5}|", "x");
    println!("|{:*>5}|", "x");
    println!("|{:*^5}|", "x");
}
```

如果要指定填充字符，通常也要显式指定对齐方式。

## 4、动态宽度

宽度可以来自参数：

```rust
fn main() {
    println!("|{:width$}|", "x", width = 5);
    println!("|{:1$}|", "x", 5);
    println!("|{value:width$}|", value = "x", width = 5);
}
```

当表格列宽来自配置或计算结果时，动态宽度很有用。

# 六、符号、零填充与精度

## 1、符号

```rust
fn main() {
    println!("{}", 5);
    println!("{:+}", 5);
    println!("{:+}", -5);
}
```

`+` 表示正数也显式显示正号。负数始终会显示负号。

## 2、零填充

```rust
fn main() {
    println!("{:05}", 42);
    println!("{:05}", -42);
}
```

`{:05}` 表示宽度为 5，不足部分用 `0` 填充。符号也会占用宽度。

## 3、浮点精度

精度用于控制浮点数的小数位数：

```rust
fn main() {
    let pi = 3.1415926;

    println!("{:.2}", pi);
    println!("{:+.2}", pi);
    println!("{:.0}", pi);
}
```

精度可以动态指定：

```rust
fn main() {
    let pi = 3.1415926;
    let precision = 4;

    println!("{:.precision$}", pi);
    println!("{:.*}", precision, pi);
}
```

## 4、字符串精度

用于字符串时，精度表示最多输出多少个字符：

```rust
fn main() {
    let s = "hi我是Rust";

    println!("{:.3}", s);
    println!("{:.*}", 4, s);
}
```

字符串精度按字符截断，不是按字节截断，因此不会把 UTF-8 字符切坏。

# 七、数字格式

## 1、进制

| 写法 | 含义 | 示例 |
| --- | --- | --- |
| `{:b}` | 二进制 | `11011` |
| `{:o}` | 八进制 | `33` |
| `{}` | 十进制 | `27` |
| `{:x}` | 小写十六进制 | `1b` |
| `{:X}` | 大写十六进制 | `1B` |

示例：

```rust
fn main() {
    let n = 27;

    println!("{:b}", n);
    println!("{:o}", n);
    println!("{}", n);
    println!("{:x}", n);
    println!("{:X}", n);
}
```

## 2、添加进制前缀

`#` 会启用 alternate 格式。对整数进制来说，它会添加对应前缀：

```rust
fn main() {
    let n = 27;

    println!("{:#b}", n);
    println!("{:#o}", n);
    println!("{:#x}", n);
    println!("{:#X}", n);
}
```

常见输出：

```text
0b11011
0o33
0x1b
0x1B
```

`#` 可以和宽度、零填充组合：

```rust
fn main() {
    println!("{:#010b}", 27);
}
```

输出：

```text
0b00011011
```

## 3、指数形式

```rust
fn main() {
    println!("{:e}", 1_000_000_000);
    println!("{:E}", 1_000_000_000);
}
```

`e` 使用小写指数标记，`E` 使用大写指数标记。

## 4、指针地址

```rust
fn main() {
    let values = vec![1, 2, 3];

    println!("{:p}", values.as_ptr());
}
```

`{:p}` 用于输出指针地址。它适合调试底层内存关系，不适合作为业务逻辑中的稳定标识。

# 八、转义

格式化字符串中的 `{` 和 `}` 有特殊含义。如果要输出字面量花括号，需要写成双花括号：

```rust
fn main() {
    println!("{{}}");
    println!("Hello, {{Rust}}");
}
```

如果还需要输出引号，使用普通 Rust 字符串转义：

```rust
fn main() {
    println!("\"{{Rust}}\"");
}
```

注意不能使用 `\{` 或 `\}` 转义花括号。

# 九、常见组合

## 1、对齐表格

```rust
fn main() {
    println!("{:<12} {:>8}", "name", "score");
    println!("{:<12} {:>8}", "Alice", 98);
    println!("{:<12} {:>8}", "Bob", 7);
}
```

适合简单命令行输出。如果要处理宽字符、颜色控制符或复杂表格，通常应使用专门的表格 crate。

## 2、固定小数位

```rust
fn main() {
    let price = 12.5;
    println!("price: {:.2}", price);
}
```

适合金额、百分比、统计指标等需要固定展示精度的场景。但它只解决“显示格式”，不解决十进制精确计算问题。

## 3、调试复杂结构

```rust
#[derive(Debug)]
struct Config {
    host: String,
    port: u16,
}

fn main() {
    let config = Config {
        host: String::from("localhost"),
        port: 8080,
    };

    println!("{:#?}", config);
}
```

`{:#?}` 比 `{:?}` 更适合观察嵌套结构，但它仍然是调试输出，不应该被当成稳定的外部数据格式。

# 十、易错点

## 1、`Display` 不等于 `Debug`

很多类型实现了 `Debug`，但没有实现 `Display`。例如 `Vec<T>` 通常可以用 `{:?}` 输出，但不能直接用 `{}` 输出。

```rust
fn main() {
    let values = vec![1, 2, 3];

    println!("{:?}", values);
    // println!("{}", values); // 编译错误
}
```

选择规则：

- 给用户看的文本，优先设计 `Display`。
- 开发调试时，使用 `Debug`。
- 临时查看复杂结构，使用 `{:#?}`。

## 2、格式化字符串不是运行时模板

下面这种写法不能直接工作：

```rust
fn main() {
    let template = "{}";

    // println!(template, 42); // 编译错误
}
```

Rust 的格式化宏需要在编译期解析格式化字符串。如果需要运行时模板系统，应使用专门的模板库，或者手动组织逻辑。

## 3、格式化会产生开销

`format!` 会分配新的 `String`。如果只是把内容写入已有缓冲区，优先考虑 `write!` 或 `writeln!`。

日志中也要注意这一点。使用日志宏时，应把格式化参数交给日志系统：

```rust
log::debug!("value = {}", value);
```

不要提前写成：

```rust
log::debug!("{}", format!("value = {}", value));
```

后者会先构造 `String`，更容易产生不必要的分配。

## 4、`println!` 不适合库的长期诊断输出

库代码通常不应该直接 `println!`。更好的方式是返回结果、返回错误，或者使用 `log`、`tracing` 这类日志接口，把输出策略交给最终应用程序决定。
