# 一、概述

## 1、同步与异步

同步调用中，调用者发起操作后，需要等待结果返回，才能继续执行后续逻辑。

示例：

```rust
let data = read_from_network();   // 线程阻塞

process(data);
```

如果 `read_from_network()` 在等待网络响应，当前线程就会停在这里。

异步调用中，调用者发起操作后，通常会先得到一个表示未来结果的值。在 Rust 中，这个值称为`Future`。当前任务在等待点挂起并让出执行权，线程可以去处理其他就绪的任务，等当前任务准备好之后再继续执行。

```rust
let data = read_from_network().await;  // 任务阻塞，线程去执行其他任务

process(data);
```

这段代码看起来仍然是顺序逻辑，但 `.await` 位置是一个可以暂停和恢复的点。


## 2、异步编程的概念

异步编程是一种并发编程模型，核心目标是：**在等待 I/O 时让出执行权，让少量线程可以同时承载大量任务**。

对于网络请求、数据库访问、定时器、消息队列等 I/O 密集型场景，程序经常不是在计算，而是在等待外部资源返回结果。同步阻塞写法中，当前线程会停在等待点上，直到结果返回后才能继续执行；异步写法中，等待的任务会先暂停，当前线程不会被这个任务长期占住，而是可以去推进其他已经就绪的任务。

换言之，异步编程并不是让等待消失，而是让**线程阻塞等待**改成了**任务暂停等待**。

![[Pasted image 20260609001710.png|500]]


在 Rust 中，这种“任务暂停，线程继续工作”的调度过程通常有**异步运行时**完成。因此，可以简单理解：

- 异步任务时可以暂停和恢复的任务
- OS线程时真正执行代码的系统资源
- 异步运行时负责把多个异步任务调度到一个或多个OS线程上执行

Rust 异步编程主要由三部分组成：

| 层次     | 作用                                     |
| ------ | -------------------------------------- |
| 语言层    | `async`/`.await`，编译器把异步代码翻译成状态机        |
| 标准库基础  | `Future`、`Poll`、`Context`、`Waker`等异步原语 |
| 第三方运行时 | 提供执行器、任务调度、异步I/O、定时器等能力，例如`Tokio`      |

Rust 标准库提供了异步编程的核心抽象，但不内置完整运行时。因此，实际项目通常会使用`Tokio`、`async-std`、`smol`等运行时。


# 二、Rust并发模型

Rust提供了两类并发模型：OS线程和async编程。

## 1、OS线程

OS线程由操作系统调度，每个线程有独立的栈和调度状态。Rust标准库中的`std::thread`就是基于OS线程的并发能力。

OS线程的优点是模型直观，普通同步代码可以直接运行在线程中，不需要特殊语法。它适合 CPU 密集型计算、少量并发任务，以及需要直接使用阻塞式库的场景。

但OS线程的成本相对较高。线程创建、销毁、上下文切换都需要操作系统参与；当并发量很大时，不能简单地为每个连接接、每个请求都创建一个线程。尤其是I/O密集型任务重，线程经常只是阻塞等待，资源利用率并不高。

示例：

```rust
fn get_two_sites() {
	let thread_one = std::thread::spawn(|| { download("https://www.foo.com")});
	let thread_two = std::thread::spawn(|| { download("https://www.bar.com")});
	
	thread_one.join().expect("thread one panicked");
	thread_two.join().expect("thread two panicked");
}
```

如果只有两个下载任务，这种方式很直接。但如果有成千上万个下载任务，就不适合为每个任务都创建OS线程。因为每个线程都占用内存，且每个线程执行I/O密集型任务无效等待，浪费资源。

## 2、async编程

async编程是 Rust 另一类重要的并发模型。**它不要求为每个任务都创建一个OS线程，而是把任务表示成可以暂停和恢复的异步任务，再由异步运行时把这些任务调度到一个或多个OS线程上执行**。

在 async 模型中，任务遇到 I/O 等待时不会长期占住线程，而是先暂停下来，让异步运行时继续推进其他已经就绪的任务。等I/O就绪后，异步运行时再让这个任务恢复执行。

示例：

```rust
async fn get_two_sites() {

	let future_one = download_async("https://www.foo.com");
	let future_two = download_async("https://www.bar.com");
	
	let (result_one, result_two) = tokio::join!(future_one, future_two);
	
	println!("{result_one}, {result_two}");
}
```

这里的 `download_async(...)` 调用后并不会立刻阻塞线程等待下载完成，而是先创建出异步任务。`tokio::join!` 会并发推进这两个异步任务：当其中一个任务等待网络 I/O 时，当前线程可以继续推进另一个任务。

和 OS 线程相比，async 编程更适合大量 I/O 并发场景，例如 Web 服务、网络请求、数据库访问、消息队列、爬虫等。因为这些任务大部分时间都在等待外部资源，async 可以让等待期间的线程继续做其他工作。

不过，async 并不是为了加速 CPU 计算。如果任务本身是长时间 CPU 密集型计算，或者内部调用了阻塞式函数，那么它仍然可能长时间占用运行时线程，影响其他异步任务的调度。对于这类操作，通常应该使用 OS 线程、线程池，或者运行时提供的阻塞任务接口。

可以简单对比为：

|模型|执行方式|适合场景|
|---|---|---|
|`OS线程`|多个任务分配到多个系统线程上，由操作系统调度|CPU 密集计算、少量并发、阻塞式代码|
|`async编程`|多个异步任务复用少量线程，由异步运行时调度|大量 I/O 并发、网络服务、异步 I/O|


# 三、async核心模型

## 1、Future

在 Rust 中，异步任务用`Future`表示，每一个异步任务都是一个实现了`Future` Trait的值。

`Future`表示一个将来会完成的计算，完成后会产生一个`Output`。

标准库中`Future`的核心定义可以简化理解为：

```rust
use std::pin::Pin;  
use std::task::{Context, Poll};

trait Future {
	type Output;
	
	fn poll(self: Pin<&mut Self>, cx: &mut Context<'_>) -> Poll<Self::Output>;
}
```

其中：

|成员|含义|
|---|---|
|`type Output`|`Future` 完成后产生的结果类型|
|`poll`|尝试推进这个 `Future`|
|`Poll::Ready(value)`|任务已经完成，并返回结果|
|`Poll::Pending`|任务暂时不能完成，需要以后再次轮询|

`Future` 是惰性的。创建一个 `Future` 并不会立即执行它，只有当它被执行器轮询时，内部逻辑才会开始推进。

也就是说：

```rust
async fn foo() -> i32 {
    println!("run foo");
    100
}

let future = foo();
```

这里调用 `foo()` 不会立刻打印 `run foo`，因为 `foo()` 返回的是一个 `Future`，不是 `i32`。只有这个 `Future` 被 `.await` 或被执行器轮询时，函数体才会真正执行。

## 2、Poll 和 Waker 的协作

`poll`的返回类型是`Poll`是一个枚举，其定义如下：

```rust
enum Poll<T> {
	Ready(T),
	Pending
}
```

当`poll`返回`Poll::Ready(value)`时，表示当前`Future`已经完成。

当`poll`返回`Poll::Pending`时，表示当前`Future`暂时无法继续推进。更准确来说，它应该已经通过`Context`中的`Waker`安排好了唤醒机制。等I/O就绪、定时器到期或其他条件满足后，底层资源会调用`Waker`通知执行器：这个任务可以再次被`poll`。

![[Pasted image 20260609012433.png|400]]

`Waker`的作用不是直接执行任务，而是通知执行器：某个任务有继续推进的可能了。真正重新执行任务的，仍然是执行器之后的`poll`调用。

## 3、执行器负责推进Future

`Future` 本身只描述任务如何被推进，并不负责自己运行。执行器负责持有任务，并在合适的时候调用它们的 `poll` 方法。

异步运行时通常包含：

| 组成     | 作用                                  |
| ------ | ----------------------------------- |
| 执行器    | 调度任务，反复 `poll` 可运行的 `Future`        |
| I/O 驱动 | 管理网络、文件、事件通知等异步 I/O                 |
| 定时器    | 支持 `sleep`、timeout、interval 等时间相关任务 |
| 任务系统   | 支持 `spawn`、`JoinHandle`、任务队列等能力     |

Rust 标准库不提供完整运行时，所以实际项目中常用 `Tokio`：

```rust
#[tokio::main]
async fn main() {
    println!("hello async");
}
```

# 四、async关键字

`async`的作用是把一段代码转换成一个实现了`Future`的值。它可用于代码块，也可用于函数。

## 1、async块

`async {...}`会创建一个异步代码块，返回一个 `Future`。

```rust
let future = async {
	println!("run");  
	10	
};
```

这里的 `future` 不是 `10`，而是一个实现了 `Future<Output = i32>` 的值。

这段代码本身不会立即打印 `run`。只有当 `future` 被 `.await` 或被执行器轮询时，异步块内部的代码才会执行。

```rust
let value = future.await;
```

`.await` 只能写在异步上下文中，也就是 `async fn` 或 `async { ... }` 内部。普通同步函数中不能直接使用 `.await`。

## 2、async fn

`async fn` 定义的是异步函数。调用异步函数时，不会立即执行函数体，而是返回一个 `Future`。

```rust
async fn foo() -> i32 {
    42
}
```

可以近似理解为：

```rust
fn foo() -> impl Future<Output = i32> {
	async {
		42
	}
}
```

因此：

```rust
let future = foo();
```

这里的 `future` 是 `impl Future<Output = i32>`。

只有执行：

```rust
let value = foo().await;
```

才能得到最终的 `i32` 结果。

需要注意，`async fn` 的返回类型写的是最终输出类型，而不是 `Future` 类型：

```rust
async fn foo() -> i32 {
	42
}
```

这里的 `-> i32` 表示这个异步函数完成后的输出类型是 `i32`，不是说调用 `foo()` 会立刻返回 `i32`。


## 3、async move

`async move { ... }` 会把异步块中捕获的外部变量按值移动进生成的 `Future` 中。

```rust
let name = String::from("Rust");

let future = async move {
    println!("{name}");
};
```

`async move` 常用于需要让异步任务拥有数据所有权的场景，尤其是把任务交给运行时独立执行时。

例如 `tokio::spawn` 要求任务通常具有 `'static` 生命周期，因为任务可能在当前函数返回后仍然继续运行：

```rust
tokio::spawn(async move {
    do_work().await;
});
```
