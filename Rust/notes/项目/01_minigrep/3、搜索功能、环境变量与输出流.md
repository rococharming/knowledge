# 一、搜索功能目标

上一阶段 [[Rust/notes/项目/01_minigrep/2、项目重构与错误处理|项目重构与错误处理]] 已经完成了 `main.rs` 和 `lib.rs` 的拆分，并让 `run` 负责读取文件。

本篇开始实现 `minigrep` 的真正核心功能：在文件内容中搜索包含指定字符串的行，并只输出匹配结果。

目标运行方式是：

```shell
cargo run -- frog poem.txt
```

输出只包含匹配 `frog` 的行：

```text
How public, like a frog
```

本阶段还会补充两个命令行程序常见能力：

- 使用环境变量控制搜索是否大小写敏感。
- 使用 `stderr` 输出错误信息，避免错误内容混入正常结果。

# 二、用测试驱动实现搜索

搜索逻辑是纯函数：输入查询词和文件内容，输出匹配行。它不依赖终端、不读取文件，也不需要真实命令行参数，所以很适合先写测试。

在 `src/lib.rs` 中添加测试模块：

```rust
#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn case_sensitive() {
        let query = "duct";
        let contents = "Rust:
safe, fast, productive.
Pick three.
Duct tape.";

        assert_eq!(
            vec!["safe, fast, productive."],
            search(query, contents)
        )
    }
}
```

这个测试表达了两个规则：

- `duct` 可以匹配 `productive`。
- `duct` 不应该匹配 `Duct`。

因此默认搜索应该是大小写敏感的。

为了让测试先进入失败状态，可以先写一个空实现：

```rust
fn search<'a>(query: &str, contents: &'a str) -> Vec<&'a str> {
    Vec::new()
}
```

执行：

```shell
cargo test
```

此时测试会失败，因为函数还没有返回真正的匹配行。这是测试驱动开发的常见节奏：先用测试描述行为，再补实现让测试通过。

# 三、实现大小写敏感搜索

大小写敏感搜索只需要逐行遍历文件内容，并检查每一行是否包含查询字符串。

实际项目中的 `search` 函数是：

```rust
fn search<'a>(query: &str, contents: &'a str) -> Vec<&'a str> {
    let mut results = Vec::new();

    for line in contents.lines() {
        if line.contains(query) {
            results.push(line);
        }
    }

    results
}
```

执行流程如下：

```text
contents
  ↓
按行遍历
  ↓
判断 line 是否包含 query
  ↓
匹配则 push 到 results
  ↓
返回 results
```

关键方法：

| 方法 | 作用 |
|---|---|
| `contents.lines()` | 按行遍历字符串 |
| `line.contains(query)` | 判断当前行是否包含搜索字符串 |
| `results.push(line)` | 保存匹配行 |

运行测试：

```shell
cargo test
```

输出中可以看到：

```text
running 2 tests
test tests::case_insensitive ... ok
test tests::case_sensitive ... ok
```

当前项目已经包含两个测试，大小写敏感和大小写不敏感搜索都通过。

# 四、search 中的生命周期

`search` 的签名是：

```rust
fn search<'a>(query: &str, contents: &'a str) -> Vec<&'a str>
```

理解这个生命周期标注，先不要从语法入手，而要先看函数返回的值到底从哪里来。

`search` 不会创建新的字符串。它只是从 `contents` 中找出匹配的行，并把这些行的切片放进 `Vec` 返回：

```rust
contents: &str
  ├── "Rust:"
  ├── "safe, fast, productive."  // 返回这一行的切片
  ├── "Pick three."
  └── "Duct tape."
```

所以返回值 `Vec<&str>` 里的每一个 `&str` 都是指向 `contents` 内部某一段文本的借用。它们不是独立拥有数据的 `String`。

这里的核心关系是：

```text
contents 活着
  ↓
从 contents 切出来的匹配行才能活着
```

生命周期 `'a` 正是在表达这层关系：

> 返回的字符串切片来自 `contents`，并且不能比 `contents` 活得更久。

把签名拆开看：

```rust
fn search<'a>(
    query: &str,
    contents: &'a str,
) -> Vec<&'a str>
```

含义如下：

| 部分 | 含义 |
|---|---|
| `query: &str` | 查询词，只用来判断是否匹配，不会被返回 |
| `contents: &'a str` | 被搜索的文本，返回的行切片从这里借用 |
| `Vec<&'a str>` | 返回一组行切片，这些切片和 `contents` 共享同一个生命周期 `'a` |

也就是说，`'a` 只绑定 `contents` 和返回值，不绑定 `query`。这是因为返回结果不是从查询词里切出来的，而是从文件内容里切出来的。

这里需要显式生命周期，是因为函数有两个输入引用：

```rust
query: &str
contents: &str
```

如果写成：

```rust
fn search(query: &str, contents: &str) -> Vec<&str>
```

编译器无法仅凭省略规则判断返回值里的 `&str` 应该来自 `query` 还是 `contents`，因此会要求手动标注生命周期。

如果返回值错误地依赖了 `query`，语义就完全变了：函数好像是在返回查询词的一部分。但实际逻辑是返回文件内容中的匹配行，所以签名必须明确告诉编译器：

```text
返回值借用 contents，不借用 query
```

> 简单记法：`query` 是“筛选条件”，`contents` 是“数据来源”。返回的是数据来源中的行，因此返回值生命周期要跟 `contents` 绑定。

# 五、在 run 中调用 search

`run` 先读取文件内容，再根据配置选择搜索函数，最后逐行打印匹配结果。

当前项目中的 `run` 是：

```rust
pub fn run(config: Config) -> Result<(), Box<dyn Error>> {
    let contents = fs::read_to_string(config.file_path)?;

    let results = if config.case_sensitive {
        search(&config.query, &contents)
    } else {
        search_case_insensitive(&config.query, &contents)
    };

    for line in results {
        println!("{}", line);
    }

    Ok(())
}
```

这里有三个变化：

- 文件路径字段是 `file_path`，不是 `filename`。
- `run` 不再打印整个文件，而是打印 `search` 返回的匹配行。
- 搜索函数当前是 `lib.rs` 内部私有函数，因为外部只需要调用 `run`。

运行：

```shell
cargo run -- frog poem.txt
```

输出：

```text
How public, like a frog
```

搜索多个匹配结果：

```shell
cargo run -- body poem.txt
```

输出：

```text
I'm nobody! Who are you?
Are you nobody, too?
How dreary to be somebody!
```

搜索无匹配结果：

```shell
cargo run -- monomorphization poem.txt
```

没有输出。这是合理行为，因为没有任何一行包含查询词。

# 六、大小写不敏感搜索

## 1、添加测试

大小写不敏感搜索需要把查询词和被检查的行放到同一种大小写形式下再比较。

测试如下：

```rust
#[test]
fn case_insensitive() {
    let query = "rUsT";
    let contents = "Rust:
safe, fast, productive.
Pick three.
Trust me.";

    assert_eq!(
        vec!["Rust:", "Trust me."],
        search_case_insensitive(query, contents)
    );
}
```

这个测试希望 `rUsT` 能匹配：

```text
Rust:
Trust me.
```

也就是说，搜索时忽略大小写差异。

## 2、实现搜索函数

实际项目中的 `search_case_insensitive` 是：

```rust
fn search_case_insensitive<'a>(query: &str, contents: &'a str) -> Vec<&'a str> {
    let mut results = Vec::new();
    let query = query.to_lowercase();

    for line in contents.lines() {
        if line.to_lowercase().contains(&query) {
            results.push(line);
        }
    }

    results
}
```

关键点是先把查询字符串转成小写：

```rust
let query = query.to_lowercase();
```

然后遍历时把当前行也转成小写再比较：

```rust
if line.to_lowercase().contains(&query) {
    results.push(line);
}
```

`to_lowercase` 会创建新的 `String`，因为原来的 `&str` 只是借用已有字符串，不能原地修改。函数最终仍然返回原始 `contents` 中的行切片，而不是返回小写后的行。

# 七、使用环境变量控制搜索行为

现在有两个搜索函数：

| 函数 | 行为 |
|---|---|
| `search` | 大小写敏感 |
| `search_case_insensitive` | 大小写不敏感 |

程序通过环境变量 `CASE_INSENSITIVE` 控制使用哪一个。

当前项目中的 `Config` 是：

```rust
pub struct Config {
    query: String,
    file_path: String,
    case_sensitive: bool,
}
```

字段没有写 `pub`，因此它们只在 `lib.rs` 内部访问。外部入口只需要创建 `Config` 并传给 `run`，不必直接读写字段。

`Config::new` 中读取环境变量：

```rust
use std::env;

impl Config {
    pub fn new(args: Vec<String>) -> Result<Self, &'static str> {
        if args.len() < 3 {
            return Err("not enough arguments");
        }

        let query = args[1].clone();
        let file_path = args[2].clone();
        let case_sensitive = env::var("CASE_INSENSITIVE").is_err();

        Ok(Config {
            query,
            file_path,
            case_sensitive,
        })
    }
}
```

这一行是关键：

```rust
let case_sensitive = env::var("CASE_INSENSITIVE").is_err();
```

含义如下：

| 环境变量状态 | `case_sensitive` | 搜索行为 |
|---|---|---|
| 未设置 `CASE_INSENSITIVE` | `true` | 大小写敏感 |
| 设置了 `CASE_INSENSITIVE` | `false` | 大小写不敏感 |

这里不关心环境变量的具体值，只关心它是否存在。

# 八、在 run 中选择搜索函数

`run` 根据 `config.case_sensitive` 分支选择搜索函数：

```rust
let results = if config.case_sensitive {
    search(&config.query, &contents)
} else {
    search_case_insensitive(&config.query, &contents)
};
```

默认大小写敏感：

```shell
cargo run -- to poem.txt
```

输出：

```text
Are you nobody, too?
How dreary to be somebody!
```

设置环境变量后，大小写不敏感：

```shell
CASE_INSENSITIVE=1 cargo run -- to poem.txt
```

输出：

```text
Are you nobody, too?
How dreary to be somebody!
To tell your name the livelong day
To an admiring bog!
```

这是因为大小写不敏感时，`To tell...` 和 `To an...` 中的大写 `To` 也会匹配查询词 `to`。

# 九、标准输出与标准错误

命令行程序通常区分两种输出流：

| 输出流 | 用途 | Rust 宏 |
|---|---|---|
| `stdout` | 正常运行结果 | `println!` |
| `stderr` | 错误信息 | `eprintln!` |

例如用户可以把正常搜索结果重定向到文件：

```shell
cargo run -- to poem.txt > output.txt
```

这里的 `>` 只重定向 `stdout`。如果错误信息也用 `println!` 输出，它就会被写入 `output.txt`，用户在终端反而看不到错误原因。

因此错误信息应该使用 `eprintln!`。

# 十、main.rs 的错误输出

当前项目中的 `src/main.rs` 已经使用 `eprintln!` 输出错误：

```rust
use std::env;
use std::process;
use minigrep::Config;

fn main() {
    let args = env::args().collect::<Vec<String>>();

    let config = Config::new(args)
        .unwrap_or_else(|err| {
            eprintln!("Problem parsing arguments: {}", err);
            process::exit(1);
        });

    if let Err(e) = minigrep::run(config) {
        eprintln!("Application error: {}", e);
        process::exit(1);
    }
}
```

参数不足时运行：

```shell
cargo run
```

终端显示：

```text
Problem parsing arguments: not enough arguments
```

文件不存在时运行：

```shell
cargo run -- frog missing.txt
```

终端显示类似：

```text
Application error: No such file or directory (os error 2)
```

正常搜索结果仍然使用 `println!`，所以可以被重定向：

```shell
cargo run -- to poem.txt > output.txt
```

这时匹配行会写入 `output.txt`，错误信息不会混入正常结果。

## 2、`src/lib.rs`

```rust
use std::error::Error;
use std::fs;
use std::env;

pub struct Config {
    query: String,
    file_path: String,
    case_sensitive: bool,
}

impl Config {
    pub fn new(args: Vec<String>) -> Result<Self, &'static str> {
        if args.len() < 3 {
            return Err("not enough arguments");
        }

        let query = args[1].clone();
        let file_path = args[2].clone();
        let case_sensitive = env::var("CASE_INSENSITIVE").is_err();

        Ok(Config {
            query,
            file_path,
            case_sensitive,
        })
    }
}

pub fn run(config: Config) -> Result<(), Box<dyn Error>> {
    let contents = fs::read_to_string(config.file_path)?;

    let results = if config.case_sensitive {
        search(&config.query, &contents)
    } else {
        search_case_insensitive(&config.query, &contents)
    };

    for line in results {
        println!("{}", line);
    }

    Ok(())
}

fn search<'a>(query: &str, contents: &'a str) -> Vec<&'a str> {
    let mut results = Vec::new();

    for line in contents.lines() {
        if line.contains(query) {
            results.push(line);
        }
    }

    results
}

fn search_case_insensitive<'a>(query: &str, contents: &'a str) -> Vec<&'a str> {
    let mut results = Vec::new();
    let query = query.to_lowercase();

    for line in contents.lines() {
        if line.to_lowercase().contains(&query) {
            results.push(line);
        }
    }

    results
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn case_sensitive() {
        let query = "duct";

safe, fast, productive.

        assert_eq!(
            vec!["safe, fast, productive."],
            search(query, contents)
        )
    }

    #[test]
    fn case_insensitive() {

        let contents = "Rust:

Pick three.
Trust me.";

        assert_eq!(
            vec!["Rust:", "Trust me."],

    }
}
```

# 十二、本篇小结

这一阶段完成了 `minigrep` 的核心搜索功能。

当前程序具备：

| 功能 | 实现方式 |
|---|---|
| 大小写敏感搜索 | `search` |
| 大小写不敏感搜索 | `search_case_insensitive` |
| 测试搜索逻辑 | `#[cfg(test)]` 和 `#[test]` |
| 生命周期关联 | 返回值中的 `&str` 来自 `contents` |
| 环境变量配置 | `env::var("CASE_INSENSITIVE")` |
| 正常结果输出 | `println!` |
| 错误信息输出 | `eprintln!` |

整个项目形成了一个常见的 Rust 命令行程序骨架：

```text
main.rs
  ├── 读取参数
  ├── 创建 Config
  ├── 调用 lib.rs 中的 run
  └── 处理错误退出

lib.rs
  ├── 保存配置
  ├── 读取文件
  ├── 执行搜索
  └── 编写测试
```

这个结构适合继续扩展更多功能，例如参数解析库、正则搜索、忽略隐藏文件、递归搜索目录等。
