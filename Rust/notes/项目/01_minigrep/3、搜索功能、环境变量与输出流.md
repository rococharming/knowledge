# 一、搜索功能目标

上一阶段完成了项目结构重构，但`run`仍然只是读取并打印整个文件：

```rust

```

本篇开始实现真正的搜索功能。

目标是：

```shell
cargo run frog poem.txt
```

只输出包含 `frog` 的行：

```text
How public, like a frog
```

本篇还会补充两个命令行程序常见能力：

1. 使用环境变量控制大小写敏感行为
2. 使用 `stderr` 输出错误信息


# 二、使用测试驱动实现搜索

搜索逻辑适合先写测试，因此这里通过TDD（测试驱动开发）实现。

在 `src/lib.rs` 中添加测试模块：

```rust
#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn case_sensitive() {
        let query = "duct";
        let contents = "\
Rust:
safe, fast, productive.
Pick three.
Duct tape.";

        assert_eq!(
            vec!["safe, fast, productive."],
            search(query, contents)
        );
    }
}
```

这个测试表达了两个规则：

- `duct` 可以匹配 `productive`
- `duct` 不应该匹配 `Duct`

因此默认搜索应该是大小写敏感的。

# 三、实现大小写敏感搜索

先实现 `search` 函数：

```rust
pub fn search<'a>(query: &str, contents: &'a str) -> Vec<&'a str> {
    let mut results = Vec::new();

    for line in contents.lines() {
        if line.contains(query) {
            results.push(line);
        }
    }

    results
}
```

执行流程：

```text
contents
  ↓
按行遍历
  ↓
判断 line 是否包含 query
  ↓
匹配则 push 到 results
  ↓
返回 results
```

关键方法：

|方法|作用|
|---|---|
|`contents.lines()`|按行遍历字符串|
|`line.contains(query)`|判断当前行是否包含搜索字符串|
|`results.push(line)`|保存匹配行|

运行测试：

```shell
cargo test
```

输出类似：

```
running 1 test
test tests::case_sensitive ... ok

test result: ok. 1 passed; 0 failed
```

# 四、search中的生命周期

`search` 的签名是：

```
pub fn search<'a>(query: &str, contents: &'a str) -> Vec<&'a str>
```

返回值是 `Vec<&str>`，说明函数返回的是字符串切片，而不是新的 `String`。

这些字符串切片来自 `contents` 中的某些行，例如：

```rust
contents: &str
  ├── "Rust:"
  ├── "safe, fast, productive."  ← 返回这一行的切片
  ├── "Pick three."
  └── "Duct tape."
```

生命周期 `'a` 表示：

> 返回的字符串切片来自 contents，并且不能比 contents 活得更久

这里需要显式生命周期，因为函数有两个引用参数：

```rust
query: &str
contents: &str
```

如果写成：

```rust
pub fn search(query: &str, contents: &str) -> Vec<&str>
```

编译器无法判断返回值中的 `&str` 是来自 `query`，还是来自 `contents`。

实际返回的是文件内容中的匹配行，所以要把返回值和 `contents` 的生命周期关联起来。

# 六、大小写不敏感搜索

## 1、添加测试

继续在测试模块中添加大小写不敏感搜索测试：

```rust
#[test]
fn case_insensitive() {
    let query = "rUsT";
    let contents = "\
Rust:
safe, fast, productive.
Pick three.
Trust me.";

    assert_eq!(
        vec!["Rust:", "Trust me."],
        search_case_insensitive(query, contents)
    );
}
```

这里希望 `rUsT` 能匹配：

```shell
Rust:
Trust me.
```

也就是说，搜索时忽略大小写差异。

## 2、实现搜索函数

```rust
pub fn search_case_insensitive<'a>(
    query: &str,
    contents: &'a str,
) -> Vec<&'a str> {
    let query = query.to_lowercase();
    let mut results = Vec::new();

    for line in contents.lines() {
        if line.to_lowercase().contains(&query) {
            results.push(line);
        }
    }

    results
}
```

关键点是把查询字符串和当前行都转成小写后再比较：

```rust
let query = query.to_lowercase();

if line.to_lowercase().contains(&query) {
    results.push(line);
}
```

`to_lowercase` 会创建新的 `String`，因为原来的 `&str` 只是借用已有字符串，不能原地修改。

运行测试：

```shell
cargo test
```

输出类似：

```text
running 2 tests
test tests::case_insensitive ... ok
test tests::case_sensitive ... ok

test result: ok. 2 passed; 0 failed
```


# 七、使用环境变量控制搜索行为

现在有两个搜索函数：

| 函数                        | 行为     |
| ------------------------- | ------ |
| `search`                  | 大小写敏感  |
| `search_case_insensitive` | 大小写不敏感 |
可以通过环境变量 `CASE_INSENSITIVE` 控制使用哪一个。

修改 `Config`：

```rust
pub struct Config {
    pub query: String,
    pub filename: String,
    pub case_sensitive: bool,
}
```

修改 `Config::new`：

```rust
impl Config {
    pub fn new(args: &[String]) -> Result<Config, &'static str> {
        if args.len() < 3 {
            return Err("not enough arguments");
        }

        let query = args[1].clone();
        let filename = args[2].clone();

        let case_sensitive = std::env::var("CASE_INSENSITIVE").is_err();

        Ok(Config {
            query,
            filename,
            case_sensitive,
        })
    }
}
```

这一行是关键：

```rust
let case_sensitive = std::env::var("CASE_INSENSITIVE").is_err();
```

含义是：

|环境变量状态|`case_sensitive`|搜索行为|
|---|---|---|
|未设置 `CASE_INSENSITIVE`|`true`|大小写敏感|
|设置了 `CASE_INSENSITIVE`|`false`|大小写不敏感|
这里不关心环境变量的值，只关心它是否存在。


# 八、在run中选择搜索函数

修改 `run`：

```rust
pub fn run(config: Config) -> Result<(), Box<dyn Error>> {
    let contents = fs::read_to_string(config.filename)?;

    let results = if config.case_sensitive {
        search(&config.query, &contents)
    } else {
        search_case_insensitive(&config.query, &contents)
    };

    for line in results {
        println!("{line}");
    }

    Ok(())
}
```

默认大小写敏感：

```shell
cargo run to poem.txt
```

输出：

```text
Are you nobody, too?
How dreary to be somebody!
```

设置环境变量后，大小写不敏感：

```shell
CASE_INSENSITIVE=1 cargo run to poem.txt
```

输出：

```text
Are you nobody, too?
How dreary to be somebody!
To tell your name the livelong day
To an admiring bog!
```


# 九、标准输出与标准错误

命令行程序通常区分两种输出流：

|输出流|用途|Rust 宏|
|---|---|---|
|stdout|正常运行结果|`println!`|
|stderr|错误信息|`eprintln!`|

例如用户可以把正常搜索结果重定向到文件：

```shell
cargo run to poem.txt > output.txt
```

这里的 `>` 只重定向 stdout。

如果错误信息也用 `println!` 输出，它就会被写入 `output.txt`，用户在终端反而看不到错误原因。

因此错误信息应该使用 `eprintln!`。

# 十、修改 `main.rs` 的错误输出

最终的 `src/main.rs`：

```rust
use std::env;

        eprintln!("Application error: {e}");
        process::exit(1);

```

参数不足时运行：

```shell
cargo run > output.txt
```

终端显示：

```text
Problem parsing arguments: not enough arguments
```

`output.txt` 不会写入错误信息。

正常运行并重定向输出：

```shell
cargo run to poem.txt > output.txt
```

终端不显示内容，匹配结果写入 `output.txt`。

```rust
use std::error::Error;
use std::fs;

pub struct Config {
    pub query: String,
    pub filename: String,
    pub case_sensitive: bool,
}

impl Config {
    pub fn new(args: &[String]) -> Result<Config, &'static str> {
        if args.len() < 3 {
            return Err("not enough arguments");
        }

        let query = args[1].clone();
        let filename = args[2].clone();

        let case_sensitive = std::env::var("CASE_INSENSITIVE").is_err();

        Ok(Config {
            query,
            filename,
            case_sensitive,
        })
    }
}

pub fn run(config: Config) -> Result<(), Box<dyn Error>> {
    let contents = fs::read_to_string(config.filename)?;

    let results = if config.case_sensitive {
        search(&config.query, &contents)
    } else {
        search_case_insensitive(&config.query, &contents)
    };

    for line in results {
        println!("{line}");
    }

    Ok(())
}

pub fn search<'a>(query: &str, contents: &'a str) -> Vec<&'a str> {
    let mut results = Vec::new();

    for line in contents.lines() {
        if line.contains(query) {
            results.push(line);
        }
    }

    results
}

pub fn search_case_insensitive<'a>(
    query: &str,
    contents: &'a str,
) -> Vec<&'a str> {
    let query = query.to_lowercase();
    let mut results = Vec::new();

    for line in contents.lines() {
        if line.to_lowercase().contains(&query) {
            results.push(line);
        }
    }

    results
}
```

# 十二、本篇小结

这一阶段完成了 `minigrep` 的核心功能。

最终程序具备：

|功能|实现方式|
|---|---|
|大小写敏感搜索|`search`|
|大小写不敏感搜索|`search_case_insensitive`|
|测试搜索逻辑|`#[cfg(test)]` 和 `#[test]`|
|生命周期关联|返回值中的 `&str` 来自 `contents`|
|环境变量配置|`std::env::var("CASE_INSENSITIVE")`|
|正常结果输出|`println!`|
|错误信息输出|`eprintln!`|

整个项目形成了一个常见的 Rust 命令行程序骨架：

```text
main.rs
  ├── 读取参数
  ├── 创建 Config
  ├── 调用 lib.rs 中的 run
  └── 处理错误退出

lib.rs
  ├── 保存配置
  ├── 读取文件
  ├── 执行搜索
  └── 编写测试
```

这个结构适合继续扩展更多功能，例如命令行参数解析、正则搜索、忽略隐藏文件、递归搜索目录等。
