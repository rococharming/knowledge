
# 一、重构目标

上一版程序已经能读取参数和文件内容，但代码都集中在 `main` 中。

这一篇的目标是把程序从“能跑”重构成“结构清晰、错误处理合理”的版本。

最终结构是：

```shell
src/
├── main.rs
└── lib.rs
```

职责划分如下：

|文件|职责|
|---|---|
|`main.rs`|程序入口、读取参数、处理错误退出|
|`lib.rs`|配置结构、运行逻辑、后续搜索逻辑|

`main.rs` 应尽量短小，真正需要测试和维护的逻辑放到 `lib.rs` 中。


# 二、提取参数解析逻辑

最开始的代码直接在 `main` 中解析参数：

```rust
let query = &args[1];
let filename = &args[2];
```

可以先提取成函数：

```rust
fn parse_config(args: &[String]) -> (&str, &str) {
    let query = &args[1];
    let filename = &args[2];

    (query, filename)
}
```

`main` 中调用：

```rust
let args: Vec<String> = env::args().collect();

let (query, filename) = parse_config(&args);
```

这一步只是把“参数如何对应变量”的逻辑从 `main` 中挪出去。

不过返回元组仍然不够清晰，因为 `query` 和 `filename` 是有业务含义的配置项，不只是两个普通字符串。

# 三、使用 `Config` 组织配置

定义 `Config` 结构体：

```rust
struct Config {
    query: String,
    filename: String,
}
```

然后让参数解析函数返回 `Config`：

```rust
fn parse_config(args: &[String]) -> Config {
    let query = args[1].clone();
    let filename = args[2].clone();

    Config { query, filename }
}
```

调用方式变成：

```rust
let config = parse_config(&args);

println!("Searching for {}", config.query);
println!("In file {}", config.filename);
```

这样代码更明确：

```
query + filename = 程序运行所需的配置
```

注意事项：

1. 使用`clone`的原因：`args` 的类型是 `Vec<String>`，而 `parse_config` 接收的是借用。因为 `parse_config` 没有拥有 `args`，所以不能直接把 `args[1]` 和 `args[2]` 中的 `String` 移动出来。这里使用：

```rust
let query = args[1].clone();
let filename = args[2].clone();
```

会复制两份字符串，让 `Config` 拥有自己的数据。

对于命令行参数来说，这点开销很小。这个阶段优先保持代码清晰，不需要过早优化。


# 四、将参数解析改为Config::new

`parse_config` 的作用是创建 `Config`，因此可以改成 `Config` 的关联函数：

```rust
impl Config {
    fn new(args: &[String]) -> Config {
        let query = args[1].clone();
        let filename = args[2].clone();

        Config { query, filename }
    }
}
```

调用方式：

```rust
let config = Config::new(&args);
```

这种写法更符合 Rust 中创建类型实例的习惯。

例如：

```rust
String::new()
Vec::new()
Config::new()
```

# 五、参数错误处理

当前 `Config::new` 仍然有问题。

如果用户没有传入足够参数：

```shell
cargo run
```

代码会访问不存在的索引：

```rust
args[1]
args[2]
```

程序会 panic，并输出类似：

```text
index out of bounds
```

这不是一个好的命令行错误提示。

可以先判断参数数量：

```rust
impl Config {
    fn new(args: &[String]) -> Config {
        if args.len() < 3 {
            panic!("not enough arguments");
        }

        let query = args[1].clone();
        let filename = args[2].clone();

        Config { query, filename }
    }
}
```

这样错误信息会变成：

```text
not enough arguments
```

但仍然是 panic，会附带线程、源码位置、回溯提示等信息。

参数不足属于用户使用错误，不应该用 panic 作为最终处理方式。


# 六、从 Config::new返回 Result

更合理的方式是让 `Config::new` 返回 `Result`：

```rust
impl Config {
    fn new(args: &[String]) -> Result<Config, &'static str> {
        if args.len() < 3 {
            return Err("not enough arguments");
        }

        let query = args[1].clone();
        let filename = args[2].clone();

        Ok(Config { query, filename })
    }
}
```

返回类型：

```rust
Result<Config, &'static str>
```

含义是：

|分支|含义|
|---|---|
|`Ok(Config)`|参数解析成功|
|`Err("not enough arguments")`|参数不足|

这里的 `&'static str` 是字符串字面量类型，适合用来表示简单的静态错误信息。

# 七、在main中处理参数错误

`main` 中使用 `unwrap_or_else` 处理 `Result`：

```rust
use std::env;
use std::process;

fn main() {
    let args: Vec<String> = env::args().collect();

    let config = Config::new(&args).unwrap_or_else(|err| {
        println!("Problem parsing arguments: {err}");
        process::exit(1);
    });

    println!("Searching for {}", config.query);
    println!("In file {}", config.filename);
}
```

`unwrap_or_else` 的行为是：

|情况|行为|
|---|---|
|`Ok(config)`|取出 `config` 继续执行|
|`Err(err)`|执行闭包中的错误处理逻辑|

这里的闭包是：

```rust
|err| {
    println!("Problem parsing arguments: {err}");
    process::exit(1);
}
```

`process::exit(1)` 会立即结束程序，并返回非零退出码。

在命令行程序中，非零退出码通常表示程序运行失败。

运行：

```shell
cargo run
```

输出：

```text
Problem parsing arguments: not enough arguments
```

这比 panic 信息更适合终端用户。


# 八、提取run函数

现在 `main` 中仍然包含读取文件和执行程序逻辑的代码。

可以提取一个 `run` 函数：

```rust
fn run(config: Config) {
    let contents = fs::read_to_string(config.filename)
        .expect("Something went wrong reading the file");

    println!("With text:\n{contents}");
}
```

`main` 中只负责调用：

```rust
run(config);
```

这一步之后，`main` 的职责进一步减少：

```
main  
├── 收集参数  
├── 创建 Config  
└── 调用 run
```

# 九、让 run返回Result

`run` 中仍然使用 `expect`：

```rust
let contents = fs::read_to_string(config.filename)
    .expect("Something went wrong reading the file");
```

如果文件不存在，程序仍然会 panic。

更合理的方式是让 `run` 返回 `Result`，把错误交给 `main` 统一处理：

```rust
use std::error::Error;
use std::fs;

fn run(config: Config) -> Result<(), Box<dyn Error>> {
    let contents = fs::read_to_string(config.filename)?;

    println!("With text:\n{contents}");

    Ok(())
}
```

这里有几个关键点。

1. Result<(), Box\<dyn Error>>

```rust
Result<(), Box<dyn Error>>
```

含义是：

|部分|含义|
|---|---|
|`()`|成功时不返回有意义的数据|
|`Box<dyn Error>`|可以返回实现了 `Error` trait 的错误类型|

`run` 的主要作用是产生副作用，例如读取文件、打印内容，所以成功时返回 `Ok(())` 即可。

2. ? 传播错误

```rust
let contents = fs::read_to_string(config.filename)?;
```

如果读取成功，`contents` 得到文件内容。

如果读取失败，`?` 会提前返回错误，让调用者处理。

这比 `expect` 更适合命令行程序的业务错误处理。


# 十、在main中处理 run的错误

调用 `run` 后，需要检查是否出错：

```rust
if let Err(e) = run(config) {
    println!("Application error: {e}");
    process::exit(1);
}
```

完整结构：

```rust
fn main() {
    let args: Vec<String> = env::args().collect();

    let config = Config::new(&args).unwrap_or_else(|err| {
        println!("Problem parsing arguments: {err}");
        process::exit(1);
    });

    if let Err(e) = run(config) {
        println!("Application error: {e}");
        process::exit(1);
    }
}
```

这里使用 `if let Err(e)`，因为 `run` 成功时只返回 `()`，没有需要继续使用的值。

# 十一、拆分main.rs和lib.rs

## 1、lib.rs

现在可以把核心逻辑移动到 `src/lib.rs`。

```rust
use std::error::Error;
use std::fs;

pub struct Config {
    pub query: String,
    pub filename: String,
}

impl Config {
    pub fn new(args: &[String]) -> Result<Config, &'static str> {
        if args.len() < 3 {
            return Err("not enough arguments");
        }

        let query = args[1].clone();
        let filename = args[2].clone();

        Ok(Config { query, filename })
    }
}

pub fn run(config: Config) -> Result<(), Box<dyn Error>> {
    let contents = fs::read_to_string(config.filename)?;

    println!("With text:\n{contents}");

    Ok(())
}
```

这里需要使用 `pub`，因为 `main.rs` 要访问这些内容：

|项目|为什么需要 `pub`|
|---|---|
|`Config`|`main.rs` 需要使用这个类型|
|`Config` 字段|`lib.rs` 外部可能需要访问字段|
|`Config::new`|`main.rs` 需要调用|
|`run`|`main.rs` 需要调用|

## 2、src/main.rs

```rust
use std::env;
use std::process;

use minigrep::Config;

fn main() {
    let args: Vec<String> = env::args().collect();

    let config = Config::new(&args).unwrap_or_else(|err| {
        println!("Problem parsing arguments: {err}");
        process::exit(1);
    });

    if let Err(e) = minigrep::run(config) {
        println!("Application error: {e}");
        process::exit(1);
    }
}
```

`minigrep` 是当前包的库 crate 名称。二进制 crate 可以通过包名访问库 crate 中暴露的 API。


# 十二、本篇小结

这一阶段完成了项目结构重构。

现在的程序结构是：

```shell
main.rs
  ├── 收集命令行参数
  ├── 调用 Config::new
  ├── 处理参数错误
  ├── 调用 minigrep::run
  └── 处理运行错误

lib.rs
  ├── Config
  ├── Config::new
  └── run
```

关键变化：

|重构点|作用|
|---|---|
|`Config`|组织程序配置|
|`Config::new`|解析命令行参数|
|`Result`|用返回值表达错误|
|`unwrap_or_else`|自定义参数错误处理|
|`run`|提取程序主逻辑|
|`?`|传播文件读取错误|
|`Box<dyn Error>`|简化错误返回类型|
|`main.rs` / `lib.rs`|分离入口和业务逻辑|

下一步可以在 `lib.rs` 中实现真正的搜索功能，并为搜索逻辑编写测试。
