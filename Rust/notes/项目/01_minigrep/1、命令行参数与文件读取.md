# 一、项目目标

本项目实现一个简化版 `grep`，命名为 `minigrep`。

`grep` 的基本功能：

> 在指定文件中搜索指定文本，并打印出所有包含该文本的行。

`minigrep` 项目只实现最基础的搜索能力，使用如下：

```shell
cargo run <query> <filename>
```

其中：

- `query` 是要搜索的文本
- `filename` 是指定文件

例如：

```shell
cargo run frog poem.txt
```

含义是：在 `poem.txt` 文件中搜索包含 `frog` 的行。

这个项目会用到几个常见的 Rust 命令行程序知识点：

| 知识点 | 用途 |
| --- | --- |
| 命令行参数 | 从终端接收搜索内容和文件名 |
| 文件读取 | 读取指定文件的文本内容 |
| 字符串处理 | 在文本中查找匹配行 |
| 错误处理 | 处理参数不足、文件不存在等情况 |
| 模块拆分 | 将入口代码和业务逻辑分开 |
| 测试 | 验证搜索函数是否正确 |

本篇主要实现：读取命令行参数，并把文件内容读取出来。

# 三、读取命令行参数

Rust 可以通过 `std::env::args` 读取命令行参数。这里先手动解析参数；如果要做更完整的命令行参数体验，可以参考 [[Rust/notes/常用crate/2、clap|clap]]。

先写一个最简单的版本：

```rust
use std::env;

fn main() {
    // 获取所有命令行参数
    // std::env::args() 返回的是 Args，它是一个迭代器类型
    let args = env::args().collect::<Vec<String>>();

    // 注意，命令行的第一个参数（索引为0）是程序名
    let query = &args[1];        // 获取查询词
    let file_path = &args[2];    // 获取文件路径
    println!("Searching for {}", query);
    println!("In file {}", file_path);
}
```

运行：

```shell
cargo run -- frog poem.txt
```

输出：

```text
Searching for frog
In file poem.txt
```

这里的 `std::env::args()` 返回的 `Args` 是一个迭代器类型，通过 `.collect()` 消费得到 `Vec<String>`，包含命令行传入的所有参数。

程序真正接收到的参数是：

| 索引 | 内容 | 含义 |
| --- | --- | --- |
| `args[0]` | 程序路径 | 当前可执行文件 |
| `args[1]` | `frog` | 搜索字符串 |
| `args[2]` | `poem.txt` | 文件名 |

所以这里使用：

```rust
let query = &args[1];
let file_path = &args[2];
```

> 根据 Rust 的所有权规则和移动，这里 `let query = &args[1]` 不能写成 `let query = args[1]`。

# 四、读取文件内容

文件读取使用 `std::fs::read_to_string`。

```rust
use std::env;
use std::fs;

fn main() {
    // 获取所有命令行参数
    // std::env::args() 返回的是 Args，它是一个迭代器类型
    let args = env::args().collect::<Vec<String>>();

    // 注意，命令行的第一个参数（索引为0）是程序名
    let query = &args[1];        // 获取查询词
    let file_path = &args[2];    // 获取文件路径
    println!("Searching for {}", query);
    println!("In file {}", file_path);

    // 读取文件内容并打印
    let contents = fs::read_to_string(file_path)
        .expect("Something went wrong reading the file");
    println!("\nWith text:\n{contents}");
}
```

`std::fs::read_to_string` 会打开文件，并把整个文件内容读取到 `String`。

其返回值类型是一个 `Result`：

```rust
Result<String, std::io::Error>
```

因此需要处理可能出现的错误，当前版本先使用 `expect`：

```rust
let contents = fs::read_to_string(filename)
    .expect("Something went wrong reading the file");
```

- 如果读取成功，得到文件内容；
- 如果读取失败，程序会直接 panic，并输出 `expect` 中的错误信息。

运行：

```shell
cargo run -- frog poem.txt
```

输出：

```text
Searching for frog
In file poem.txt

With text:
I'm nobody! Who are you?
Are you nobody, too?
Then there's a pair of us - don't tell!
They'd banish us, you know.

How dreary to be somebody!
How public, like a frog
To tell your name the livelong day
To an admiring bog!
```

到目前为止，程序已经能完成两个动作：

1. 从命令行读取 `query` 和 `file_path`
2. 根据 `file_path` 读取文件内容

不过此时还没有真正实现搜索功能，只是把整个文件内容打印出来。

# 五、当前代码的问题

## 1、`main` 函数职责过多

现在 `main` 同时负责：

- 读取命令行参数
- 解析 `query` 和 `file_path`
- 读取文件
- 打印文件内容
- 处理错误

现在来看没什么问题，但随着程序变复杂，`main` 会越来越难维护。

更合理的方式是让 `main` 只负责程序入口，把真正的业务逻辑提取出去。

## 2、配置变量没有组织起来

`query` 和 `file_path` 都是程序配置，但现在只是两个分散的变量。

更好的方式是定义一个 `Config` 结构体将它们组织起来：

```rust
struct Config {
    query: String,
    file_path: String,
}
```

这样可以明确表达：这些值共同决定程序如何运行。

## 3、没有错误处理

如果用户没有传入足够参数：

```shell
cargo run
```

程序会因为访问 `args[1]` 或 `args[2]` 直接 panic，输出：

```shell
index out of bounds
```

这种信息更适合开发者，不适合面向用户。而且，这是因为用户没清楚用法导致的，应该给用户足够的提示而不是让程序 `panic`，例如：

```text
Problem parsing arguments: not enough arguments
```

## 4、核心逻辑不方便测试

如果所有逻辑都写在 `main` 中，就很难单独测试搜索逻辑。

后续应该把核心功能移动到 `src/lib.rs` 中，让搜索函数可以通过 `cargo test` 测试。
