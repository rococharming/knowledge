# 一、阶段目标

[[Rust/notes/项目/02_rlog/4、日志过滤与级别解析|日志过滤与级别解析]] 已经让 `view` 子命令支持 `--contains` 和 `--level`。

当前 `Stats` 分支仍然是空的：

```rust
Commands::Stats {
    file: _,
    level: _,
    contains: _,
} => {}
```

这里的 `file: _` 表示当前阶段虽然已经匹配到了 `Stats` 子命令里的文件路径字段，但还没有使用它。写成 `_` 可以明确告诉编译器“这个字段暂时忽略”，避免 unused variable warning。

本篇进入下一阶段：用红绿节奏实现 `stats` 子命令。

本阶段完成后，下面的命令应该能输出统计结果：

```shell
cargo run -- stats full_log.txt
cargo run -- stats full_log.txt --contains connection
cargo run -- stats full_log.txt --level error
```

第一版统计目标很简单：统计过滤后的日志中 `TRACE`、`DEBUG`、`INFO`、`WARN`、`ERROR` 分别出现了多少次。

# 二、先写统计模型测试

统计功能的核心行为是：给一组日志行，得到五种日志级别的数量。先在 `stats.rs` 中写红灯测试：

```rust
#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn counts_all_levels() {
        let lines = [
            "[2026-07-20T09:29:00Z TRACE rlog::app] entering startup sequence",
            "[2026-07-20T09:29:30Z DEBUG rlog::config] resolved config path",
            "[2026-07-20T09:30:00Z INFO rlog::app] started",
            "[2026-07-20T09:31:00Z WARN rlog::network] slow",
            "[2026-07-20T09:32:00Z ERROR rlog::network] failed",
            "[2026-07-20T09:33:00Z INFO rlog::app] done",
        ];

        let stats = calculate_stats(lines, None, None);

        assert_eq!(
            stats,
            LogStats {
                trace: 1,
                debug: 1,
                info: 2,
                warn: 1,
                error: 1,
            }
        )
    }
}
```

这个测试会先红，因为 `LogStats` 和 `calculate_stats` 还不存在。它的断言不是复算逻辑，而是直接写出已知日志样本的期望结果。

# 三、实现 LogStats

统计功能的核心是一个计数结构。它不关心文件怎么读取，也不关心命令行怎么解析，只负责记录不同日志级别的数量。

可以新增 `src/stats.rs`：

```rust
use crate::cli::Level;

#[derive(Debug, Default, PartialEq)]
pub struct LogStats {
    pub trace: usize,
    pub debug: usize,
    pub info: usize,
    pub warn: usize,
    pub error: usize,
}

impl LogStats {
    pub fn add(&mut self, level: &Level) {
        match level {
            Level::Trace => self.trace += 1,
            Level::Debug => self.debug += 1,
            Level::Info => self.info += 1,
            Level::Warn => self.warn += 1,
            Level::Error => self.error += 1,
        }
    }
}
```

这段代码里有三个重点：

| 设计 | 用途 |
|---|---|
| `LogStats` | 保存 `trace`、`debug`、`info`、`warn`、`error` 五个计数 |
| `Default` | 允许用 `LogStats::default()` 创建全 0 统计 |
| `add` | 根据日志级别累加对应字段 |

`usize` 适合做计数，因为它是 Rust 中常用的集合长度和索引类型。

`assert_eq!` 要求左右两边能比较，也要能在失败时打印出来。因此 `LogStats` 派生了：

```rust
#[derive(Debug, Default, PartialEq)]
```

| Trait | 用途 |
|---|---|
| `Debug` | 测试失败时打印结构体内容 |
| `Default` | 创建全 0 的初始统计 |
| `PartialEq` | 让 `assert_eq!` 可以比较两个 `LogStats` |

# 四、复用级别解析

上一阶段的 `parse_level` 在 `filter.rs` 中是私有函数：

```rust
fn parse_level(line: &str) -> Option<&Level> {
    // ...
}
```

现在统计功能也需要从一行日志中识别级别。如果在 `stats.rs` 里重新写一遍解析逻辑，就会出现重复代码。更好的方式是让 `parse_level` 在 crate 内可见：

```rust
pub(crate) fn parse_level(line: &str) -> Option<&Level> {
    if line.contains(" ERROR ") {
        Some(&Level::Error)
    } else if line.contains(" WARN ") {
        Some(&Level::Warn)
    } else if line.contains(" INFO ") {
        Some(&Level::Info)
    } else if line.contains(" DEBUG ") {
        Some(&Level::Debug)
    } else if line.contains(" TRACE ") {
        Some(&Level::Trace)
    } else {
        None
    }
}
```

`pub(crate)` 的含义是：这个函数可以被当前 crate 的其他模块使用，但不会作为对外公开 API 暴露出去。

对当前项目来说：

| 可见性 | 含义 | 是否适合 |
|---|---|---|
| `fn` | 只在 `filter.rs` 内可见 | 不够，`stats.rs` 也要用 |
| `pub(crate) fn` | 当前 crate 内可见 | 适合 |
| `pub fn` | 对外公开 | 暂时没必要 |

这样 `filter.rs` 继续用它做过滤，`stats.rs` 也能复用同一个解析规则。

# 五、实现 calculate_stats

有了 `LogStats` 和 `parse_level` 后，可以在 `stats.rs` 中加入统计函数：

```rust
use crate::cli::Level;
use crate::filter::{matches_filter, parse_level};

#[derive(Debug, Default, PartialEq)]
pub struct LogStats {
    pub trace: usize,
    pub debug: usize,
    pub info: usize,
    pub warn: usize,
    pub error: usize,
}

impl LogStats {
    pub fn add(&mut self, level: &Level) {
        match level {
            Level::Trace => self.trace += 1,
            Level::Debug => self.debug += 1,
            Level::Info => self.info += 1,
            Level::Warn => self.warn += 1,
            Level::Error => self.error += 1,
        }
    }
}

pub fn calculate_stats<'a>(
    lines: impl IntoIterator<Item = &'a str>,
    level: Option<&Level>,
    contain: Option<&str>,
) -> LogStats {
    let mut stats = LogStats::default();

    for line in lines {
        if !matches_filter(line, level, contain) {
            continue;
        }

        if let Some(parsed_level) = parse_level(line) {
            stats.add(parsed_level);
        }
    }

    stats
}
```

`calculate_stats` 接收一个可迭代的日志行集合，而不是直接接收文件路径。这样设计有两个好处：

- 文件读取逻辑仍然留在 `app.rs`。
- 测试时可以直接传入字符串数组，不需要创建真实文件。

这里用到了 `impl IntoIterator<Item = &'a str>`，表示调用者可以传入任何能迭代出 `&str` 的集合，例如：

```rust
[
    "[2026-07-20T09:30:00Z INFO rlog::app] started",
    "[2026-07-20T09:31:00Z ERROR rlog::app] failed",
]
```

# 六、再补过滤后统计测试

无过滤统计跑通后，再加一个红灯测试：统计前先应用关键词过滤。

```rust
#[test]
fn counts_after_keyword_filter() {
    let lines = [
        "[2026-07-20T09:29:00Z TRACE rlog::network] connection poll started",
        "[2026-07-20T09:29:30Z DEBUG rlog::network] connection timeout set",
        "[2026-07-20T09:30:00Z INFO rlog::app] started",
        "[2026-07-20T09:31:00Z WARN rlog::network] connection slow",
        "[2026-07-20T09:32:00Z ERROR rlog::network] connection failed",
    ];

    let stat = calculate_stats(lines, None, Some("network"));

    assert_eq!(
        stat,
        LogStats {
            trace: 1,
            debug: 1,
            info: 0,
            warn: 1,
            error: 1,
        }
    )
}
```

这个测试复用了上一阶段的 `matches_filter`，确认 `stats` 不是只统计全部日志，也能统计过滤后的日志。

# 七、接入 app.rs

`app.rs` 需要引入 `stats` 模块的统计函数，并让 `Stats` 分支真正工作。

下面的代码是本阶段要从当前空分支推进到的目标形态。

先在 `main.rs` 中接入模块：

```rust
mod app;
mod cli;
mod filter;
mod stats;
```

然后在 `app.rs` 中新增 `print_stats`：

```rust
use crate::cli::{Commands, Level};
use crate::filter::matches_filter;
use crate::stats::calculate_stats;
use std::fs::File;
use std::io::{self, BufRead, BufReader};
use std::path::Path;

pub fn run(command: Commands) -> io::Result<()> {
    match command {
        Commands::View {
            file,
            level,
            contains,
        } => {
            print_matching_lines(&file, level.as_ref(), contains.as_deref())?;
        }

        Commands::Stats {
            file,
            level,
            contains,
        } => {
            print_stats(&file, level.as_ref(), contains.as_deref())?;
        }
    }

    Ok(())
}

fn print_stats(path: &Path, level: Option<&Level>, contain: Option<&str>) -> io::Result<()> {
    let file = File::open(path)?;
    let reader = BufReader::new(file);
    let lines = reader.lines().collect::<io::Result<Vec<String>>>()?;

    let stats = calculate_stats(lines.iter().map(|line| line.as_str()), level, contain);

    println!("TRACE: {}", stats.trace);
    println!("DEBUG: {}", stats.debug);
    println!("INFO: {}", stats.info);
    println!("WARN: {}", stats.warn);
    println!("ERROR: {}", stats.error);

    Ok(())
}
```

这里为了让 `calculate_stats` 接收 `&str`，先把文件行收集成 `Vec<String>`：

```rust
let lines = reader.lines().collect::<io::Result<Vec<String>>>()?;
```

再通过：

```rust
lines.iter().map(|line| line.as_str())
```

把 `String` 的迭代器转换成 `&str` 的迭代器。

> 注意：这种写法会把所有行暂时收集到内存里。第一版为了让统计逻辑更容易测试，可以先接受。后续如果日志文件很大，可以把统计函数改成逐行累加，避免一次性保存所有行。

# 九、小结

本阶段完成的是：先用测试固定统计规则，再实现 `LogStats`、`calculate_stats` 和 `stats` 子命令输出。

当前项目结构建议变成：

```shell
src/
├── main.rs
├── cli.rs
├── app.rs
├── filter.rs
└── stats.rs
```

本篇涉及的 Rust 知识点：

| 知识点 | 用途 |
|---|---|
| `Default` | 创建全 0 的统计结构 |
| `PartialEq` | 支持 `assert_eq!` 比较结果 |
| `impl IntoIterator` | 让统计函数接收多种行集合 |
| `continue` | 跳过不匹配的日志行 |
| `#[cfg(test)]` | 只在测试时编译测试模块 |
| `assert!` | 验证布尔条件 |
| `assert_eq!` | 验证结构体统计结果 |
