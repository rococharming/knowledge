# 一、Trait Object

## 1、基本概念

`Trait Object`是 Rust 中实现**运行时多态**的一种方式。它允许代码在不知道具体类型的情况下，通过某个`Trait`提供的接口操作值。

例如，`Dog`和`Cat`是不同类型，但只要它们都实现了`Animal`，就可以通过`dyn Animal`统一使用。

先定义一个 Animal Trait：

```rust
trait Animal {
    fn speak(&self);
}

struct Dog;
struct Cat;

impl Animal for Dog {
    fn speak(&self) {
        println!("woof");
    }
}

impl Animal for Cat {
    fn speak(&self) {
        println!("meow");
    }
}
```

如果使用**泛型函数**，可以这样写：

```rust
fn make_sound<T: Animal>(animal: &T) {
	animal.speak();
}
```

这里的 `T: Animal` 使用的是静态分发，具体类型在编译期确定。

如果使用**Trait Object**，可以这样写：

```rust
fn make_sound(animal: &dyn Animal) {
	animal.speak();
}
```

这里的`&dyn Animal`表示：`animal`是一个实现了`Animal`的值的引用，但具体类型在函数签名中被隐藏了，在实际运行时才知道。

调用时：

```rust
fn main() {
    let dog = Dog;
    let cat = Cat;

    make_sound(&dog);
    make_sound(&cat);
}
```

**`&Dog` 和 `&Cat` 都可以被自动转换成 `&dyn Animal`**。

这就是`Trait Object`的核心作用：

> 用同一个接口处理不同类型的值


## 2、常见形式

`Trait Object`常见形式包括：

| 写法               | 含义                           |
| ---------------- | ---------------------------- |
| `&dyn Trait`     | 共享借用一个实现了 `Trait` 的值         |
| `&mut dyn Trait` | 可变借用一个实现了 `Trait` 的值         |
| `Box<dyn Trait>` | 拥有一个实现了 `Trait` 的值，具体值通常放在堆上 |
`Box<T>`智能指针后续会在[[18、智能指针|智能指针]]中继续展开。当前阶段只需要知道：`Box<dyn Trait>` 是拥有型的 Trait Object。

示例：

```rust
fn read(animal: &dyn Animal) {
    animal.speak();
}

fn read_mut(animal: &mut dyn Animal) {
    animal.speak();
}

fn own(animal: Box<dyn Animal>) {
    animal.speak();
}
```

- `&dyn Trait` 和 `&mut dyn Trait` 不拥有具体值，只是借用。
- `Box<dyn Trait>`拥有具体值，适合需要把不同类型放进同一个容器、或者需要返回不同具体类型的场景。

## 3、Trait Object必须放在指针后面

不能直接写：

```rust
let animal: dyn Animal;
```

因为`dyn Animal`是动态类型大小，也就是DST。编译器在编译期不知道它背后到底是 `Dog`、`Cat`，还是其他实现了 `Animal` 的类型，因此也不知道它的具体大小。

Rust的局部变量、结构体字段等默认要求大小在编译期已知，所以不能直接把 `dyn Animal` 当作普通值使用。

正确写法是放在指针（引用）后面：

```rust
let animal: &dyn Animal;
let animal: &mut dyn Animal;
let animal: Box<dyn Animal>;
```

原因：**指针本身的大小是已知的，即使它指向的具体值大小未知，也可以通过指针间接访问**。


## 4、Trait Object本质

`Trait Object`的引用本质是**胖指针**。

普通引用通常只包含一个数据地址，例如`&Dog`可以理解为：

```text
   &Dog
┌──────────┐
│ data_ptr │  指向 Dog 值
└──────────┘
```

而 `&dyn Animal` 需要同时知道两件事：

1. 具体值在哪里
2. 这个具体类型如何实现`Animal`的方法

所以`&dyn Animal`包含两个指针：

```rust
   &dyn Animal
┌──────────────────────┐
│ data_ptr             │  指向具体值，例如 Dog 或 Cat
│ vtable_ptr           │  指向该具体类型对应的虚表
└──────────────────────┘
```

其中：

- `data_ptr`指向真实数据
- `vtable_ptr`指向虚表，虚表中保存了该具体类型对这个`Trait`的方法实现入口，以及一些与析构、大小、对齐相关的信息。

当调用：

```rust
animal.speak();
```

大致过程可以理解为：

```rust
&dyn Animal
   │
   ├── data_ptr   ─────▶  具体值
   │
   └── vtable_ptr ─────▶  speak 方法入口
```

也就是说，`Trait Object` 调用方法时，不是在编译期直接写死调用哪个函数，而是在运行时通过虚表找到对应方法。

## 5、Trait Object与异构集合

`Trait Object`的典型用途是**异构集合**，也就是把不同具体类型放进同一个集合中。

```rust
trait Animal {
    fn speak(&self);
}

struct Dog;
struct Cat;

impl Animal for Dog {
    fn speak(&self) {
        println!("Woof!");
    }
}

impl Animal for Cat {
    fn speak(&self) {
        println!("Meow!");
    }
}

fn main() {
    let animals: Vec<Box<dyn Animal>> = vec![
        Box::new(Dog),
        Box::new(Cat),
    ];

    for animal in animals {
        animal.speak();
    }
}
```

结果：

![[Pasted image 20260527091919.png|200]]

`Vec<T>` 要求所有元素是同一种类型。`Dog` 和 `Cat` 本来是不同类型，不能直接放进同一个 `Vec`。但 `Box<dyn Animal>` 是同一种类型，所以可以放进同一个 `Vec<Box<dyn Animal>>`。

这里被统一的是外层接口类型。具体值仍然分别是 `Dog` 和 `Cat`，只是通过 `dyn Animal` 暴露为统一接口。


## 6、Trait Object中的关联类型

如果带有关联类型的`Trait`被用作`Trait Object`，必须明确写出关联类型。

```rust
fn dump(iter: &mut dyn Iterator<Item = String>) {
	for value in iter {
		println!("{value}");
	}
}
```

不能只写`fn dump(iter: &mut dyn Iterator)`，原因是：

如果不指定`Item`，编译器不知道`next()`返回什么类型。

因此，`dyn Iterator` 通常要写成类似 `dyn Iterator<Item = String>`。

# 二、静态分发和动态分发

## 1、Trait的两种使用方式

`Trait`可以通过两种主要方式使用：

| 写法                        | 分发方式 | 调用目标  |
| ------------------------- | ---- | ----- |
| `T: Trait` / `impl Trait` | 静态分发 | 编译期确定 |
| `dyn Trait`               | 动态分发 | 运行时确定 |
这两种方式不是谁替代谁，而是适合不同场景。


## 2、静态分发

静态分发是指：

> 编译器在编译期就知道最终调用哪个具体类型的方法。

例如：

```rust
trait Animal {
    fn speak(&self);
}

struct Dog;

impl Animal for Dog {
    fn speak(&self) {
        println!("woof");
    }
}

fn make_sound<T: Animal>(animal: &T) {
    animal.speak();
}

fn main() {
    let dog = Dog;

    make_sound(&dog);
}
```

调用 `make_sound(&dog)` 时，编译器可以推导出 `T = Dog`。

因此，`animal.speak()` 最终会调用 `Dog` 对 `Animal::speak` 的实现。

静态分发通常依赖**单态化**。也就是说，泛型函数会在编译期根据实际使用的具体类型生成专门版本。

可以粗略理解为，编译器为`Dog`类型生成了专门的函数版本：

```rust
fn make_sound_for_dog(animal: &Dog) {
    animal.speak();
}
```

这不是 Rust 真实生成的源码，只是帮助理解。

静态分发的特点：

| 特点    | 说明                          |
| ----- | --------------------------- |
| 调用目标  | 编译期确定                       |
| 运行时开销 | 通常没有额外间接调用开销                |
| 优化能力  | 编译器更容易内联和优化                 |
| 代价    | 不同具体类型可能生成多份代码，增加编译时间和二进制体积 |

## 3、动态分发

动态分发是指：

> 编译器在编译期只知道值实现了某个`Trait`，不知道它背后的具体类型。真正调用哪个方法，需要在运行时通过虚表确定。

例如：

```rust
fn make_sound(animal: &dyn Animal) {
    animal.speak();
}
```

这个函数接收的是 `&dyn Animal`。

调用时可以传入 `Dog`：

```rust
let dog = Dog;
make_sound(&dog);
```

也可以传入 `Cat`：

```rust
let cat = Cat;
make_sound(&cat);
```

对 `make_sound` 来说，它不关心背后具体是 `Dog` 还是 `Cat`，只知道这个值可以调用 `Animal` 提供的方法。

| 特点    | 说明           |
| ----- | ------------ |
| 调用目标  | 运行时通过虚表确定    |
| 运行时开销 | 有一次间接调用开销    |
| 灵活性   | 可以统一处理不同具体类型 |
| 优化能力  | 通常不如静态分发容易内联 |

## 4、静态分发与动态分发的选择

一般来说，如果编译期能够确定具体类型，并且不需要把不同类型统一放在一起，优先使用静态分发：

```rust
fn make_sound<T: Animal>(animal: &T) {
    animal.speak();
}
```

如果需要运行时统一处理不同具体类型，可以使用动态分发：

```rust
fn make_sound(animal: &dyn Animal) {
    animal.speak();
}
```

如果需要拥有不同具体类型并放进同一个容器，可以使用：

```rust
Vec<Box<dyn Animal>>
```


# 三、dyn 兼容

## 1、基本概念

不是所有的`Trait`都能写成`dyn Trait`。

如果一个`Trait`可以作为`Trait Object`使用，就说它满足`dyn`兼容，也叫对象安全。

例如，下面这个`Trait`可以写成`dyn Animal`：

```rust
trait Animal {
    fn speak(&self);
}
```

因为它的方法可以通过`&dyn Animal`的虚表正常调用：

```rust
fn speak(animal: &dyn Animal) {
    animal.speak();
}
```

`dyn Trait`的核心前提是：**方法调用在具体类型擦除后仍然可行**。

也就是说，编译器只知道`&dyn Trait`，而不知道背后具体是哪个类型。

**如果某个方法必须依赖具体类型信息才能正常调用，这个方法就可能破坏`dyn`兼容**。

常见影响`dyn`兼容的情况：

- 方法返回`Self`
- 方法参数中使用`Self`表达同类型关系
- 方法本身带泛型参数
- 关联函数没有`self`接收者
- 关联常量需要依赖具体实现类型

这些规则背后的共同点是：`dyn Trait` 会擦除具体类型，而这些写法又依赖具体类型信息。

## 2、返回Self的方法

例如：

```rust
trait CloneLike {  
	fn clone_like(&self) -> Self;  
}
```

为`Dog`实现`CloneLike`：

```rust
struct Dog;

impl CloneLike for Dog {
    fn clone_like(&self) -> Self {
        Dog
    }
}
```

在 `impl CloneLike for Dog` 中，`Self` 就是 `Dog`。

如果通过具体类型调用：

```rust
let dog = Dog;
let new_dog = dog.clone_like();
```

这没问题，因为编译器知道`Self`是`Dog`，返回值就是`Dog`。

但如果通过`dyn CloneLike`调用：

```rust
let dog = Dog;  
let value: &dyn CloneLike = &dog;  
  
let new_value = value.clone_like();
```

这里的`new_value`返回值就不确定了，而是`dyn CloneLike`，但它是DST。编译器也会报错：

![[Pasted image 20260528201607.png|400]]

编译器报错，`CloneLike`不是`dyn`兼容的。


## 3、参数中使用Self的方法

再看一个例子：

```rust
trait Combine {
	fn combine(&self, other: &Self) -> Self;
}
```

这个`Trait`表示：只能和同类型的另一个值合并，并返回同类型结果。

```rust
impl Combine for String {
	fn combine(&self, other: &Self) -> Self {
		format!("{self}{other}")
	}
}

impl Combine for i32 {
	fn combine(&self, other: &Self) -> Self {
		self + other
	}
}
```

在`impl Combine for String`中，`Self`是`String`

在`impl Combine for i32`中，`Self`是`i32`

如果尝试写成：

```rust
fn combine_any(left: &dyn Combine, right: &dyn Combine) -> Box<dyn Combine> {  
    left.combine(right)  
}
```

编译器报错：

![[Pasted image 20260528202756.png|400]]

问题在于：left背后可能是`String`，right背后可能是`i32`，但`combine`要求两者必须是同一种具体类型。

`dyn Trait`擦除了具体类型，因此无法在类型系统中保证这个同类型关系


## 4、泛型方法

`Trait`中的方法如果本身带泛型参数，也通常不能用于`Trait Object`。

```rust
trait Printer {
	fn print<T: std::fmt::Display>(&self, value: T);
}
```

泛型方法需要编译器根据不同的`T`版本生成不同版本。

但`dyn Trait`的虚表需要**固定的方法入口**。运行时通过虚表调用时，不能再为任意 `T` 生成新版本。

因此，泛型方法的单态化机制和 Trait Object 的动态分发机制在这里不匹配。

如果需要动态分发，通常要把泛型参数改成具体类型，或者改成另一个 Trait Object。

例如：

```rust
trait Printer {
    fn print(&self, value: &dyn std::fmt::Display);
}
```

这只是一个简化示例，实际设计时要根据需求权衡。

## 5、使用where Self: Sized排除方法

有些`Trait`里既有适合动态分发的方法，也有不适合动态分发的方法。

例如：

```rust
trait StringSet {  
    fn new() -> Self;  
      
    fn contains(&self, value: &str) -> bool;  
    fn add(&mut self, value: &str);  
}  
  
fn use_set(set: &mut dyn StringSet) {  
      
    set.add("hello");  
      
    if set.contains("hello") {  
        print!("found");  
    }  
}
```

`contains` 和 `add` 有 `self` 接收者，可以通过 Trait Object 调用。

但 `new() -> Self` 没有 `self` 接收者，并且返回 `Self`，不适合通过 Trait Object 调用。

上述代码报错：

![[Pasted image 20260528204804.png|500]]

这时可以给 `new` 加上：

```rust
where
	Self: Sized
```

完整写法：

```rust
 trait StringSet {
    fn new() -> Self
    where
        Self: Sized;

    fn contains(&self, value: &str) -> bool;

    fn add(&mut self, value: &str);
}
```

这样，`new` 只适用于已知大小的具体类型，不属于 Trait Object 可调用的接口。

于是可以写：

```rust
fn use_set(set: &mut dyn StringSet) {
    set.add("hello");

    if set.contains("hello") {
        println!("found");
    }
}
```

但不能通过 `dyn StringSet` 调用 `new()`。
