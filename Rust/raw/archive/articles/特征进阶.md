
# 一、Trait中的Self

## 1、Self表示当前实现类型

`Self` 表示当前实现该 `Trait` 的具体类型。它是类型层面的名称，不是方法参数中的 `self`。

`Self` 的作用是让 Trait 可以表达“当前实现类型”相关的关系，例如返回当前类型、要求参数是同一种类型、访问当前实现类型的关联项。

示例：

```rust
trait CloneLike {
    fn clone_like(&self) -> Self;
}
```

这里的 `Self` 表示实现 `CloneLike` 的那个具体类型。

```rust
struct Dog;

impl CloneLike for Dog {
    fn clone_like(&self) -> Self {
        Dog
    }
}
```

在 `impl CloneLike for Dog` 中，`Self` 就是 `Dog`。所以上面的实现可以理解为：

```rust
impl CloneLike for Dog {
    fn clone_like(&self) -> Dog {
        Dog
    }
}
```


## 2、返回当前类型

`Self` 常用于表示方法返回当前实现类型。

```rust
trait Reset {
    fn reset(self) -> Self;
}
```

实现：

```rust
struct Counter {
	value: i32,
}

impl Reset for Counter {
	fn reset(self) -> Self {
		Self { value: 0 }
	}
}
```

在 `impl Reset for Counter` 中，`Self` 就是 `Counter`。

这种写法适合构造、重置、转换后仍然返回同类型的场景。

## 3、要求参数是同一种类型

`Self`也可以用来表达“参数必须和当前实现类型相同”。

```rust
trait Merge {
    fn merge(&self, other: &Self) -> Self;
}
```

为 `String` 实现：

```rust
impl Merge for String {
	fn merge(&self, other: &Self) -> Self {
		format!("{self}{other}")
	}
}
```

在这个实现里，`other: &Self` 等价于 `other: &String`。

示例：

```rust
fn main() {
    let a = String::from("hello");
    let b = String::from(" world");

    let c = a.merge(&b);

    println!("{c}");
}
```

这种写法可以明确表达“只能和同类型的另一个值交互”。它在具体类型和泛型代码中很有用，但会影响 `dyn Trait` 的使用，后面讲 `dyn` 兼容时再展开。


## 4、Self与关联项

`Self`也常用于访问当前实现类型的关联项。

```rust
trait Parser {
	type Output;
	
	fn parse(&self) -> Self::Output;
}
```

`Self::Output` 表示当前实现类型指定的关联类型。

```rust
struct NumberParser;

impl Parser for NumberParser {
	type Output = i32;
	
	fn parse(&self) -> Self::Output {
		42
	}
}
```

在 `impl Parser for NumberParser` 中，`Self::Output` 就是 `i32`。

`Self::关联项` 这种写法在关联类型、关联常量和关联函数中都很常见。


# 二、Trait中的关联项

## 1、关联项的基本分类

`Trait`中不仅可以定义方法，还可以定义关联项。

关联项是和某个类型关联在一起的项目，常见形式包括关联函数、关联类型和关联常量。

Rust的Trait接口可以包含这些关联项。

| 关联项  | 作用                |
| ---- | ----------------- |
| 关联函数 | 定义没有 `self` 参数的函数 |
| 关联类型 | 由实现者指定某个相关类型      |
| 关联常量 | 由实现者提供某个类型相关常量    |

## 2、关联函数

`Trait`中可以定义没有`self`参数的函数，这些函数叫关联函数。

```rust
trait Factory {
	fn create() -> Self;
}
```

`create()` 没有 `self`、`&self` 或 `&mut self` 参数，所以它不是方法，而是类型关联函数。

```rust
struct User {
    name: String,
}

impl Factory for User {
    fn create() -> Self {
        Self {
            name: String::from("anonymous"),
        }
    }
}
```

调用：

```rust
fn main() {
	let user = User::create();
	
	println!("{}", user.name);
}
```

这里的 `User::create()` 表示调用 `User` 对 `Factory::create` 的实现。


## 3、在泛型代码中调用关联函数

关联函数可以在泛型代码中通过类型参数调用：

```rust
fn make<T: Factory>() -> T {
	T::create()
}
```

因为 `T: Factory`，编译器知道 `T` 一定提供 `create()`。

```rust
fn main() {
	let user: User = make();
	println!("{}", user.name);
}
``` 

这里 `T` 被推导为 `User`，所以 `T::create()` 调用的是 `User` 对 `Factory::create` 的实现。

## 4、关联类型

关联类型是在`Trait`中定义的类型占位符。它表示：实现该`Trait`的具体类型，需要指定某个和类型相关的类型。

最典型的例子`Iterator`：

```rust
trait Iterator {
	type Item;
	
	fn next(&mut self) -> Option<Self::Item>;
}
```

`type Item`是关联类型，表示迭代器每次产生的元素类型。不同迭代器可以有不同的`Item`。关联类型常用于把输出类型或成员类型绑定到具体实现上。

例如，命令行参数迭代器`std::env::Args`产生的是`String`，可以粗略理解为：

```rust
impl Iterator for std::env::Args {
	type Item = String;
	
	fn next(&mut self) -> Option<Self::Item> {
		
	}
}
```

这里的 `type Item = String` 表示 `std::env::Args` 每次产生 `String`。


## 5、在泛型代码中使用关联类型

可以在泛型代码中使用`I::Item`引用关联类型：

```rust
fn collect_into_vec<I>(iter: I) -> Vec<I::Item> 
where
	I: Iterator 
{
	let mut values = Vec::new();
	
	for item in iter {
		values.push(item)
	}
	
	values
}
```

`Vec<I::Item>` 表示返回一个 `Vec`，其中元素类型就是迭代器 `I` 的元素类型。

如果要对元素做更多操作，可以继续约束关联类型：

```rust
use std::fmt::Debug;

fn dump<I>(iter: I)
where 
	I: Iterator,
	I::Item: Debug
{
	for (index, value) in iter.enumerate() {
		println!("{index}: {value:?}");
	}
}
```

`I::Item: Debug` 表示迭代器产生的元素必须实现 `Debug`。

也可以直接指定关联类型：

```rust
fn dump_string<I>(iter: I) 
where 
	I: Iterator<Item = String>
{
	for value in iter {
		println!("{value}")
	}
}
```

`Iterator<Item = String>` 表示这个迭代器的元素类型必须是 `String`。

## 6、关联常量

`Trait`中也可以定义关联常量。关联常量表示：实现该`Trait`的类型需要提供某个和类型相关的常量值。

```rust
trait HasDefaultCapacity {
	const DEFAULT_CAPACITY: usize;
}
```

具体类型实现时，需要提供常量值：

```rust
struct SmallBuffer;
struct LargeBuffer;

impl HasDefaultCapacity for SmallBuffer {
	const DEFAULT_CAPACITY: usize = 8;
}

impl HasDefaultCapacity for LargeBuffer {
	const DEFAULT_CAPACITY: usize = 1024;
}
```

## 7、在泛型代码中使用关联常量

关联常量可以在泛型代码中使用：

```rust
fn create_buffer<T: HasDefaultCapacity>() -> Vec<u8> {
	Vec::with_capacity(T::DEFAULT_CAPACITY)
}
```


## 8、带默认值的关联常量

```rust
trait HasName {
    const NAME: &'static str = "unknown";
}
```

实现者可以复用默认值，也可以重写：

```rust
struct User;

impl HasName for User {
    const NAME: &'static str = "User";
}

struct Product;

impl HasName for Product {}
```


# 三、泛型Trait和默认类型参数

## 1、泛型Trait的基本概念

`Trait`本身也可以带泛型参数。

示例：

```rust
trait Convert<T> {
	fn convert(&self) -> T;
}
```

这里的 `T` 是 Trait 的泛型参数。

不同的类型参数可以理解为不同的`Trait`实例：

```rust
Convert<String>
Convert<i32>
```

一个类型可以针对不同类型参数实现同一个泛型 Trait。


## 2、为同一个类型实现不同Trait实例

```rust
trait Convert<T> {
    fn convert(&self) -> T;
}

struct NumberText(String);

impl Convert<i32> for NumberText {
    fn convert(&self) -> i32 {
        self.0.parse().unwrap()
    }
}

impl Convert<String> for NumberText {
    fn convert(&self) -> String {
        self.0.clone()
    }
}
```

同一个类型 `NumberText` 分别实现了 `Convert<i32>` 和 `Convert<String>`。

这说明 Trait 的泛型参数也是 Trait 身份的一部分。

调用：

```rust
fn main() {  
    let nt = NumberText(String::from("12345"));  
    let number: i32 = nt.convert();  
    let text: String = nt.convert();  
    println!("{}", number);  
    println!("{}", text);  
}
```

由于`NumberText`实现了多个不同的Trait实例，因此编译器不知道调用哪一个`nt.convert()`，这里通过变量类型标注区分，还可以使用完全限定方法，例如：

```rust
let number = <NumberText as Convert<i32>>::convert(&nt);
```

完全限定语法马上会详细介绍。


## 3、默认参数类型

泛型`Trait`可以给类型参数设置默认值。

例如标准库中的`std::ops::Add`使用了这种设计：

```rust
trait Add<Rhs = Self> {
	type Output;
	
	fn add(self, rhs: Rhs) -> Self::Output;
}
```

这里：

| 项目           | 含义               |
| ------------ | ---------------- |
| `Rhs`        | 右操作数类型           |
| `Rhs = Self` | 默认右操作数和左操作数是同一类型 |
| `Output`     | 加法结果类型，是关联类型     |
| `self`       | 左操作数按值传入         |
当代码中写 `a + b` 时，Rust 会根据类型调用对应的 `Add::add` 实现。


# 四、完全限定方法调用

## 1、完全限定方法调用的基本形式

Rust 中的方法调用有时会出现歧义，尤其是当多个`Trait`存在同名方法，并且同一个类型同时实现了这些`Trait`时，编译器可能无法判断应该调用哪一个方法。

这时可以使用**完全限定方法调用**，明确指定方法来自哪一个`Trait`、作用在哪个具体类型上。

完全限定语法称为UFCS，即 Universal Function Call Syntax。

例如，普通方法调用：

```rust
value.to_string()
```

可以理解为把`value`作为第一个参数传给方法。

因为 `to_string()` 来自 `ToString` Trait，所以也可以写成：

```rust
ToString::to_string(&value);
```

更完整的完全限定形式是：

```rust
<Type as Trait>::method(receiver, args...)
```

其中：

|部分|含义|
|---|---|
|`Type`|接收者的具体类型|
|`Trait`|方法来源的 Trait|
|`method`|要调用的方法|
|`receiver`|显式传入的 `self`|

例如：

```rust
<String as ToString>::to_string(&value);
```

含义：调用`String`类型作为`ToString`实现时提供的`to_string`方法。

日常代码中很少需要写得这么完整，但在方法重名或类型推导不明确时，它很有用。

## 2、多个Trait存在同名方法

两个 `Trait` 可以定义同名方法：

```rust
trait Render {  
    fn draw(&self);  
}  
  
trait Shoot {  
    fn draw(&self);  
}  
  
struct OutLaw;  
  
impl Render for OutLaw {  
    fn draw(&self) {  
        println!("draw on screen");  
    }  
}  
  
impl Shoot for OutLaw {  
  
    fn draw(&self) {  
        println!("draw a pistol");  
    }  
}  
  
fn main() {  
      
    let outlaw = OutLaw;  
      
    outlaw.draw();  
      
}
```

编译报错：

![[assets/Pasted image 20260529090824.png|500]]

因为`OutLaw` 同时实现了 `Render` 和 `Shoot`，两个 `Trait` 都有 `draw` 方法。如果直接调用`draw()`方法，编译器无法确定到底要调用 `Render::draw`，还是 `Shoot::draw`。

可以通过`Trait`名称明确指定：

```rust
Render::draw(&outlaw);  
Shoot::draw(&outlaw);
```

也可以使用完全限定语法：

```rust
<OutLaw as Render>::draw(&outlaw);  
<OutLaw as Shoot>::draw(&outlaw);
```

这两种写法都能消除歧义。

完全限定语法更明确，适合在歧义较强、或者需要同时说明“具体类型 + Trait 来源”的场景中使用。

## 3、固有方法与Trait方法同名

如果类型本身有一个固有方法，同时某个`Trait`也提供了同名方法，**普通方法调用会优先调用固有方法**。

```rust
trait Describe {
    fn describe(&self);
}

struct User;

impl User {
    fn describe(&self) {
        println!("inherent method");
    }
}

impl Describe for User {
    fn describe(&self) {
        println!("trait method");
    }
}

fn main() {  
	let user = User;  
	  
	user.describe();  
}
```

结果：

```text
inherent method
```

如果想调用 `Trait` 中的同名方法，需要显式指定：

```rust
Describe::describe(&user);
```

或者写成完全限定形式：

```rust
<User as Describe>::describe(&user);  
```

> 固有方法优先级高于Trait方法


## 4、关联函数的歧义

完全限定语法不仅能解决方法歧义，也能解决关联函数歧义。

例如：

```rust
trait Animal {
    fn baby_name() -> String;
}

struct Dog;

impl Dog {
    fn baby_name() -> String {
        String::from("Spot")
    }
}

impl Animal for Dog {
    fn baby_name() -> String {
        String::from("puppy")
    }
}
```

`Dog` 本身有一个关联函数 `baby_name()`。

`Dog` 实现的 `Animal` Trait 中也有一个关联函数 `baby_name()`。

调用固有实现中的关联函数：

```rust
fn main() {
    println!("{}", Dog::baby_name());
}
```

输出：

```
Spot
```

如果想调用 `Animal` Trait 中的关联函数，需要使用完全限定语法：

```rust
fn main() {  
    println!("{}", <Dog as Animal>::baby_name())  
}
```

输出：

```
puppy
```

不能简单写成：

```rust
Animal::baby_name();
```

因为 `baby_name()` 没有 `self` 接收者，编译器无法从调用对象推断具体实现类型。完全限定语法同时指定了 `Dog` 和 `Animal`，因此可以明确找到对应实现。


## 5、泛型Trait实例的区分

对于带泛型参数的`Trait`，同一个类型可以实现不同的`Trait`实例。

回到之前的`Convert<T>`Trait：

```rust
trait Convert<T> {
    fn convert(&self) -> T;
}

struct NumberText(String);

impl Convert<i32> for NumberText {
    fn convert(&self) -> i32 {
        self.0.parse().unwrap()
    }
}

impl Convert<String> for NumberText {
    fn convert(&self) -> String {
        self.0.clone()
    }
}
```

这里`NumberText`同时实现了`Convert<i32>`和`Convert<String>`。

调用时，如果有明确的目标类型，编译器可以根据上下文推断：

```rust
let n = NumberText(String::from("123"));  
  
let value: i32 = n.convert();  
let text: String = n.convert();
```

如果上下文不足：

```rust
let result = n.convert();
```

编译器无法判断应该选择 `Convert<i32>` 还是 `Convert<String>`。

这时可以使用完全限定语法：

```rust
let value = <NumberText as Convert<i32>>::convert(&n);  
let text = <NumberText as Convert<String>>::convert(&n);
```



# 五、子Trait和超Trait

## 1、基本概念

Rust中可以声明一个`Trait`依赖另一个`Trait`。

其中：

- 依赖其他`Trait`的`Trait`称为子`Trait`
- 被依赖的`Trait`称为超`Trait`

基本语法：

```rust
trait SubTrait: SuperTrait {
	// ...
}
```

这表示：实现 `SubTrait` 的类型，必须也实现 `SuperTrait`。

例如，先定义一个`Render` Trait：

```rust
trait Render {
    fn render(&self);
}
```

再定义一个依赖`Render`的`Movable`Trait：

```rust
trait Movable: Render {
	fn position(&self) -> (i32, i32);
}
```

这里的`trait Movable: Render`表示：实现 `Movable` 的类型必须也实现 `Render`。也就是说，`Movable` 是子 Trait，`Render` 是超 Trait。

## 2、子Trait中使用超Trait方法

因为所有实现`Movable`的类型都必须实现`Render`，所以`Movable`的默认方法中可以直接调用 `Render` 提供的方法。

```rust
trait Render {
    fn render(&self);
}

trait Movable: Render {
    fn position(&self) -> (i32, i32);

    fn report(&self) {
        let (x, y) = self.position();

        println!("position = ({x}, {y})");
        self.render();
    }
}
```

`report()` 中可以调用`self.render()`。因为 `Movable: Render` 已经保证了实现者一定具备 `render()` 方法。

## 3、实现子Trait时的要求

定义一个具体类型：

```rust
struct Player {
    x: i32,
    y: i32,
}
```

如果要让 `Player` 实现 `Movable`，就必须同时实现 `Render`：

```rust
impl Render for Player {
    fn render(&self) {
        println!("draw player");
    }
}

impl Movable for Player {
    fn position(&self) -> (i32, i32) {
        (self.x, self.y)
    }
}
```

`impl Render for Player` 和 `impl Movable for Player` 的顺序不重要。重要的是：最终 `Player` 必须同时满足两个实现。


## 4、子Trait表达能力依赖

子 Trait 不是面向对象语言中的类继承。它不会继承字段，也不会自动继承具体实现。

它表达的是一种能力约束：

> 如果一个类型具备`Movable`能力，那么它必须也具备`Render`能力


## 5、多个超 Trait

一个子 Trait 也可以依赖多个超 Trait。

```rust
trait Printable: std::fmt::Display + std::fmt::Debug {
	fn print_all(&self) {  
		println!("{}", self);  
		println!("{:?}", self);  
	}
}
```

这表示：实现 `Printable` 的类型，必须同时实现 `Display` 和 `Debug`。
