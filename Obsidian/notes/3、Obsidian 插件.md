# 一、插件系统的基本概念

Obsidian 的插件系统用于为笔记软件增加、调整或组合功能。它的核心价值不是把 Obsidian 变成万能软件，而是在本地 Markdown、双向链接和知识管理的基础上，按需补足工作流中的缺口。

Obsidian 的插件大致分为两类：

| 类型 | 来源 | 安装方式 | 适合用途 |
| --- | --- | --- | --- |
| 核心插件 | Obsidian 官方 | 随应用提供，按需启用 | 关系图谱、反向链接、日记、模板、页面预览等基础能力 |
| 社区插件 | 第三方开发者 | 需要单独安装和启用 | 增强编辑、导出、任务管理、外部服务连接等个性化需求 |

插件越多，系统能力越强，但维护成本、学习成本和潜在风险也会增加。初学阶段可以先掌握 [[1、Obsidian入门|Obsidian 入门]] 中的基础写作、链接、搜索和设置，再逐步引入插件。

# 二、核心插件

核心插件由 Obsidian 官方开发，并随应用一起安装。它们不需要额外下载，但很多插件可以按需开启或关闭。

启用核心插件的步骤：

1. 打开 **设置** 。
2. 进入 **核心插件** 。
3. 搜索需要的插件。
4. 打开插件右侧开关。

白板用于在一张无限画布上组织笔记、卡片、图片和链接，适合做主题梳理、关系草图、项目规划或阅读材料的空间化整理。

## 3、标签列表

标签列表是管理标签体系的核心插件。启用后，侧边栏会显示当前库中所有标签，并可以按照使用频次查看和检索。

![[assets/Pasted image 20260708002753.png|500]]

嵌套标签使用 `/` 表示层级：

```markdown
#maintag/subtag
```

其中 `maintag` 是主标签，`subtag` 是子标签。开启“显示嵌套标签”后，标签面板会按层级展示这些标签。

![[assets/Pasted image 20260708002916.png|600]]

点击主标签可以搜索该主标签下的所有相关笔记。标签不能包含空格，如果需要表达多个词，可以使用驼峰、下划线或破折号：

| 写法 | 示例 |
| --- | --- |
| 驼峰式 | `#TwoWords` |
| 下划线 | `#two_words` |
| 破折号 | `#two-words` |

## 13、录音机

录音机插件用于在 Obsidian 中直接录音。启用后，功能区会出现录音按钮：点击开始录音，再次点击结束录音。录音文件会保存并插入到当前打开的笔记中。

## 16、模板

模板用于把模板文件夹中的固定内容插入当前笔记，适合日记、会议纪要、读书笔记、项目记录等重复格式。

首先，创建一个专门的模板目录存放模板，例如`01_模板`：

![[assets/Pasted image 20260711164824.png|600]]

然后在 **设置 -> 核心插件 -> 模板** 中，将模板文件夹位置指定为`01_模板`：

![[assets/Pasted image 20260711165838.png|600]]

假如想创建一个会议记录模板，可以在 `01_模板` 下创建：

![[assets/Pasted image 20260711165605.png|600]]

这里可以关注到模板开头的`{{title}}`，它是一个模板变量。

模板变量是模板中的动态占位符。插入模板时，Obsidian 会把变量替换成当前笔记或当前时间对应的真实内容。

常用模板变量如下：

| 变量          | 含义     | 示例结果         |
| ----------- | ------ | ------------ |
| `{{title}}` | 当前笔记标题 | `会议记录`       |
| `{{date}}`  | 今天的日期  | `2026-07-11` |
| `{{time}}`  | 当前时间   | `16:30`      |

因此，如果模板中写：

```markdown
# {{title}}

日期：{{date}}
时间：{{time}}
```

插入到一篇名为“会议记录”的笔记后，就会变成类似：

```markdown
# 会议记录

日期：2026-07-11
时间：16:30
```

`{{date}}` 和 `{{time}}` 默认使用模板插件设置中的日期格式和时间格式。也可以在变量后加冒号，自定义本次插入时的格式：

```markdown
创建日期：{{date:YYYY-MM-DD}}
创建时间：{{time:HH:mm}}
完整时间：{{date:YYYY-MM-DD HH:mm}}
```

这里的格式来自 Moment.js 风格的日期时间标记。常用标记包括：

| 标记 | 含义 | 示例 |
| --- | --- | --- |
| `YYYY` | 四位年份 | `2026` |
| `MM` | 两位月份 | `07` |
| `DD` | 两位日期 | `11` |
| `HH` | 24 小时制小时 | `16` |
| `mm` | 两位分钟 | `30` |

当你新建一篇会议记录笔记时，在左侧功能区点击 **插入模板** ：

![[assets/Pasted image 20260711170018.png|600]]

选中对应的会议记录模板，则新建的笔记会自动填充为模板内容：

![[assets/Pasted image 20260711170116.png|600]]

还可以观察到，之前在模板开头写的`{{title}}`自动替换为了新建笔记的标题。

## 19、书签

书签用于为常用文件、搜索结果或其他重要入口添加固定访问位置。它适合把高频笔记、项目入口和常用搜索保存起来。

启用书签插件后，可以在左侧边栏打开 **书签** 面板。书签面板相当于一个固定入口列表，点击其中的条目就能直接跳转到对应位置。

![[assets/Pasted image 20260711172625.png|600]]

Obsidian 的书签可以保存多种对象：

| 可收藏对象 | 适合场景 |
| --- | --- |
| 文件 | 固定常用笔记、项目首页、索引页 |
| 文件夹 | 快速进入某个长期维护的目录 |
| 搜索结果 | 保存常用检索条件，例如未完成任务或某个标签 |
| 关系图谱 | 保存一个常用的全局图谱视图 |
| 标题 | 跳转到长文中的某个章节 |
| 块 | 跳转到笔记中的某个具体段落 |
| 外部链接 | 配合网页浏览器保存常用网页入口 |

常见的添加方式有三种：

1. 在书签面板顶部点击 **收藏当前标签页** 。
2. 在文件列表中右键点击文件或文件夹，选择 **收藏** 。
3. 在命令面板中搜索 “书签”，执行对应的添加命令。

例如，这里想把一篇笔记保存到书签中：

这类似于浏览器中的收藏夹。

如果要保存一个搜索结果，先在搜索面板输入搜索条件，然后点击搜索结果旁的 `...` 按钮，选择 **收藏** 。

书签也可以分组管理。在书签面板中点击 **新书签组** ，创建分组后，将书签拖入对应分组即可。适合按照“常用入口”“项目入口”“检索入口”“临时资料”等方式整理。

删除书签时，在书签面板中右键点击对应书签，选择 **移除** 即可。删除书签只会删除这个快捷入口，不会删除原始笔记、文件夹或搜索条件对应的内容。

## 20、属性列表

笔记属性（Properties）是用于描述笔记的结构化元数据，例如标题、创建日期、标签、状态和别名。属性通常显示在笔记顶部，但不属于正文内容，可以用于搜索、筛选、排序以及构建 Obsidian Bases 等数据视图。

一条属性由属性名称和属性值组成。例如，`status: in-progress` 表示属性名称为 `status`，属性值为 `in-progress`。

属性列表用于显示仓库中笔记的元数据（metadata）信息（即笔记顶部的 YAML Frontmatter），帮助查看和管理当前库里使用过的属性名称。

### （1）查看与管理属性

打开命令面板，输入“属性列表”，选择“属性列表：显示当前笔记的属性列表”并按 <kbd>Enter</kbd>：

![[assets/Pasted image 20260621223254.png|600]]

此时，右侧边栏会显示属性列表入口：

![[assets/Pasted image 20260621223329.png|600]]

在这里可以查看、添加和删除笔记属性。属性列表适合用来检查仓库中是否出现了重复字段，例如同时存在 `date`、`created`、`created_at` 这类含义相近但命名不一致的属性。

### （2）创建属性

除了使用属性列表入口，在笔记开头输入 `---` （YAML frontmatter）并按 <kbd>Enter</kbd>，Obsidian 会创建属性区域：

![[assets/Pasted image 20260621223404.png|600]]

也可以在源码模式下使用 YAML frontmatter：

```yaml
---
title: 示例笔记
date: 2026-07-07
tags:
  - obsidian
  - note-taking
aliases:
  - 示例别名
status: in-progress
related: "[[相关笔记]]"
---
```

YAML 属性区必须位于文件最顶部，并由两行 `---` 包围。

### （3）常见属性

| 属性 | 用途 | 示例 |
| --- | --- | --- |
| `title` | 笔记标题 | `title: 示例笔记` |
| `date` | 创建或更新日期 | `date: 2026-07-07` |
| `tags` | 分类和检索标签 | `tags: [obsidian, note-taking]` |
| `aliases` | 笔记的其他名称 | `aliases: [示例别名]` |
| `status` | 笔记或任务状态 | `status: in-progress` |
| `related` | 相关笔记链接 | `related: "[[相关笔记]]"` |

属性值支持文本、数字、复选框、日期、日期时间、列表和内部链接等类型。属性名称应保持统一，例如不要同时使用 `created`、`create-date` 和 `date-created` 表示同一含义。

> [!tip]
> 初学时只添加确实会用于搜索或整理的属性。属性过多会增加维护成本；标题、日期、标签和状态通常已经能够满足基础需求。

## 22、搜索

搜索用于在所有笔记中查找关键词，也可以通过路径、标签、文件名等条件缩小范围。它是中大型仓库中最基础的检索能力。

启用搜索插件后，可以在左侧边栏打开 **搜索** 面板。搜索既可以匹配文件名，也可以匹配正文内容。

基本使用方法：

1. 打开搜索面板。
2. 输入标题、正文关键词或标签。
3. 在结果列表中选择笔记，并查看匹配位置。

除了普通关键词，还可以使用搜索条件缩小范围：

```text
tag:#obsidian
path:"notes"
file:"安装"
```

常用条件：

| 条件 | 作用 | 示例 |
| --- | --- | --- |
| `tag:` | 按标签搜索 | `tag:#obsidian` |
| `path:` | 限定文件路径 | `path:"notes"` |
| `file:` | 按文件名搜索 | `file:"安装"` |

多个条件写在一起时，默认需要同时满足。例如，`tag:#obsidian path:"notes"` 会查找 `notes` 路径中带有 `#obsidian` 标签的笔记。

搜索适合处理三类问题：

- 只记得关键词，不记得笔记位置。
- 想查找某个标签、主题或项目相关的所有笔记。
- 想在特定文件夹中定位某类内容。

如果某个搜索条件经常复用，可以把搜索结果加入 [[#19、书签|书签]]，之后直接从书签面板打开，不必重复输入。

## 25、文件恢复

文件恢复插件会定期保存笔记快照，用来降低误删、误覆盖或同步冲突带来的损失。该插件默认通常已经开启，也可以在 **设置 → 核心插件 → 文件恢复** 中确认。

默认情况下，Obsidian 至少每隔 5 分钟保存一次快照，并保留 7 天。可以在 **设置 → 文件恢复** 中修改保存间隔和保留天数。

恢复快照的步骤：

1. 打开 Obsidian 设置。
2. 在左侧找到 **文件恢复** 。
3. 在 **快照** 旁点击 **查看** 。
4. 搜索要恢复的文件名。
5. 选择对应快照。
6. 点击 **复制到剪贴板** 。
7. 将内容粘贴回原笔记，或粘贴到新笔记中进行对比。

> [!warning]
> 文件恢复不是长期备份。快照会在超过保留天数后删除，而且“清除历史”会永久删除所有快照。重要仓库仍然需要独立备份或版本管理。

# 三、社区插件

社区插件由第三方开发者提供，可以扩展 Obsidian 原本没有的功能，例如增强表格编辑、导出 Word、统计笔记数量、显示最近文件、主题样式配置或连接外部服务。

## 1、安装社区插件

通过插件市场安装社区插件的步骤：

1. 打开 **设置 → 社区插件** 。
2. 关闭安全模式，开启社区插件功能。
3. 点击 **浏览** ，进入社区插件市场。
4. 搜索并打开需要的插件。
5. 点击 **安装** 。
6. 安装完成后点击 **启用** 。

安装后的插件会显示在“已安装插件”列表中，可以在这里启用、停用、更新、配置或卸载插件。

> [!note]
> 社区插件会运行第三方代码。安装前应查看插件说明、开发者、更新时间和使用人数，只安装确实需要且仍在维护的插件。

## 2、手动安装社区插件

如果无法直接访问社区插件市场，也可以手动安装插件。常见做法是下载插件压缩包，解压到当前仓库的 `.obsidian/plugins/插件名/` 目录中，然后重启 Obsidian 或重新加载插件。

手动安装的大致流程：

1. 下载插件压缩包。
2. 解压后确认其中包含插件所需文件。
3. 将插件文件夹放入仓库的 `.obsidian/plugins/` 目录。
4. 重启 Obsidian。
5. 进入 **设置 → 社区插件** ，在已安装插件中启用它。

手动安装适合网络受限或需要安装非市场插件的情况，但也更依赖来源可信度。不要安装来历不明的压缩包。

## 3、查找插件

查找插件时，不必从插件名称开始，可以从需求关键词开始。例如：

- 想导出 Word 文档，可以搜索 `word` 或 `docx`。
- 想查看最近打开的文件，可以搜索 `recent files`。
- 想统计文件夹下笔记数量，可以搜索 `note count`。
- 想改进主题配置，可以搜索主题名称或 `style settings` 一类关键词。

找到候选插件后，应先阅读插件说明，确认它解决的问题、使用方式、配置入口和可能限制。复杂插件尤其要先看文档，再决定是否纳入长期工作流。

## 4、使用社区插件

社区插件安装后，入口不一定相同。常见使用方式有三种：

- **界面展示** ：插件直接在侧边栏、功能区、状态栏或文件列表中显示入口。
- **命令面板** ：插件把功能注册为命令，需要通过命令面板搜索并执行。命令面板的基础用法见 [[1、Obsidian入门#6、命令面板|命令面板]]。
- **语法调用** ：部分插件需要在笔记中写特定语法，和 [[2、Obsidian 扩展语法|Obsidian 扩展语法]] 一起组成更复杂的笔记能力。

每个插件在设置页中提供专属配置，需要先调整选项再使用。

如果某个插件装好后“看不见”，优先检查命令面板、设置页和插件文档。

# 四、插件选择原则

插件应该围绕 Obsidian 的核心定位使用：本地 Markdown 写作、双向链接、检索、复用和知识管理。越贴近这些目标，插件越可能长期留在系统中。

## 1、优先选择轻量插件

适合优先尝试的插件通常有几个特点：

- 只补足一个明确的小功能。
- 不改变笔记文件的基本结构。
- 不强迫采用复杂工作流。
- 可以随时停用，停用后笔记内容仍然可读。

例如文件数量统计、最近文件列表、轻量导出工具、主题设置辅助等，都更适合作为早期插件。

## 2、谨慎选择重型插件

以下类型的插件需要谨慎：

- **改变 Obsidian 定位的插件** ：例如把 Obsidian 强行改造成时间管理、项目管理或数据库应用，可能让笔记系统变得臃肿。
- **改变数据结构的插件** ：如果插件生成大量脱离 Markdown 的专有数据，后续迁移和恢复会更困难。
- **依赖复杂语法的插件** ：功能强但学习成本高，适合在明确需求出现后再引入。
- **长期无人维护的插件** ：可能在 Obsidian 更新后失效。

> [!tip]
> 一个实用判断是：停用插件后，笔记本身是否仍然能阅读、搜索和迁移？如果答案是否定的，就要谨慎把它放进核心工作流。

## 3、按需启用与禁用

插件不必一直开启。某些插件只在特定任务中使用，例如导出 Word、批量处理或临时调整主题。任务结束后可以停用，让界面保持简洁，也减少插件之间互相影响的概率。

## 3、Pandoc

Obsidian 默认支持将 Markdown 文件转换为 PDF，只需要在笔记左上方点击 `...`，选择导出为 PDF 即可：

![[assets/Pasted image 20260712003638.png|600]]

但如果有导出为 DOCX、HTML 等其他格式的需求，就需要安装第三方插件。

`pandoc` 命令本身是一个文档格式转换器，它可以把 Markdown 转成 HTML、PDF、DOCX 等格式。

Obsidian 的 `Pandoc Plugin` 插件就是把 `pandoc` 接进 Obsidian，让你可以在 Obsidian 中直接把当前笔记导出为其他格式。

常见使用方式是通过命令面板执行导出命令。

![[assets/Pasted image 20260712012134.png|600]]

导出效果取决于插件配置、Pandoc 环境和原始 Markdown 内容复杂度。

不过，要顺利使用 Pandoc 插件，前置工作大概分为三层：安装命令行工具、配置插件路径、准备导出相关资源。

1. 安装 Pandoc

Pandoc Plugin 只是 Obsidian 里的调用入口，真正干活的是系统里的 `pandoc` 命令。因此需要先安装 Pandoc。macOS 可以使用 Homebrew 安装：

```shell
brew install pandoc
```

安装完成后，在终端确认：

```shell
which pandoc
pandoc --version
```

之后，将 `which pandoc` 输出的路径复制粘贴到 `Pandoc Plugin` 设置的 `Pandoc path` 下：

![[assets/Pasted image 20260712014849.png|600]]

设置后可能需要重启 Obsidian 应用。

# 六、小结

Obsidian 插件系统的关键不是“装得多”，而是“装得准”。核心插件提供稳定的基础能力，社区插件补足个性化需求；真正长期可靠的工作流，应当在停用大多数插件后仍然保留清晰的 Markdown 内容和可维护的链接结构。
