# 一、概述

Bilibili Obsidian Clipper 是一个面向 B 站视频的浏览器插件，用来把 B 站视频字幕、简介、章节和视频链接整理成 Markdown，并保存到 Obsidian 本地仓库。

它解决的是 [[Obsidian/notes/4、Obsidian Web Clipper|Obsidian Web Clipper]] 在 B 站页面上不够好用的问题。官方 Web Clipper 适合普通网页和部分海外视频平台，但对 B 站视频没有专门适配，直接剪藏时往往得不到真正有价值的字幕内容。

这个插件的核心价值不是“收藏视频链接”，而是把视频里的可检索文本沉淀到本地知识库。这样后续可以在 Obsidian 中搜索、链接、整理，也可以交给 AI 继续总结和改写。

> [!note]
> Bilibili Obsidian Clipper 保存的是字幕、元数据和嵌入链接，不等于把视频文件本身下载到本地。如果视频被删除或下架，嵌入视频仍可能无法播放。

# 二、插件能保存什么

## 1、字幕内容

插件在有字幕轨的 B 站视频页面中运行，能够读取当前视频的字幕文件。字幕来源包括作者上传的外挂字幕，以及平台提供的 AI 字幕。

如果同一个视频有多语言字幕，插件也可以选择具体语言版本。切换语言后，预览内容会随之变化。

> [!warning]
> 插件依赖视频本身存在“字幕”选项。没有字幕轨的视频无法直接获取字幕，需要另行使用 Whisper、Bilinote 或其他转录工具生成文字稿。

## 2、视频元数据

除了字幕，插件还会把视频简介、章节信息和视频链接等一并放入 Markdown 中。

这比只复制字幕更完整，因为后续回看时可以知道这份文字稿来自哪个视频、视频原本如何分段，以及作者对内容的简介是什么。

## 3、多种导出方式

插件提供几种常见输出方式：

| 操作 | 输出结果 | 适用场景 |
|---|---|---|
| 复制 Markdown | 将完整 Markdown 放入剪贴板 | 临时粘贴到 Obsidian、聊天工具或 AI 工具 |
| 下载 txt | 下载纯文本内容 | 上传给 AI、做轻量文本处理 |
| 下载 srt | 下载字幕文件 | 保留时间轴，适合字幕编辑或后续处理 |
| 保存到 Obsidian | 写入指定仓库目录 | 长期沉淀到本地知识库 |

保存到 Obsidian 是最适合知识库工作流的方式，因为它能跳过手动复制粘贴，让 B 站视频内容直接进入本地 Markdown 文件系统。

# 三、保存到 Obsidian 的实现链路

## 1、浏览器插件负责抓取字幕

首先需要安装浏览器插件，这里以 Google 浏览器为例，在 [Chrome 应用商店](https://chromewebstore.google.com/)搜索Bilibili Obsidian Clipper：

![[assets/Pasted image 20260711154007.png|600]]

安装即可。

浏览器插件运行在 B 站视频页时，可以读取页面里的视频信息、字幕列表和字幕内容。用户点击插件后，插件展示预览，并提供复制、下载和保存按钮，如下图所示：

![[assets/Pasted image 20260711154300.png|600]]

如果明明有字幕却读取失败，可以先刷新当前视频页面，再重新点击插件。这类问题通常与页面状态、播放器数据加载时机有关。

## 2、Local REST API 负责写入本地仓库

最主要的需求还是保存到 Obsidian ，但保存之前还需要对 Obsidian 进行配置。

浏览器插件本身运行在网页环境中，不能随意写入本地文件。要实现“一键保存到 Obsidian”，需要借助 Obsidian 社区插件 **Local REST API with MCP**。这个 Obsidian 插件会在本地开启一个 HTTP 接口，让外部脚本或浏览器插件可以通过请求创建、读取、更新和删除仓库中的 Markdown 文件。

典型流程如下：

1. 在 Obsidian 第三方插件中安装 Local REST API with MCP。

![[assets/Pasted image 20260711154841.png|600]]

2. 启用本地 HTTP 服务并复制 API Key 备用

![[assets/Pasted image 20260711154722.png|600]]

![[assets/Pasted image 20260711155035.png|600]]

3. 在 Bilibili Obsidian Clipper 设置页中填入接口地址和 API key。

![[assets/Pasted image 20260711155302.png|600]]

4. 设置默认保存目录，例如 `Clippings/Bilibili`。
5. 回到 B 站视频页，点击保存到 Obsidian。

> [!tip]
> 如果只在个人电脑本地使用，HTTP 端口配置更简单；HTTPS 端口需要处理证书导入，安全性更高，但配置成本也更高。

## 3、保存目录决定后续整理方式

视频原始剪藏适合放在专门的收集目录中，例如 `Clippings/Bilibili`。这个目录相当于“素材入口”，保留原始字幕、视频链接和元信息。

整理后的正式笔记则可以移动到 `notes`、`wiki` 或其他长期维护目录。这样可以区分两类文件：

- **原始剪藏**：保留来源内容，尽量少改动。
- **整理笔记**：按主题重写结构，加入解释、链接和结论。

这种分层方式和 [[Obsidian/notes/7、LLM Wiki|LLM Wiki]] 的思路相近：先保存原始材料，再由 AI 或人工把材料提炼成更稳定的知识页面。

# 四、和 AI 结合的整理流程

## 1、先收集，再重写

B 站字幕通常是口语化文本，适合保存为原材料，但不适合作为长期阅读笔记。更好的流程是先用插件保存完整文字稿，再让 AI 根据规则生成结构化笔记。

例如，可以要求 AI 完成这些工作：

- 提炼主题和关键结论。
- 按章节重组内容。
- 删除口语填充和重复表达。
- 补充必要的背景解释。
- 添加 Obsidian 维基链接。
- 将原始剪藏移动到归档目录。

这样得到的笔记会比单纯字幕更易读，也更适合后续搜索和复习。

## 2、用规则文件约束 AI 输出

在 Obsidian 仓库中放置 `CLAUDE.md`、`AGENTS.md` 或类似规则文件，可以告诉 AI 固定的输出格式、命名方式、目录约定和翻译要求。

规则文件的价值在于减少每次重复说明。只要规则写清楚，AI 就能更稳定地把不同视频的文字稿整理成一致风格的笔记。

常见规则包括：

- 原始剪藏保存在哪里。
- 整理后的笔记保存在哪里。
- 标题和文件名如何命名。
- 是否保留视频嵌入链接。
- 是否需要添加 frontmatter。
- 是否需要把原始文件归档。

## 3、在 Obsidian 内调用 AI

在 Obsidian 内调用 AI 通常有两种方式：一种是通过 Terminal 插件直接运行命令行工具，另一种是通过 Claudian 等插件更方便地调用 Claude。

无论使用哪种方式，本质都是让 AI 能访问本地 Markdown 文件，并按照仓库规则完成整理任务。这里的关键不在某个具体 AI 工具，而在于“本地材料 + 明确规则 + 可追踪文件系统”。

# 五、使用时的注意点

## 1、字幕轨是前提

插件只能获取已有字幕轨。对于没有字幕的视频，它不会自动下载视频、提取音频或执行语音转文字。

如果需要覆盖无字幕视频，可以考虑另一条链路：

1. 下载或获取视频音频。
2. 用 Whisper 等工具转写。
3. 将转写文本保存为 Markdown。
4. 再交给 AI 结构化整理。

这条链路更重，但覆盖范围更广。

## 2、视频链接不是长期保存

插件可以把视频 iframe 嵌入到笔记中，方便在 Obsidian 里回看。但嵌入链接依然依赖 B 站原视频存在。

如果某个视频对长期研究很重要，至少应该保留字幕文本、简介、章节和作者信息。必要时再单独考虑视频文件归档。

## 3、API key 不要填错

配置 Local REST API with MCP 时，需要把 API key 填入浏览器插件设置。

配置失败时可以按顺序检查：

1. Obsidian 是否已打开。
2. Local REST API with MCP 是否已启用。
3. HTTP 服务是否已开启。
4. 端口和地址是否与插件设置一致。
5. API key 是否只复制了真正的 key 内容。
