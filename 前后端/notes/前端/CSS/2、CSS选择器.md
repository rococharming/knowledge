# 一、选择器

CSS 选择器用于描述“哪些 HTML 元素应该应用这组样式”。如果把声明看成“设置什么样式”，选择器就是“找哪些元素”。

选择器的学习重点不是背所有写法，而是理解它们根据什么条件匹配元素：任意元素、标签名、类名、ID、属性、状态、位置，以及元素之间的结构关系。

# 二、基础选择器

## 1、通用选择器

通用选择器 `*` 会匹配任意元素。它常用于设置全局基础规则，例如统一盒模型或清理默认间距。

示例：

```css
* {
  box-sizing: border-box;
}
```

`*` 的匹配范围很大，所以不要用它随意设置具体视觉样式。下面这种写法会让页面中几乎所有文字都变色，之后还需要再一层层覆盖回来：

```css
* {
  color: red;
}
```

通用选择器适合写“全局基础约定”，不适合替代有明确意图的类选择器。

## 2、元素选择器

元素选择器根据 HTML 标签名匹配元素，适合设置某类元素的基础样式。

示例：

```html
<h1>今日任务</h1>
<p>整理 CSS 选择器笔记。</p>
<p>完成一个小练习。</p>
```

```css
p {
  color: #374151;
  line-height: 1.7;
}
```

这里所有 `p` 元素都会被选中。元素选择器覆盖面比较大，适合写通用基础样式，不适合表达某个具体模块的特殊外观。

## 3、类选择器

类选择器根据元素的 `class` 属性匹配元素，写法以点号开头。

示例：

```html
<p class="hint">保存文件后刷新页面。</p>
<p>这是一段普通说明。</p>
```

```css
.hint {
  color: #92400e;
  background-color: #fffbeb;
}
```

类选择器是日常写 CSS 最常用的选择器，因为同一个类可以复用在多个元素上，也不会像 ID 那样把样式绑定得太死。

## 4、ID 选择器

ID 选择器根据元素的 `id` 属性匹配元素，写法以井号开头。

示例：

```html
<h1 id="page-title">CSS 学习页</h1>
```

```css
#page-title {
  color: #111827;
}
```

一个页面中同一个 `id` 应该只出现一次。真实项目中，ID 更常用于页面锚点、脚本定位或无障碍关联；样式复用通常优先使用类选择器。`id` 与 `class` 的 HTML 基础可回看 [[前后端/notes/前端/HTML/3、HTML分组与脚本#三、id 与 class|id 与 class]]。

# 三、选择器列表

## 1、共享声明

如果多个选择器需要同一组声明，可以把它们写成选择器列表，用逗号分隔：

```css
h1,
h2,
.lead {
  color: #1e3a8a;
}
```

这表示 `h1`、`h2` 和 `.lead` 都会使用同一组声明。逗号不是“并且”，而是“这些选择器分别匹配到的元素都算”。

## 2、可读写法

选择器列表通常每个选择器单独占一行：

```css
.card-title,
.dialog-title,
.section-title {
  margin: 0;
  font-weight: 700;
}
```

这种写法便于增加、删除或检查某个选择器。不要为了省行数把很多选择器挤在一行，尤其是选择器变长以后，很容易漏看逗号或误读关系。

# 四、组合器

组合器用于表达选择器之间的结构关系。它们不会凭空创建关系，只是根据 HTML 文档树中已经存在的父子、后代、兄弟关系来匹配元素。

## 1、后代组合器

后代组合器用一个空格表示，匹配某个祖先元素内部的所有后代元素。

示例：

```html
<article class="post">
  <p>文章摘要。</p>
  <section>
    <p>正文段落。</p>
  </section>
</article>

<p>页面外部说明。</p>
```

```css
.post p {
  color: #374151;
}
```

`.post p` 会选中 `.post` 内部的两个 `p`，无论它们是直接子元素，还是隔着 `section` 的更深层后代。页面外部的 `p` 不会被选中。

## 2、子代组合器

子代组合器用 `>` 表示，只匹配直接子元素。

示例：

```html
<section class="panel">
  <p>直接说明。</p>
  <div>
    <p>嵌套说明。</p>
  </div>
</section>
```

```css
.panel > p {
  color: #2563eb;
}
```

这里只有“直接说明”会变蓝，因为它是 `.panel` 的直接子元素；“嵌套说明”隔着一层 `div`，不符合直接子代关系。

子代组合器适合避免样式误伤深层结构。相比 `.panel p`，`.panel > p` 的范围更窄，也更能表达“只管第一层内容”的意图。

## 3、相邻兄弟组合器

相邻兄弟组合器用 `+` 表示，匹配紧跟在前一个元素后面的兄弟元素。

示例：

```html
<h2>安装步骤</h2>
<p>先下载工具。</p>
<p>再运行安装命令。</p>
```

```css
h2 + p {
  margin-top: 0;
  color: #065f46;
}
```

`h2 + p` 只会选中紧跟在 `h2` 后面的第一个 `p`。第二个 `p` 虽然也是 `h2` 后面的兄弟元素，但不是“紧挨着”的那个。

## 4、后续兄弟组合器

后续兄弟组合器用 `~` 表示，匹配某个元素后面所有符合条件的兄弟元素。

示例：

```html
<h2>注意事项</h2>
<p>不要直接改线上文件。</p>
<p>修改前先保存当前版本。</p>
<div>示例区域</div>
<p>最后再做验证。</p>
```

```css
h2 ~ p {
  color: #7c2d12;
}
```

这里 `h2` 后面的三个 `p` 都会被选中。中间出现的 `div` 不会中断匹配，因为 `~` 看的是“后面所有同级兄弟”，不是“紧挨着”。

# 五、选择边界

## 1、少写长链

组合器越多，选择器越依赖当前 HTML 结构。下面这种写法虽然能命中元素，但维护成本高：

```css
main article section div ul li a {
  color: #2563eb;
}
```

一旦中间多包一层或少包一层，选择器就可能失效。更稳的方式通常是给有明确职责的元素加类名：

```html
<a class="resource-link" href="/docs">阅读文档</a>
```

```css
.resource-link {
  color: #2563eb;
}
```

## 2、先表达意图

选择器应该优先表达样式意图，而不是机械复刻 DOM 路径。也就是说，先想清楚“我要给哪类内容加样式”，再决定选择器写法，而不是把元素从外到内的层级全部照抄一遍。

> DOM（Document Object Model，文档对象模型）可以先理解为：浏览器把 HTML 解析后形成的一棵元素树。这里的“DOM 路径”指沿着这棵树的父子层级一路写选择器，例如从 `main` 写到 `a`。

| 需求 | 更合适的方向 | 原因 |
|---|---|---|
| 某类卡片标题统一样式 | `.card-title` | 可复用，和结构层级解耦 |
| 只处理列表第一层项目 | `.menu > li` | 明确限制直接子项 |
| 标题后第一段特殊处理 | `.article h2 + p` | 表达相邻关系 |
| 某个模块内所有说明文字 | `.notice p` | 后代范围符合需求 |

写选择器时可以先问一句：这个样式是属于“元素类型”、属于“模块角色”，还是属于“结构关系”？答案不同，选择器也应该不同。
