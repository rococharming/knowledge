# 一、样式冲突

CSS 的 “Cascading” 指的就是 **层叠**：当多个样式声明都可能影响同一个元素时，浏览器会按一套规则决定最终使用哪个值。

样式冲突通常需要同时满足三个条件：

1. 多条规则都能匹配到同一个元素。
2. 它们设置的是同一个 CSS 属性。
3. 这些属性值不一样。

示例：

```html
<p class="intro">这段文字最终是什么颜色？</p>
```

```css
p {
  color: gray;
}

.intro {
  color: blue;
}
```

两条规则都匹配这个 `p` 元素，也都设置了 `color`。浏览器需要比较它们，最终让文字显示为蓝色。

# 二、层叠

## 1、相关性

浏览器首先会过滤“不相关”的规则。选择器没有匹配到当前元素，或者媒体查询条件不成立，这条规则就不会参与本次比较。

示例：

```css
p {
  color: blue;
}

@media (max-width: 600px) {
  p {
    color: green;
  }
}
```

在宽度大于 `600px` 的窗口里，媒体查询内部的规则不参与比较；在宽度小于或等于 `600px` 的窗口里，它才会进入层叠。

## 2、来源与重要性

CSS 可以来自不同来源：

| 来源 | 说明 |
|---|---|
| 浏览器样式 | 浏览器自带的默认样式 |
| 用户样式 | 用户自己设置的阅读偏好或辅助样式 |
| 作者样式 | 页面作者写的 CSS |

平时写页面时，主要接触的是作者样式：外部样式表、内部样式表和行内样式。浏览器默认样式在 [[1、CSS基础#四、默认样式|默认样式]] 中已经出现过。

`!important` 会改变声明的重要性：

```css
.message {
  color: red !important;
}
```

`!important` 写在属性值后面、分号前面。它不是选择器优先级的一部分，而是让这条声明进入“重要声明”的比较层级。

这意味着：一个普通的高优先级选择器，仍然可能输给同一来源中的 `!important` 声明；但如果两条冲突声明都带有 `!important`，浏览器又会继续比较它们的选择器优先级。

> [!warning] 谨慎使用 `!important`
> `!important` 会打断正常的层叠判断，让维护变困难。只有在覆盖第三方样式、临时处理无法改动的来源，或有明确可访问性需求时，才应谨慎使用，并说明原因。

## 3、优先级与顺序

当规则来自同一层级、重要性也相同时，浏览器才比较选择器优先级。优先级也相同时，后出现的声明生效。

示例：

```css
p {
  color: blue;
}

p {
  color: green;
}
```

两条规则的选择器完全一样，优先级相同，所以后面的 `green` 生效。

# 三、优先级

## 1、计算方式

选择器优先级可以先按四段理解：

```text
行内样式 - ID - 类/属性/伪类 - 元素/伪元素
```

常见选择器的权重大致如下：

| 写法 | 示例 | 记法 |
|---|---|---|
| 行内样式 | `style="color: red;"` | `1-0-0-0` |
| ID 选择器 | `#title` | `0-1-0-0` |
| 类选择器 | `.title` | `0-0-1-0` |
| 属性选择器 | `[type="text"]` | `0-0-1-0` |
| 伪类 | `:hover` | `0-0-1-0` |
| 元素选择器 | `p` | `0-0-0-1` |
| 伪元素 | `::before` | `0-0-0-1` |
| 通用选择器 | `*` | `0-0-0-0` |

比较时从左到右看，不要把它当成普通十进制数字相加。一个 ID 选择器通常会压过很多类选择器，因为它在更靠前的一段里有值。

## 2、选择器示例

示例：

```html
<p id="notice" class="message">保存成功。</p>
```

```css
p {
  color: gray;
}

.message {
  color: green;
}

#notice {
  color: red;
}
```

三条规则都能匹配这个段落：

| 选择器 | 记法 | 结果 |
|---|---|---|
| `p` | `0-0-0-1` | 低 |
| `.message` | `0-0-1-0` | 中 |
| `#notice` | `0-1-0-0` | 高 |

最终 `#notice` 的 `red` 生效。

组合选择器会把命中的选择器部分累计：

```css
p.message {
  color: green;
}
```

`p.message` 同时包含一个元素选择器和一个类选择器，记作 `0-0-1-1`。它比单独的 `.message` 更具体，但不建议为了“赢”而不断加长选择器。

## 3、引入方式

行内样式写在元素的 `style` 属性上，通常会覆盖普通作者样式：

```html
<p class="message" style="color: red;">这段文字是红色。</p>
```

```css
.message {
  color: blue;
}
```

这里红色生效，因为行内样式比普通选择器更靠前。

内部 CSS 和外部 CSS 本身没有谁天然更高。真正决定优先级的是选择器；如果选择器优先级相同，则看谁后出现。

```html
<link rel="stylesheet" href="./base.css">

<style>
  p {
    color: green;
  }
</style>
```

如果 `base.css` 里也有 `p { color: blue; }`，上面的内部样式因为出现得更晚，会让段落变成绿色。反过来，如果把 `<link>` 放在 `<style>` 后面，外部样式表里的同优先级规则就可能覆盖内部样式。

# 四、继承

## 1、默认继承

继承指的是：当某个元素没有直接设置某个属性时，它可能从父元素那里拿到这个属性的计算值。

```html
<section class="article">
  <h2>继承示例</h2>
  <p>这段文字会继承文字颜色和字体。</p>
</section>
```

```css
.article {
  color: #1f2937;
  font-family: system-ui, sans-serif;
}
```

`color` 和 `font-family` 通常会继承，所以 `h2` 和 `p` 会沿用 `.article` 上的文字颜色和字体。

## 2、不继承属性

不是所有属性都会继承。盒模型和背景相关属性通常不会默认继承：

```css
.article {
  padding: 24px;
  border: 1px solid #d1d5db;
  background-color: #f9fafb;
}
```

这里 `padding`、`border` 和 `background-color` 作用在 `.article` 自己身上，不会自动复制到内部每一个标题和段落上。

常见判断可以先这样记：

| 常见会继承 | 常见不会继承 |
|---|---|
| `color` | `margin` |
| `font-family` | `padding` |
| `font-size` | `border` |
| `line-height` | `background-color` |
| `text-align` | `width` / `height` |

## 3、显式继承

如果确实希望子元素使用父元素的某个值，可以用 `inherit`：

```html
<section class="card">
  <p>普通段落</p>
  <p class="same-padding">继承父元素内边距</p>
</section>
```

```css
.card {
  padding: 20px;
}

.same-padding {
  padding: inherit;
}
```

`padding` 默认不继承，但 `padding: inherit;` 会明确要求它从父元素拿值。

> [!note] 直接命中优先于继承
> 如果某个元素被选择器直接设置了属性，这个直接设置通常会覆盖从父元素继承来的值。继承只是“没有直接设置时的默认来源”。

# 五、维护习惯

## 1、少用高权重

ID 选择器、行内样式和 `!important` 都能让样式更难覆盖。它们不是不能用，而是要用在真正需要的位置。

更稳的写法通常是：

- 用类选择器表达组件或内容角色。
- 让选择器短而清楚。
- 避免为了覆盖样式不断加长选择器。
- 避免把可复用样式写成行内样式。

这些习惯和 [[2、CSS选择器#五、选择边界|选择边界]] 是同一件事：选择器既要能命中元素，也要给将来的修改留下空间。

## 2、按顺序排查

遇到“为什么这个样式没生效”时，可以按这个顺序想：

1. 选择器有没有匹配到这个元素？
2. 媒体查询等条件是否成立？
3. 有没有 `!important` 或行内样式参与？
4. 选择器优先级谁更高？
5. 优先级相同时，哪条规则更晚出现？
6. 这个值是直接设置的，还是从父元素继承来的？

只要把“层叠、优先级、继承”分开看，CSS 冲突就不会像随机发生的魔法。
