# 一、属性选择器

属性选择器用于根据 HTML 元素是否具有某个属性、属性值是否符合某种规则来选择元素。它比普通元素选择器更精确，也比额外添加类名更贴近某些 HTML 自带语义。

基本写法是把属性条件写在方括号里：

```css
选择器[属性] {
  属性: 值;
}
```

例如：

```css
input[type="checkbox"] {
  accent-color: #f97316;
}
```

这里 `input` 先限定元素类型，`[type="checkbox"]` 再限定这个 `input` 的 `type` 属性必须等于 `checkbox`。属性选择器仍然属于 [[2、CSS选择器|CSS 选择器]]，只是匹配依据从标签名、类名扩展到了元素属性。

常见写法可以先掌握这些：

| 写法           | 含义                       |
| ------------ | ------------------------ |
| `[属性]`       | 匹配拥有指定属性的元素              |
| `[属性="值"]`   | 匹配属性值等于指定值的元素            |
| `[属性^="值"]`  | 匹配属性值以指定字符串开头的元素         |
| `[属性$="值"]`  | 匹配属性值以指定字符串结尾的元素         |
| `[属性*="值"]`  | 匹配属性值任意位置包含指定字符串的元素      |
| `[属性~="值"]`  | 匹配空格分隔列表中包含指定词的元素        |
| `[属性\|="值"]` | 匹配属性值等于指定值，或以 `值-` 开头的元素 |

# 二、存在和值

## 1、存在匹配

`[属性]` 只关心元素有没有这个属性，不关心属性值是什么。

示例：

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>属性存在匹配</title>
  <style>
    .user-form input[required] {
      border: 2px solid #f97316;
    }
  </style>
</head>
<body>
  <form class="user-form">
    <input type="text" placeholder="昵称">
    <input type="email" placeholder="邮箱" required>
  </form>
</body>
</html>
```

这里第二个输入框带有 `required` 属性，所以会被 `.user-form input[required]` 选中并显示橙色边框。

## 2、精确匹配

`[属性="值"]` 要求属性值和指定值完全相等，常用于区分不同类型的表单控件。

示例：

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>属性值精确匹配</title>
  <style>
    .choice input[type="checkbox"],
    .choice input[type="radio"] {
      accent-color: #f97316;
    }
  </style>
</head>
<body>
  <form class="choice">
    <label><input type="checkbox"> 接收更新通知</label>
    <label><input type="radio" name="plan"> 标准版</label>
    <label><input type="radio" name="plan"> 专业版</label>
  </form>
</body>
</html>
```

这里 `[type="checkbox"]` 和 `[type="radio"]` 分别匹配复选框和单选按钮。表单状态相关的写法可回看 [[4、伪类选择器#四、表单伪类选择器|表单伪类选择器]]。

# 三、字符串匹配

字符串匹配用于根据属性值的开头、结尾或包含关系选择元素。它适合处理链接、图标类名、文件类型等有稳定命名规律的场景。

示例：

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>属性字符串匹配</title>
  <style>
    .resource-list a[href^="https://"] {
      color: #16a34a;
    }

    .resource-list a[href$=".pdf"] {
      font-weight: 700;
    }

    .resource-list [class*="icon-"] {
      margin-right: 6px;
      color: #f97316;
    }
  </style>
</head>
<body>
  <ul class="resource-list">
    <li><a href="https://example.com">安全链接</a></li>
    <li><a href="./guide.pdf">PDF 指南</a></li>
    <li><span class="icon-download">下载</span></li>
  </ul>
</body>
</html>
```

这段代码中：

- `[href^="https://"]` 匹配以 `https://` 开头的链接。
- `[href$=".pdf"]` 匹配以 `.pdf` 结尾的链接。
- `[class*="icon-"]` 匹配 `class` 属性中包含 `icon-` 的元素。

`*=` 很灵活，但也更容易误伤。例如 `[class*="icon"]` 会匹配 `icon-download`，也可能匹配 `biconnect` 这种并不想要的字符串。实际使用时，尽量让匹配片段足够明确。

# 四、词语和语言

## 1、单词匹配

`[属性~="值"]` 用于匹配由空格分隔的一组词，常见于 `class`、`rel` 等属性。

示例：

```css
[class~="active"] {
  color: #f97316;
}
```

这个选择器能匹配 `class="tab active"`，但不会匹配 `class="tab-active"`，因为 `active` 必须是空格分隔列表里的一个完整词。

## 2、语言匹配

`[属性|="值"]` 会匹配属性值等于指定值，或者以 `值-` 开头的情况，常用于语言代码。

示例：

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>语言属性匹配</title>
  <style>
    [lang|="zh"] {
      font-family: "Microsoft YaHei", sans-serif;
    }

    [lang|="en"] {
      font-family: Georgia, serif;
    }
  </style>
</head>
<body>
  <p lang="zh-CN">这是一段中文。</p>
  <p lang="en-US">This is an English sentence.</p>
</body>
</html>
```

`[lang|="zh"]` 可以匹配 `lang="zh"`，也可以匹配 `lang="zh-CN"`、`lang="zh-Hans"`。这种写法适合按语言区域设置字体。
