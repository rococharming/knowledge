# 一、转换的两种方式

JavaScript 有时会自动转换类型，也允许程序明确指定转换方式。读取用户输入或外部数据时，优先主动转换并验证，避免隐式规则掩盖输入错误。

## 1、显式转换

```js
console.log(Number("10")); // 10
console.log(String(10));    // "10"
console.log(Boolean(""));  // false
```

## 2、隐式转换

运算符会根据上下文自动转换操作数：

```js
console.log("10" - 5); // 5，字符串转为数字
console.log("10" * 2); // 20
console.log("10" + 5); // "105"，加号改为字符串拼接
```

`true` 在数值上下文通常转为 `1`，`false` 转为 `0`；`null` 转数字为 `0`，`undefined` 转数字为 `NaN`。理解这些规则即可，不要把它们当作业务逻辑的捷径。

# 二、解析数字文本

`Number()` 要求整个字符串都是可识别的数值格式；`parseInt()` 和 `parseFloat()` 则从开头尽可能读取有效前缀。解析整数时始终传入基数 `10`。

```js
console.log(Number("42px"));       // NaN
console.log(parseInt("42px", 10)); // 42
console.log(parseFloat("3.14rem")); // 3.14
console.log(parseFloat("314e-2")); // 3.14
```

表单必须是“完整数字”时，先用 `Number()`，再验证结果；`parseInt("12px", 10)` 适合提取开头的单位数值，不适合作为严格校验。

```js
const rawAge = "18";
const age = Number(rawAge);

if (Number.isFinite(age)) {
  console.log(age + 1);
}
```

# 三、NaN 与有限性

全局 `isNaN()` 会先按规范的 `ToNumber` 规则把参数转为 `number`，再判断转换结果是否是 `NaN`。对字符串、布尔值、`null` 等常见值，这和调用 `Number(value)` 的结果相同：可识别的数字文本会转为数字，空字符串或只含空白的字符串会转为 `0`，`true`、`false` 分别转为 `1`、`0`，`null` 转为 `0`，而不能识别的文本和 `undefined` 转为 `NaN`。

```js
console.log(isNaN("42"));    // false：先转为 42
console.log(isNaN("hello")); // true：先转为 NaN
console.log(isNaN(""));      // false：先转为 0
console.log(isNaN(null));    // false：先转为 0
console.log(isNaN(true));    // false：先转为 1
```

这也是全局 `isNaN()` 不适合直接验证“值本身是否为 `NaN`”的原因。`NaN` 与任何值都不相等，包括它自己。

```js
console.log(NaN === NaN); // false
```

要判断一个已计算的值是否就是 `NaN`，使用不转换类型的 `Number.isNaN()`；要验证它是有限数字，使用 `Number.isFinite()`：

```js
console.log(Number.isNaN(0 / 0));       // true
console.log(Number.isNaN("NaN"));      // false
console.log(Number.isFinite(42));       // true
console.log(Number.isFinite(Infinity)); // false
```

> [!note] BigInt 与 Symbol
> 全局 `isNaN()` 对 `bigint` 和 `symbol` 不能完成 `ToNumber` 转换，会抛出 `TypeError`。它并不完全等同于 `Number()`：`Number(1n)` 可以得到 `1`，但 `isNaN(1n)` 会报错。
