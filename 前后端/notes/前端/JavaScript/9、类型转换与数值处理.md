# 一、显式与隐式转换

JavaScript 有时会在运算时自动转换类型，称为隐式类型转换。它很方便，但也容易掩盖输入错误；读取用户输入或外部数据时，应优先显式使用 `Number()`、`String()` 或 `Boolean()`。

```js
console.log("10" - 5);  // 5，字符串转为数字
console.log("10" * 2);  // 20
console.log("10" + 5);  // "105"，加号改为字符串拼接

console.log(Number("10")); // 10
console.log(String(10));     // "10"
console.log(Boolean(""));    // false
```

`true` 在数值上下文通常转为 `1`，`false` 转为 `0`；`null` 转数字为 `0`，`undefined` 转数字为 `NaN`。这些规则应理解，但不要把它们当作业务逻辑的捷径。

# 二、解析字符串数字

`Number()` 要求整个字符串都是可识别的数值格式；`parseInt()` 和 `parseFloat()` 则从开头尽可能读取有效前缀。解析整数时始终传入基数 `10`。

```js
console.log(Number("42px"));       // NaN
console.log(parseInt("42px", 10)); // 42
console.log(parseFloat("3.14rem")); // 3.14
console.log(parseFloat("314e-2")); // 3.14
```

因此，表单必须是“完整数字”时，先用 `Number()`，再验证结果；`parseInt("12px", 10)` 适合提取开头的单位数值，不适合作为严格校验。

```js
const rawAge = "18";
const age = Number(rawAge);

if (Number.isFinite(age)) {
  console.log(age + 1);
}
```

# 三、NaN 与有限性

全局 `isNaN()` 会先转换参数，所以 `isNaN("hello")` 为 `true`，但 `isNaN("")` 为 `false`。当要判断一个已计算的值是否就是 `NaN` 时，使用不转换类型的 `Number.isNaN()`。

```js
console.log(NaN === NaN);           // false
console.log(Number.isNaN(0 / 0));   // true
console.log(Number.isNaN("NaN"));  // false
console.log(Number.isFinite(42));   // true
console.log(Number.isFinite(Infinity)); // false
```

# 四、格式化与 Math

`toFixed(digits)` 用固定小数位格式化数字，并返回 **字符串**，因此适合展示而不是继续计算。

```js
const price = 19.99;

console.log(price.toFixed(2)); // "19.99"
console.log((3.14159).toFixed(2)); // "3.14"
```

`Math` 提供常见数学工具：

```js
console.log(Math.min(1, 5, 3)); // 1
console.log(Math.max(1, 5, 3)); // 5
console.log(Math.floor(4.7));   // 4
console.log(Math.ceil(4.3));    // 5
console.log(Math.round(4.5));   // 5
console.log(Math.trunc(4.9));   // 4
console.log(Math.sqrt(81));     // 9
console.log(Math.abs(-5));      // 5
```

生成闭区间 `[min, max]` 内的随机整数：

```js
const min = 5;
const max = 10;
const randomInteger = Math.floor(Math.random() * (max - min + 1)) + min;
```

> [!warning]
> `Math.random()` 适合界面和练习中的随机效果，不适合密码、令牌或安全验证码。
