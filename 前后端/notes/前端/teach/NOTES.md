# Teaching Notes

- User wants to learn frontend from zero to advanced practical ability.
- Primary goals: independently build products; strengthen full-stack and AI-product programming ability.
- Secondary goal: job readiness.
- Target portfolio direction: data dashboard / management system plus personal blog.
- Preferred course style: early stage uses explanation plus small exercises; later stage switches to project lessons where each lesson completes one feature.
- Future project phase should include reading and dissecting high-quality GitHub projects, then rebuilding important parts with guidance.
- Lesson visuals should default to a warm light wood-texture background and support theme switching.
- When a concept benefits from a generated image or diagram, the teacher may create one and explain with it; not every lesson needs images.
- Generated or user-provided lesson images should be stored directly in `assets/`; do not create image subdirectories.
- Lessons should be grouped by topic under `lessons/<topic>/`; each topic has its own directory.
- Before finishing a lesson, check that rendered examples, code snippets, labels, class names, links, and explanations use the same values.
- Future frontend lessons may reference freeCodeCamp exercises and projects as supplementary practice, especially for HTML/CSS, JavaScript, front-end libraries, and certification-style projects.
- When a freeCodeCamp topic has a strong match for a lesson, either integrate the useful concept into the lesson page or add a direct practice link in that lesson's resources section.
- Use `Song` rather than `松` for user-facing names in lesson examples.
