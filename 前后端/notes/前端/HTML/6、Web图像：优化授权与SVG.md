# 一、图像性能优化

图像往往是网页中体积最大的资源之一。未经处理的图片会增加下载量，延长页面加载时间，并消耗用户流量。

优化图像时，需要重点考虑三个方面：

1. 图像尺寸
2. 文件格式
3. 压缩方式

除此之外，还可以通过响应式图片、懒加载和缓存等手段进一步改善加载体验。

## 1、尺寸控制与响应式图片

图像的尺寸通常使用“宽度 × 高度”表示，单位是像素。例如：

```text
640 × 480
```

其中 `640` 表示宽度，`480` 表示高度。

假设网页只需要以 `640 × 480` 的尺寸显示一张图片，却提供了一张 `3840 × 2160` 的原图。浏览器仍然需要下载完整的大图，然后再把它缩小显示。这会让用户下载大量最终看不到的细节。

因此，准备图片时应让资源尺寸尽量接近实际显示需求。

> [!tip] 不要只依靠CSS缩小大图
> CSS 的 `width` 和 `height` 只能改变图片的显示大小，不会自动减少服务器传输的文件体积。

图片资源也不能总是与 CSS 显示尺寸完全相同。高像素密度屏幕可能需要更清晰的图片。

例如，一张图片在页面中显示为 `400 × 300`，可以准备：

- `400 × 300` 的普通版本
- `800 × 600` 的高分辨率版本

然后使用 `srcset` 让浏览器选择：

```html
<img
  src="./images/workspace-400.jpg"
  srcset="
    ./images/workspace-400.jpg 1x,
    ./images/workspace-800.jpg 2x
  "
  width="400"
  height="300"
  alt="摆放着显示器和键盘的学习桌"
>
```

`1x` 和 `2x` 称为像素密度描述符，它们不是文件名或图片格式的一部分：

| 描述符 | 含义 | 本例对应资源 |
|---|---|---|
| `1x` | 面向普通像素密度屏幕 | `400 × 300` 图片 |
| `2x` | 面向两倍像素密度屏幕 | `800 × 600` 图片 |

这两个版本在页面中都会显示为大约 `400 × 300`。`2x` 图片在线性方向上包含两倍像素，因此在高像素密度屏幕上（例如 macOS Retina 等高像素密度屏幕）可以显示更多细节。浏览器会根据设备像素密度等条件选择合适的资源。

当图片会随页面宽度变化时，可以为不同宽度准备多个版本：

```html
<img
  src="./images/library-800.jpg"
  srcset="
    ./images/library-480.jpg 480w,
    ./images/library-800.jpg 800w,
    ./images/library-1280.jpg 1280w
  "
  sizes="(max-width: 600px) 100vw, 800px"
  width="800"
  height="533"
  alt="阳光照进一间安静的图书馆"
>
```

- `srcset` 列出候选图片及其固有宽度
- `sizes` 告诉浏览器图片在不同条件下预计显示多宽
- 浏览器结合屏幕宽度、像素密度等信息选择资源

`480w`、`800w` 和 `1280w` 称为宽度描述符，表示图片文件本身的固有宽度：

| 描述符 | 含义 |
|---|---|
| `480w` | 图片文件本身宽 480 像素 |
| `800w` | 图片文件本身宽 800 像素 |
| `1280w` | 图片文件本身宽 1280 像素 |

这里的 `w` 不表示 CSS 中的显示宽度。浏览器会先根据 `sizes` 估算图片在页面中的显示宽度，再结合设备像素密度，从候选资源中选择合适的一张。

> [!note] 两类描述符不能混用
> 同一个 `srcset` 应统一使用 `1x`、`2x` 这类像素密度描述符，或者统一使用 `480w`、`800w` 这类宽度描述符，不能把两类写在同一个候选列表中。

`src` 仍然提供默认资源，也可以作为不支持 `srcset` 时的后备方案。

为 `img` 设置 `width` 和 `height`，可以让浏览器在图片下载前预留正确的宽高比例，减少图片加载后页面内容突然移动的问题：

```html
<img
  src="./images/course-cover.webp"
  width="640"
  height="360"
  alt="HTML课程封面"
>
```

这两个属性描述图片的固有宽高比例。之后仍然可以使用 CSS 让图片响应式缩放：

```css
img {
  max-width: 100%;
  height: auto;
}
```

## 2、格式选择与兼容回退

不同图像格式适合不同类型的内容：

| 格式 | 特点 | 常见用途 |
|---|---|---|
| JPEG | 有损压缩，兼容性好，不支持透明 | 照片、色彩丰富的图像 |
| PNG | 支持透明，通常使用无损压缩 | 截图、需要透明背景的图像 |
| WebP | 支持有损和无损压缩，也支持透明与动画 | 通用网页图片 |
| AVIF | 压缩效率通常较高，支持透明和高动态范围 | 对体积要求较高的现代网页图片 |
| SVG | 矢量格式，缩放不失真 | 图标、Logo、简单插图 |

WebP 和 AVIF 通常能以更小的体积提供与 JPEG、PNG 相近的视觉质量。但格式选择不能只看“新旧”，还需要考虑：

- 图片内容类型
- 目标浏览器支持情况
- 编码和解码成本
- 是否需要透明或动画
- 项目的图片处理流程

`picture` 元素可以为同一张图片提供不同格式，浏览器会选择自己支持的第一个来源：

```html
<picture>
  <source srcset="./images/course-cover.avif" type="image/avif">
  <source srcset="./images/course-cover.webp" type="image/webp">
  <img
    src="./images/course-cover.jpg"
    width="800"
    height="450"
    alt="笔记本电脑上显示着HTML代码"
  >
</picture>
```

选择过程如下：

1. 浏览器先检查是否支持 AVIF
2. 不支持时继续检查 WebP
3. 两者都不支持时使用 `img` 中的 JPEG

`picture` 本身不显示图片，真正负责展示和提供替代文本的仍然是内部的 `img` 元素。

## 3、压缩策略与处理流程

无损压缩在解压后可以还原原始数据，不会因为压缩而永久丢失图像信息。

PNG 常使用无损压缩。优化工具可以通过调整编码方式、移除不必要的元数据等方法减少文件体积，而不改变图片像素内容。

无损压缩适合：

- 需要保留精确像素的截图
- 简单图形和界面素材
- 需要透明背景的图片
- 不能接受压缩伪影的场景

有损压缩会永久舍弃一部分图像数据，以换取更小的文件体积。JPEG、WebP 和 AVIF 都可以使用有损压缩。

有损压缩适合照片等细节丰富的图像，因为适度丢失信息通常不容易被察觉。

压缩强度需要在文件体积和视觉质量之间取得平衡：

```text
压缩过弱 → 画质较高，但文件仍然很大
压缩适中 → 画质与体积之间较平衡
压缩过强 → 出现色块、模糊和边缘失真
```

> [!warning] 避免反复压缩有损图片
> 每次重新保存或重新压缩 JPEG 等有损图片，都可能继续丢失数据。应保留高质量原始文件，再从原文件生成发布版本。

一个常见的图像处理流程是：

1. 保存未经破坏性处理的原始素材
2. 按页面所需比例裁剪图片
3. 生成不同尺寸的候选资源
4. 选择适合内容的文件格式
5. 调整压缩质量
6. 在真实设备上检查清晰度和加载速度

不要只比较文件扩展名，还应比较处理后的实际体积和视觉效果。

## 4、加载优化与替代文本

首屏之外的图片可以使用 `loading="lazy"`，让浏览器在图片接近可视区域时再加载：

```html
<img
  src="./images/article-example.webp"
  width="800"
  height="450"
  loading="lazy"
  alt="文章中的HTML代码示例"
>
```

懒加载可以减少页面刚打开时的请求和下载量。

> [!note] 首屏关键图片通常不应懒加载
> 页面一打开就能看到的主视觉图或重要内容图片需要尽快加载，对它们使用 `loading="lazy"` 反而可能延迟显示。

性能优化不能以牺牲可访问性为代价。具有内容意义的图片应提供准确的 `alt` 文本：

```html
<img
  src="./images/chart.webp"
  width="720"
  height="480"
  alt="优化后首页图片体积从2.4MB降至620KB"
>
```

纯装饰图片可以使用空的 `alt`：

```html
<img src="./images/decorative-line.svg" alt="">
```

关于 `alt` 的基本作用，可以参考 [[1、HTML基础：元素与属性#3、图片的src和alt属性|图片的src和alt属性]]。

# 二、图像版权与许可

## 1、版权基础与使用依据

图片属于知识产权。通常情况下，一张图片从创作完成时就受到版权保护，权利可能属于创作者，也可能根据合同归属于雇主、出版方或其他主体。

“能够在网上找到”不等于“可以自由使用”。如果图片没有明确许可，不能仅因为它可以下载就直接放入自己的网站。

合法使用图片通常需要具备相应依据，例如：

- 自己创作并拥有相关权利
- 获得权利人的明确授权
- 购买符合使用场景的许可证
- 按照开放许可证的条款使用
- 图片确实属于公有领域
- 使用方式符合所在司法辖区的版权例外

**All Rights Reserved（保留所有权利）** 表示版权人没有通过通用许可开放复制、修改或传播权限。

使用这类图片前，通常需要获得权利人的许可或购买合适的许可证。授权时还需要确认：

- 是否允许商业使用
- 是否允许修改
- 是否限制使用期限或地区
- 是否限制发布渠道
- 是否要求署名

## 2、开放许可与公有领域

Creative Commons 提供多种标准化许可。不同许可附加的条件并不相同：

| 标记 | 含义 |
|---|---|
| BY | 使用时必须署名 |
| SA | 演绎作品必须使用相同许可发布 |
| NC | 不允许商业用途 |
| ND | 不允许发布修改后的版本 |

这些条件可以组合，例如：

- CC BY：允许使用和修改，但必须署名
- CC BY-SA：必须署名，演绎作品使用相同许可
- CC BY-NC：必须署名，且不能用于商业用途
- CC BY-ND：必须署名，且不能发布修改版本

使用前应阅读图片对应的完整许可，而不是只看到“CC”就认为没有限制。

公有领域作品通常不再受版权限制，可以在无需版权许可的情况下使用。但作品是否属于公有领域，可能受到创作时间、来源和司法辖区等因素影响。

CC0 是权利人尽可能放弃相关版权和邻接权、将作品贡献给公众使用的工具。即使使用 CC0 图片，也应留意其中是否包含：

- 商标
- 肖像权或隐私权
- 图片中其他受保护的作品
- 对用途有影响的当地法律

## 3、合理使用与授权核查

某些司法辖区存在合理使用或类似的版权例外，例如为了评论、研究、新闻报道或戏仿而有限使用作品。

但它通常需要结合用途、使用比例、作品性质和对原作市场的影响等因素综合判断，并不是“注明来源”或“非商业使用”就一定成立。

> [!warning] 版权规则因地区而异
> 对图片许可存在疑问，特别是涉及商业发布时，应核对原始授权文件，必要时咨询专业法律人士。

使用外部图片前，可以记录：

- 图片作者和原始来源
- 许可名称及版本
- 获取图片和许可信息的日期
- 是否允许商业使用
- 是否允许修改
- 署名方式
- 原始许可页面或授权证明

搜索引擎提供的许可筛选只能用于缩小范围，最终仍应打开原始来源，核对图片对应的真实许可。

# 三、SVG矢量图

 ## 1、位图与矢量图

PNG、JPEG 和 WebP 等通常是 **位图（raster image）** 。它们使用像素网格保存图像，每个像素记录自己的颜色。

位图具有固定的像素数量。放大到超过原始尺寸时，一个像素会被扩展到更大的区域，因此图像可能出现模糊或锯齿。

SVG 的全称是 **Scalable Vector Graphics（可缩放矢量图形）** 。它使用点、线、曲线和路径等几何信息描述图形，而不是记录每一个像素。

因此，SVG 可以缩放到不同尺寸而保持边缘清晰，非常适合图标、Logo 和简单插图。

## 2、SVG结构与坐标系统

SVG 使用基于 XML 的文本语法，可以直接写入 HTML：

```html
<svg
  width="120"
  height="120"
  viewBox="0 0 120 120"
  xmlns="http://www.w3.org/2000/svg"
  role="img"
  aria-labelledby="sun-title"
>
  <title id="sun-title">太阳图标</title>
  <circle
    cx="60"
    cy="60"
    r="38"
    fill="gold"
    stroke="darkorange"
    stroke-width="4"
  />
</svg>
```

在这个例子中：

- `svg` 是整个矢量图的容器
- `viewBox` 定义内部坐标系统和可视区域
- `circle` 绘制圆形
- `cx`、`cy` 指定圆心坐标
- `r` 指定半径
- `fill` 设置填充颜色
- `stroke` 设置描边颜色
- `stroke-width` 设置描边宽度

`viewBox` 通常包含四个数字：

```html
viewBox="min-x min-y width height"
```

例如：

```html
viewBox="0 0 24 24"
```

它表示 SVG 内部使用一个从 `(0, 0)` 开始、宽高均为 `24` 的坐标区域。浏览器可以把这套坐标按比例映射到不同显示尺寸，因此图形能够保持比例缩放。

| 元素 | 作用 |
|---|---|
| `circle` | 绘制圆形 |
| `rect` | 绘制矩形 |
| `line` | 绘制直线 |
| `polyline` | 绘制多段折线 |
| `polygon` | 绘制封闭多边形 |
| `path` | 使用路径命令绘制复杂形状 |

例如，使用 `path` 绘制一个对勾图标：

```html
<svg
  width="48"
  height="48"
  viewBox="0 0 24 24"
  xmlns="http://www.w3.org/2000/svg"
  role="img"
  aria-label="操作成功"
>
  <path
    d="M5 12.5L9.5 17L19 7.5"
    fill="none"
    stroke="seagreen"
    stroke-width="2.5"
    stroke-linecap="round"
    stroke-linejoin="round"
  />
</svg>
```

`path` 的 `d` 属性保存绘制路径所需的命令和坐标。

## 3、引入方式与样式控制

SVG 可以像普通图片一样通过 `img` 引入：

```html
<img
  src="./icons/check.svg"
  width="48"
  height="48"
  alt="操作成功"
>
```

也可以直接将 SVG 代码写进 HTML，这称为内联 SVG：

```html
<svg viewBox="0 0 24 24" aria-hidden="true">
  <path d="M5 12.5L9.5 17L19 7.5"></path>
</svg>
```

两种方式各有特点：

| 方式 | 优点 | 注意事项 |
|---|---|---|
| `img` 引用 | HTML 简洁，SVG 文件可缓存 | 页面 CSS 不容易直接控制 SVG 内部图形 |
| 内联 SVG | 可以使用 CSS 和 JavaScript 控制内部元素 | 会增加 HTML 体积，重复图标可能产生重复代码 |

内联 SVG 可以使用 `currentColor` 继承元素的 CSS `color`：

```html
<button class="confirm-button" type="button">
  <svg viewBox="0 0 24 24" aria-hidden="true">
    <path
      d="M5 12.5L9.5 17L19 7.5"
      fill="none"
      stroke="currentColor"
      stroke-width="2.5"
    ></path>
  </svg>
  确认
</button>
```

```css
.confirm-button {
  color: seagreen;
}

.confirm-button svg {
  width: 1em;
  height: 1em;
}
```

修改按钮的 `color` 时，图标描边也会随之改变。

## 4、适用场景与使用规范

SVG 适合：

- 图标
- Logo
- 简单插图
- 图表和数据可视化
- 需要根据主题改变颜色的图形
- 需要适应多种屏幕尺寸的几何图形

SVG 不一定适合：

- 细节复杂的照片
- 包含大量纹理和颜色变化的图像
- 路径数量过多、导致文件体积和渲染成本很高的复杂作品

照片通常更适合 JPEG、WebP 或 AVIF。

如果 SVG 只是按钮旁边的装饰图标，而按钮文字已经表达含义，可以将其对辅助技术隐藏：

```html
<svg viewBox="0 0 24 24" aria-hidden="true">
  <!-- 图形内容 -->
</svg>
```

如果 SVG 本身传达重要信息，应提供可访问名称，例如使用 `aria-label`，或组合 `title` 与 `aria-labelledby`。

SVG 是可执行、可链接的文档格式。不要直接把来源不可信的 SVG 代码插入页面；使用前应检查或清理其中的脚本、事件属性和外部资源引用。

# 四、完整示例

下面的页面使用现代图片格式、响应式候选资源、懒加载和内联 SVG：

```html
<!doctype html>
<html lang="zh-CN">
  <head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>图像优化示例</title>
  </head>
  <body>
    <main>
      <h1>前端图像优化</h1>

      <picture>
        <source
          srcset="
            ./images/workspace-480.avif 480w,
            ./images/workspace-960.avif 960w
          "
          type="image/avif"
        >
        <source
          srcset="
            ./images/workspace-480.webp 480w,
            ./images/workspace-960.webp 960w
          "
          type="image/webp"
        >
        <img
          src="./images/workspace-960.jpg"
          srcset="
            ./images/workspace-480.jpg 480w,
            ./images/workspace-960.jpg 960w
          "
          sizes="(max-width: 600px) 100vw, 960px"
          width="960"
          height="640"
          loading="lazy"
          alt="桌面上摆放着用于学习前端开发的电脑"
        >
      </picture>

      <button class="save-button" type="button">
        <svg viewBox="0 0 24 24" aria-hidden="true">
          <path
            d="M5 12.5L9.5 17L19 7.5"
            fill="none"
            stroke="currentColor"
            stroke-width="2.5"
          ></path>
        </svg>
        保存设置
      </button>
    </main>
  </body>
</html>
```

# 五、总结

- 图像优化需要同时考虑尺寸、格式和压缩
- 不要让用户下载远大于实际显示需求的图片
- `srcset` 和 `sizes` 可以让浏览器选择适合当前设备的资源
- `picture` 可以提供 AVIF、WebP 和传统格式的回退方案
- 无损压缩可以还原原始数据，有损压缩会永久舍弃部分数据
- 应保留高质量原图，避免反复压缩有损图片
- `loading="lazy"` 适合首屏之外的图片
- 网络上能找到的图片不等于可以自由使用，应核对版权与许可
- Creative Commons 的不同许可可能要求署名、禁止商用或禁止修改
- SVG 使用矢量路径描述图形，缩放时不会像位图一样像素化
- SVG 适合图标、Logo 和简单插图，不适合复杂照片
- 内联 SVG 可以通过 CSS 和 JavaScript 控制，但应注意可访问性和安全
