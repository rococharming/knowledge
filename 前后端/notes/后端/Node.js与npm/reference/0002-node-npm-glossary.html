Node.js 与 npm 术语表

后续课程统一使用这些词。遇到概念混乱时，先回到这里看“它负责什么，不负责什么”。

术语 一句话定义 边界
Node.js 运行 JavaScript 的服务器端运行时。 负责执行代码和提供核心模块；不负责替你管理项目依赖。
npm CLI 本机终端里的 npm 命令。 负责安装、运行脚本、发布包；它不是远程仓库本身。
npm Registry 保存 npm package 和版本元数据的远程仓库服务。 负责分发包；不会运行你的项目代码。
package.json npm 项目的描述文件。 记录项目名、版本、脚本、依赖、入口；不保存安装后的完整依赖树。
package-lock.json npm 安装后生成的依赖锁文件。 记录精确依赖树；通常应该提交到应用项目仓库。
dependencies 项目运行时需要的依赖。 生产运行仍然需要；例如 Web 框架、数据库客户端。
devDependencies 只在开发、测试、构建时需要的依赖。 生产运行通常不直接需要；例如测试框架、编译器、格式化工具。
scripts 项目约定命令的集合。 让团队用统一入口执行任务；实际执行的仍是右侧命令字符串。
Module 一个可被导入或导出的代码单元。 Node.js 同时存在 CommonJS 和 ES Module 两套历史模型。
CLI 命令行工具。 用户通过终端调用；npm package 可以通过 bin 字段暴露 CLI。
