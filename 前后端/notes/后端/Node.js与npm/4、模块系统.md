# 一、核心边界

模块系统解决的是“把一个大文件拆成多个小文件，再让文件之间互相使用”的问题。一个文件可以把能力导出，另一个文件再导入使用。

在前面的 [[3、npm scripts|npm scripts]] 中，`npm run dev` 最终会执行某个入口文件；到了模块系统，入口文件还可以继续导入其他文件。

![[assets/module-systems.png|620]]

> 简单来说：`npm run dev` 找到入口命令，Node.js 运行入口文件，模块系统负责让入口文件连接其他文件。

# 二、两种模块

Node.js 同时支持两套模块系统：CommonJS 和 ES Module。它们解决的问题相同，都是“文件之间如何导入导出”，但语法和判断规则不同。

## 1、CommonJS

CommonJS 是 Node.js 早期主要使用的模块格式，常见关键字是 `require` 和 `module.exports`。

示例：

```js
const tool = require("./tool.js");

module.exports = tool;
```

可以先这样理解：`require()` 负责导入，`module.exports` 负责导出。

## 2、ES Module

ES Module 是 JavaScript 标准模块格式，常见关键字是 `import` 和 `export`。现代 TypeScript、前端构建工具和很多新 Node.js 项目都会使用它。

示例：

```js
import { message } from "./message.js";

export const message = "hello";
```

这门课后续优先使用 ES Module，因为它更接近现代 JavaScript 项目的默认写法。

## 3、对比关系

两套模块系统可以先按关键字区分：

| 模块系统 | 导入 | 导出 | 常见场景 |
|---|---|---|---|
| CommonJS | `require()` | `module.exports` | 传统 Node.js 项目、旧包 |
| ES Module | `import` | `export` | 现代 JavaScript、TypeScript、新项目 |

入门阶段不要混用两套语法。一个练习项目里先选 ES Module，把 `import` / `export` 跑通即可。

# 三、type 字段

`package.json` 不只描述项目身份和脚本，也会影响 Node.js 如何解释 `.js` 文件。模块系统里最关键的字段是 `type`。

## 1、module

当最近的 `package.json` 写了：

```json
{
  "type": "module"
}
```

这个 package 里的 `.js` 文件会按 ES Module 解释，可以使用 `import` 和 `export`。

示例：

```js
import { message } from "./message.js";

console.log(message);
```

这里的 `./message.js` 表示当前目录下的 `message.js`。在 ES Module 中，导入本地文件时建议写完整文件扩展名。

## 2、commonjs

当最近的 `package.json` 写了：

```json
{
  "type": "commonjs"
}
```

这个 package 里的 `.js` 文件会按 CommonJS 解释，可以使用 `require()` 和 `module.exports`。

示例：

```js
const { message } = require("./message.js");

console.log(message);
```

如果 `package.json` 没有写 `type`，Node.js 对 `.js` 的默认处理会更偏向 CommonJS。学习项目建议显式写出 `"type": "module"`，减少猜测。

## 3、文件后缀

除了 `type` 字段，文件后缀也能强制指定模块规则：

| 标记 | Node.js 怎么理解 |
|---|---|
| `"type": "module"` | 当前 package 里的 `.js` 文件按 ES Module 解释 |
| `"type": "commonjs"` | 当前 package 里的 `.js` 文件按 CommonJS 解释 |
| `.mjs` | 不管 `type` 怎么写，都按 ES Module 解释 |
| `.cjs` | 不管 `type` 怎么写，都按 CommonJS 解释 |

入门阶段优先使用：`package.json` 写 `"type": "module"`，普通文件继续用 `.js`。

# 四、导入导出

ES Module 的核心动作只有两个：`export` 把内容暴露出去，`import` 从另一个文件拿到内容。

## 1、导出

创建 `message.js`：

```js
export const message = "Hello from message.js";
```

`export` 的意思是：这个文件把 `message` 暴露出去，允许别的文件使用。没有导出的变量，只属于当前文件内部。

## 2、导入

创建 `app.js`：

```js
import { message } from "./message.js";

console.log(message);
```

`import { message } from "./message.js"` 的意思是：从当前目录下的 `message.js` 中导入名为 `message` 的内容。

这里的路径要注意：

- `./` 表示当前目录；
- `message.js` 是文件名；
- 文件名大小写要和真实文件一致；
- ES Module 中本地文件导入建议写完整扩展名。

## 3、CommonJS 对照

如果同一个例子改用 CommonJS，导出和导入要换成 `module.exports` 与 `require()`。

`message.js`：

```js
const message = "Hello from message.js";

module.exports = {
  message
};
```

`app.js`：

```js
const { message } = require("./message.js");

console.log(message);
```

两种写法可以这样对照：

| 动作 | ES Module | CommonJS |
|---|---|---|
| 导出 | `export const message = ...` | `module.exports = { message }` |
| 导入 | `import { message } from "./message.js"` | `const { message } = require("./message.js")` |

需要注意的是：如果 `package.json` 写了 `"type": "module"`，`.js` 文件会按 ES Module 解释，不能直接使用上面的 CommonJS 写法。要运行 CommonJS 示例，可以把 `type` 改成 `"commonjs"`，或者把文件后缀改成 `.cjs`。

## 4、运行链路

结合 `npm scripts`，一个最小运行链路是：

```text
npm run dev
      ↓
读取 package.json 的 scripts.dev
      ↓
执行 node app.js
      ↓
app.js 导入 message.js
      ↓
打印 message
```

这条链路把前几课连起来了：[[2、JSON 与 package.json|package.json]] 提供项目配置，[[3、npm scripts|npm scripts]] 提供命令入口，模块系统提供文件连接方式。

# 五、实践：拆分文件

这个实践用于创建一个最小 ES Module 项目。重点是观察 `message.js` 如何导出内容，`app.js` 如何导入并使用它。

## 1、创建目录

创建并进入练习目录：

```bash
mkdir module-lab
cd module-lab
```

## 2、写入配置

创建 `package.json`，写入：

```json
{
  "name": "module-lab",
  "version": "1.0.0",
  "private": true,
  "type": "module",
  "scripts": {
    "dev": "node app.js"
  }
}
```

这里有两个关键点：

- `"type": "module"`：让 `.js` 文件按 ES Module 解释；
- `"dev": "node app.js"`：让 `npm run dev` 执行 `app.js`。

## 3、写入模块

创建 `message.js`，写入：

```js
export const message = "Hello from message.js";
```

创建 `app.js`，写入：

```js
import { message } from "./message.js";

console.log(message);
```

## 4、运行对照

执行：

```bash
npm run dev
```

应该看到：

```text
Hello from message.js
```

再新增 `name.js`：

```js
export const username = "Kamen Rider";
```

修改 `app.js`：

```js
import { message } from "./message.js";
import { username } from "./name.js";

console.log(message);
console.log(username);
```

重新执行：

```bash
npm run dev
```

如果能看到两行输出，说明已经会让一个入口文件导入多个模块：

```text
Hello from message.js
Kamen Rider
```

如果运行时报错，优先检查三件事：`package.json` 是否写了 `"type": "module"`，导入路径是否写成 `./message.js` / `./name.js`，文件名大小写是否一致。
