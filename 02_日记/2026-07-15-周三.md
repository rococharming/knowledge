# 跟踪日志

**ui-previewer 编译及运行报错修复问题汇总

一、Cargo feature  新版本与  feature 配置不兼容

1. qr_layout 新版本与 feature 配置不兼容（ui-previewer）

- 原因：7/13 合入的 qr_layout 27bb8dbd3（flexbox/grid 布局算法）与当前 Cargo feature 配置不匹配。
- 策略：ui-previewer/Cargo.toml 的 qr_layout 由 \["yoga", "yoga-cargo"] 改为 \["flexbox","grid","layout_cache"]。

2. CSS 新属性缺失（ui-previewer + ui_frontend）

- 原因：4c71c98(backdrop-filter)、a3fdd866(drawer enablewholedrag) 新增 CSS 属性；frontend_css_def 靠 ui_style feature 决定加载真实 UI 样式表还是旧 mock 表。GN/真机显式启用 ui_style，但 Cargo manifest 没声明，previewer 只能加载旧 mock 表，缺 ATTRIBUTE_BACKDROP_FILTER / ATTRIBUTE_ENABLE_WHOLE_DRAG。
- 策略：ui_frontend css_def/Cargo.toml：新增 ui_style = \[] feature。ui-previewer Cargo.toml：frontend_css_def features 改为 \["std","ui_style"]。

3. 布局引擎编译/运行不一致（ui + ui-previewer）

- 原因：布局重构把设备 GN 默认引擎切到 Blue（flexbox/grid）并关闭 UI/layout 层的 Yoga，但 Cargo 配置仍停留在 Yoga，导致编译期与运行期逻辑不一致。
- 策略：ui/Cargo.toml 与 ui-previewer/Cargo.toml 的 qr_layout 统一改为 \["flexbox","grid","layout_cache"]（与 #1 同一处，二者一并解决）。

二、设备能力 std_local 隔离

1. 输入菜单依赖设备窗口与剪贴板（ui）

- 原因：639d56c 按设备 GN 依赖编写 context_menu，未覆盖 std_local；previewer 无设备 bgui 与剪贴板服务。
- 策略：
	- 设备窗口类型 WindowDepth/WindowFlags：std_local 下改用 qr_common_rs::runtime::window_type_stubs 桩（handle_window.rs / toolbar_window.rs）
	- 剪贴板不适配，保留设备端真实剪贴板行为。

2. GraphicBuffer 设备能力泄露（ui）

- 原因：f736589 实现设备图形栈能力，未加 std_local 条件编译。
- 策略：image.rs 中 bgui::GraphicBuffer、Mutex、SgluiImageResource、GRAPHIC_BUFFER_MAP 的 import、ImageData.graphic_buffer 字段及其初始化/重置/使用、set_graphic_buffer 函数、TypeGraphicBuffer 绘制分支，全部加 # \[cfg(not(feature="std_local"))]；std_local 下 GRAPHICBUFFER_SRC 路径走 mark_needs_paint() 桩。

6. 视频 seek preview（ui）

- 原因：911854f 中 PlayerStateType 的设备 import 已受 not(std_local) 控制，但新增的 is_seekable() 函数放在条件编译外。
- 策略：video.rs 的 is_seekable() 函数加 # \[cfg(not(feature="std_local"))]；video_component.rs 中两条 seek 失败的 debug! 日志同样加该 cfg（避免在 std_local 下引用未定义符号）。

7. start_service 参数数量不匹配（ui 仓）

- 原因：81b72d5d8 把设备端接口更新为 start_service(action, params, callback)（3 参数），但 std_local 路径的 AppInterfaceManager::start_service 仍是 start_service(action)（1 参数）。共用调用方 render_element.rs 无法用一套写法同时满足两个签名
- 统一签名。把 std_local 实现侧的 start_service 升级为与设备端一致的 3 参数签名：


8. geolocation/exchange feature 漏掉 std_local 隔离（feature 仓）

- 原因：geolocation_feature 和 exchange_feature 模块漏掉了 std_local 隔离。
- 策略：features/mod.rs 中为 geolocation_feature 和 exchange_feature 的模块声明各补一行 #[cfg(not(feature = "std_local"))]。

# 总结

今天主要围绕 ui-previewer 编译与运行报错做集中排查，问题集中在 Cargo feature 与新版布局/CSS 能力不匹配，以及设备端能力没有做好 std_local 隔离。处理思路是先定位真实依赖链，再分别在 ui-previewer、ui_frontend、ui、feature 仓补齐 feature 配置和条件编译边界，避免影响真机路径。最终将修复拆到对应仓库并整理成多条 MR，推动 previewer 在当前版本下恢复可编译、可运行。
