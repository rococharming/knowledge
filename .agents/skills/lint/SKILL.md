# Lint — 知识库健康检查

定期对 wiki 进行健康检查，自动修复可机械判断的结构问题，并报告需要人工判断的内容质量问题。

## 核心精神

lint 是**确定性修复 + 启发式报告 + 建议**三位一体：
1. **确定性修复**：自动同步 `wiki/index.md`、顶层 `index.md`、可唯一确定的链接路径等结构问题
2. **启发式报告**：识别矛盾、陈旧说法、重要概念缺页等需要判断的问题，但不自动改正文
3. **建议**：对每个启发式发现给出具体建议——调查问题、应 ingest 的素材、搜索方向

## 触发条件

- "lint 一下知识库"
- "检查 wiki 有没有问题"
- "知识库健康检查"

- 任何涉及检查 wiki 完整性、链接有效性的请求

## 检查范围

默认扫描整个知识库。用户可指定单个或多个领域。

## Markdown 解析规范

Lint 不得直接用全文件正则判断正文链接、标题、frontmatter 或来源章节；必须先把 Markdown 解析为结构化区域，再对目标区域执行检查。

### 解析步骤

1. **分离 frontmatter**：只把文件开头第一组 `--- ... ---` 识别为 YAML frontmatter；正文、代码块或示例里的 `---` 不算 frontmatter。
2. **识别代码围栏**：识别三反引号和三波浪线围栏，支持语言标识。围栏内的 `[[链接]]`、`---`、`<T>`、标题符号都必须忽略。
3. **识别行内代码**：反引号包裹的内容不参与链接、尖括号、标签和缺失引用检查。
4. **识别 Obsidian 注释**：`%% ... %%` 注释块和行内注释默认不参与正文检查。
5. **识别标题 token**：只对非代码区域中的 Markdown 标题做标题层级、未转义 `<`、重复标题等检查。
6. **识别 wiki link token**：只提取非代码、非注释区域中的 `[[...]]`；支持 `[[页面]]`、`[[页面|别名]]`、`[[页面#标题]]`、`![[嵌入]]`。
7. **识别章节范围**：按真实标题切分章节，用于判断 `## 来源`、`## 基于页面`、相关页面区块是否存在。

### 可接受的实现方式

- 优先使用现成 Markdown parser 或 Obsidian/Markdown 解析能力。
- 若只能使用脚本，应先写一个轻量 tokenizer，至少正确处理 frontmatter、fenced code block、inline code、Obsidian 注释、标题和 wiki links。
- 正则只能作用于解析后的局部 token 或纯文本片段，不能直接扫整份 Markdown。

### 解析后的检查对象

| 检查对象 | 使用区域 | 必须忽略 |
|---|---|---|
| frontmatter 字段 | 文件开头 YAML 区 | 正文中的 YAML 示例 |
| wiki 链接 | 非代码、非注释正文 token | 代码块、行内代码、注释、frontmatter |
| `## 来源` / `## 基于页面` | 真实标题 token | 代码块中的标题示例 |
| 未转义 `<` | 标题和普通正文文本 token | 行内代码、代码块、HTML 标签、frontmatter |
| 内容长度 | 去除 frontmatter、代码块、注释后的正文 | 纯代码示例页需单独判断 |

## 检查项分层

### 确定性检查（自动修复）

确定性检查只处理可以用文件系统、索引、解析后的 frontmatter/正文 token 或唯一匹配结果机械判断的问题。发现后直接修复，并在报告中列出变更。

| 检查项 | 说明 | 自动修复 | 报告内容 |
|---|---|---|---|
| **索引缺项** | 存在于 `wiki/` 但未列入 `wiki/index.md` 的 `.md` 文件 | 添加到 `wiki/index.md` 的合适分类（优先按文件路径目录名推断，无法推断时标注"待分类"） | 已添加的页面及分类 |
| **索引悬空项** | `wiki/index.md` 中列出的页面文件不存在 | 从 `wiki/index.md` 移除该索引项 | 已移除的索引项 |
| **重复分类段** | `wiki/index.md` 中同一分类标题重复出现 | 合并同名分类，去重页面条目，保留原摘要 | 合并的分类和去重条目 |
| **顶层索引计数** | 对比顶层 `index.md` 标注数与 `wiki/` 实际文件数（排除 index.md 和 log.md） | 更新顶层 `index.md` 中的页面计数 | 计数变更 |
| **frontmatter 结构** | wiki 页面缺少标准 frontmatter 或缺少 `title/date/tags/source_count` 字段；Query 归档页缺少 `type: query_archive` | 补齐可从文件名、当天日期、空标签、来源章节或 Query 日志推断的字段；无法推断时报告 | 已补齐字段与无法推断项 |
| **来源章节缺失** | 普通 wiki 页面缺少 `## 来源`；Query 归档页缺少 `## 来源` 或 `## 基于页面` | 若能从 log、已归档 raw 或 Query 日志唯一反查则补齐；否则报告 | 已补齐来源/基于页面或待人工确认 |
| **唯一死链修复** | 解析后的正文 wiki link token 无法解析，但同领域 wiki 内存在唯一同名/近似文件 | 自动改为可解析的 `[[页面名]]` | 已修复链接 |

> 所有确定性检查必须基于上面的 Markdown 解析结果，禁止把代码块、行内代码、注释或 YAML 示例中的 `[[...]]`、`---`、`<...>` 当作真实结构。

### 启发式检查（只报告）

启发式检查依赖内容理解、事实判断或用户意图判断。默认只报告，不自动修改 wiki 正文；用户明确要求按建议修复时，才进入后续修复流程。

| 检查项 | 说明 | 输出 |
|---|---|---|
| **矛盾主张** | 同一概念在不同页面中的矛盾描述 | 列出矛盾点，分析哪方更可能正确，建议验证方向 |
| **陈旧说法** | 被新素材取代的旧说法。读取近期 ingest 记录和相关页面，对比识别事实性冲突 | 列出冲突点（旧 vs 新），建议搜索关键词或应 ingest 的新素材 |
| **无法唯一修复的死链** | 解析后的正文 wiki link token 无法解析，且没有唯一候选目标 | 列出死链位置和候选处理方式 |
| **重要概念缺页** | 被频繁提及但无独立页面的概念 | 列出建议创建页面的概念，按重要性排序，给出分类建议和关联页面 |
| **缺失交叉引用** | 页面中提到已有概念但未建立链接 | 列出应添加的链接方案 |
| **数据空白** | 可通过搜索填补的空白：frontmatter 缺失、缺少来源支撑的事实、内容过短（少于 100 字） | 列出空白点，给出具体搜索建议或应补充的字段 |
| **低质量 Query 归档页** | `type: query_archive` 页面缺少 `## 基于页面`、`## 来源`、Query 摘要，或普通页面误用 `source_count: 0` | 列出页面和建议补充方式 |

## 执行方式

优先运行 bundled 确定性脚本：

```bash
python .agents/skills/lint/scripts/wiki_lint.py --root /Users/songpengfei/knowledge --fix
```

脚本负责 Markdown token 解析、`wiki/index.md` 规范化、顶层计数、Query 归档页基础页更新提示和 qmd 配置体检。脚本报告之外的内容质量问题按启发式检查人工阅读和报告。

### 小规模（wiki 页面数 ≤ 300）

直接读取 `wiki/index.md` 定位页面，读取所有相关页面内容进行分析。

### 大规模（wiki 页面数 > 300）

1. 读取 `wiki/index.md` 了解全貌
2. 抽样读取关键页面（枢纽页面、最近更新的页面）
3. 聚焦用户指定的问题类型，不做全量扫描

## 报告结构

报告直接输出到对话。

```markdown
# 知识库健康检查 — YYYY-MM-DD

## 确定性检查

- 将 `entities/[[rustup]]` 添加到 index.md 的 entities 分类
- 从 index.md 移除已删除页面 `[[不存在的页面]]`
- 更新顶层 index.md 页面计数: Rust 19 → 20

## 启发式检查

### 矛盾主张
- [[页面A]] 说 "X"，但 [[页面B]] 说 "Y"。建议：搜索官方文档确认。

### 陈旧说法
- [[旧页面]] 说 "旧说法"，但 [[新页面]] 提到 "新说法"。建议：ingest 新素材验证。

### 死链（页面内容中）
- `concepts/所有权.md` 中的 `[[不存在的页面]]` — 建议：移除链接或创建页面。

### 重要概念缺页
- **借用检查器** — 被 5 个页面提及但无独立页面。建议：创建 `concepts/借用检查器.md`。

### 缺失交叉引用
- [[所有权]] 中提到 "借用"但未链接。建议：添加 `[[借用]]` 链接。

### 数据空白
- [[某页面]] 提到事实但无来源。建议：搜索验证。
- [[某页面]] 缺少 `tags` 字段。建议：补充。

## LLM 建议

### 新调查问题
1. X 是否仍然成立？

### 建议 ingest 的新素材
1. `raw/articles/rust-2024-edition.md` — 验证陈旧说法

### 建议搜索验证的方向
1. 搜索 "Rust 2024 Edition release note" 确认变动
```

## 更新日志

Lint 日志只记录对 wiki 结构产生实际影响的检查，不记录纯报告型、零修复的普通健康快照。

**操作原则**：
- **有确定性自动修复时**：在每个被修改领域的 `wiki/log.md` 追加一条 `Lint` 记录
- **只有启发式发现、没有文件修改时**：默认不写 `wiki/log.md`，只在对话中报告
- **用户明确要求留档时**：即使没有自动修复，也可以追加一条 `Lint` 记录，标明 `结果: 仅报告`
- **用户随后要求按该次 lint 的建议继续修复时**：如果存在同轮 Lint 日志，回写该条记录；如果此前没有写日志，则在实际修复完成后追加一条记录
- 历史中已经过期的 `Lint` 快照日志可以删除，避免 `log.md` 变成陈旧健康状态堆积

```markdown
## [YYYY-MM-DD] Lint | <范围>

- 范围: <全库 / 本领域>
- 确定性修复: <N> 个（索引缺项 <N>、索引悬空 <N>、重复分类 <N>、计数更新 <N>、frontmatter <N>、来源章节 <N>、唯一死链 <N>）
- 启发式发现: <N> 个（矛盾 <N>、陈旧 <N>、无法唯一修复死链 <N>、缺页 <N>、缺引用 <N>、空白 <N>、低质量 Query 归档 <N>）
- 建议: <N> 条（调查问题 <N>、新素材 <N>、搜索方向 <N>、页面创建建议 <N>）
- 结果: <自动修复 / 仅报告 / 修复建议已执行>
```

## 关键原则

- **确定性问题自动维护**：`wiki/index.md`、顶层 `index.md`、可唯一修复链接和结构字段由 lint 自动修复。
- **启发式问题只报告**：矛盾、陈旧、无法唯一修复的死链、缺页、缺引用等内容修复由用户决策。
- **不修改 `notes/` 和 `raw/`**。
- **不基于 date 推断陈旧**。陈旧仅通过内容冲突识别。
- **建议重于罗列**。每个发现都应附带分析建议。
