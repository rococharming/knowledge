# 按主题选择章节

选择符合材料的骨架，并用实际概念命名标题。各块按需取用，不要为了模板完整而补写内容。

## 概念或语法

````markdown
# 一、定位

[是什么、解决什么问题。]

# 二、核心规则

## 1、规则 A

[解释。]

示例：

```语言
[最小示例]
```

[这里发生了什么。]

## 2、规则 B

[解释或对比。]

# 三、边界

> [!warning]
> [容易误用的条件或限制。]
````

## 工具或配置

````markdown
# 一、用途

[工具在整体流程中的位置。]

# 二、配置

## 1、前置条件

[安装、账号或环境。]

## 2、最小配置

```格式
[真实配置片段]
```

# 三、常用操作

## 1、执行

[命令和结果。]

## 2、验证

[如何确认配置生效。]
````

## 对比或选择

```markdown
# 一、比较前提

[为什么需要比较。]

# 二、核心差异

| 方案 | 适用场景 | 代价 |
|---|---|---|
| A | ... | ... |
| B | ... | ... |

# 三、选择

[用明确条件说明何时选哪一种。]
```

## 优化既有笔记

```markdown
1. 先完整阅读原文，标记重复段落、错位标题、过长代码和缺失解释。
2. 以原有事实重组章节；保持图片、链接、锚点、创建日期和额外属性。
3. 将链接嵌入相关概念段落，删除只为收尾而添加的链接列表。
4. 只在补充资料已验证时添加新事实；否则仅调整结构与表达。
```
