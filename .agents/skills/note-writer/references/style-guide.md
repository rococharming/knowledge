# 技术笔记风格指南

本指南从一批优秀技术笔记（以 Rust 学习笔记为范本）中提炼，描述**通用**技术笔记的风格规范，与具体编程语言无关。生成笔记时遵循这些规范，让笔记结构清晰、可读性强、便于长期维护。

## 核心原则

技术笔记的目标是让读者（包括未来的自己）能快速理解一个概念并上手。好的技术笔记：

- **概念先行**：先讲清楚"是什么、为什么"，再展开"怎么做"。
- **示例驱动**：抽象概念配最小可运行示例，让读者看到具体形态。
- **结构递进**：从基础到进阶，每节独立成段，标题反映内容。
- **网状关联**：相关概念互相链接，形成知识网络。

## 标题层级（中文序数）

用中文序数组织标题，层级严格、一眼可辨：

```
# 一、章节名        ← 一级，大主题分块
## 1、小节名        ← 二级，小主题
### （1）子小节名   ← 三级，细分点
```

要点：

- 一级用"一、二、三…"，二级用"1、2、3…"，三级用"（1）（2）（3）"。
- 标题不要跳级（不要从一级直接跳到三级）。
- 标题反映该节核心内容，不堆砌关键词。
- 标题中的尖括号要转义（如涉及泛型写 `# 三、Vec\<T> 的使用`）。

## 概念先行

每节开头用一两句白话点明这个概念是什么、解决什么问题，再展开细节。避免一上来就甩代码或术语堆叠。

示例（好）：

> 结构体（struct）是一种自定义数据类型，用于把多个相关的数据组合到一起。在 Rust 中，使用 `struct` 关键字定义结构体。

示例（差）：

> struct 关键字定义结构体。语法：`struct Name { field: Type }`。下面看代码。

前者先建立认知锚点，后者直接掉进语法细节。

## 示例驱动

涉及代码的知识点，配**最小可运行**示例：

- 示例前用"示例："引出。
- 代码块标明语言（如 ` ```rust `）。
- 每个示例只演示一个知识点，不混杂多个概念。
- 示例后用一两句解释"这里发生了什么"，帮读者把代码和概念对上。

```rust
fn main() {
    let s = String::from("hello");
    let s2 = s; // 移动
    // println!("{}", s); // 错误，s 已失效
    println!("{}", s2);
}
```

示例后面跟一句解释：`let s2 = s` 之后 `s` 失效，因为 String 的所有权被移动了。

**按内容需要配示例**：纯概念/理论笔记用图示、表格、类比代替代码；语法/特性笔记多配示例；对比笔记用表格。不强求每节都有代码。

## 对比与权衡

归纳多个要点时，用粗体短句 + 列表。对比不同方案时，列举各自的权衡，让读者知道"什么时候选哪个"。

示例：

- **移动（Move）**：所有权转移，源失效。适合独占资源。
- **复制（Copy）**：值被复制，源仍可用。仅限简单值类型。
- **借用（Borrow）**：临时访问，不取所有权。适合只读或临时修改。

对比表格适合维度多、需要并排看的场景：

| 方案 | 适用场景 | 代价 |
|---|---|---|
| GC | 开发体验优先 | 运行时开销 |
| 手动管理 | 性能优先 | 容易出错 |
| 所有权 | 兼顾安全与性能 | 学习曲线陡 |

## 引注与提示

用引用块（`>`）强调核心思想或重要注意事项：

```markdown
> 当值离开作用域，会自动调用其析构逻辑。
```

穿插口语化过渡让笔记更易读："需要注意的是…"、"简单来说…"、"这里的关键是…"。这些过渡能帮读者抓住重点，但要适度，不要每段都来一句。

注意事项和容易踩的坑，用引用块单独标出，避免淹没在正文里。

## 交叉引用

相关概念用维基链接关联，让笔记形成网络：

```markdown
后续学习 [[10、泛型|Trait]] 后，可以为类型实现某个 Trait。
```

- 链接指向同目录或同领域的相关笔记。
- 显示名（`|` 后）用该笔记的简短主题，比完整文件名更易读。
- 只链接真正相关的内容，不要为凑链接而硬连。
- 首次提到某个将在其他笔记详述的概念时，就该加链接。

## 来源去语境化

长期笔记不是来源材料的转述稿，而是面向未来复用的知识页面。处理视频字幕、播客转录、评论区补充或访谈材料时，应把来源中的口语、现场指代和评论语境改写成稳定表述。

- 不写“视频中提到”“作者说”“评论中有人提醒”等无必要溯源话术。
- 把来源表述改写成事实、步骤、限制、注意事项或判断。
- 只有在需要保留争议、评价可信度或引用原观点时，才显式说明来源。

## 图片占位

示意图用 Obsidian 嵌入语法，标注宽度：

```markdown
![[Pasted image 20260513102821.png|300]]
```

如果暂时没有图片，可以在该位置留文字描述（如"内存示意图如下"），后续补图。

## 可调维度

笔记风格可按内容性质调整。生成时自动判断默认值，用户也可在调用时覆盖。

### 风格侧重（--style）

- **教程**（默认适用于语法/特性）：概念→示例→解释，示例密集，循序渐进。
- **概念**：侧重原理和心智模型，少代码多类比图示，适合理论性主题。
- **对比**：多表格、多权衡，并列展示多方案差异。
- **参考**：结构化清单，速查导向，适合 API/命令/配置类。

### 代码示例（--with-code，默认 auto）

- `auto`：按内容需要，涉及代码就配，不涉及就不配。
- `yes`：尽量都配，哪怕伪代码。
- `no`：不配代码，纯文字/图示。

### 详略程度（--depth，默认中）

- `浅`：覆盖主干，每节点到为止，适合入门速览。
- `中`：主干 + 关键细节 + 典型示例，平衡详略。
- `深`：深入原理、边界情况、常见陷阱，适合深挖。

## Frontmatter

frontmatter 使用四个常用字段：

```yaml
---
title: 笔记标题
date: 2026-07-11
tags: [标签1, 标签2]
aliases:
  - 常用别名
---
```

- `title`：笔记标题，与正文一级标题一致或更完整。
- `date`：生成或更新笔记的当前日期，格式为 `YYYY-MM-DD`。
- `tags`：主题标签，2-4 个，覆盖主题和关键技术点。
- `aliases`：1-3 个常用别名，用于 Obsidian 搜索、链接补全和不同称呼之间的统一。

不强制加 `source_count` 等额外字段，保持轻量。
