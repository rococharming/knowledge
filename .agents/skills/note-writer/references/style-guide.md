# 技术笔记统一风格

本指南从 Rust 基础、CSS 和 Claude Code 笔记中提炼共同写法。新笔记与优化后的笔记以本指南为准；目标目录的旧笔记仅提供术语、链接和主题衔接。

## 1. 结构

标题使用中文序数：

```markdown
# 一、定位
## 1、基本概念
### （1）特殊情况
```

- `title` 表示整篇主题；第一节直接是实际知识块，如“简介”“定位”“概述”“安装”，不再重复主题名。
- 从材料组织知识块，不按讲稿顺序，也不固定“关联主题”“组成或对比”“后续”等章节。
- 一级标题下有二级标题时，二级标题至少两个；只有一个子主题时将正文并入一级标题。
- 标题短而准确，优先概念、规则、操作或对比维度，不使用讲稿式长标题。

## 2. 行文

每节先用一两句说明概念是什么、为什么需要它，再展开规则、操作或限制。使用直接、白话的陈述，术语首次出现时给出必要的中文解释和代码形式。

- 用段落承载一个完整意思；多个并列要点用列表；需要横向判断时用表格。
- 把“视频中说”“作者演示”等来源现场语境改写为可复用的事实、步骤或限制；只有保留争议或证据时才显式提来源。
- 不为显得完整而补充没有材料或权威来源支持的结论。

## 3. 示例与提示

- Rust 等语法主题用一个知识点一个最小片段，并在后面解释结果或规则。
- CSS/HTML 等视觉主题在上下文影响效果时给出完整最小页面；仅解释单条规则时可用局部片段。
- 工具、命令和配置主题保留真实字段、命令和验证方式；不要用脱离实际的伪配置替代关键步骤。
- 重要原理可使用普通引用块；风险、限制和易错点使用 `> [!note]`、`> [!warning]` 等语义 Callout。

## 4. Frontmatter 与链接

```yaml
---
title: 笔记标题
date: 2026-08-11
tags: [主题标签, 技术标签]
aliases:
  - 常用别名
---
```

- 新笔记写入四个标准字段；优化既有笔记时保留已有 `date` 和额外属性，只补缺或修复无效格式。
- 标签必须符合 Obsidian 规则；带空格的命令、自然语言短语放入 `aliases`。
- 相关页面在概念首次自然出现的位置链接。仓库内使用 `[[维基链接]]`，外部资料使用普通 Markdown 链接。
- 图片使用 `![[文件名|宽度]]`；保留已有图片、嵌入、锚点和块 ID。

## 5. 优化既有笔记

优化的目标是让原笔记更易读、更一致，不是重写主题：

1. 保留原有事实范围、图片、链接、锚点与可用示例。
2. 重排章节为“概念 → 规则/步骤 → 示例 → 边界”等适合主题的顺序。
3. 合并重复表述，拆分过长段落或过载标题，补足原材料已经支持的解释。
4. 保留原文件名、创建日期和额外 frontmatter；不要因格式调整改变内容含义。

## 6. Obsidian 安全项

- 标题和普通正文中，未处于代码块、行内代码或链接内的 `<` 必须写成 `\<`。
- 维基链接必须指向真实页面，或是明确的既有预留链接。
- 不在末尾追加“相关笔记”链接清单；链接应留在相关概念所在段落。
