# Docker 镜像分层机制

## 一、分层结构

Docker 镜像由**多层只读层叠加**而成。每一层对应 Dockerfile 中的一条指令。

常见的产生层的指令：

| 指令 | 作用 |
|---|---|
| `FROM` | 指定基础镜像，产生一层 |
| `RUN` | 执行命令，产生一层 |
| `COPY` | 拷贝文件，产生一层 |

## 二、分层的好处：复用

分层带来两个核心收益：

1. **磁盘复用**：多个镜像若共享相同的基础层，磁盘上只存一份。
2. **构建缓存**：构建时能命中缓存，未变更的层不会重新构建，加快构建速度。

## 三、写时复制（Copy-on-Write）

容器启动时，Docker 会在镜像层之上**追加一层可写层**：

- 所有运行时的修改都写入这层可写层。
- 镜像本身**保持不变**。

这种机制被称为**写时复制**（Copy-on-Write, CoW）。

## 四、删除文件的陷阱

分层结构也带来一个副作用：

- 在新层中"删除"文件，其实只是在该层**标记删除**。
- 底层镜像中的文件**依然存在**。
- 因此镜像实际体积可能比预期更大。

## 五、小结

| 概念 | 要点 |
|---|---|
| 镜像构成 | 多层只读层叠加 |
| 层的来源 | Dockerfile 每条指令一层 |
| 复用收益 | 磁盘节省、构建缓存 |
| 可写层 | 容器启动时追加，写时复制 |
| 删除陷阱 | 删除只是标记，底层文件仍在 |

> 写 Dockerfile 时，合并 `RUN` 指令、及时清理中间文件，是控制镜像体积的关键手段。
