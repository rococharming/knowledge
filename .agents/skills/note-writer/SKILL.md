# 技术笔记生成与优化

将材料整理为一篇结构清晰、可长期复用的技术笔记，或对一篇既有笔记做同等范围的结构与风格优化。

## 边界

- 一次只处理一篇笔记。`ingest` 负责 raw 素材到 wiki 的批量整合、索引与日志维护；`query` 负责基于 wiki 的问答。
- 生成或改写前必须读取 [style-guide.md](references/style-guide.md) 和 [template.md](references/template.md)。
- 先读取输出位置适用的 `AGENTS.md`、`domain.md` 和写入规则。规则禁止直接改写时，输出完整可复制草稿及变更说明，不写文件。

## 工作流

### 1. 判定任务与材料

区分两种模式：

| 模式 | 输入 | 目标 |
|---|---|---|
| 新建 | URL、本地资料、文本片段或主题 | 生成一篇新笔记 |
| 优化 | 已有 Markdown 笔记，可附补充资料 | 改善该笔记的结构、表达和示例 |

- URL 先用 `defuddle` 提取正文；本地资料直接读取。字幕稿去除时间戳、口语填充和来源现场话术。
- 用户要求“最新”“当前”“核实”时，先查权威一手来源；只做风格优化时，不擅自补充或更新事实。
- 优化模式必须完整读取原笔记，再读取用户提供的补充材料。保留原笔记的主题边界、事实、图片/嵌入、外部链接、块 ID 和有效维基链接；除非用户明确要求，不把它扩写成另一篇笔记。

### 2. 确定输出与元数据

- 新建模式：由用户指定目录；未指定时询问。沿用目录的编号规则，并检查未创建文件的预留维基链接，不能确定序号时先请用户决定。
- 优化模式：默认目标就是原文件。保留文件名、`date`、已有 frontmatter 和额外属性；只补齐缺失的标准字段或修复明确无效的格式。
- 标准 frontmatter 包含 `title`、`date`、`tags`、`aliases`。标签使用合法 Obsidian 标签；别名用于常见中英文名称或旧称。

### 3. 建立写作上下文

扫描目标目录，识别相关术语、真实可链接页面和序号约定。它们只用于术语、链接与主题衔接；章节层级、Callout、frontmatter 和整体组织以 `style-guide.md` 的统一规则为准，不复刻旧笔记的历史格式差异。

### 4. 组织内容

从材料选择合适的知识块，而不是套固定章节：

- 概念/语法：定位 → 规则或组成 → 最小示例 → 边界。
- 工具/配置：用途 → 安装或配置 → 常用操作 → 诊断或限制。
- 对比：比较前提 → 维度表格 → 选择条件。
- 操作流程：目标 → 步骤 → 验证 → 常见阻碍。

用户可用 `--style=教程|概念|对比|参考`、`--with-code=yes|no|auto`、`--depth=浅|中|深` 指定侧重；这些参数只影响详略和表达方式，不改变原笔记的事实范围。

标题使用 `一、` → `1、` → `（1）`。正文第一节直接从实际知识块开始，例如“简介”“定位”“概述”；不要额外创建“主题名”总标题，也不要强加“后续”“相关笔记”结尾。

优化模式优先重排已有段落、合并重复解释、拆分过载章节、补足材料已明确支持的解释和示例。只有在用户提供或已核实资料支持时，才添加新事实。

### 5. 写作与链接

- 每个知识块先用一两句白话说明是什么、解决什么问题，再展开规则、示例或操作。
- 代码、命令、配置和表格按主题选择最小且真实的上下文；页面视觉效果需要完整页面时，提供完整最小页面。
- 仅在概念自然出现的位置添加真实维基链接：同领域且唯一时用短链接，跨领域或重名时用路径限定链接。不要为凑链接创建页尾清单。
- 风险、限制和易错点使用语义明确的 Obsidian Callout；普通核心结论可用引用块。

### 6. 自检与交付

检查：

- 标题层级和序号连续；只有一个子主题时不保留孤立二级标题。
- 正文与标题中非代码位置的 `<` 已转义；代码块、行内代码、链接和嵌入不受影响。
- frontmatter、标签、维基链接、图片嵌入和块 ID 有效；优化时原有有效资源未丢失。
- 没有固定总标题、固定结尾、来源现场话术或无依据扩写。

交付时说明模式（新建/优化）、保存路径或草稿原因、调整内容、相关链接和自检结果。

## 协作

- URL 内容使用 `defuddle`。
- Obsidian 语法遵循 `obsidian-markdown`。
- 领域 wiki 的批量整合改用 `ingest`，基于既有 wiki 的问答改用 `query`。
