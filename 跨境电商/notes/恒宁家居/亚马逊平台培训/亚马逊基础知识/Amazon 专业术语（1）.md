# Listing

Listing 即商品详情页。

例如亚马逊美国站[https://www.amazon.com/dp/B00ETP7D8Y](https://www.amazon.com/dp/B00ETP7D8Y)。

该链接就是一个完整的 Listing 页面：

![[assets/Pasted image 20261012162538.png|800]]

这款商品的标题是 THERMOS Stainless King Vacuum-Insulated Travel Tumbler, 16 Ounce, Matte Black。在电脑上，可以一边看商品页，一边按下面三个区域找：

- 左侧：图片和视频，看商品长什么样。这里就是第一张图就是黑色辈子的主图，以及下方的缩略图，属于商品展示内容。
- 中间：标题与商品要点，看商品是什么。找到标题，再向下看 About this item，有五项商品卖点说明（五点描述）
- 右侧：销售报价，看怎么买。看价格、配送信息，以及购买按钮下的 Shipper / Seller（发货方/卖家），这些帮助你识别当前销售报价。

**Listing 包含商品详情页及关联的卖家销售报价。** 因此，它既有“这只杯子是什么”的展示内容，也有关联卖家提供的价格和配送信息。

>注：ASIN就在这个链接里：amazon.com/dp/**B00ETP7D8Y**，/dp/ 后的 B00ETP7D8Y 是这个商品的编号。

# ASIN

ASIN 即 Amazon Standard Identification Number，亚马逊标准识别码，也就是亚马逊商品编号。它是亚马逊分配的10位唯一字母数字编号。

# SKU

SKU 即Stock Keeping Unit，库存进出计量单位。SKU用于管理自己库存的商品标识。一款商品多尺寸，多属性，多颜色则有多个SKU。

下面仍然以 THERMOS 黑色 16 Ounce 保温杯，B00ETP7D8Y 为例，两位卖家与他们的 SKU 是假设情景，用来说明编号关系；不代表该页面的实际卖家或库存。

![[assets/Pasted image 20261012165214.png|600]]

**两位卖家销售同一件完全匹配的商品时，可以关联同一个 ASIN，并各自使用不同的 SKU。**这称为**跟卖**，后续会介绍。

需要注意的是，SKU是卖家管理用的编码，通常不会作为购买信息展示给买家，因此亚马逊前台看不到。

运营日常中，会有这样的说法：

- 优化 Listing：即改善商品展示与销售信息。
- 查这个ASIN：定位商品。
- 查这个SKU的库存：定位你管理的库存项。

# 父子变体

## 变体及变体主题

变体（Variation）指同一商品家族中按颜色、尺寸等区分的具体版本；这些版本作为子体关联到父体，整体称为变体家族（Variation family）。

**变体主题（Variation theme）** 说明商品按什么属性区分，例如颜色或尺寸；允许的主题取决于商品类型。上面的被子变体主题就是颜色。

进入 [https://www.amazon.com/dp/B00ETP7D8Y](https://www.amazon.com/dp/B00ETP7D8Y)找到标题附近的 Color。如存在折叠，先展开颜色选项，再选择 Midnight Blue（深蓝色）。

![[assets/Pasted image 20261012170155.png|600]]

此时留意标题和网址里的 ASIN，会发现标题中的颜色改变，同时网址里的 ASIN 页发生了变化：

|实际款式|真实子 ASIN|前台观察|
|---|---|---|
|Matte Black · 黑色 · 16 Ounce|[B00ETP7D8Y ↗](https://www.amazon.com/dp/B00ETP7D8Y)|选中黑色时的具体商品。|
|Midnight Blue · 蓝色 · 16 Ounce|[B002PY7AYS ↗](https://www.amazon.com/dp/B002PY7AYS)|从黑色页面切换颜色后，标题变为蓝色，网址变为此 ASIN。|
这是因为不同的颜色有不同的变体，且每个变体的 ASIN 不同。

## 父体与子体

**父体（Parent）是亚马逊目录中用来连接相关子体的虚拟商品记录。** 它表达的是“这些具体款式属于同一个变体家族”。

**子体（Child）** 是每个父体下关联的商品。

例如，以杯子举例，父体本身不对应一只可以买走的杯子，黑色杯子和蓝色杯子才是具体的商品，即对应的**子体**。

建立父子关系后，亚马逊能把这些款式组织到同一个Listing 中，让买家通过颜色选项比较、选择，而不用逐个寻找彼此独立的链接。

![[assets/Pasted image 20261013002715.png|500]]

## SKU 与 父子变体

假设上架这两个真实款式，给自己的记录设置下列 SKU：

| 记录角色 | 自己的 SKU（教学示例） | 关联的父 SKU   | 用途              |
| ---- | ------------- | ---------- | --------------- |
| 父体   | CUP-PARENT    | 无          | 组织子体，不填可售库存。    |
| 黑色子体 | CUP-BLK-16OZ  | CUP-PARENT | 管理你销售的黑色款报价与库存。 |
| 蓝色子体 | CUP-BLU-16OZ  | CUP-PARENT | 管理你销售的蓝色款报价与库存。 |
子体记录通过“父 SKU”指向父体。这个“父 SKU”字段填的是父体的卖家 SKU，例如 CUP-PARENT，与父 ASIN 是两种编号。

## 父体 ASIN

父体也有 ASIN，但在亚马逊前台搜索页一般看到的都是子体 ASIN。如果想快速查看父体 ASIN，可以右键显示网页源代码，搜索`parentAsin`。

# FBA和FBM

FBA 和 FBM 是两种订单的履约方式。所谓履约，可以先理解为：把订单中的商品准备好，发到买家手里。

认识 FBA 和 FBM，就能在真实前台页面分清“谁卖给你”和“谁负责发货”。

- FBA（Fulfillment By  Amazon）

亚马逊配送。卖家先把货送入亚马逊的配送网络；买家下单后，由亚马逊拣货、打包、发货。

- FBM（Fulfillment By Merchant）

卖家自配送。买家下单后，由卖家安排拣货、打包和配送。

仍然以杯子为例，假设买家销售 THERMOS 黑色杯 [B00ETP7D8Y](https://www.amazon.com/dp/B00ETP7D8Y)。

- 采用 FBA：

1. 下单前：你备货，并安排把杯子送入亚马逊配送中心。
2. 下单后：亚马逊从库存中取出杯子、打包并安排送到买家。
3. 订单服务：亚马逊处理相关客服与退货。

- 采用 FBM：

1. 下单前：你安排存放并管理可售杯子的库存
2. 下单后：你组织取货、打包，并安排承运商配送
3. 订单服务：你承担相应客服与退货处理职责，按平台使用相关工具。

>注意：FBA接手的是订单配送工作，使用它，卖家仍需安排备货、入库和补仓。

在前台搜索页也的右侧区域，找到购买按钮下的卖家和配送信息：

![[assets/Pasted image 20261013103249.png|800]]

| 英文标签             | 中文含义        | 回答的问题             |
| ---------------- | ----------- | ----------------- |
| Sold by          | 销售方 / 卖家    | 谁向你销售这件商品？        |
| Ships from       | 发货方         | 由谁负责从库存发出订单？      |
| Shipper / Seller | 发货方与销售方合并显示 | 本次观察中，两种角色显示为同一家。 |
卖家和配送信息可以由不同主体承担：

- Sold by 为 第三方卖家，Ships from 为亚马逊，则是 FBA 模式
- Shipper / Seller 都是第三方卖家，则是 FBM 模式。

除了上述的 Shipper / Seller：hotncoldkitchen 合并显示为 FBM 模式，还有几个例子：

| 链接                                   | 标签                                       | 模式    |
| ------------------------------------ | ---------------------------------------- | ----- |
| https://www.amazon.com/dp/B07ZGMX2MS | Ships from  Amazon<br>Sold by SUNWILL US | FBA   |
| https://www.amazon.com/dp/B01DZQT0FG | Shipper / Seller Amazon.com              | 亚马逊自营 |

**亚马逊自营，就是亚马逊自己作为卖家，把商品卖给买家。** 亚马逊既经营购物平台，也可以在平台上自己卖货。

例如上述的[THERMOS 钢色保温杯](https://www.amazon.com/dp/B01DZQT0FG)，显示 **Shipper / Seller：Amazon.com**。品牌是 THERMOS，销售方却是亚马逊——**自营不等于商品由亚马逊制造。**

| 情况              | 谁销售？Sold by | 谁发货？Ships from |
| --------------- | ----------- | -------------- |
| **亚马逊自营**       | Amazon      | Amazon         |
| **第三方卖家使用 FBA** | 第三方卖家       | Amazon         |
| **第三方卖家使用 FBM** | 第三方卖家       | 第三方卖家          |
# FNSKU

FBA 和 FBM 都需要卖家 SKU，用来区分和管理你的销售记录。

FNSKU（Fulfillment Network Stock Keeping Unit，配送网络库存单位）是使用 FBA 服务时生成的一种独特商品编码，便于亚马逊 FBA 仓储系统标识、管理和追踪库存。

当产品以 FBA 模式进行配送时，由亚马逊 FBA 系统生成，通常以 X0 开头，也称  X0 码。

![[assets/Pasted image 20261016134746.png|300]]

SKU 和 FNSKU 的区别：

| 编号    | 主要用途                         |
| ----- | ---------------------------- |
| SKU   | 让你区分和管理自己的销售记录，FBA、FBM 都会使用。 |
| FNSKU | 供亚马逊在 FBA 配送网络中识别相关商品库存。     |

假设你销售两款杯子，每只单独出售，并采用亚马逊条码管理 FBA 库存。对应关系可以这样理解：

| 款式  | 你的卖家 SKU     | 亚马逊分配的 FNSKU | 库存数量 |
| --- | ------------ | ------------ | ---- |
| 黑色杯 | CUP-BLK-16OZ | 黑色款对应的 FNSKU | 30 只 |
| 蓝色杯 | CUP-BLU-16OZ | 蓝色款对应的 FNSKU | 20 只 |

这 30 只黑色杯使用同一个对应的 FNSKU；20 只蓝色杯使用另一个对应的 FNSKU。黑色杯卖出一只后，数量从 30 变为 29，编号不变。

因此，**FNSKU 识别的是相应的一类库存，不是每只杯子各自的序列号。**

采用亚马逊条码时，亚马逊把相应的库存识别编号做成可扫描条码。卖家从后台打印商品标签，贴到对应商品的单件销售包装上，供仓库扫描识别。

可以把三者分开理解：

- **FNSKU：**库存识别编号。
- **亚马逊条码：**供仓库扫描读取的条码。
- **商品标签：**承载条码、贴在实物包装上的标签。

是否需要另贴亚马逊条码标签，要看商品适用的条码要求。

**制造商条码**指商品原有的商品条码，例如包装上常见的零售条码 **UPC（Universal Product Code，通用产品代码）**。下面的“品牌登记”是亚马逊的品牌管理计划，“品牌代表”是其中的一种销售角色。

美国站针对 **2026 年 3 月 31 日及以后发出的库存**，规则包括：

| 情况                         | 条码要求                            |
| -------------------------- | ------------------------------- |
| 未取得亚马逊品牌登记“品牌代表”销售角色的转售卖家。 | 即使商品已有 UPC 等制造商条码，也需要使用亚马逊条码贴纸。 |
| 在品牌登记中取得“品牌代表”销售角色的品牌所有者。  | 商品已有制造商条码并符合相关资格时，可使用制造商条码。     |
| 商品没有制造商条码。                 | 品牌所有者和转售卖家都需要使用亚马逊条码贴纸。         |

所以，如果你是没有上述品牌代表资格的 THERMOS 转售卖家，按这项规则发货到美国站 FBA，就需要给商品贴相应的亚马逊条码标签。
