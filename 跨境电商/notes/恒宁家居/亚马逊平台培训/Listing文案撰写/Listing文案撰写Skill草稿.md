## 1、确认输入：明确产品、买家和写作范围。

开始前，需要这些资料：

| 输入                        | 用来做什么                |
| ------------------------- | -------------------- |
| 产品事实：材质、尺寸、功能、工艺、配件、测试数据等 | 确定哪些内容有依据、可以写        |
| 目标站点与语言                   | 确定文案语言，例如美国站用英文      |
| 产品类目                      | 判断产品表达方式及需要核对的字段限制   |
| 目标买家、使用场景                 | 决定重点解决谁的问题           |
| 可用关键词                     | 作为标题、正文和后台搜索词的输入     |
| 本次输出范围                    | 确定只写标题，还是写完整 Listing |

## 2、拆解资料：从买家角度找疑问

它会以“不熟悉产品的买家”的视角重新读资料，找出：

- 看不懂的术语，例如某种材料或工艺名称。
- 没有依据的评价，例如“品质好”“非常舒适”。
- 可能有价值、但尚未讲清楚的功能。
- 会影响购买判断的缺失信息。

例如，资料写“椅子可以折叠”，买家还可能想知道：折叠后有多大、如何收纳、是否需要拆卸。

这一步产出的是疑问和资料缺口，还没有开始写正式卖点。


## 追问事实：把模糊评价变成可用依据

| 原资料      | 需要追问的内容            |
| -------- | ------------------ |
| “节省空间”   | 折叠前后尺寸是多少？         |
| “经久耐用”   | 有什么材质、结构或测试依据？     |
| “方便携带”   | 重量是多少？有没有提手？       |
| “解决用户痛点” | 有哪些真实反馈、退货原因或客服记录？ |
它也会询问使用场景，以及你希望买家最先记住哪个特点。

**缺少事实时，Skill 要求先列问题、等待补充，不能自行补数字或认证。** 最终仍无法证实的卖点，应删掉或缩小表达范围。

## 3、做 FAB 转换：将事实变成购买理由

这是它的核心步骤：

| 层次           | 要回答的问题     | 示例                  |
| ------------ | ---------- | ------------------- |
| Feature：特性   | 产品有什么？     | 椅子可以折叠              |
| Advantage：作用 | 这个特性有什么作用？ | 闲置时可以收起，减少占地        |
| Benefit：好处   | 对买家有什么意义？  | 小房间需要活动空间时，可以把椅子收起来 |
它会检查每个卖点是否同时满足两点：买家能理解具体好处，而且这个好处能追溯到产品事实。

例如，“可以折叠”可以支持收纳便利的表达；“能放进任何床底”则需要尺寸和适配依据。

这一步形成 **“事实｜作用｜好处｜使用字段”对照表**，作为后续文案的基础。


## 4、**安排信息：决定先讲什么、如何说服**

卖点明确后，它会按三个标准组织信息：

| 标准   | 具体做什么                  |
| ---- | ---------------------- |
| 注意力  | 把最相关的痛点或差异点放在前面        |
| 理解效率 | 用具体场景和日常语言解释功能，减少抽象形容词 |
| 说服效果 | 用真实参数、测试和证据支撑表达        |
例如，如果目标买家是小户型用户，“闲置时方便收纳”可能比某个次要工艺更靠前。

对于描述或 A+，参考资料还提供了 **AIDTA** 思路：吸引注意 → 引起兴趣 → 让买家想象使用体验 → 提供信任依据 → 给出行动理由。它允许灵活安排，无须机械套用顺序。

## 5、撰写字段：让不同位置承担不同任务

| 字段                     | 当前 Skill 的写作要求                    |
| ---------------------- | --------------------------------- |
| **标题 Title**           | 说明品牌、产品是什么、核心关键词、关键差异和规格；重要信息靠前   |
| **五点 Bullet Points**   | 每条围绕一个卖点，用“好处＋事实依据”表达，五条之间避免重复    |
| **产品描述 Description**   | 展开场景、使用体验和购买疑问                    |
| **A+ 内容**              | 分模块组织卖点和证据，避免照抄五点                 |
| **后台搜索词 Search Terms** | 补充同义词、拼写变体、材质词、场景词等，按其说明避免重复前台已有词 |

## 6、自检修改

成稿需要整理成“字段名：内容”的形式，再运行附带的检查脚本。

脚本主要检查：

- 各字段长度，后台搜索词按字节计算。
- 一组预设的促销、绝对化、医疗、安全及环保相关表达。
- 链接、联系方式、emoji，以及部分全大写单词。

发现问题后，修改文案并重新检查。

**这个脚本是辅助检查工具。** 它使用固定参考上限和词表，不会自动核实产品事实、检查完整的关键词覆盖，也不会读取亚马逊后台的最新类目规则。脚本通过，代表其检查项通过。


## 7、交付：同时给成稿与依据

默认交付一份 Markdown，包含四部分：

| 交付内容    | 你可以检查什么            |
| ------- | ------------------ |
| FAB 对照表 | 每个卖点来自什么事实、给买家什么好处 |
| 待确认清单   | 还有哪些资料缺口           |
| 各字段成稿   | 可以复制使用的 Listing 文案 |
| 自检结果    | 长度和预设风险词的检查情况      |

FAB 翻译 写亚马逊 Listing

| 层次                | 含义        | 以可折叠椅子为例            |
| ----------------- | --------- | ------------------- |
| **F — Feature**   | 产品有什么特性   | 椅子可以折叠              |
| **A — Advantage** | 这个特性有什么作用 | 收起后占用空间更小           |
| **B — Benefit**   | 给买家带来什么好处 | 用完可以收进角落，为小房间腾出活动空间 |
所以，它会把：

> “采用可折叠结构。”

写成类似：

> “用完即可折叠收起，为小房间腾出更多活动空间。”

这里的翻译，指的是从产品视角转换到买家视角，并解释它给买家带来的具体好处。
